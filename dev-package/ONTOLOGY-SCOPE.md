## ① 요약 — 무엇을 담고 무엇을 뺐나

D9 가 먹여 살릴 소비처는 **계약으로 이미 두 개로 닫혀 있다**(`contracts/seams/core-ai.yaml`).

| 소비처 | 계약이 요구하는 출력 | 그것을 만들려면 D9 에 무엇이 필요한가 |
|---|---|---|
| **계보 제안**(K3 · E-04) | 부모 데이터셋 후보 + `methodText`(가공 방식 한 줄, 자유문자열 1~120자) + 확신도 3값 + 근거 한 줄 | 정본이 든 제안 근거는 **파일 헤더·이력 속성의 직접 참조 · 같은 프로젝트 소속 · 격자 해상도 변화 · 이름 유사** 넷이다(목업 E-04). 이 넷 중 **온톨로지가 필요한 것은 없다.** 필요한 것은 제안 문장에 쓸 **가공 방식 어휘 후보**뿐 |
| **자연어 검색**(K4 · E-02) | 데이터셋 id + 관련도 막대 + 근거 한 줄 | 정본이 든 유일한 해석 예시가 3축이다 — **"'25년도'는 2025년, '낙동강 유역'은 공간, '강우데이터'는 강수 주제로 모두 일치해요"**(목업 E-02·제품). 필요한 것은 **주제 동의어**와 **유역 이름 별칭** 정도 |

그래서 이 초안이 제안하는 1차 범위는 **셋뿐**이다.

- **A. 가공 방식 어휘 후보 목록** (제안 문장 생성용 · 값을 닫지는 않는다 → §④-1)
- **B. 주제 동의어 사전** (검색 질의 → 주제 고정 목록 4값)
- **C. 유역·지명 별칭 사전** (검색 질의의 공간 축 인식용 · **위계가 아니라 별칭만**)

**범위 밖으로 뺀 것** — `DOMAINS §2` 가 D9 소유물로 열거했으나, 정본이 값을 주지 않았고 두 소비처가 그것 없이도 계약대로 동작한다.

| 뺀 것 | 왜 빼는가 |
|---|---|
| **관측소 명부** | 정본에 관측소가 **시각화 표현 방식**으로만 나온다(`P03` "점(관측소 등)은 값 크기에 따른 원 마커"). 명부·좌표·식별자가 한 건도 없다. 두 소비처 어디도 관측소를 요구하지 않는다 |
| **행정 공간 위계** | 정본에 행정구역이 **참조 레이어**(DEM 음영·행정경계, `P03`)로만 등장한다. 시군구 목록도 유역↔행정 대응도 없다 |
| **유역 위계(상·하위 유역 그래프)** | 정본은 `낙동강 유역`·`한강 상류`·`금강 하굿둑`·`소유역`을 **이름으로만** 쓴다. 포함 관계를 정의한 곳이 없다. 검색은 별칭 매칭(C)으로 충분하다 |
| **좌표계 온톨로지** | 좌표계는 **EPSG 외부 표준**이고 파일 헤더에서 자동 추출되며(`DM §4.1`), 계약도 `crs: string` 자유문자열이다. D9 가 다시 정의할 것이 없다 |
| **데이터 출처 기관 마스터** | 정본이 원천을 **"데이터셋이 아니라 표기"**로 못 박았다(`DM §4.1` 원천 표기 · `P04 §4`). 자유문자열 0~60자다. 기관 엔티티를 만들면 정본이 거부한 것을 되살린다 |
| **변수 표준 사전** | 변수는 파일 헤더에서 자동 추출되고 사람이 타이핑하지 않는다(`PRD04 §6`). 정본이 준 것은 예시 4~5개뿐이라 사전이라 부를 수 없다(§②) |

> 이 절이 이 WU 의 값어치다. **범위를 좁힌 결과가 결론이다** (`CLAUDE.md §5` 범위 늘리기 금지).

## ② 범주별 표

각 범주에 대해 ⑴ 정본이 준 값 ⑵ 정본이 안 준 것 ⑶ v2 1차 필요 여부 ⑷ 출처.

### 2.1 변수

⑴ **정본이 준 값(전수)**
- `tp · 강수량 (mm)` / `t2m · 2m 기온 (K)` / `sp · 지면 기압 (Pa)` — 미리보기 변수 선택 (목업 E-04·E-03)
- `RR · QC` — 다른 데이터셋의 변수 표기 (목업 E-04)
- 화면 표기 파생: `유역 평균 강수량` · `유역 평균 기온` · `유역 평균 기압` (목업 E-03)
- 규칙: 변수 목록은 **파일에서 자동으로 읽는다**(`DM §4.1`), 조각 묶음은 모든 조각의 변수가 같아야 한다(`DM §4.3`)

⑵ `[정본 무근거]` — **변수 사전이 없다.** `DOMAINS §2` 가 예시로 든 **유출·수위는 정본 어디에도 변수로 등장하지 않는다.** 표준 변수명 ↔ 한국어 이름 ↔ 단위의 대응표, 변수 동의어(`tp`↔`강수량`↔`강우`)도 없다.

⑶ **1차 범위 밖.** 계약(`UploadedFileMeta.variables`)이 헤더에서 읽은 문자열 배열을 그대로 넘긴다. 검색의 주제 축은 주제 고정 목록(2.2)이 맡는다.

⑷ 출처 — **업로드 메타에서 자동 추출**(D5 파서 → D3 저장). 사람이 적지 않는다.

### 2.2 주제 (검색이 실제로 쓰는 분류 축)

⑴ **정본이 준 값 — 고정 목록 4값**(`P04 §5 입력값 규칙`): **`강우·강수` · `식생·NDVI` · `지형·DEM` · `토지피복·LULC`**
- "연구실이 항목을 추가할 수 없다 — 목록이 늘면 검색·데이터 맵의 묶음 기준이 깨진다. 항목 추가는 운영팀이 한다"(`P04 §5`)
- 검색 해석 예: `'강우데이터'는 강수 주제로 일치`(목업 E-02) → **동의어가 실제로 필요한 유일한 증거**
- 0건 예시: `금강 · 염분`(`P02 §3.3`) — 목록에 없는 주제

⑵ `[정본 무근거]` — 주제별 동의어 목록이 없다. 또 **정본 내부 불일치가 있다**: 홈 데이터 맵 목업(제품_260817)의 주제별 막대는 `강우·강수 / 식생·NDVI / 지형·DEM / **유출·수문**` 으로, `P04 §5` 의 `토지피복·LULC` 대신 `유출·수문` 을 쓴다 → §④-2.

⑶ **필요(B).** 다만 **주제 값 자체는 D3 소유**(사람이 고정 목록에서 고른다)이고, D9 가 갖는 것은 **질의어 → 주제 4값 매핑(동의어)** 뿐이다.

⑷ 출처 — 값은 **정본 고정 목록**, 동의어는 **D9 시드**(K2).

### 2.3 좌표계

⑴ **정본이 준 값(전수)** — `EPSG:5179` (`EPSG:5179 (Korea 2000 / Central Belt)`, 목업 핵심시나리오) · `EPSG:4326` (목업 제품, 데이터 목록) · `GK2A 정지궤도 격자` (목업 E-04 — **EPSG 코드가 아닌 표기**)

⑷ 출처 — **정본 인용 목록(위 표)을 D9 시드로**. 사람이 고쳐 쓴 문장은 D4 에 저장되지만 **D9 로 되돌아오지 않는다**(D10→D4 방향 규칙과 대칭으로, 학습 루프를 1차에 만들지 않는다).

## ④ 결정이 필요한 것 (Ted)

### ④-1. 가공 방식 어휘 — enum 인가, 자유 문자열인가 ★ 세 세션이 막힌 자리

| 선택지 | 내용 | 얻는 것 | 치르는 대가 |
|---|---|---|---|
| **(가) 자유 문자열 유지 (현행)** | `methodText` 1~120자 그대로. D9 는 이 범주를 아예 갖지 않는다 | 정본과 100% 일치. 계약·DB 무변경. 발명 위험 0 | 계보 화살표 라벨이 사람마다 제각각(`유역 평균` vs `유역별 평균` vs `basin mean`). 카탈로그에서 가공 방식으로 좁힐 수 없다. K3 제안 문장의 표현이 흔들려 평가셋을 만들기 어렵다 |
| **(나) enum 으로 닫기** | §2.6 후보 13개를 값 집합으로 확정, `common.json` 에 추가 | 라벨 일관성. 필터·집계 가능. 제안 품질 측정 쉬움 | **정본 위반이다.** `P04 §5` 가 자유 문장 1~120자로 못 박았고 `DM §4.2` 의 예시(`일 단위 평균 후 유역 경계로 잘라냄`)는 어떤 enum 값에도 안 들어간다. 계약·DB·FE 동시 개정. **목록에 없는 가공을 한 사람이 사실을 못 적는다** — 정본의 "모르면 모른다고 남긴다" 정신과 충돌 |
| **(다) 하이브리드 — 자유 문자열 + 제안 후보 목록** *(초안 권고)* | 저장·계약은 (가) 그대로. D9 는 §2.6 의 13개를 **시드 어휘**로만 갖고, K3 제안 문장 생성과 업로드 화면 자동완성 후보에 쓴다. 사람은 언제든 다른 문장을 쓴다 | 라벨이 자연히 수렴. 계약·DB·정본 무변경. 사람의 자유 유지 | 강제력이 없어 완전한 일관성은 안 온다. 시드 목록을 유지할 자리가 하나 는다(K2) |

**결정 필요:** (가) / (나) / (다) 중 하나. 초안 권고는 **(다)**.
> (다) 를 고르면 계약·스키마를 건드리지 않으므로 **D2·D3 산출물 재개정이 없다.**

### ④-2. 주제 고정 목록 — 정본 내부 불일치

`P04 §5`(문서, 정본): `강우·강수 / 식생·NDVI / 지형·DEM / **토지피복·LULC**`
홈 데이터 맵 목업(제품_260817): `강우·강수 / 식생·NDVI / 지형·DEM / **유출·수문**`

| 선택지 | 대가 |
|---|---|
| (가) 문서(`P04 §5`) 4값이 정본 | 목업 홈 화면과 어긋난 채 구현된다 |
| (나) 5값으로 확장(`토지피복·LULC` + `유출·수문`) | 정본 어느 문서에도 5값이 없다 — 범위 확대이므로 정본을 먼저 고쳐야 한다 |
| (다) 기획 정본 수정 요청 후 대기 | K2·P2 가 그만큼 기다린다 |

**결정 필요.** D9 의 주제 동의어 사전이 이 값에 매달려 있다. (주제 값 자체의 소유는 D3 다 — 여기서는 "무엇에 동의어를 달 것인가"만 묻는다.)

### ④-3. 주제 동의어·지명 별칭을 D9 시드로 둘 것인가

정본이 요구하는 것은 검색 근거 문장 한 줄(`'강우데이터'는 강수 주제로 일치`)이고, `PLAN-SoT §9-㊶` 로 검색 엔진은 **Postgres(tsvector+pgvector) 단독**이 됐다.

| 선택지 | 대가 |
|---|---|
| **(가) D9 시드로 둔다** *(초안 권고)* | 어휘가 한 자리에 모이고 K3·K4 가 같은 사전을 본다(`WORK-UNITS` "의미 체계가 두 벌 생긴다"는 경고의 해소). 대신 D9 저장소·시드 WU(K2)가 실제로 필요해진다 |
| (나) Postgres 검색 사전(`ts_config` 동의어)에만 둔다 | D9 가 사실상 비게 되어 K1·K2 를 축소·통합할 수 있다. 대신 계보 제안(K3)은 그 사전을 못 본다 — 의미 체계가 두 벌 생긴다 |

### ④-4. 결과로: D9 를 1차에 **둘 것인가**

위 셋을 (다)·(가)·(가)로 고르면 D9 의 1차 내용물은 **세 개의 작은 사전(가공 방식 후보 · 주제 동의어 · 지명 별칭)**이다. 그래프 DB 도, 개념 유형 체계도 필요하지 않다.

**결정 필요:** K1(온톨로지 스키마)을 **그래프 구조로 만들 것인가, 세 개의 시드 테이블로 만들 것인가.** 초안 권고는 **후자** — 정본이 준 값의 양이 그래프를 정당화하지 않는다. (도메인 분리·마이그레이션 체인 분리 규칙 `CLAUDE.md §3-3` 은 그대로 지킨다.)

## ⑥ K1 이 이어받을 것

이 문서가 승인되면 K1(온톨로지 스키마)은 아래만 한다. **승인 전에는 착수하지 않는다.**

1. **범주 3종의 저장 형태 정의** — 가공 방식 후보 · 주제 동의어 · 지명 별칭. §④-4 의 결정에 따라 그래프 or 시드 테이블
2. **저장소 분리 확인** — `db/ai` 는 `db/platform` 과 **마이그레이션 체인이 분리**된다(`CLAUDE.md §3-3` · `DOMAINS §5`)
3. **읽기 전용 Port 시그니처** — D10 만이 소비자다(`DOMAINS §2` "D10 전용"). D9 는 D1~D8 어느 테이블도 참조하지 않는다
4. **K2 시드의 커버리지 기준** — `WORK-UNITS` K2 완료 정의의 "핵심 어휘 미커버 0" 에서 **핵심 어휘 = §2.6 표의 정본 인용 13개 + 주제 4값 + 지명 4개**로 고정(승인 시 확정)
5. **넘기지 않는 것** — §③ 의 `[정본 무근거]` 10건은 K1 이 채우지 않는다. 채우려면 정본 개정이 먼저다
