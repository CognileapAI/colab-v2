# DOMAINS — v2 도메인 분할

> 이 문서가 **무엇을 무엇과 섞지 않을지**의 정본이다. 코드·스키마·소유권·계약이 전부 여기서 갈린다.
> 화면(에픽)은 도메인이 아니다. 에픽은 사용자가 보는 단위, 도메인은 **소유와 변경이 갈리는 단위**다.

---

## 1. 분할 기준 두 개

도메인 경계를 그을 때 쓰는 자는 둘뿐이다. 다른 이유(파일이 커서, 개념이 달라서, 관습적으로)로는 자르지 않는다.

### 기준 A — 협업 (누가 소유하고, 어디서 손이 바뀌는가)

경계는 **사람이 갈리는 지점**에 그린다. 손이 바뀌는 곳에만 계약이 필요하고, 손이 바뀌지 않는 곳에 계약을 두면 의식(ceremony)만 늘어난다.

| 소유 집단 | 무엇을 정하는가 | 산출물의 성격 |
|---|---|---|
| **수문학 도메인** | 변수·좌표계·유역·관측소·가공 방식의 의미 체계 | 어휘와 규칙. 코드보다 빨리 바뀐다 |
| **플랫폼 개발** | 무엇이 저장되고 누가 볼 수 있는가 | 스키마와 API. 느리게, 소급 없이 바뀌어야 한다 |
| **AI 엔지니어링** | 제안·해석·근거를 어떻게 만드는가 | 모델·프롬프트·평가. 실험적으로 바뀐다 |
| **프론트엔드** | 화면과 상호작용 | 생성된 타입만 소비 |

세 집단의 산출물이 한 저장소에 섞이면 **아무도 소유자가 아니게 된다.** 이것이 도메인을 나누는 첫째 이유다.

### 기준 B — 개발 최적화 (에이전트 한 컨텍스트에 담기는가)

AI가 개발한다. 전통적인 팀 규모·조율 비용 대신 두 제약이 지배한다.

| 제약 | 뜻 | 경계 규칙 |
|---|---|---|
| **컨텍스트 윈도우** | 에이전트 하나가 한 번에 legible하게 다룰 수 있는 책임은 3~4개 | 도메인 하나 = 한 에이전트가 스펙·스키마·테스트·구현을 통째로 들 수 있는 크기 |
| **조율 비용 ≈ 0** | 병렬 dispatch가 사실상 공짜 | 의존이 적을수록 병렬도가 오른다. **의존을 줄이는 절단이 항상 이긴다** |
| **드리프트 = #1 버그** | 인수인계 암묵지 손실이 기계적 불일치로 나타난다 | 경계는 기계가 강제한다 — 계약 게이트·import-linter·스키마 diff |

> 모듈 ≠ 서비스 ≠ 레포. **도메인을 10개로 나누는 것과 서비스를 10개 띄우는 것은 다른 결정이다.** 런타임 분리는 워크로드 프로파일이 실제로 다를 때만(§4).

## 3. AI 도메인을 분리하는 이유 — 세 가지

### ① 정본 규칙을 구조로 보증한다

260818 정본은 **"AI가 제안하고, 사람이 확인한 것만 계보로 확정된다"**를 규칙으로 못 박았다. [모두 승인] 버튼조차 두지 않았다.

이 규칙을 코드 관례로만 지키면 언젠가 깨진다. **D10이 D4(Lineage) 테이블에 쓰기 권한을 갖지 않게 만들면** 규칙이 구조가 된다.

```
D10 계보 제안  →  제안 저장소(임시, D10 소유)  →  화면에서 사람이 확인
                                                        ↓
                                            D4 Lineage 커밋 (사람 행위로만)
```

제안은 D10 안에서 태어나 D10 안에서 죽는다. 확인된 것만 경계를 넘는다.

### ② 변경 속도가 다르다

| | 변경 주기 | 소급 비용 |
|---|---|---|
| D1~D8 스키마 | 느리다. 마이그레이션 필요 | 높다 — E-00이 "여기서 틀리면 뒤가 전부 소급된다"고 적어둠 |
| D9 온톨로지 | 빠르다. 어휘·관계가 계속 는다 | 낮다 — 지식은 다시 적재하면 된다 |
| D10 프롬프트·모델 | 가장 빠르다. 실험 단위 | 없다 |

같은 저장소·같은 마이그레이션 체인에 두면 **온톨로지 한 줄 추가가 플랫폼 마이그레이션을 기다린다.** 반대로 플랫폼 스키마 변경이 진행 중인 실험에 막힌다.

### ③ 소유자가 다르다

D9는 **수문학을 아는 사람**이 정한다. "낙동강 유역이 어떤 행정구역을 포함하는가", "리샘플과 보간이 같은 가공인가"는 개발 판단이 아니다. D9를 플랫폼 스키마에 녹이면 그 판단이 개발자에게 떠넘겨지고, 결국 아무도 검증하지 않는다.

## 4. 런타임 분리 — 도메인 10개 ≠ 서비스 10개

도메인은 **코드 소유권**의 단위다. 배포 단위는 워크로드 프로파일이 실제로 다를 때만 나눈다.

| 배포 단위 | 담는 도메인 | 프로파일 |
|---|---|---|
| **core-api** | D1 D2 D3 D4 D6 D8 | stateless · IO bound · 지연 민감 · **geo 라이브러리 0** |
| **pipeline-worker** | D5 | 고 CPU·메모리 · bursty · 스팟 가능 |
| **viz-render** | D7 | 중 CPU · 캐시 가능 · geo 라이브러리 필요 |
| **ai-service** | D9 D10 | 외부 모델 호출 · 지연 편차 큼 · 실패가 제품을 멈추면 안 됨 |
| **frontend** | — | 정적 |

**ai-service를 따로 띄우는 이유는 성능이 아니라 격리다.** 모델 호출이 느리거나 실패해도 카탈로그 조회와 업로드는 계속 돌아야 한다. AI는 v2에서 두 지점의 **보조 기능**이지 경로상 필수가 아니다 — 정본이 그렇게 설계했다.

## 5. 경계 강제 규칙 (기계가 검사한다)

| 규칙 | 강제 수단 |
|---|---|
| 도메인은 자기 테이블 + D1(shared kernel)만 참조. 타 도메인 테이블 직접 FK·접근 금지 | `import-linter` 계약 + 테이블 접두사 |
| 도메인 간 호출은 Port 경유만 | `import-linter` |
| **D10 → D4 쓰기 경로 없음** | D10에 Lineage 쓰기 Port 자체를 주지 않는다 + 음성 테스트 |
| **D9/D10 저장소는 D1~D8과 마이그레이션 체인 분리** | 별도 스키마 · 별도 alembic head |
| core-api에 geo 라이브러리 import 금지 | banned-import 게이트 |
| 모든 조회에 연구실 경계 자동 주입 | tenant-scoping 커널 + PostgreSQL RLS + cross-tenant 음성 테스트 |
| 단일 정규 ID 타입 | shared kernel 1곳 정의 (ULID `CHAR(26)`) |
| FE는 생성된 타입만 사용 | codegen + generated-up-to-date 게이트 |

> 마지막 세 줄은 v1(PoC)에서 실제로 터진 버그의 재발 방지다 — `users.id`를 String(20/30/36)로 제각각 선언한 스키마 드리프트, FE-BE 타입 수동 동기화, 한 줄 스코프 누락으로 인한 타 연구실 노출.

## 7. 승인권자 배정 (WU-D1)

> **소유자 = 그 도메인의 스키마·계약·규칙을 바꿀 때 승인하는 사람** (`PLAN-SoT §9-㉒`).
> 코드 오너십도, 배포 단위 책임도 아니다. 배정 근거와 딸린 규칙은 `PLAN-SoT §9-㉚`·`§9-㊴`.
>
> ✅ **닫혔다** (2026-08-23, WU-D1).

**승인권자는 Ted 한 사람이다.** 별도의 수문학 도메인 소유자를 두지 않는다(`§9-㊴`).
Ted 가 다른 사람을 지정하면 **아래 표의 해당 칸만** 바꾼다 — 구조는 그대로다.

| 도메인 | 승인권자 | 협의 필수 | 근거 |
|---|---|---|---|
| D1 Identity & Lab | Ted | — | shared kernel. 순수 플랫폼 판단 |
| D2 Access & Policy | Ted | 정본 대조 | 규칙의 실사용자가 교수다(§2 "한 사람이 한 화면에서 다루는 판단"). 다만 역할 2층·스위치 4종은 정본이 이미 확정해 남는 것은 구현 판단이다 |

### 딸린 규칙 3개 (배정만으로는 성립하지 않는다)

1. **자기 승인의 형식** — 8개 도메인에서 승인자와 변경자가 같다. 그대로 두면 승인이 아무것도 거르지 못한다. Ted 소유 도메인의 변경은 **`PLAN-SoT §9` 에 값과 근거를 남긴 것만** 승인된 것으로 본다. 세션 종료 규약이 이미 요구하는 것이라 새 비용이 없다.
2. **협의 필수의 의미** — 협의자가 반대하면 막힌다는 뜻이 **아니다**. **협의 없이 한 변경은 되돌릴 수 있다**는 뜻이다. 비대칭이라 협의 비용을 적게 쓴다.
3. **인원 증가를 전제한 문구를 여기 적지 않는다.** 없는 미래를 적으면 다음 세션이 그것을 실체로 읽는다. 지정이 생기면 그때 칸을 바꾼다.
4. **D9 의 판단은 정본에서 길어 온다.** 어휘·관계·범위는 기획 정본에서 **인용해 오고**, 정본에 없으면 **`[정본 무근거]` 로 남기지 만들지 않는다.** `§3-③` 이 경고한 것 — 도메인 판단이 개발자에게 떠넘겨져 결국 아무도 검증하지 않는 것 — 을 막는 방어가 이것이다. **판단의 출처를 사람에서 문서로 옮기면 검증이 가능해진다.**
