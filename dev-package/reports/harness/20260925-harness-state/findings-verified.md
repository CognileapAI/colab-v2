### R1-hooks — Claude hooks
Summary: The Claude Code hook layer registers 11 hooks in .claude/settings.json. Each .claude/hooks/*.sh file is a 3-line adapter that calls a shared script in scripts/harness/hooks. The hook list in .agents/harness.yaml exactly matches settings.json, and a test checks that match. Most hooks have direct tests: git-guard, migration-guard, decision-number-guard, the H6/H7 SubagentStop evidence hooks, researcher-task, ponytail-inject and bootstrap-diet. The biggest problem is that test-file-guard does nothing in Claude lanes. It only turns on when COLAB_FIX_LANE=1 is set in the environment of the Claude Code process, and nothing on the Claude side sets it per lane. The design-fix round saw this happen, yet design-review SKILL.md still says fix lanes run with the guard on. Second, css-edit-audit writes plain stdout on PostToolUse, and the repo's own quoted hook docs say that output never reaches the model, so its UI feedback never reaches the model on Claude while Codex gets it through the bridge. git-guard stops the forms it lists, but it judges the branch from the payload cwd, not from a `git -C` target. It only catches the exact `gh pr merge` command and misses bundled force flags. It also reads text inside heredocs and quotes as commands: in this session it blocked my own notes heredoc as a non-ff merge on develop. All Edit/Write guards can be bypassed by writing files through Bash. The PreToolUse guards and H6/H7 fail closed when python3 is missing. H6/H7 also ignore the COLAB_HOOKS=0 kill switch, which the README says works for every hook. worktree-setup does create venvs and run npm ci, but only when a lane-worker is spawned. It works in the payload cwd and deletes any venv without its own stamp, so lane-workers running in the parent checkout can delete and rebuild venvs, possibly at the same time. The README hook section is badly out of date (7 hooks vs 11, origin/main vs origin/develop, old H6/H7 behavior). The /hooks re-trust after #130 has no record, so no one has confirmed that researcher-task and ponytail-inject are active on this PC.
