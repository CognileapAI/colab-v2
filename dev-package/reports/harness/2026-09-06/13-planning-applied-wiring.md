## 1. 왜 「이동」이 아니라 「매니페스트 ＋ 사본」인가

정본 폴더 색인(`40 COLAB-기획/README.md`)은 `30_적용완료/` 를 「반영이 끝난 입력물 원본을 `10` 에서 **이관**」으로 적었다. 그대로 집행하면 규칙 둘이 정면으로 부딪친다 —

| 규칙 | 요구 |
|---|---|
| 폴더 색인 | 적용이 끝나면 `10_적용전` → `30_적용완료` 로 **옮긴다** |
| `rules §7` | `10_적용전/` 은 **읽기 전용** · 파일명·내용 변경 금지 |

옮기는 것은 그 파일에 대한 쓰기다. 그리고 `dev-package` 원장 여러 곳이 `10_적용전/<파일명>` 을 경로로 인용하고 있어(PRD-260905 §0.2 자료표 3행 포함) 이동은 그 인용을 전부 끊는다.

**해소** — 「적용됐다」는 사실을 기획 폴더의 파일 배치로 표현하지 않고 **레포의 매니페스트 한 파일**로 표현한다. 폴더는 사본을 받는다.

- 적용 상태의 **원본** = `dev-package/prd/planning-applied.yaml` (커밋·리뷰·게이트 대상)
- `40 COLAB-기획/30_적용완료/<라운드>/` = **사본 보관소** (원본과 바이트 동일)
- `40 COLAB-기획/10_적용전/` = 무수정 · 무이동 · 인용 경로 그대로 유효

## 2. 기계장치 5줄

1. **매니페스트** `dev-package/prd/planning-applied.yaml` — 문서별로 `source`(기획 폴더 기준 상대) · `author` · `rounds` · `applied_round` · `status`(merged\|in_progress\|pending) · `applied_date` · `decisions` · `prd`/`intent`/`spec` · `copy` · `copied_at` 을 적는다.
2. **게이트** `planning-freshness`(`dev-package/tools/check-package-freshness.py`)가 두 번째 판정을 추가로 낸다 — ㈎ `status: merged` 항목은 `30_적용완료/` 에 **원본과 sha256 동일한 사본**이 있어야 한다 ㈏ `30_적용완료/` 아래 모든 파일은 매니페스트에 등재돼 있어야 한다. 병합 전 사본(`EARLY-COPY`)·원본 부재·`applied_date` 누락도 red 다.
3. **동기 도구** `dev-package/tools/planning-applied.py --sync [--apply]` — 기본 dry-run. `--apply` 는 `shutil.copy2` 로 **복사만** 하고, 복사 뒤 해시를 재대조한 다음 그 항목의 `copy`·`copied_at` 줄만 고쳐 쓴다(전체 `yaml.dump` 금지 — 주석·따옴표·순서가 통째로 갈린다). 쓰기 전 되읽어 항목 수·id 가 그대로인지 확인하고 어긋나면 **쓰지 않는다**.
4. **판정 규칙은 한 곳에만 있다** — 동기 도구가 검사기 모듈을 `importlib` 로 불러 `check_applied`·`copy_rel`·`_sha_file` 을 그대로 쓴다. 도구와 게이트가 서로 다른 기준을 갖는 상태를 만들지 않았다.
5. **선언 없는 것은 red** — 매니페스트 부재 · PyYAML 부재 · YAML 파손 전부 red 다(skip 아님 · `CLAUDE.md §4`).

## 3. 워크트리 경로 해소 (기존 red 1건)

- 증상 = 워크트리에서 `planning-freshness` 가 「정본 폴더가 없다: `…/30 CoLAB-v2/.claude/worktrees/40 COLAB-기획/…`」로 red. 실측 로그 = `pe-sweep-3.12.log` 37~40행.
- 원인 = 검사기가 자기 파일에서 세 단계 위를 레포 루트로 봤다. 워크트리에서 그 자리는 `<레포>/.claude/worktrees/<이름>` 이라 작업공간이 두 단계 어긋난다.
- 조치 = `git rev-parse --git-common-dir` 로 **본 체크아웃의 `.git`** 을 얻고 그 부모를 레포 루트, 다시 그 부모를 작업공간으로 삼는다. git 이 없으면 옛 방식으로 물러선다.
- **두 루트를 갈랐다** — 레포 **밖**(기획 폴더)은 본 체크아웃 기준, 레포 **안**(매니페스트)은 지금 검사받는 트리 기준이다. 섞으면 워크트리가 본 체크아웃의 매니페스트를 검사해 브랜치 변경분이 안 보인다(집행 중 실제로 한 번 그렇게 나와 고쳤다).
- 자리 이동은 `COLAB_PLANNING_ROOT`(정본 패키지) · `COLAB_PLANNING_HOME`(`40 COLAB-기획`) · `COLAB_PLANNING_MANIFEST`(매니페스트) 세 환경변수가 받는다. 종전 `COLAB_PLANNING_ROOT` 의 뜻은 바뀌지 않았다.

## 6. 다음 라운드가 하는 일 (환류가 실제로 도는 자리)

1. R-A′ 병합 → 매니페스트 `rev2-260905-이태헌` 의 `rounds` 에서 R-A′ 소진 확인. 아직 R-B 가 남으므로 `in_progress` 유지.
2. R-B 병합 → `status: merged` · `applied_round: R-B` · `applied_date` 기입 → `--sync --apply` → 게이트 green.
3. 새 기획 입력물이 `10_적용전` 에 들어오면 **먼저 매니페스트에 `pending` 으로 등재**한다. 등재 없이 사본만 생기면 게이트가 `UNLISTED` 로 red 를 낸다.

## 7. 후속 (이번 범위 밖 · 판정 필요)

1. **`planning-freshness-selftest` 가 `ALL_GATES` 에 없다.** 검사기의 `--selftest` 는 실재하나 게이트 이름으로 등록돼 있지 않아 `run.sh all`·`run.sh selftest` 가 돌지 않는다. 등록하면 fixture 2·3 이 정본 마운트를 요구해 CI(contract-gates 잡)에서 red 가 된다 — 등록하려면 면제표 기재 또는 fixture 분리가 먼저다.
2. **폴더 색인 문안이 실제와 갈린다.** `40 COLAB-기획/README.md` 는 `30_적용완료/` 를 「`10` 에서 이관 · `적용일_원파일명`」으로 적었으나 집행은 「사본 · `<라운드>/<원파일명>`」이다. 기획 폴더는 읽기 전용 취급이라 이번에 고치지 않았다 — 개정 제안만 남긴다.
3. **`10_적용전` 밖의 입력물은 아직 등재 대상이 아니다.** `00_기획원본/` 의 목업 패키지·`업로드_계보_260825` 는 임베드 판정(①)이 이미 보고 있어 중복 등재하지 않았다. 두 판정의 담당 범위를 문서 한 줄로 못 박을지는 판정 사항이다.
4. **사본 폴더의 git 관리 여부 미정.** `40 COLAB-기획` 은 레포 밖이라 사본 3건은 어떤 커밋에도 들어가지 않는다. 호스트가 바뀌면 사본이 없어 게이트가 red 를 내고, 그때 복구 절차는 `--sync --apply` 한 줄이다(원본이 있는 한 무손실). 별도 백업 대상으로 삼을지는 판정 사항이다.
