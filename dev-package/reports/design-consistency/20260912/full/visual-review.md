# 전체 화면 시각 검토

승인 intent: `dev-package/intent/2026-09-12-design-consistency.md`.
대표안 수용 뒤 실제 제품 컴포넌트와 동일한 `src/shell/styles.ts`를 쓰는 정적 fixture를 검토했다. 모바일 375px, 태블릿 768px, 데스크톱 1440px 각각 light/dark. 상태 목록과 원본 PNG는 `scenes.json` / `screens/`, 비교 이미지는 `contact/`, 탐색은 `gallery.html`.

## 직접 확인한 문제와 교정

- 기본 select·button처럼 보이던 카탈로그/프로젝트 필터와 빈 연구실 시작 안내를 공통 글꼴·40/44px 컨트롤·카드 여백으로 통일했다.
- 프로젝트 목록/상세 표는 모든 열을 유지하고 내부 가로 스크롤 및 좁은 화면 안내를 제공한다.
- 업로드 파일명 한 글자 줄바꿈, 등록 폼의 축소, 모바일 기간/좌표계/격자 칸의 오른쪽 잘림을 교정했다. 변수 표는 의도한 내부 스크롤을 유지한다.
- 카탈로그 계보 배지 `.lin`과 업로드 계보 컨테이너 `.lin` 충돌로 연결 안내와 버튼이 잘리던 문제를 선택자 범위 분리로 해결했다. `residual-checks.json`은 양 테마에서 계보 높이, 내용 너비 및 폼 경계를 검증한다.
- 미리보기 구간 수 select와 검색 오류/없는 주소 링크에 남은 UA 기본 스타일을 공통 테마로 연결했다.
- ParentPicker 선택 버튼의 모바일 최소 너비 및 primary 글자색, 승인 취소 버튼의 dark 글자색을 교정했다.
- 프로젝트 생성 모달은 제목/본문/푸터를 구분하고 긴 본문만 스크롤한다. 실제 키보드 검사에서 오류 표시, Tab 순환, 마지막 입력칸, Escape 후 초점 복귀를 확인했다.

## 수용 판단과 계측 예외

목록은 비교하기 쉬운 밀도를 유지하고, 폼·안내는 읽을 여백을 둔다. light/dark의 표면·본문·상태색을 구별하며 기능·문구·권한·업무 상태는 유지한다. `Verified` 취소선은 기존 미승인 상태 표현으로 확인하여 유지했다.

정적 CSS 계측은 18개 파일에서 미정의 토큰 0건이다. 9px 선언 2건은 카탈로그 정렬/체크 장식이며 체크 표시는 실제 공통 규칙에서 13px로 덮인다. 본문 글자 면제로 취급하지 않는다. detail의 정적 대비 경고 1건은 같은 규칙만 읽는 계측이 최종 cascade를 적용하지 못한 경우다. 실제 화면의 글자색/배경색 계측과 대조한다. 로컬 토큰 선언은 기존 구조에 남아 있으며 전부 tokens.css로 물리적으로 옮겼다고 주장하지 않는다. 카드 그림자는 없애고, 포커스/선택 상태 inset 경계와 팝오버는 구분한다. reduced-motion은 공통 셸 규칙에서 적용한다.

긴 페이지의 full screenshot은 스크롤바 제거 과정에서 오른쪽 끝 테두리가 잘린 것처럼 보이는 경우가 있다. 실제 뷰포트 screenshot과 DOM 경계 검사에서 로그아웃 버튼 접근성 및 문서 너비를 대조했다. 이미지의 잘림만으로 화면 정상 여부를 판정하지 않았다.

## 검증 환경의 범위

초기 Vite 개발 서버 반복 탐색 중 간헐적 빈 화면이 발생하여 최종 촬영은 production 모드의 정적 audit 빌드(5180)로 전환했다. 실패한 초기 탐색 로그는 이력이며 최종 성공 촬영으로 세지 않는다. 별도 실제 앱 빌드(5179)에서도 로그인·Gnb·localStorage 테마 동작을 검증한다. 두 빌드는 동일한 제품 컴포넌트와 CSS 진입점을 소비한다.

상태 fixture의 백엔드는 격리된 로컬 응답이며 운영 서비스로 전달하지 않는다. 지도 그림도 합성 fixture다. 업무 데이터 저장·서버 지도 렌더 성공 E2E나 실제 iOS/Safari 기기 검증으로 확대하지 않는다. 대상은 선언된 경로 및 30개 상태이고 모든 가능한 데이터/권한 조합을 뜻하지 않는다.
