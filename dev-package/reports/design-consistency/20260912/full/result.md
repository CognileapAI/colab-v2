# 전체 화면 디자인 정비 결과

승인된 대표 디자인을 전체 화면에 적용하고 검수를 마쳤다. 글꼴·글자 위계·간격·컨트롤·상태색을 공통 기준으로 연결했다. 모바일 폼 잘림과 화면 간 CSS 이름 충돌도 교정했다.

- 공통 스타일: `frontend/src/shell/styles.ts`, `design-system.css`, `tokens.css`.
- 테마: 시스템/밝게/어둡게 선택, 새로고침 지속, OS/다른 탭 동기화, 저장 차단 시 현재 화면 유지.
- 카탈로그/프로젝트 표는 내부 가로 스크롤, 폼은 넉넉한 여백과 고정된 실행 푸터를 사용한다.
- 업로드의 계보 영역과 목록 배지 선택자를 분리하고, 모바일 입력칸 너비와 미리보기 구간 수 컨트롤을 교정했다.

## 검증

- 30개 화면 상태 × 375/768/1440px × 밝게/어둡게 = **180개 화면** 촬영·계측. 모든 상태의 6개 변형을 비교 이미지로 직접 검토했고 문제가 보인 모바일 원본을 확대 대조했다.
- 계측상 13px 미만 본문, 대비 4.5 미달, 문서 가로 넘침, 브라우저 오류 **각 0건**. 폰트 실제 로딩 확인.
- 실제 앱 빌드의 테마·로그인·Gnb **11단계**, 키보드/필터/모달/표 스크롤 **8개**, 추가 폼 경계/계보/미리보기 검사 **6개** 통과.
- frontend-typecheck / frontend-test / frontend-fixture-reach / frontend-visual **4개 게이트 통과, 회귀 테스트 1,216개 통과**. 타입 검사 및 제품·audit 빌드 통과. fixture 별도 엄격 타입 검사와 diff 공백 검사도 통과.
- 첫 회귀 실행은 1,214/1,215 통과. 실패한 대비 검사는 hex 리터럴만 읽던 방식이 공통 변수 참조를 해석하도록 보완했다. 양 테마의 실제 토큰을 검사하며 미정의/순환 참조를 실패시키고 대비 합격선 4.5를 유지했다. 최종 전체 실행 건수는 `task-gates.log`와 `gate-summary.json`이 정본이다.

전체 촬영과 병행한 회귀 실행에서 비동기 화면 대기 검사 3건이 실패했다(`run-with-contention.log`). 해당 3파일은 코드 변경 없이 별도 실행하여 42개 모두 통과했다(`retry-three.log`). 최종 전체 게이트는 촬영을 마친 뒤 worker 4개로 실행했다. 시간 초과의 실행 부하 영향이 의심되지만 일반적인 무결함 증명으로 해석하지 않는다.

회귀 1,216개가 통과한 다음 실행에서는 마지막 visual 단계의 로컬 서버 접속이 거절됐다(`run-server-stopped.log`). 최종 실행은 `run-with-server.py`가 서버를 같은 프로세스의 스레드로 유지하고 readiness를 확인한 뒤 필수 게이트 4개를 한 번에 수행했다. 부분 실행들을 합산하지 않았다.

## intent 대조

| 원한 결과 | 결과 |
|---|---|
| 차분하고 정돈된 도구 | 절제된 의미 색상, 공통 글꼴/글자 위계/여백 적용 |
| 촘촘한 목록, 여유 있는 폼/안내 | 표의 열 보존, 카드/폼 여백과 모달 본문 스크롤 적용 |
| 대표 확인 후 전체 확장 | 대표안 긍정 확인 뒤 전체 적용 |
| 실제 시각 검토와 회귀 검사 | 180개 변형 직접 대조 및 현재 코드의 4개 게이트 통과 |
| 모바일·양 테마 동일 기준 | 세 너비와 두 테마 계측, 키보드 및 테마 지속성 확인 |

선언한 범위의 미달·미해결 항목은 없다. 업무 기능·권한·API 변경, 메뉴 개편, 배포·push·커밋·제품 데이터 변경은 수행하지 않았다.
