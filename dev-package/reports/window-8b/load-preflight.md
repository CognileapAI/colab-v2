## 2. OOM 가드 — 실측으로 좁혔다 (`〈349〉`-㉱)

**물음** = 서버(core-api **384m** on `t4g.small`)가 요청 본문을 메모리에 담는가.

**실측 ⑴ — 라우트는 파일을 하나씩 흘려 보낸다.**
`services/core-api/.../routes/ingestion.py:239-250` — `for upload_file in files:` 안에서
`_storage(request).put_stream(key=..., stream=upload_file.file)` 를 **파일마다** 부른다.
같은 파일 82행 축자 — 「종전 `await upload_file.read()` 전량 적재가 **5GB 업로드 하나로 프로세스를 멈췄다**」.
⟹ **데이터셋 전량(최대 1.35 GB)이 한꺼번에 메모리에 오르지 않는다.**

**실측 ⑵ — 그런데 s3 모드의 `put_stream` 은 파일 **하나**를 통째로 읽는다.**
`kernel/storage_backends.py:184-201` 축자 — 「**`read()` 폴백이다 — 진짜 스트리밍이 아니다.**
SigV4 가 `x-amz-content-sha256` 에 **본문 전체 해시**를 넣어 서명하므로 본문을 다 읽기 전에는
요청을 시작할 수 없다」 ⟹ `payload = stream.read()`.
⟹ **메모리 상한을 정하는 것은 「가장 큰 파일 하나」다.**

**실측 ⑶ — 가장 큰 파일 = 149,514,336 B(`file_format_1_grib/00.Data/surface.grib`).**
그다음 = `04.Lat_Lon_info` 의 npy **107,164,928 B ×4**(tif 벌). **300 MB 넘는 파일 0건.**

**판정 —**

| 값 | 실측 |
|---|---|
| core-api 상한 | **384 MiB** (EC2 `dev.env`) |
| 배포 뒤 정상 RSS | **85.9 MiB** |
| 최대 단일 파일 | **142.6 MiB** (149,514,336 B) |
| 예상 피크 | ≈ 85.9 ＋ 142.6 ＋ 서명·전송 사본 ⟹ **여유가 크지 않다** |
| 스왑 | 4 GB 활성 · 사용 0 |

⟹ **경로 (b) 를 택한다** — 프리사인드 직행은 `load-seed.py` 가 부르는 op 넷에 없다(코드 변경 없이는 못 쓴다).
**회차 오름차순(1 → 2 → 3 → 4)** 으로 돌리고 **회차 사이마다** `docker stats`·`dmesg`·헬스를 잰다.
가장 큰 파일이 든 **회차 4(`FF-*`)를 마지막**에 두는 것이 이 순서다.

⛔ **규칙(`〈349〉`-㉱ 그대로)** — 어느 단위든 OOM-kill 되면 **그 자리에서 멈추고 보고**한다.
남은 데이터셋은 **「미적재 · 사유 = 서버 메모리」** 로 적는다. **재시도하지 않는다.**

**회차별 크기** — 회차1 = `LD-PRCP-LV0-HSR`·`LD-PRCP-LV0-RN15`·`LD-VEG-LV0`(60 파일 · 179.5 MB) ·
회차2 = `LD-PRCP-LV1`·`LD-VEG-LV1`·`LD-VEG-LV1-MODELIN`·`LD-DRGH-LV1`(16 파일 · 137.7 MB) ·
회차3 = `LD-PRCP-LV2`·`LD-VEG-LV2`(32 파일 · 203.8 MB) · 회차4 = `FF-*` 5건(326 파일 · **3,259.9 MB**).

⚠ **디스크도 함께 본다** — 멀티파트 본문은 파트마다 임시 파일로 흘러간다.
회차 4 의 `FF-HDF5` 한 요청이 **1.35 GB** 를 임시로 쓴다. EC2 여유 **8.2 GB** ⟹ 선다.
S3 로 올라가는 총량 3.78 GB 는 버킷이라 문제가 아니다.

## 3. ⛔ 적재를 막는 것 — `topic` 이 DB CHECK 4값 밖이다

**실측** — `db/platform/schema.sql:370`

```
topic text CHECK (topic IS NULL OR topic IN ('강우·강수', '식생·NDVI', '지형·DEM', '토지피복·LULC'))
```

**매니페스트가 쓰는 값** — `강수` 4건 · `식생` 4건 · `파일 포맷` 5건 · `가뭄` 1건 = **14건 전건이 4값 밖**이다.

**앱 층에 enum 검사가 없다**(`routes/catalog.py` 전수 — `topic` 을 거르는 자리 0건) ⟹ 값이 **DB 까지 내려가
CHECK 에 걸린다**. `load-seed.py` 는 `createDataset` 가 201 이 아니면 `Abort` 다 ⟹ **첫 데이터셋에서 멈춘다.**
⭐ **조용히 틀리지 않고 시끄럽게 실패한다** — 그 점은 다행이나, **지금 상태로는 한 건도 적재되지 않는다.**

### 고치는 법 둘 — ⛔ 이 레인이 고르지 않는다

**⑴ 기계적 대응(값 매핑).** `강수` → **`강우·강수`** · `식생` → **`식생·NDVI`** 는 **뜻이 정확히 같은 자리**라
지어내는 것이 없다. 그러나 **`가뭄`(1건)·`파일 포맷`(5건)에는 줄 값이 없다** ⟹ **`NULL`** 뿐이다.
⟹ **14건 중 6건이 주제 없이 선다.** Ted 가 폴더로 나눈 분류의 일부가 카탈로그에서 사라진다.

**⑵ 정본 개정.** `topic` CHECK 에 값을 더한다(**계약·스키마 개정 ＋ 마이그레이션 ＋ 게이트**).
`가뭄`·`파일 포맷` 이 정말 「주제」인지가 먼저 정해질 자리다.

⭑ **이것은 `level-format-check.md §4` 의 결정 ①(가뭄 `topic`)과 같은 물음이고, 아직 답이 없다.**
Ted 판정은 「A안으로 적재하라」였고 **`topic` 어휘는 그 판정이 다루지 않았다.**
되돌릴 수단이 0 이므로(`deleteDataset` 501) **여기서 멈춘다.**
