# 미커밋 검수 도구 정리

사용자 승인: 현재 폴더의 작업을 하나씩 판단해 커밋·계속·중복 정리하고 Stage3 신규 작업을 준비한다(2026-09-12).

- 기존 `frontend/audit.vite.config.ts`에 업로드·대표 화면·갤러리 진입점을 모았다. 중복 `vite.audit.config.ts`는 채택하지 않았다.
- 참조가 없는 `design-preview.css` 재수출 파일은 채택하지 않고 현재 공통 스타일을 사용한다.
- 나머지 원본 검수 파일과 업로드의 공통 스타일·테마 변경을 보존했다. 제품 `frontend/src`, 서비스, DB, 배포 코드는 변경하지 않았다.
- 지도 예시 SVG가 빌드에서 누락되는 실패를 `asset-red.json`으로 확인한 후 URL import로 수정했다. 정적 파일 출력을 강제하여 타일 쿼리가 데이터 URL에 붙지 않게 했다.
- 별도 TypeScript 설정으로 검수 진입점까지 검사하고 실행 방법을 `frontend/README-audit.md`에 기록했다. 검수 빌드 생성물은 Git에서 제외하여 다시 미커밋 파일로 쌓이지 않게 했다.

로컬 확인 대상은 `127.0.0.1:4187`의 모의 화면이다. 외부 계정·제품 데이터를 사용하지 않는다. 지도 이미지 로딩, 갤러리 테마·너비 선택, 데이터셋 표, 업로드 화면을 확인한다. 저장·조회 E2E를 수행했다는 의미는 아니다.

실행 증거는 이 폴더의 빌드 로그, 브라우저 결과, 스크린샷과 `gates`에 둔다. 최초 빌드는 audit 설정의 `node:url` 타입 해석 실패였고, 의존성을 추가하지 않고 frontend 기준 상대 진입점으로 수정했다. 지도 자산 실패 기록은 과거 실패로 남긴다. 검수 번들 크기 경고는 제품 번들 문제로 확대 해석하지 않는다. 의존성 설치 시 기존 고정 의존성에서 high 2건이 보고됐으며 이번 정리에서 의존 버전은 바꾸지 않았다.

원본 2,259개와 채택하지 않은 두 진입점도 보호 백업 `repo-cleanup-20260912T102532Z`에 보존했다. 기존 근거 906개 커밋과 별도로 이 도구 변경을 커밋한다.
