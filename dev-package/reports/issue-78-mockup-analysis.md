## 3. 중요한 발견: 자동으로 읽는 것과 입력칸에 보이는 것이 다르다

- 목업과 현행 카드 부제에는 “파일에서 읽는 값은 확장자·용량뿐”이라고 적혀 있다.
- 하지만 실제 워커는 지원 포맷에서 변수·기간·좌표계·격자를 읽고 `file.header-parsed`로 전달한다.
- 현재 업로드 상태 API는 이 값 전체를 등록 폼으로 전달하지 않는다. 폼의 해당 값은 빈 상태에서 시작한다.
- 서버는 등록 시 사람이 비운 CRS·기간·격자를 보완하는 경로가 있다. 이 설명을 모든 변수·모든 포맷의 자동 입력으로 일반화하면 안 된다.
- 따라서 “화면에 자동 표시하는 정보”라는 설명은 검토할 수 있지만, 이미 읽은 값을 폼에 미리 채우는 것은 API·상태 연결 및 사용자 수정값 보존 정책이 필요한 별도 개선이다.

코드 근거: `RegisterArea.tsx` 메타데이터 카드 부제/확장자·용량 영역; `UploadModal.tsx` 초기 메타데이터 상태; pipeline-worker `d5_ingestion.py`의 `file.header-parsed`; core-api `routes/ingestion.py` 상태 응답 및 등록 시 COALESCE 보완.

## 4. 발산한 개선 후보와 비용

### A. 예시와 안내만 맞추기 — 가장 작은 범위
- 목업의 변수 네 칸 예시와 좌표계 예시 복원.
- 관측 간격 숫자 예시/단위 선택 안내 수정.
- 예시는 실제 값으로 저장하지 않는다.

### B. 세 단계의 입력 안내를 함께 정리하기 — 권고
- A를 포함한다.
- 분류: 각 선택의 뜻과 가공 단계→연결 가능 범위 관계를 기존 안내 안에서 일관되게 표현.
- 메타데이터: 기간은 자료가 다루는 시작/종료, 관측 간격은 값과 값 사이의 간격임을 구분. 대표 변수는 무엇을 대표하는지 안내하되 선택 정책은 바꾸지 않음.
- 자동 정보/직접 입력 설명을 실제 UI 동작에 맞춤. 필요하면 #77의 “사람이 적어요” 문구와 겹치는 범위도 합의해 기록.
- 연결: 가공 전 데이터 연결과 외부 출처의 차이, 이미 연결한 항목의 상태를 기존 카드에서 명확히 표현.
- 화면 크기·입력칸 폭·3단계 순서·저장 계약·필수 여부는 유지.
- 기존 설명에 없는 새 안내 문구는 시안으로 제시한 뒤 intent에서 확정한다. 새 도움말을 모든 칸에 무조건 늘리는 방식은 피한다.

### C. 실제 입력 작업까지 줄이기 — 별도 intent 권고
- 파싱된 메타데이터를 폼의 제안값으로 제공하고, 사람이 바꾼 값과 출처를 구분.
- 프로젝트 검색 및 후보 필터.
- 대표 변수 초기 자동 선택, 필수 항목/기본값/공개 범위 정책 변경.
- 위 항목은 서로 별개 결정이며 한꺼번에 승인된 것으로 취급하지 않는다. A/B보다 API와 정책 영향이 크다.
