# 로그인 전수 감사 — 2026-09-12

범위: WSL stage 계정 구현 사본의 로그인 입력·발급·서명·세션 버전·첫 비밀번호 변경·관리자 권한·프론트 세션 저장 및 오류 복구. 제품 파일 수정·추가 배포·운영 DB/사용자 비밀번호 변경 없음. 전체 기존 테스트와 별도 결함 재현을 구분한다.

## 발견 사항 7종 — 미수정

1. **우선 수정: 비밀 입력 오류응답 반사.** 실제 create_app을 TestClient로 열고 /api/v1/sessions에 513자 초과 시험 password/accessCode를 보냈다. 각각 HTTP 400이며 응답에 원문 marker 포함 True. app/main.py의 str(exc.errors())가 input을 포함한다. DB 평문 저장 또는 제3자 유출을 입증한 것은 아니다. 시험값만 사용했고 원문 출력은 하지 않았다.
2. **네트워크 실패 후 재시도 불가.** LoginPage와 PasswordChangePage가 fetch 예외 후 busy를 해제하지 못한다. 실제 React 컴포넌트를 사용한 네트워크 거부 대역 시험 2건으로 확인.
3. **늦은 401이 새 세션 삭제.** 이전 토큰으로 보낸 요청의 응답이 새 토큰 설정 뒤 도착하면 api/client.ts가 현재 토큰을 무조건 제거한다. 지연 응답 대역으로 재현.
4. **탭 간 로그아웃 미동기화.** 실제 StorageEvent 시험에서 localStorage 삭제 후 store.getToken()의 이전 cached 토큰 유지. 서버 logout 자체가 토큰을 회수하지 않는 기존 설계와 구분한다.
5. **이메일 길이 불일치.** 유효 형태의 137자 이메일은 AccountCreate 모델 허용, SessionCredentials 모델 거절. 생성 최대320·로그인 최대128의 불일치다. 모델 검증 재현이며 이 이메일로 실제 DB 계정을 만들지는 않았다.
6. **부분 혼합 로그인 입력과 자격 제한 우회.** accessCode+accountName(비밀번호 없음)을 허용한다. 실제 create_session 함수·PlantedCodeIssuer·AttemptLimiter(max3)로 같은 잘못된 코드 5회: 단일형401/401/401/429/429, 이름을 바꾼 혼합형401/401/401/401/401. 동일 클라이언트 버킷을 함께 적용하면401/401/401/429/429다. 클라이언트 제한까지 완전히 우회한다고 주장하지 않는다.
7. **문자 길이 단위 불일치.** 화면 UTF-16과 서버 Unicode 코드포인트. 😀5개 화면10/서버5, 😀257개 화면514/서버257. 이전 실제 배포 모델 검사에서 확인한 미수정 결함이다.

## 통과 및 기존 증거

이전 추가 검사에서 실제 격리 DB 동시 변경 성공1·거절1·version2, 인증 재조회 경합의 옛 토큰 거절, 비운영자 교수 POST403·계정/자격 불변을 확인했다. 순차 옛 토큰401/일반 토큰 재변경403과 초기 비밀번호 재사용400도 기존 테스트에 있다. 배포 인증 파일 5종과 소스 일치도 앞선 검사에서 확인했다. 이번 결과를 그 검사의 신규 재실행이라고 표현하지 않는다.

## 한계

프로세스 메모리 기반 시도 제한은 재시작/다중 worker 사이에 공유되지 않는다. 서버 logout의 기존 서명 토큰 즉시 회수는 구현돼 있지 않다. 변경 commit 뒤 find 재조회 장애 가능성은 검토 의견이며 장애주입 실재현은 이번 범위에서 하지 않았다. 외부 침투시험·부하인증·브라우저별 전수 호환성을 완료했다고 주장하지 않는다.
