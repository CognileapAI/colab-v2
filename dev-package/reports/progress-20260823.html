02

왜 이 순서인가

이 프로젝트에서 진행을 지배하는 변수는 시간이 아니라 의존이다. 그래서 "무엇을 먼저 할까"가 아니라 "무엇이 무엇을 막고 있는가"로 계획을 읽는다. 아래 그림에서 버튼을 눌러 지금과 이름이 들어온 뒤를 비교해 보라.

왜 D1 이 D9 를 막는가

"도메인 소유자"는 코드 오너십이 아니라 변경 승인권자로 정의됐다. 도메인 열 개 중 아홉은 Ted 이고, D9(온톨로지·KG)만 HYD 다. 그런데 G8 의 완료 판정 자체가 "수문학 도메인 소유자 승인"이다 — 승인할 사람이 지정되지 않으면 G8 이 닫힐 방법이 없고, K 트랙 다섯 개가 전부 그 뒤에 있다. 계약(D2)은 이 값을 소비하지 않으므로 플랫폼 쪽은 계속 갈 수 있었지만, 지식 쪽은 갈 수 없다.

03

이번에 닫힌 것

여덟 개가 닫혔고 하나가 절반 왔다. 각각 한 줄 요지와, 왜 그것이 중요한가.

D2 ✅

계약 동결 — 문서가 아니라 타입으로

공통 스키마 정본(정의 21종·값 집합 enum 9종) · seam 3종 fe-core(op 34) core-ai(op 2) core-viz(op 5) · 이벤트 봉투 7종.

왜 중요한가. 정본이 못 박은 AI 응답 규격 — 확신도 3단계 enum, 근거 필수, 배치 승인 없음 — 이 이제 문서의 약속이 아니라 스키마다. 특히 core-ai seam 에는 계보를 확정하는 오퍼레이션이 없다. 있어서 안 되는 게 아니라 아예 없어서, D10 → D4 쓰기 경로가 코드로 존재할 수 없다. 규칙을 지키는 대신 규칙을 위반할 수단을 제거했다.
동결에 딸린 판단 셋
㉟ 표기 규약 — 속성 이름은 영문 lowerCamelCase, enum 값은 정본 한국어 그대로. 영문 코드값을 만들면 정본에 없는 어휘를 발명하게 되고 코드↔DB↔화면 매핑 테이블이 생긴다. 예외는 라우팅 키 성격인 이벤트 type 하나(upload.accepted).

㊱ 잠김은 403 이 아니라 200 + bodyAccessible:false — 403 으로 접으면 이름·요약이 응답에서 사라져 잠긴 데이터에 접근 요청 버튼이 붙을 자리가 없어지고 E-06 승인 흐름이 죽는다. 연구실 경계 밖은 404(존재를 알리지 않는다), 권한 스위치 위반은 403. 세 축을 하나로 합치지 않았다.

㊲ 멱등 키 둘 — eventId(재전달에도 불변) + idempotencyKey(결정론적). 하나로는 두 중복 경로 중 하나만 막는다.
D3 🟦

경계 강제 장치 — 절반, 그리고 red 가 정상이다

import-boundary(계약 7개) · banned-import · ai-no-lineage-write(음성, red 조건 12개) 배선 완료. boundary-selftest 30 케이스 전부 의도대로 green.

왜 중요한가. 세 게이트 자체는 지금 red 다. services/·db/ 에 코드가 없기 때문이다. "AI 가 계보에 쓰지 않는다"와 "AI 가 아직 없다"는 다른 사실이라, 0건을 green 으로 세지 않았다. 게이트가 살아 있다는 증명은 검사 결과가 아니라 selftest 가 한다 — 위반 fixture 를 넣으면 실제로 red 를 낸다. v1 CI 가 DB 없이 돌아 RLS 테스트를 조용히 통과시킨 것과 정확히 반대 방향의 설계다.
남은 절반
migration-single-head · schema-diff · rls-coverage 셋이 미구현이다. 부수 산출로 모듈 경로 관례가 확정됐고 P0 가 이것을 따른다. selftest 는 contract-selftest 와 합치지 않고 분리했다 — 계약 게이트는 spectral·docker 에, 경계 게이트는 파이썬 venv 에 의존하므로 합치면 도커 없는 환경에서 경계 증명까지 함께 죽는다.
G7 ✅

기획 정본 통합 — 깨진 링크 38 → 1

260808 인덱스 6파일을 260818 정본 루트로 통합·갱신. 상대 링크 222개 중 깨진 것은 1개만 남았다(P1 README 의 없는 패키지 html, P1 은 1차 범위 밖이라 미수정).

왜 중요한가. 이건 미용 작업이 아니라 정본의 구조적 결손이었다. G3(권한) 수행 중, 정본 Policy_역할과_권한 v1.3 이 "권한표 원본: IA_사이트맵.md 7장" 을 가리키는데 그 파일이 정본에 없다는 것이 드러났다. 스윕해 보니 깨진 링크 38건이 전부 통합 대상 인덱스를 가리키고 있었다. 원본을 못 본 채 권한 원칙을 닫았다면 나중에 다시 열어야 했다 — 그래서 G7 을 G3 앞으로 당겼다.
G1 ✅

패키지 신선도 게이트 — 재빌드는 필요 없었다

임베드 블록 15개가 8개 에픽 전부에서 원본과 sha256 일치. 낡은 것은 내용이 아니라 "미반영"이라 적어둔 서술이었다.

왜 중요한가. 오라클을 content-hash 전용으로 못 박았다. 파일명(260817)과 mtime 은 둘 다 거짓말을 한다. selftest 가 변조 fixture 와 정본 부재 두 경우 모두 red 를 냄을 증명한다. 이 게이트가 매일 도는 한 같은 착각이 다시 생기지 않는다. 블로커 하나(#5 패키지 재빌드)가 여기서 소멸했다.
G5 ✅

저장 형태 기준표 — v1 계승 0

DataModel v1.8 ↔ v1 실제 스키마 대조. 기준표 누락 0, 소급 위험 11건 식별.

왜 중요한가. v1 테이블 17개에 계보·프로젝트 테이블이 아예 없었다 — v1 은 파이프라인 처리 모델이고 v1.8 은 연구 협업 모델이라 형태가 겹치지 않는다. 물려받은 것은 기법 둘뿐이다(ULID 정규 ID, GUC 정규식 가드 + FORCE RLS). 여기서 파생값 2종(가공 단계 Lv·계보 상태)을 저장하지 않고 계산한다가 확정됐다 — 저장하면 계보가 바뀌어도 따라가지 않아 "확정"이 거짓말이 된다.
G3 ✅

권한 원칙 문서 — 정본이 열어둔 9건 중 4건을 닫았다

PERMISSION-PRINCIPLES.md(P-1~P-34). 닫은 넷 = 잠금 시행 위치 · 접근 상태 기본값 · 감사 기록 · 재위임 금지.

왜 중요한가. 잠금을 통째로 RLS 에 얹으면 잠긴 행이 목록에서 사라져 승인 흐름 자체가 죽는다 — 없는 데이터는 요청할 수 없다. 그래서 두 층으로 쪼갰다: 메타(이름·요약)는 필터 없음, 파일 본체만 RLS. 그리고 권한 변경 감사는 스위치 하나당 한 줄, append-only — 기록은 소급이 불가능한 종류라 P0 에서 자리를 안 만들면 그 기간은 영원히 공백이다.
G4 ✅

미배치 화면 배정 — 실은 3건이 아니라 2건이었다

연구실 설정 > 구성원·권한 → P1 · S-08 → 이미 P2 에 있었다 · 연구실 정보 읽기 모달 → P7 편입.

왜 중요한가. P6(승인 처리)이 위임 값을 실제로 소비하므로 그 전에 값을 켜고 끌 화면이 있어야 한다. 그래서 "읽을 화면을 먼저 세운다"는 P1 의 취지에 예외 하나를 명시적으로 열었다 — 권한 값의 원천만.
IS1 ✅

staging 오리진 — 빈 터널에 다시 붙였다

infra/staging/ = nginx + cloudflared 둘뿐. 호스트 노출은 127.0.0.1:3000 만. 롤백 왕복 200 → 530 → 200 증명.

왜 중요한가. staging 을 AWS 없이 열 수 있게 되면서 I2(walking skeleton) 가 I0 를 기다리지 않는다 — 분수령이 앞당겨졌다. PoC 가 서비스를 0.0.0.0 에 노출했던 것을 반복하지 않았고, 커넥터 로그가 원격 ingress 정본을 노출해준 덕에 서비스명을 nginx 로 고정할 수 있었다.
D2b ⬜

새로 발견돼 신설된 구멍

이벤트 계약(contracts/events/**)을 보는 게이트가 하나도 없다. contract-lint 는 seam 만 훑고 contract-breaking(oasdiff)은 OpenAPI 전용이다.

왜 중요한가. 지금 이벤트 계약의 파괴적 변경을 아무도 못 잡는다. D2 를 닫으면서 발견해 WU 로 만들었다 — "나중에"로 남기지 않는다는 규약이 실제로 작동한 사례다.
04

05

실패 하나, 장치 하나

이 프로젝트의 장치들은 추상적 모범사례가 아니다. 거의 전부가 v1 또는 PoC 에서 실제로 터진 사고에 대응한다. 왼쪽이 일어난 일이고, 오른쪽이 그래서 지금 있는 것이다.

v1 에서 일어난 일

CI 가 DB 없이 돌았다. RLS 테스트는 skip 되면서 green 으로 기록됐다. 아무도 몰랐다.

그래서 지금

모든 게이트가 red fixture 로 자신이 fail-closed 임을 증명한다. 미구현 게이트는 skip 이 아니라 red 를 낸다. selftest 45 케이스가 그 증명이다.

v1 에서 일어난 일

ID 타입 드리프트, FE-BE 타입 수동 동기화, 스코프 누락 노출. 전부 "관례로 지키기로 했던 것" 이었다.

그래서 지금

계약이 유일한 발원지다. 정규 ID 타입은 common.json 에서만 정의되고, 생성물은 손으로 고치지 않으며, 경계 위반은 import-linter 계약 7개가 잡는다.

v1 에서 일어난 일

전 테이블에 CHECK·enum 이 하나도 없었다. 허용값은 마이그레이션 docstring 에만 적혀 있었다.

그래서 지금

v1.8 의 확정 열거값 9종을 DB 가 강제한다(P0 에서 CHECK 또는 native enum). 앱 코드로만 지키면 보장이 문서상 약속으로 내려앉는다.

PoC 에서 일어난 일

백업 크론이 8주 동안 빈 백업을 성공으로 기록했다. 그리고 죽은 스택을 향한 매일의 실패 알람이 그것을 놓치게 만들었다 — 알람 피로 그 자체다.

그래서 지금

IS3 의 완료 판정은 백업 1회가 아니라 복원 리허설 1회 + 빈 백업 fixture 로 fail-closed 증명이다. 성공했다는 로그가 아니라 실제로 되살아나는 것이 오라클이다.

이번에 다시 일어난 일

기록이 실물보다 깨끗했다. 철거 기록은 "전부 삭제"라 적었지만 죽은 컨테이너 2개·네트워크 3개·익명 볼륨 41개가 남아 있었다 — 센 것은 명명 볼륨뿐이었다.

그래서 지금

정정을 결정 로그에 남겼다(㉞). 기록을 고치지 않고 실물만 고치면 다음 세션이 기록을 믿는다. 어긋남을 발견하면 실물을 점검해 문서를 먼저 바로잡는다.

두 번 프로젝트를 세운 일

기획 정본이 외부 드라이브에 있었다. 폴더 목록은 보이는데 파일 읽기가 실패하는 상태가 실재했고, 게이트가 그것을 "패키지가 낡았다"로 오탐했다.

그래서 지금

정본을 작업공간 형제 폴더로 들여오고 마운트 설정까지 지워 참조 고리를 끊었다. 세션 진입조건도 "폴더가 보이는가"에서 "게이트가 15개 문서를 실제로 읽어 해시를 내는가"로 바꿨다.

기획이 남긴 함정

[가정] 기본은 열림. [가정] 은 정하지 않았다는 표식인데 그대로 두면 다음 사람이 확정으로 읽는다.

그래서 지금

가정을 결정으로 승격하거나 명시적으로 열어둔다. 접근 상태 기본값 = 열림, 데이터 공개 범위 = 2값으로 확정(㉗). 3값 이상은 v2 에 쓸 화면이 없다 — 쓰지 않는 값을 만들면 P0 스키마에 굳어 소급 비용이 붙는다.

07

되돌릴 수 있는 것

Ted 의 결정이 필요했지만 기다리면 작업이 멈추는 지점에서, 근거를 남기고 내가 정한 것들이다. 전부 비토 가능하고, 되돌리는 방법을 함께 적어 뒀다.

이탈 1건

D1 이 열린 채로 D2·D3 을 진행했다

진입조건 표가 D2 의 선행으로 D1, A3 를 적고 있었는데 둘 다 문제가 있었다.

(a) A3 는 존재하지 않는 WU 다 — 트랙 목록에 A 트랙 자체가 없다. v1 잔재로 보이는 유령 참조라 삭제했다. (b) D1 의 잔여는 HYD 실명 한 칸뿐이고, 그 값은 누가 승인하는가의 문제이지 계약의 내용이 아니다 — OpenAPI·JSON-Schema 어디도 그것을 소비하지 않는다.

전제 = "D1 의 경계·배정 구조는 확정, 이름 한 칸만 미기재". 이 전제가 틀렸다면(=배정이 바뀌면) 되돌릴 것은 계약이 아니라 DOMAINS §7 이다. 계약 자체는 배정과 독립이라 소급이 없다.
㉝

"에픽당 스토리 최대 6개" 상한 폐기

260808 인덱스의 이 규칙이 정본 실물과 어긋났다. 실측 = E-01 7개 · E-07 8개, 합계 45개(260808 기록은 42).

규칙이 실물과 다르면 규칙이 조용히 무시되거나 실물이 규칙에 맞춰 잘린다 — 둘 다 나쁘다. 상한을 지우고 "스토리는 개수가 아니라 여정 단위로 나눈다"로 교체했다. 이것은 기획 정본의 내용 변경이므로 되돌릴 수 있다 — 백업이 99 temp/정본-백업-20260822 에 있다.
㉟ ㊱ ㊲

계약에 붙은 판단 셋

표기 규약(속성 영문·값 한국어) · 잠김은 200 + bodyAccessible:false · 멱등 키 둘.

셋 다 D2 에서 seam 여러 개를 동시에 쓰며 표기·상태코드·중복 처리가 갈릴 위험이 실재해 그 자리에서 정한 것이다. 되돌리는 비용은 지금이 가장 싸다 — 코드가 아직 없어서 소비자가 없다. P0 가 시작되면 각각 스키마·라우터·워커에 굳는다.
