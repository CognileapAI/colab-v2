코드로 결정하지 않고 남긴 항목 8건. 각 항목은 「배경 → 현재 → 선택지 → 고르면 달라지는 것 → 권고와 되돌리는 비용」 순.

main 병합과 대장 등재

배경 — 다른 세션이 main 에 병행 커밋 중이라 이 회차는 브랜치 하나에서만 작업하고 번호 발급을 하지 않음.

현재 — 작업 갈래 7개가 lane-review-clean 하나로 병합돼 있고 최신 main 을 끌어와 병합까지 마침(겹치는 파일 0). 확인용 초안 PR 한 건이 열려 있음.

  • ⓐ 지금 main 에 병합하고 대장에 등재
  • ⓑ 판정 대기 항목(계약 개정·로그인 열쇠)을 먼저 닫고 병합
  • ⓒ 초안 PR 상태로 더 둠

고르면 달라지는 것 ⓐ 는 검사기 50종이 곧바로 main 의 모든 변경을 판정하기 시작함. ⓒ 는 그동안 main 이 계속 검사 없이 병합됨.

권고 · 되돌리는 비용 ⓐ. 되돌리는 비용은 병합 커밋 하나를 되돌리는 것이며, 브랜치는 그대로 남음.

로그인 제한의 클라이언트 열쇠

배경 — 접근코드 제한을 코드 칸과 클라이언트 칸 둘로 나눴고, 클라이언트를 무엇으로 식별할지가 남음.

현재 — 전달 표시의 마지막 홉. 지금 웹 서버 설정에서 그 값은 웹 서버가 덧붙인 것이라 부른 쪽이 바꾸지 못함.

  • ⓐ 첫 홉 — 부른 쪽이 실어 보낸 값
  • ⓑ 마지막 홉 — 현재 동작
  • ⓒ 웹 서버가 단독으로 세우는 별도 표시(X-Real-IP)

고르면 달라지는 것 ⓐ 는 표시를 갈아 끼우는 상대에게 제한이 걸리지 않음. ⓑ 는 지금 배포에서 신뢰 가능하되 웹 서버 앞에 로드밸런서가 서면 한 칸으로 접힘(제한이 열리지는 않고 클라이언트 칸이 없던 시절과 같아짐). ⓒ 는 프록시 홉 수 가정이 사라짐, 다만 배포 설정 변경.

권고 · 되돌리는 비용 ⓒ, 로드밸런서를 실제로 쓰게 될 때 착수. 되돌리는 비용은 웹 서버 설정 한 줄 + core-api 한 줄. 미확인 실요청으로 재지 않았고 설정 문자열로만 판정.

계약 개정 여부

배경 — 코드가 계약이 선언하지 않은 자리로 나가는 곳 넷. 미리보기 3기능의 4xx 응답 · 렌더 서비스의 경계 표시 · 렌더 조회의 400 · 화면 갈무리 층 상한.

현재 — 계약 파일 수정 0건. 개정 초안만 각 기록에 적어 둠. 새 스키마는 필요 없고 전부 기존 응답 봉투 참조.

  • ⓐ 계약을 열어 실물에 맞춤
  • ⓑ 코드를 계약 안으로 되돌림

고르면 달라지는 것 ⓐ 는 화면에 이미 있는 「그릴 수 없는 형식」 분기가 계약에 서고 다른 팀이 계약대로 코딩할 수 있음. ⓑ 는 「그릴 수 없는 형식」이 다시 「연결 못 함」으로 돌아가고 지원 형식 목록이 화면에 닿지 못함.

권고 · 되돌리는 비용 ⓐ. 되돌리는 비용은 relay.py 의 통과 상태 목록 한 줄.

캐시 열쇠 변경 뒤의 재생성

배경 — 캐시 열쇠에 시각과 격자 표식이 들어가 배포 직후 기존 산출물이 전부 열쇠 불일치.

현재 — 코드에는 반영됨. 배포 시점과 재실측 일정은 정하지 않음.

  • ⓐ 그대로 배포 — 첫 조회가 다시 렌더
  • ⓑ 배포 전에 주요 대상을 미리 렌더

고르면 달라지는 것 ⓐ 는 배포 직후 첫 조회가 느려지고 산출물 소유 등급을 다시 재야 함. ⓑ 는 준비 시간이 들되 첫 조회가 이전과 같음.

권고 · 되돌리는 비용 ⓐ + 소유 등급 재실측 일정을 함께 잡음. 되돌리는 비용은 열쇠 구성 한 줄.

배포 설정의 비밀값 파일 전환

배경 — 읽는 쪽 네 값은 이번에 파일 참조를 지원하게 됐고 배포 설정은 그대로 둠.

현재 — 뒤로 호환. 값은 여전히 컨테이너 환경변수로 들어가고 정보 조회로 읽힘.

  • ⓐ 파일 참조 + 권한 제한 파일로 전환
  • ⓑ 그대로 둠

고르면 달라지는 것 ⓐ 는 컨테이너 정보 조회로 열쇠가 읽히는 자리가 닫힘. 두 출처를 동시에 두면 앱이 뜨지 않으므로 옮길 때 기존 환경변수를 반드시 제거. ⓑ 는 세션 서명 열쇠가 계속 조회 가능한 상태.

권고 · 되돌리는 비용 ⓐ. 되돌리는 비용은 배포 설정 되돌리기 + 재기동. 미확인 배포된 두 값에 앞뒤 공백이 있는지 재지 않음(있으면 두 서비스가 다른 문자열을 쥠).

산출물 소유 검사기의 관용 기한

배경 — 구판 산출물을 고아로 세어 지우는 오삭제를 막으려고 관용 설정을 켜 둠. 그 상태에서 전건이 판정 불가라 이 검사기는 0건 판정으로 통과 중.

현재 — 손대지 않음. 기한 없음.

  • ⓐ 기한을 정함 — 그날 이후 판정이 섬
  • ⓑ 지금 끔 — 구판이 오삭제 대상이 됨
  • ⓒ 유지 — 검사기가 계속 아무것도 판정하지 않음

고르면 달라지는 것 판정에 필요한 것은 「구판 산출물을 언제까지 보류할지」 날짜 하나.

권고 · 되돌리는 비용 ⓐ. 되돌리는 비용은 설정 한 줄.

수명이 없는 렌더의 보관

배경 — 축출 조건이 수명 하나인데, 등록된 데이터셋의 렌더에는 수명이 붙지 않아 축출 대상 밖.

현재 — 서명 수명(기본 3600초)이 지나면 타일 주소가 죽고, 그 뒤의 작업은 조회에만 쓰임.

  • ⓐ 등록 데이터셋 렌더에도 수명을 줌
  • ⓑ 그대로 둠

고르면 달라지는 것 ⓐ 는 계약이 「임시로만 둔다」고 못박은 범위를 넘는 판단이 필요. ⓑ 는 조회용 작업이 계속 남음(원본 배열은 이미 놓임).

권고 · 되돌리는 비용 ⓑ 유지 후 다음 회차 판단. 되돌리는 비용은 상수 하나.

재시도 상한과 죽은 편지함

배경 — 재전달 시도 횟수는 이번 회차로 사실이 됨. 계약에는 상한과 보관 열이 있고 보내는 경로가 레포에 없음.

현재 — 상한을 넘겨도 횟수가 계속 오르고 재시도도 계속됨.

  • ⓐ 죽은 편지함 경로를 세움
  • ⓑ 상한만 지키고 멈춤
  • ⓒ 그대로 둠

고르면 달라지는 것 ⓐ 는 실패한 발행을 사람이 볼 자리가 생김. ⓒ 는 실패한 발행이 영구 재시도로 남음.

권고 · 되돌리는 비용 ⓐ 를 다음 회차 항목으로. 되돌리는 비용 해당 없음(아직 배선 없음).

미확인 · 이번에 재지 않은 것

각 기록의 [미확인] 절을 한자리에 모음. 「돌지 않은 것은 통과가 아니다」를 그대로 적용함.

환경이 없어 실행하지 못한 시험

  • core-api 종단 시험 6건 · 렌더 서비스 종단·성능 40건 — 원천 데이터 마운트 필요. core-api 종단 5건은 기존 실패이며 이 회차가 만든 것이 아님
  • 업로드 처리 서비스의 데이터베이스 시험 갈래 · AI 서비스 사전 데이터베이스 시험 26건
  • 화면 검사기 셀프테스트 2건 — 의존 설치 필요
  • Actions 러너에서의 서비스 시험 계수 — 잡 로그에 있고 이 기록에 옮기지 않음

실측하지 않은 값

  • 업로드를 흘려 쓰기의 메모리 사용량과 상태 확인 응답시간
  • 렌더 작업 축출로 줄어든 메모리 양
  • 격자 표식 충돌의 실데이터 발생 빈도
  • 이벤트 스풀 잔류량
  • 배포된 비밀값 두 개의 앞뒤 공백 유무(길이만 비교하면 풀림)

실서버에서 확인하지 않은 경로

  • 로그인 클라이언트 열쇠의 실제 신뢰도 — 설정 문자열로만 판정
  • 투영 밖 좌표의 정상 응답 전환 — 시험 클라이언트로만 확인
  • AI 서비스 사유 문구의 실제 유출 값 — 실물 모양의 문구로만 확인
  • 브라우저 실동작 — 인증 만료 왕복 중 화면 전환 · 실패 자리 배치 · 포커스와 낭독 순서 · 서머타임 지역의 날짜 경계
  • 두 push 에서 PR 검사 실행이 생성되지 않은 원인(수동 실행으로 대체 확인)

계수 단위가 달라 비교하지 않은 것

  • 리뷰가 적은 「시험 함수 1102 중 871 미실행」 — 이번에 센 것은 「게이트가 실행한 케이스」라 단위가 다름. 같은 단위로 맞추려면 전수 수집 계수가 필요
  • 화면 시험의 개정 전 실패 계수 「19건」 — 출력이 남아 있지 않아 되짚지 못함. 다시 잰 값은 13건과 14건
  • AI 서비스 88 과 125 — 앞은 6파일 제외 부분집합, 뒤는 표식 선택자 기준
  • 판정부의 종료코드 구멍을 실제로 밟는 검사기가 지금 있는지는 세지 않음
