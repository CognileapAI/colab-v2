**J5 가 왜 여전히 red 인가 — 자기 자신은 빠졌고, 이번엔 「자기 자식」을 고른다.** 대조군 8회 중 7회 비어 있지 않았고, 그 선택은 두 부류다.
- **가공 단계가 더 높은 후손**을 부모로 고름 — 예: 「GK-2A NDVI 월평균 (Lv.1)」의 부모로 「U-Net NDVI 예측장 (Lv.2)」, 「HSR 반사도 (Lv.0)」의 부모로 「U-Net 강우 추정 (Lv.2)」. 후보 목록에 상위 단계가 남아 있는 한 모델은 주제가 같은 그것을 잡는다. 업로드의 가공 단계를 요청에 싣지 않기로 한 판정(intent 미해결 3)이 여기서 값을 물었다.
- **같은 주제의 시험 시드**(「A 강우 격자화」)를 근거 문장을 그럴싸하게 붙여 고름(확신도 「확실」 1회·「애매」 2회). 「모름」 확신도는 여전히 **16회 중 0회**.

즉 J5 의 남은 원인은 ⓐ **후보 층에서 상위 단계를 걸러 주지 않는 것**과 ⓑ **모델이 「없다」를 말하지 않는 성향** 둘이다. ⓐ 는 core-api(업로드 Lv 를 알아야 함 → 계약 필드 또는 이름 초안의 「(Lv.n)」 힌트), ⓑ 는 SYSTEM_PROMPT(「후보 어느 것도 이 자료를 만드는 데 쓰였다는 근거가 없으면 빈 배열」 · 「가공 단계가 더 높은 후보는 부모가 아니다」)에서 각각 다룰 수 있고, 둘 다 재실측으로 판정해야 한다. 이 회차는 둘을 열지 않았다.
