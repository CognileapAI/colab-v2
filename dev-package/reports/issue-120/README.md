## 미측정 + 이유

- **ⓓ 휠 확대의 커서 고정점 (실화면)** — `agent-browser` 의 `mouse wheel` 은 커서 좌표를 실은 DOM
  `wheel` 이벤트를 만들지 않는다. 같은 세션에서 `mouse move`＋`down/move/up` 드래그는 그림을 정확히
  200 px 옮겼으므로 좌표 추적 자체는 동작하며, 휠만 페이지 스크롤로 처리된다(훅의 네이티브 리스너가
  호출되지 않음을 임시 로그로 확인). 워크트리 가드가 `eval` 을 막아 이벤트를 직접 만들 길이 없다.
  **대신 jsdom 시험이 같은 불변식을 잰다** — `frontend/test/preview-map-viewport-20260918.test.tsx`
  「⑷ 휠 확대 — 커서 아래 지점이 그 자리에 머문다」가 확대 전후 `(고정점 − 이동값) / 배율` 의 일치를
  단언하고, 「버튼 확대는 뷰포트 중심 고정점을 유지한다」·「도구 층 위의 휠은 그림을 확대하지 않는다」를
  함께 잠근다. 실화면 판정은 **하지 못했다.**
- **업로드 인라인 미리보기·확장보기 (실화면)** — `PreviewPanel` 은 모달에서 `picked.length > 0`,
  즉 실제 `File` 바이트가 붙어야 마운트된다. 그 앞에 전송 생성 → put-url → 실제 XHR PUT → 조각 완료 →
  early-preview → 전송 완료 → 업로드 상태 `ready·renderable` 이 모두 성공해야 한다. 이 레인의 HTTP
  스텁만으로는 도달할 수 없어 **확장보기의 `.pvx-b` 비스크롤도 실화면에서 재지 못했다.**
  네 화면의 DOM 구조·CSS 규칙은 jsdom 시험 ⑴⑺ 이 각각 별도 케이스로 잠근다.
