# 실제 파일 검수표

최신 실행의 파일명·바이트·SHA256·단계별 판정은 [브라우저 근거](browser/index.md)에 있다. 독립 일회용 DB·로컬원본저장소·실제worker/viz·agent-browser이며 모의 API 저장 성공으로 대체하지 않았다.

| 포맷/사례 | 분석·그림 | 저장·재조회·편집·원본 해시 | 추가 확인 |
|---|---|---|---|
| GeoTIFF B02+B03 | 실제 2파일 렌더·확장 | 통과 | 개별 및 ZIP2파일 이름/내용SHA256일치 |
| GK2A NetCDF(HDF5 내부) | LST 자동그림·확장 | 통과 | native동시접근 충돌 재현 후 수정,80읽기 회귀 |
| MOD15 HDF4 | 실제Fpar그림·확장 | 통과 | 프로젝트새생성/기존연결·변수·날짜·10분·계보CRUD/노드이동·셀별편집 |
| HSR Binary .bin.gz 좌표없음 | 실제 값그림 | 통과 | 격자없는 stage2실패 수정, 지도좌표를 만들지 않음 |
| HSR Binary + rdr격자.nc | 지도형 | 통과 | 격자업로드/위치확인·줌/초기화/숫자위경도 |
| Prediction NumPy + LAT/LON_crop | 지도형 | 통과 | 실제산출배열+맞는격자,줌/초기화/숫자위경도 |
| GRIB | 미리보기 명시적 제외 | 통과 | 불가안내가 등록/수정/다운로드를 막지 않음 |
| 실제TIF + 의도적손상TIF | 부분렌더 2중1 | 통과 | 누락 원본명·정상 그림·등록/재조회·개별/ZIP 해시 일치. core 전체 경계검사 후속 수정 중 |

## 지원 범위

실파일은 프로젝트 형제 참조자료에서 확보했다. NumPy는 좌표파일을 본체로 둔 시험이 아니라 vegetation Lv.2 Prediction 산출물이다. HDF폴더 이름은 HDF5지만 MOD15파일 실구조는 HDF4이며, GK2A NetCDF가 HDF5 내부구조를 사용한다. `.tiff/.nc4/.h5/.hdf5/.bin.gz` 별칭은 화면회귀로 지원안내를 검증했고 각별칭마다 별개실물전체흐름을 했다고 계산하지 않는다.

GRIB은 현행 파서가 edition/message 수준의 분석·저장만 지원한다. 실제지도 지원은 reader/변수·시각/좌표해석 및 실파일회귀가 추가로 필요한 별도 범위다. 이번 계획의 조사·제외안내·원본보존 검증과 새렌더러 구현을 혼동하지 않는다.

## 실패 기록

- 제품: NetCDF병렬읽기 SIGSEGV, 기간없는10분 상세누락, BIN좌표없음 업로드실패/안내누락, GRIB기본슬롯 미지원안내부재를 재현·수정했다.
- 시험도구: native select option 가시성 대기, 화면밖 버튼 클릭, URL glob, CSS Unicode escape, get attribute→attr, 커서목표이미지→viewport를 수정했다. 이 실패들을 제품통과로 계산하지 않았다.
