## 3. 「미확인」 상세

### 3-1. `#25`⑥ — 「시각」 고르개로는 재지 못했다

- 값 = 두 표본 모두 `pvx-pick-instant`·`up-pick-instant` 의 옵션 **0건**, 컨트롤 `disabled=true`.
  - radar `RDR_CMP_HSR_PUB_*.bin.gz` 3조각 = 파일 3 · 변수 1(`에코`) · 시각 0.
  - NDVI `GK-2A_NDVI_*.tif` 10조각(상세 화면) = 파일 10 · 변수 1(`band1`) · 시각 0.
- 뜻 = 이 자료들은 **파일 1건이 시점 1개**다. 시간 축이 파일 안에 없으므로 시각 고르개에 채울 값이 없다. 화면 결함이 아니라 표본 성질이다.
- 대체 실측 = 같은 줄의 **파일** 고르개로 오버레이 → 인라인 전파를 확인했다(판정표 「선택 공유」 행). 세 컨트롤은 같은 `PreviewPickRow` 한 부품이고 같은 `onPick` 을 탄다.
- 닫으려면 = 시각 축이 여럿인 표본(한 파일 안에 시간 차원이 있는 자료) 1건이 필요하다.

### 3-2. `#34` — 배너 행이 눈앞에서 사라지는 장면은 못 봤다

- 구조 = 닫기 확인의 세 번째 버튼은 **모달이 이번에 만든 업로드**(`uploadId` 상태)만 지운다(`canForgetPending = uploadId && labId`). 그 업로드는 배너 카드가 목록을 읽은 **뒤에** 생기므로, 클릭 시점의 배너에는 그 행이 없다.
- 그래서 확인한 것 = ⑴ 브라우저 기억에서 그 uploadId 만 사라짐 ⑵ 서버 요청 0건 ⑶ 재적재 뒤에도 그 행이 서지 않음.
- 라이브 제거 자체는 `#32` 에서 확인됨(배너 자체의 버튼은 같은 카드의 상태를 직접 줄인다).

## 4. 함께 관측한 것 (판정 대상 아님 · 보고만)

- **`GET /api/v1/uploads/transfers/incomplete` = 501** — staging 저장 모드가 local 이라 전송 미완 목록이 서지 않는다. 화면은 501 을 빈 배열로 접고 그 뒤 같은 op 을 다시 부르지 않는다(`uploadSource.ts` 의 `transferUnavailable` 잠금). L4 §5 가 이미 후속 항목으로 올린 자리와 같다. **걸리는 검사 = 없다**(게이트·Dockerfile·배포 스크립트 어디에도 이 op 의 판정이 없다).
- **재개 식별자의 소비처가 s3 경로 하나다** — `resumeUploadId` 를 읽는 곳은 `transferSource.ts`(프리사인드 전송)뿐이고, local 모드의 `uploadSource.create` 는 그 값을 쓰지 않는다. 따라서 이 환경에서 `#33`㉠ 은 **배선까지만** 실측되고 「남은 조각부터 이어 올라간다」는 동작은 재지 못한다. 모달 안 재개 배너(`up-incomplete`)와 그 안내(`up-resume-hint`)도 같은 이유로 서지 않는다.
- **라운드 파일이 예고한 폐기 공통 헬퍼 `discardUpload` 는 트리에 없다** — 세 자리가 `forgetPending` 을 각각 부른다(`UploadModal.tsx` 닫기 확인 · `UnfinishedUploads.tsx` 배너 행 · 상태 확인 실패 갈래). 동작은 표대로이고 계수·문면에 영향이 없다. 걸리는 검사 = 없다.
- **미리보기 산출물은 `/api` 밖 경로(`/previews/…`)로 온다** — 프런트만 따로 띄우는 회차는 그 자리도 함께 이어야 화면이 그림을 받는다. `frontend/vite.config.ts` 의 개발 프록시는 `/api` 하나만 잇는다.
- **staging 데이터셋 14건의 `category` 가 전부 비어 있다** — 카탈로그 필터가 「미지정 (14)」로 표시한다. L4 §4-2 의 같은 관측과 일치.
