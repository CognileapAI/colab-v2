> **여덟 중 일곱이 「에러 없이 그럴듯한 값」이었다.** 잘못된 값이 예외를 던지지 않았고, 사람 눈에도 그럴듯했다. **이 프로젝트에서 양성 시험은 이런 것을 못 잡는다** — 그래서 음성 시험(`㊺`·`㊽`·`D3b`)을 고집한다.

## 1. 좌표 기준 격자 — `04.Lat_Lon_info`

**격자가 파일 안에 없는 포맷이 있다 — 실측상 하나다.** 바이너리(HSR)는 헤더에 좌표도 투영 파라미터도 없어 **밖에서 받아야만 한다**(§1.1). 나머지 4종(nc·tif·hdf·grib)은 파일 내부 정보만으로 격자가 계산되지만, 동봉 배열을 그대로 쓰는 쪽이 싸고 안전하다. 원천이 그것을 준다 — **포맷 5종 폴더 전부에 있다.**

경로 = `03 Reference-Data/02.File-format/{포맷폴더}/04.Lat_Lon_info/`

| 포맷 | 파일 | 형상 `(rows, cols)` | dtype | 검증 |
|---|---|---|---|---|
| **Binary (HSR)** | `Lat_HSR.npy` · `Lon_HSR.npy` | **`(2881, 2305)`** | `<f4` | **`HSR_NY × HSR_NX` 와 정확히 일치** |
| **GeoTIFF (HLS S30)** | `{타일ID}_lat2d.npy` · `_lon2d.npy` ×2타일 | `(3660, 3660)` | `<f8` | COG 실측 크기와 일치 |
| **HDF4 (MODIS)** | `lat2d_h27v05` · `h28v05` · `lon2d_…` | `(2400, 2400)` | `<f8` | Sinusoidal 타일 2장 |
| **NetCDF (GK2A)** | `lat2d` · `lon2d` (+ `gk2a_ko020lc_latlon.nc`) | `(900, 900)` | `<f4` | `ko020lc` 격자 |
| ~~GRIB (ERA5)~~ | `lat2d` · `lon2d` | `(721, 1440)` | `<f8` | 0.25° 전지구. **`〈51〉` 로 범위 밖** — 파일은 남긴다 |

**후주입·교체는 정상 동작이다** (`〈59〉`) — 격자는 **한 번 올리고 끝나는 원자료가 아니라 조정하는 대상**이다. 잘못 붙인 격자를 바로잡는 것도 포함한다.
**그때 계보는 접지 않는다** (`〈60〉`) — `마지막 수정` 을 안 건드리므로 `계보 상태` 가 `확정` 에서 `확인 필요` 로 넘어가지 않는다. **바뀐 것은 과학 데이터가 아니라 좌표를 읽을 수단**이고 파생 관계는 그대로다.
**대신 `d8_activity` 에 `좌표계·격자 변경` 을 남긴다** — 좌표계·격자는 **데이터를 해석하는 근거**라 바뀌면 알아야 한다. 그 표는 append-only 라 **누가 언제 바꿨는지가 지워지지 않는다.** *(판정은 안 건드리고 사실은 남긴다 — 둘을 갈랐다.)*
**그리고 `자동으로 읽은 정보`(좌표계·격자)는 재계산한다** — 그 값이 이 파일에서 나온다.

**⚠ 이 파일들은 `기준 격자 파일` 이다** — `d3_file.kind` 의 두 번째 값(`본체` | `기준 격자 파일`). **데이터셋당 2건까지**(위도·경도 한 쌍), **등록 뒤 후주입 가능**(`〈58〉`).
> **권고 = 축 열**(`grid_axis text CHECK (grid_axis IN ('위도','경도'))`, 본체는 NULL)을 두고 **`(dataset_id, grid_axis)`** 로 유일성을 건다. 개수만 2로 늘리면 **위도 파일 두 개**가 들어가고 둘을 구분하지 못한다 — **개수 제약은 「몇 개냐」만 답하고 「무엇이냐」는 안 답한다.**
> ⚠ **`CHECK (kind <> '기준 격자 파일' OR grid_axis IS NOT NULL)` 를 함께 건다.** NULL 은 유일성에 안 걸리므로, 이게 없으면 **축이 빈 격자 파일이 여럿** 들어가 「축 열을 뒀는데 안 채우면 그만」이 된다. 부분 인덱스의 `WHERE kind = '기준 격자 파일'` 조건은 **그대로 둔다**(본체 여러 개를 막지 않기 위해).

### 1.1 격자를 어디서 얻는가 — 포맷마다 다르다

**후주입을 모든 포맷에 요구하면 안 된다. 그러나 HSR 에는 요구해야 한다.**
*(2026-08-23 정정 — 아래 표는 원래 「HSR 은 헤더가 격자를 직접 준다 ✅확인」이었다. **근거가 포맷 명세 PDF 였고 실물 바이트가 아니었다.** 헤더를 열어 보니 투영 파라미터 자리가 전부 0 이었다 — `§0 M-8`.)*

| 포맷 | 격자를 어디서 얻는가 | 계산값 vs 동봉 격자 오차 | **근거 등급** |
|---|---|---|---|
| **Binary (HSR)** | **동봉 격자 파일이 필요하다 — 유일하게 진짜로 필요한 포맷.** 헤더가 주는 것은 `nx=2305`·`ny=2881`·`dxy=500`·`map_code=1` 뿐이고 **투영 파라미터 자리(36~63 B)가 전부 0** 이다. 크기·해상도는 있는데 투영을 세울 값이 없다 | **재현 불가** — 명세 기재값으로 세우면 dx 가 499 m 로 어긋나고 최적 피팅해도 위도 **0.053°(≈5.9 km · 500 m 셀 11.8 개)** 오차 | ✅ **확인** — 헤더 1024 B 실물 판독 |
| **GeoTIFF (HLS)** | **파일 내부만으로 계산된다** — IFD 태그(tiepoint·픽셀크기·EPSG:32651) | **2.8e-14°** (사실상 완전 일치) | ✅ **확인** — 실파일 계산·대조 |
| **HDF4 (MODIS Sinusoidal)** | **파일 내부만으로 계산된다** — 꼬리쪽 `StructMetadata`(ASCII)에 코너좌표·Sinusoidal·지구반경 `R=6371007.181` | **7e-14°** | ✅ **확인** — 상동 |
| **NetCDF (GK2A)** | **파일 내부만으로 계산된다** — 좌표 변수·투영 속성 | **1.3e-5°** (float32 반올림 한계) | ✅ **확인** — 상동 |
| **GRIB (ERA5)** | 파일 내부 GDS 섹션 | **0.0** — 단 원본 `.grib` 은 폴더에 없고 변환된 `.npy` 만 있다. `〈51〉` 로 범위 밖 | ✅ **확인** — 상동 |

> **뒤집힌 결론.** 「HSR 도 격자 파일 없이 그릴 수 있는데 코드가 막고 있다」는 **틀렸다.** 현행 D5 가 HSR 에 기준 격자를 요구하고 못 찾으면 `FAILURE + [미상]` 으로 끝내는 것은 **옳은 동작이다.** 반대로 **HDF4·GeoTIFF·NetCDF 는 「격자 파일 없이도 계산 가능」 쪽**이다 — 이 셋에 후주입을 강제하는 규칙이 있다면 그것이 완화 대상이다.
> ⚠ 동봉 `rdr_500m_latlon.nc` 도 표준위도가 없어 **불완전하다** — HSR 격자의 정본은 `Lat_HSR.npy`·`Lon_HSR.npy` 쌍이다.
> ⚠ **여기서 「칸이 셋」이라던 옛 틀도 함께 버린다.** 실측 결과 칸은 둘이다 — **밖에서 받아야만 하는 것(HSR 하나)** 과 **안에서 계산되는 것(나머지 4종)**.
> 상세 = `DATA-PIPELINE-MEASUREMENT.md`.

**⚠ 좌표를 지어내지 않는다.** PoC 는 HSR 위경도를 **dummy `linspace`** 로 합성했고, 좌표를 못 찾으면 **임의 격자를 만들어 「성공」을 반환**했다(4곳, `DR-9`). **그럴 이유가 없었다 — 진짜 좌표가 옆에 있었다.** 좌표를 못 읽으면 **`[미상]` 이고 실패다.**

**재현** — npy 헤더는 ASCII 라 numpy 없이 읽힌다:
```bash
head -c 128 <파일>.npy | strings | grep -o "'descr':[^}]*"
```

## 2. HSR 바이너리 포맷 — 확정 스펙

| 항목 | 값 | 출처 |
|---|---|---|
| 헤더 | **1024 B** | PoC 두 세대 공통 |
| 격자 | `NX=2305` · `NY=2881` | 상동 |
| dtype | **`<i2`** (little-endian int16) | 상동 |
| 배열 | `reshape((NY, NX))` **row-major** | 상동 |
| 스케일 | **`/100` → dBZ** | 상동 |
| 결측 | `ref <= 0 → NaN` | 상동 |
| **파일 크기** | **`1024 + 2305×2881×2 = 13,282,434 B`** | **원천 `.bin.gz` 12건이 전부 정확히 이 크기로 풀린다** |
| Z→R | `Z = 10**(dBZ/10)` · `R = (Z/200)**(1/1.6)` mm/h | Marshall-Palmer |

✅ **풀렸다 — 3블록이 참 스펙이고 우리 파일이 축소 배포본이다** (2026-08-23, `레이더합성자료포맷정보.pdf` 판독. 스캔 이미지라 임베드 이미지를 뽑아 3쪽 직접 읽었다).

```
문서의 비압축 용량          = 39,845,254 B
1024 + 3 x (2305*2881*2)  = 39,845,254   <- 한 바이트도 안 틀린다
1024 + 1 x 13,281,410     = 13,282,434   <- 원천 12건이 푸는 크기
```

자료구조 = 헤더 1024 B + **반사도** + **고도정보** + **지점정보**, 각 `2 B(short) x 2305 x 2881`.

**⚠ 그리고 `num_data` 도 그대로 믿으면 안 된다 — 헤더가 실제 내용과 다르다.** 원천 12건은 헤더가 `num_data=3`, 블록코드 `1·2·3`(에코·고도·지점)이라고 선언하는데 **파일 실크기는 전부 13,282,434 B = 1블록치**다(3블록이면 39,845,254 B). **`num_data` 만 믿고 3블록을 읽으러 가면 파일 끝을 넘는다.**
> **규칙 = `num_data` 를 읽되 파일 길이와 교차검증한다. 둘이 다르면 길이를 믿고, 차이를 mismatch 로 기록한다**(조용히 버리지도, 넘겨짚지도 않는다). D5 `hsr.py` 가 이미 이렇게 동작한다.

**⚠ 그런데 블록 수를 가정하면 안 된다 — 파일이 스스로 말한다.** 헤더에 **`char num_data`**(저장된 자료블록수)와 **`char data_code[16]`**(블록별 종류: `1` 에코 · `2` 고도 · `3` 지점순서 · `4` 자료수 · `5` 강수량 · `6` 수상체 · `15` …)가 있다. **파서는 `3` 도 `1` 도 가정하지 말고 `num_data` 를 읽는다.**
PoC 두 세대가 반사도만 읽은 것은 **결과적으로 맞았지만 이유가 달랐다** — 길이를 `1024 + nx·ny·2` 로 **고정**했을 뿐 `num_data` 를 안 봤다. **3블록 파일을 주면 뒤 두 블록을 조용히 버린다.**

### 2.1 ⚠ NULL 이 세 값이다 — 하나로 묶으면 데이터를 버린다

| 값 | 뜻 |
|---:|---|
| **`-20000`** | 관측영역내 **표시를 위한 최소값** — **결측이 아니다. 유효한 하한이다** |
| `-25000` | 관측영역내 **비관측영역** NULL |
| `-30000` | **관측반경 밖** NULL |

**`값 <= -20000` 으로 자르면 표시 최소값을 결측으로 만든다.** PoC 가 `>= 249` 로 `256`·`1000` 을 함께 덮었던 그 버그가 **이 포맷에서 실물로 다시 나온다.** **fill 은 정확일치로 판정한다.**

### 2.2 나머지 확정 상수 (문서 기재값)

| 항목 | 값 |
|---|---|
| 주기 · 해상도 | **5분** · **500 m** |
| 투영 | **Lambert conformal conic** · 기준 위경도 **N38.0 E126.0** · 기준격자점 **(1121, 1681)** — ⚠ **문서 기재값일 뿐 헤더에 없다.** 이 값으로 격자를 재현하면 5.9 km 어긋난다(§1.1). **격자는 `Lat_HSR.npy`/`Lon_HSR.npy` 에서 읽는다** |
| 영역 | **HB** — 기준점에서 서 560 km · 남 840 km |
| 값 환산 | **반사도(dBZ) = 값/100** · 고도정보(m) = 값 · 지점정보 = 값 |
| 헤더 구성 | `RDR_CMP_HEAD(64 B)` + `RDR_CMP_STN_LIST(20 B) x 48` = **1024 B** |
| 시각 | `TIME_SS(7 B)` = `short YY` + `char MM·DD·HH·MI·SS` |

**⚠ 헤더가 `nx`·`ny`·`nz`·`dxy`·`dz`·`z_min`·`ptype`·`map_code` 를 이미 준다.** 격자 **크기**를 하드코딩할 이유가 없었다. **PoC 는 변수·격자를 하드코딩 반환하고 위경도를 합성했는데, 크기는 헤더가 주고 있었고 좌표 배열은 같은 폴더에 있었다** — **읽을 것이 두 군데 있는데 안 읽고 지어냈다**(`DR-9`·`DR-14`).
> **⚠ 단, 헤더가 주는 것은 여기까지다.** 투영 파라미터 자리(36~63 B)는 **실물에서 전부 0** 이라 **위경도는 헤더로 세울 수 없다**(`§1.1`·`§0 M-8`). 「헤더가 격자를 준다」와 「헤더가 격자 **크기**를 준다」는 다르다.

## 3. 포맷 감지 — 확장자를 믿지 않는다

**세 번 다 확장자가 거짓말을 했다.**

| 실제 | 확장자·폴더명이 주장한 것 | 매직바이트 |
|---|---|---|
| **HDF4** (MODIS MOD15A2H) | 폴더명 `file_format_5_HDF5` · DB enum `HDF5` | **`0e 03 13 01`** |
| **HDF5 컨테이너** (NetCDF4) | `.nc` | `89 48 44 46` (`\x89HDF`) |
| **이미 COG** (HLS S30) | `.tif` — 일반 GeoTIFF 로 보인다 | TIFF 매직 + **내부 타일·오버뷰** |

**규칙**
1. **감지는 매직바이트로 한다.** 확장자는 힌트일 뿐이다.
2. **`\x89HDF` 만으로 NetCDF4 와 HDF5 를 못 가른다** — 같은 매직이다. **try-open 단계가 필수다.**
3. **PoC 는 매직 판별기를 갖고 있으면서 감지기에 연결하지 않았다** — 코드에 있는 것과 쓰이는 것은 다르다.

## 5. 라이브러리 선택과 빌드 의존성

**PoC 가 실제로 호출한 것** (선언이 아니라 호출):

| 포맷 | 여는 방법 |
|---|---|
| NetCDF | `xr.open_dataset(path, engine="netcdf4")` |
| **HDF4** | **`rasterio.open()` → `src.subdatasets` → `rasterio.open(sds)`** — **`pyhdf` 를 안 쓴다** |
| HDF5 | `h5py.File()` |
| GeoTIFF | `rasterio.open()` + `src.read(band)` |
| Binary | `gzip` + `np.frombuffer` — **지오 라이브러리 불필요** |
| 재투영 | `pyproj.Transformer(..., always_xy=True)` · `rasterio.warp.reproject` |

**빌드에 걸리는 것 둘**
- **HDF4 를 rasterio 로 읽으려면 conda-forge `hdf4`(GDAL HDF4 드라이버)가 필수다. pip 휠에 없다.**
- **GRIB 을 빼면(`〈51〉`) `eccodes` + `libeccodes-dev` 시스템 의존성이 통째로 빠져 컨테이너가 크게 가벼워진다.**

**⚠ 선언과 실사용이 다르다** — PoC 는 `titiler` 를 설치하고 **import 0건**이었다(타일링은 자작). 프론트는 XYZ 타일이 아니라 **Leaflet `ImageOverlay` 단일 PNG** 였다. **v2 에 타일링 선례가 없다.**

## 7. 계승하지 않는 것

**PoC 에 있지만 v2 가 반대로 가는 것.** C3 가 「PoC 지식을 뽑는다」로만 적혀 있으면 **여기서 잘못 뽑힌다.**

| PoC | v2 | 근거 |
|---|---|---|
| 등재 시점에 **파일을 안 연다** — 포맷=확장자, 기간·좌표계·격자=**사람이 타이핑**, 용량=**클라이언트 신고값** | **파일에서 자동으로 읽는다 — 사람이 타이핑하지 않는다** | `DATAMODEL §4.1` · `DR-14` |
| 파일을 **통째로 메모리에 적재** | **전체 적재 금지 — 윈도우/스트리밍** (50 GB 가 들어온다) | `pipeline-worker/README.md` · `DR-11` |
| 포맷이 섞이면 **`MIXED` 로 기록** | **포맷이 다르면 데이터셋을 나눈다** — *「하나라도 다르면 조각이 아니라 다른 데이터다」* | `DATAMODEL §4.3` |
| 계보에 **가공 방식 필드가 없다** (`relation_type` 항상 `derived`) | **가공 방식은 관계에 부착한다** | `DATAMODEL §4.2` · `DR-15` |
| 좌표 못 찾으면 **격자를 지어내고 성공 반환** | **못 읽으면 `[미상]` 이고 실패다** | `DR-9` · `㊴-②` |
| **멱등성 없음** — 같은 파일 두 번 = 데이터셋 둘 | **재실행 멱등**이 S2 완료 판정 | `WORK-UNITS §8.5` |

**반대로 물려받을 만한 것** — PoC 계보의 **순환 감지 · 레벨 제약 · 권한 마스킹**은 이미 풀어 둔 문제다(`DR-15`).
