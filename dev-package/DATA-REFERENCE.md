## 1. 좌표 기준 격자 — `04.Lat_Lon_info`

**격자가 파일 안에 없는 포맷이 있다.** 바이너리(HSR)는 헤더에 좌표가 없고, HDF4·NetCDF 도 투영 격자라 위경도를 밖에서 받아야 한다. 원천이 그것을 준다 — **포맷 5종 폴더 전부에 있다.**

경로 = `03 Reference-Data/02.File-format/{포맷폴더}/04.Lat_Lon_info/`

| 포맷 | 파일 | 형상 `(rows, cols)` | dtype | 검증 |
|---|---|---|---|---|
| **Binary (HSR)** | `Lat_HSR.npy` · `Lon_HSR.npy` | **`(2881, 2305)`** | `<f4` | **`HSR_NY × HSR_NX` 와 정확히 일치** |
| **GeoTIFF (HLS S30)** | `{타일ID}_lat2d.npy` · `_lon2d.npy` ×2타일 | `(3660, 3660)` | `<f8` | COG 실측 크기와 일치 |
| **HDF4 (MODIS)** | `lat2d_h27v05` · `h28v05` · `lon2d_…` | `(2400, 2400)` | `<f8` | Sinusoidal 타일 2장 |
| **NetCDF (GK2A)** | `lat2d` · `lon2d` (+ `gk2a_ko020lc_latlon.nc`) | `(900, 900)` | `<f4` | `ko020lc` 격자 |
| ~~GRIB (ERA5)~~ | `lat2d` · `lon2d` | `(721, 1440)` | `<f8` | 0.25° 전지구. **`〈51〉` 로 범위 밖** — 파일은 남긴다 |

**⚠ 이 파일들은 `기준 격자 파일` 이다** — `d3_file.kind` 의 두 번째 값(`본체` | `기준 격자 파일`). **데이터셋당 2건까지**(위도·경도 한 쌍), **등록 뒤 후주입 가능**(`〈58〉`).
> 권고 = **축 열**(`grid_axis ∈ {위도, 경도}`)을 두고 `(dataset_id, 축)` 으로 유일성을 건다. 개수만 2로 늘리면 **위도 파일 두 개**가 들어가고 시스템이 둘을 구분하지 못한다.

**⚠ 좌표를 지어내지 않는다.** PoC 는 HSR 위경도를 **dummy `linspace`** 로 합성했고, 좌표를 못 찾으면 **임의 격자를 만들어 「성공」을 반환**했다(4곳, `DR-9`). **그럴 이유가 없었다 — 진짜 좌표가 옆에 있었다.** 좌표를 못 읽으면 **`[미상]` 이고 실패다.**

**재현** — npy 헤더는 ASCII 라 numpy 없이 읽힌다:
```bash
head -c 128 <파일>.npy | strings | grep -o "'descr':[^}]*"
```

## 2. HSR 바이너리 포맷 — 확정 스펙

| 항목 | 값 | 출처 |
|---|---|---|
| 헤더 | **1024 B** | PoC 두 세대 공통 |
| 격자 | `NX=2305` · `NY=2881` | 상동 |
| dtype | **`<i2`** (little-endian int16) | 상동 |
| 배열 | `reshape((NY, NX))` **row-major** | 상동 |
| 스케일 | **`/100` → dBZ** | 상동 |
| 결측 | `ref <= 0 → NaN` | 상동 |
| **파일 크기** | **`1024 + 2305×2881×2 = 13,282,434 B`** | **원천 `.bin.gz` 12건이 전부 정확히 이 크기로 풀린다** |
| Z→R | `Z = 10**(dBZ/10)` · `R = (Z/200)**(1/1.6)` mm/h | Marshall-Palmer |

**⚠ 3블록 상수는 죽은 코드다.** PoC 에 `_TOTAL_DATA_BYTES = HEADER + 3*GRID`(≈39.8 MB)가 있지만 **실제로는 첫 블록(반사도)만 읽고 길이 검증도 1블록 기준**이다. 실측 크기가 1블록과 정확히 맞으므로 **이 배포본에는 반사도만 있다.**

`[미확인]` — **3블록이 참 스펙이고 이것이 축소 배포본인가.** 말해 주는 문서가 없다. **`레이더합성자료포맷정보.pdf`**(`file_format_3_bin/04.Lat_Lon_info/`)에 답이 있을 수 있으나 **CID 인코딩이라 아직 못 읽었다.**

## 3. 포맷 감지 — 확장자를 믿지 않는다

**세 번 다 확장자가 거짓말을 했다.**

| 실제 | 확장자·폴더명이 주장한 것 | 매직바이트 |
|---|---|---|
| **HDF4** (MODIS MOD15A2H) | 폴더명 `file_format_5_HDF5` · DB enum `HDF5` | **`0e 03 13 01`** |
| **HDF5 컨테이너** (NetCDF4) | `.nc` | `89 48 44 46` (`\x89HDF`) |
| **이미 COG** (HLS S30) | `.tif` — 일반 GeoTIFF 로 보인다 | TIFF 매직 + **내부 타일·오버뷰** |

**규칙**
1. **감지는 매직바이트로 한다.** 확장자는 힌트일 뿐이다.
2. **`\x89HDF` 만으로 NetCDF4 와 HDF5 를 못 가른다** — 같은 매직이다. **try-open 단계가 필수다.**
3. **PoC 는 매직 판별기를 갖고 있으면서 감지기에 연결하지 않았다** — 코드에 있는 것과 쓰이는 것은 다르다.

## 4. COG 판정 — 타일링만으로는 안 된다

**판정 기준** = 내부 타일(태그 `322`/`323`) **그리고** 오버뷰(IFD 2개 이상). 스트립 기반은 태그 `278`.

**원천 tif 62건 전수 판정** (두 세션이 각자 독립 구현으로 같은 수를 얻었다):

| 묶음 | 개수 | 판정 |
|---|---:|---|
| 포맷견본 `file_format_4_tif` | **6** | **COG** — 256×256 타일 + 오버뷰 4단(3660→1830→915→458→229) |
| KWRA `Input` | **11** | **타일만 · 오버뷰 없음** ← **급소** |
| `01.level-data/02.vegetation` | **5** | **타일만 · 오버뷰 없음** ← **급소** |
| KWRA `Output/{4방법}` | **40** | 스트립 |

**⚠ 「타일링 있으면 COG」로 판정하면 16건을 우리 산출물로 오인한다.** 그 16건이 실파일로 존재한다. **음성 시험 픽스처가 원천에 세 부류로 다 있다** — 진짜 COG 6 · 타일만 16 · 스트립 40. **①만으로는 규칙을 못 짠다.**

`[정본 무근거]` — **「타일만 있고 오버뷰 없는 tif」를 우리 산출물로 볼 것인가.** 정본 E-04 에 `COG` 라는 말 자체가 없다. **레인이 관례로 정하면 안 된다**(`㊴-②`).

**재현** — TIFF IFD 는 순수 파이썬으로 읽힌다(gdal·rasterio 불필요): 헤더 8B 에서 엔디안·첫 IFD 오프셋을 읽고, IFD 를 따라가며 태그 322/323/278 유무와 IFD 개수를 센다.

## 5. 라이브러리 선택과 빌드 의존성

**PoC 가 실제로 호출한 것** (선언이 아니라 호출):

| 포맷 | 여는 방법 |
|---|---|
| NetCDF | `xr.open_dataset(path, engine="netcdf4")` |
| **HDF4** | **`rasterio.open()` → `src.subdatasets` → `rasterio.open(sds)`** — **`pyhdf` 를 안 쓴다** |
| HDF5 | `h5py.File()` |
| GeoTIFF | `rasterio.open()` + `src.read(band)` |
| Binary | `gzip` + `np.frombuffer` — **지오 라이브러리 불필요** |
| 재투영 | `pyproj.Transformer(..., always_xy=True)` · `rasterio.warp.reproject` |

**빌드에 걸리는 것 둘**
- **HDF4 를 rasterio 로 읽으려면 conda-forge `hdf4`(GDAL HDF4 드라이버)가 필수다. pip 휠에 없다.**
- **GRIB 을 빼면(`〈51〉`) `eccodes` + `libeccodes-dev` 시스템 의존성이 통째로 빠져 컨테이너가 크게 가벼워진다.**

**⚠ 선언과 실사용이 다르다** — PoC 는 `titiler` 를 설치하고 **import 0건**이었다(타일링은 자작). 프론트는 XYZ 타일이 아니라 **Leaflet `ImageOverlay` 단일 PNG** 였다. **v2 에 타일링 선례가 없다.**

## 7. 계승하지 않는 것

**PoC 에 있지만 v2 가 반대로 가는 것.** C3 가 「PoC 지식을 뽑는다」로만 적혀 있으면 **여기서 잘못 뽑힌다.**

| PoC | v2 | 근거 |
|---|---|---|
| 등재 시점에 **파일을 안 연다** — 포맷=확장자, 기간·좌표계·격자=**사람이 타이핑**, 용량=**클라이언트 신고값** | **파일에서 자동으로 읽는다 — 사람이 타이핑하지 않는다** | `DATAMODEL §4.1` · `DR-14` |
| 파일을 **통째로 메모리에 적재** | **전체 적재 금지 — 윈도우/스트리밍** (50 GB 가 들어온다) | `pipeline-worker/README.md` · `DR-11` |
| 포맷이 섞이면 **`MIXED` 로 기록** | **포맷이 다르면 데이터셋을 나눈다** — *「하나라도 다르면 조각이 아니라 다른 데이터다」* | `DATAMODEL §4.3` |
| 계보에 **가공 방식 필드가 없다** (`relation_type` 항상 `derived`) | **가공 방식은 관계에 부착한다** | `DATAMODEL §4.2` · `DR-15` |
| 좌표 못 찾으면 **격자를 지어내고 성공 반환** | **못 읽으면 `[미상]` 이고 실패다** | `DR-9` · `㊴-②` |
| **멱등성 없음** — 같은 파일 두 번 = 데이터셋 둘 | **재실행 멱등**이 S2 완료 판정 | `WORK-UNITS §8.5` |

**반대로 물려받을 만한 것** — PoC 계보의 **순환 감지 · 레벨 제약 · 권한 마스킹**은 이미 풀어 둔 문제다(`DR-15`).
