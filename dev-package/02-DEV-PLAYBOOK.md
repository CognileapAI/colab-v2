# 02 · DEV PLAYBOOK — 전체 여정 (Ted용)

> 이 문서는 Ted가 **흐름을 따라가고, 결정을 내리고, 결과를 검증**하기 위한 것이다.
> 세부 규약은 `01-CLAUDE-DRIVER.md`, 경계는 `DOMAINS.md`, 순서는 `WORK-UNITS.md`.

---

## 1. 이 프로젝트가 이기는 조건

세 번째 코드베이스다. 앞의 둘이 왜 멈췄는지가 답이다.

| | 왜 멈췄나 | v2의 답 |
|---|---|---|
| PoC | **경계가 없었다** — Dataset 112컬럼, 모듈 간 침범, 타입 수동 동기화 | 도메인 10개 + 기계 강제 경계(`DOMAINS.md §5`) |
| v1 Launch | **기획이 흔들렸다** — 12 BC를 짓는 중에 기획이 두 방향으로 갈라짐 | 정본을 먼저 닫고(260818) 도메인을 거기서 유도 |

그래서 v2에서 Ted가 지켜야 할 것은 코드가 아니라 **두 가지 경계**다 — 기획 정본의 경계(범위를 늘리지 않는 것), 도메인의 경계(섞지 않는 것).

## 2. 여정 (일정 아님, 의존 순서)

```
① 열기      I0 AWS계정 · G2 검색엔진 · G8 온톨로지범위 · C1 푸시확인
              └ 전부 병렬. 사람 결정과 승인 리드타임이 지배한다
                        ↓
② 정리      C2 v1 이관 · C3 PoC 지식추출 · C4 v1 방법론추출
              G1 패키지 재빌드 · G5 스키마 대조 · G7 SSOT 통합
                        ↓
③ 고정      D1 도메인 확정 → D2 계약 동결 → D3 경계 강제 장치
              └ 여기를 지나면 병렬 개발이 안전해진다
                        ↓
④ 뼈대      P0 공통 기반  +  I2 walking skeleton 배포
              └ 빈 서비스 5종을 AWS에 한 번 올린다. 통합 지옥 예방
                        ↓
⑤ 짓기      P1~P7 (플랫폼)  ∥  K1~K5 (온톨로지·AI)
              └ 완전 병렬. 만나는 곳은 P2←K3, P4←K4 두 곳
                        ↓
⑥ 닫기      P8 · I4 운영준비 · I5 prod 전환
              └ 완료 정의 7조건 전부 충족 (WORK-UNITS §1.5)
```

## 3. Ted가 내릴 결정

| 결정 | 왜 Ted여야 하나 | 언제까지 |
|---|---|---|
| **AWS 계정·결제·리전** | 돈과 계약 | I1 전 — **지금** |
| **자연어 검색 엔진** | 제품 품질의 성격을 정한다. 관련도 값의 형태와 근거 생성 방식 | P4·K4 전 — **지금 논의 개시** |
| **온톨로지 1차 범위** | 수문학 도메인 판단. 개발자가 대신 정하면 아무도 검증 못 한다 | K1 전 — **지금** |
| **도메인 소유자 배정** | 협업 경계 = 사람 경계 | D1 |
| **E-01 권한 원칙 분리** | 기획 소유 | P0 전 |
| **미배치 화면 3건 단계** | 기획 소유 | P0~P2 |
| **접근 승인 회수 규칙** | 정책 | P6 전 |

## 4. 검증법 — 무엇을 보고 "됐다"고 하나

Ted가 직접 확인할 수 있는 것만 적는다.

| 국면 | 무엇을 보나 |
|---|---|
| 계약 동결 (D2) | 계약 게이트가 **일부러 깨뜨렸을 때 red**가 되는가 (self-test) |
| 경계 (D3) | D10→D4 쓰기 음성 테스트, cross-tenant 음성 테스트가 **red→green**으로 증명됐는가 |
| 뼈대 (I2) | staging URL에서 5개 서비스 헬스 green + **롤백 1회 성공** |
| 각 단계 (P) | 목업 대비 화면 · 스토리 수용 기준 · **staging 배포 green** |
| AI (K3·K4) | 평가셋 결과. 그리고 **AI를 꺼도 제품이 동작하는가** |
| 완료 | `WORK-UNITS §1.5` 7조건 + §11 체크리스트 전부 ✅ |

## 5. 위험 신호 — 이게 보이면 멈춘다

| 신호 | 무엇을 뜻하나 |
|---|---|
| "일단 이 도메인에서 저 테이블 직접 읽자" | 경계 붕괴 시작. PoC가 이렇게 무너졌다 |
| "AI 제안을 자동 반영하면 편할 텐데" | 정본 규칙 위반. [모두 승인]을 두지 않은 이유가 있다 |
| "배포는 나중에 한 번에" | I2를 건너뛰는 것. 통합 지옥이 마지막에 온다 |
| "이 화면은 다음 버전에" | 완료 정의 훼손. 범위를 줄이려면 **정본을 먼저 고친다** |
| "대화형으로 하면 더 좋지 않나" | v3 스코프 유입. v2 정본이 명시적으로 뺀 것 |
| HANDOFF가 며칠째 그대로 | 인계가 끊겼다. 다음 세션이 헤맨다 |
