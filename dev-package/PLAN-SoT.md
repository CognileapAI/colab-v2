### 1.1 확정 사항 (2026-08-22, Ted)

| | |

## 2. 설계 원리 세 개

### ① 도메인 경계는 협업과 컨텍스트 윈도우가 정한다

전통적 분해 동인(팀 규모, 조율 비용)은 AI 개발에서 두 제약으로 치환된다 — **에이전트 컨텍스트 윈도우**와 **드리프트**. 조율 비용은 사실상 0이므로, 의존을 줄이는 절단이 항상 이긴다. 상세 = `DOMAINS.md §1`.

### ② 계약이 유일한 도메인 간 API이고, 기계가 검증한다

"계약"은 HTTP만이 아니다. **HTTP seam + DB 스키마 + 도메인 간 in-process 호출 경계** 셋 다. v1에서 실제로 터진 버그가 전부 이 셋에서 났다.

### ③ 테스트가 명세이자 오라클

WU의 완료 판정은 사람 의견이 아니라 게이트 green이다. 오라클을 만들 수 없는 WU는 쪼갠다.

## 3. 아키텍처 — 도메인에서 런타임으로

10 도메인 → 5 배포 단위. 근거는 워크로드 프로파일뿐이다.

| 배포 단위 | 도메인 | 프로파일 | 배치 |
|---|---|---|---|
| **core-api** | D1 D2 D3 D4 D6 D8 | stateless · IO bound · 지연 민감 · **geo 라이브러리 0** | 컨테이너 (modular monolith) |
| **pipeline-worker** | D5 | 고 CPU·메모리 · bursty | 배치 워커 (스팟 가능) |
| **viz-render** | D7 | 중 CPU · 캐시 가능 · geo 필요 | 타일 서버 + CDN |
| **ai-service** | **D9 D10** | 외부 모델 호출 · 지연 편차 큼 · **실패가 제품을 멈추면 안 됨** | 별도 서비스 |
| **frontend** | — | 정적 | CDN |

> 도메인 10개를 서비스 10개로 띄우지 않는다. 같은 프로파일을 쪼개면 분산 모놀리스가 된다.

### 3.1 AI 경로는 임계경로가 아니다

정본 설계상 AI는 **두 지점의 보조**다. 계보 제안이 실패하면 사용자가 직접 입력하고, 검색이 실패하면 카탈로그 필터로 간다. 따라서:

- `ai-service` 장애가 core-api를 막지 않는다 (타임아웃 + 우아한 성능 저하)
- AI 응답 대기가 업로드 트랜잭션을 잡고 있지 않는다 (제안은 비동기, 화면은 대기 상태 표시)
- **AI 없이도 v2는 완결된 제품이다.** 이 성질을 잃는 설계는 거부한다

## 4. 계약 거버넌스

### 4.1 seam 목록 (여기만 계약을 손으로 쓴다)

| seam | 성격 | 계약 형식 |
|---|---|---|
| FE ↔ core-api | sync, 드리프트 최다 발생 지점 | OpenAPI 3.1 (hand-authored) |
| core-api ↔ viz-render | sync | OpenAPI 3.1 |
| **core-api ↔ ai-service** | sync, 실패 허용 | OpenAPI 3.1 + **degraded 응답 규격 필수** |
| core-api ↔ pipeline-worker | async | 이벤트 봉투 JSON-Schema + 멱등 키 + DLQ 재처리 규칙 |

도메인 내부 엔드포인트는 code-first로 emit하고, **emit 결과가 frozen seam과 충돌하면 CI가 거부**한다.

### 4.2 DB 스키마 계약

- **단일 정규 ID 타입** — shared kernel 1곳 정의(ULID `CHAR(26)`). v1의 `String(20/30/36)` 드리프트를 구조적으로 제거
- **도메인별 테이블 소유 + 접두사**, 타 도메인 테이블 직접 FK 금지 (import-linter)
- **마이그레이션 single-head** 강제
- **스키마 diff 게이트** — 선언 스키마 ↔ 적용 DB 비교
- **D9/D10은 별도 스키마 · 별도 마이그레이션 head** (`DOMAINS.md §3②`)

### 4.3 멀티테넌시

전 연구실이 한 DB를 공유한다. 앱 레이어만으로는 부족하다.

1. **tenant-scoping 커널** — 모든 조회에 연구실 스코프 자동 주입, un-scoped raw 쿼리 lint 금지
2. **PostgreSQL RLS** — ENABLE + FORCE + tenant-isolation 정책
3. **cross-tenant 음성 통합테스트** — 한 줄 스코프 누락을 DB가 막는지 증명
4. **RLS 커버리지 게이트** — allow-list 밖 테이블에 RLS 없으면 red

> v1에서 이 3중 방어가 실제로 동작함을 증명했다. **설계를 참조하되 코드는 다시 쓴다**(§6.2).

## 5. 지식 레이어 아키텍처 (D9 · D10)

### 5.1 왜 그래프인가

v2가 AI에게 시키는 두 일은 모두 **관계 질의**다.

| 지점 | 실제로 묻는 것 |
|---|---|
| 계보 제안 (E-04) | "이 파일과 같은 변수·같은 공간·더 낮은 가공 단계인 데이터셋이 우리 연구실에 있는가, 그리고 그 둘 사이의 가공 방식은 무엇으로 설명되는가" |
| 자연어 검색 (E-02) | "'낙동강 유역 강우'가 가리키는 변수·공간 개념은 무엇이고, 그 개념에 걸리는 데이터셋은 무엇인가" |

둘 다 **벡터 유사도만으로는 답이 안 된다.** "낙동강 유역"이 어떤 행정구역·관측소를 포함하는지, "리샘플"과 "보간"이 같은 가공 계열인지는 **명시적 관계 지식**이다. 그래서 온톨로지 + 그래프가 필요하고, 임베딩은 그 위의 보조 색인이다.

### 5.2 D9 구성

| 층 | 내용 |
|---|---|
| **개념(T-Box)** | 변수 · 좌표계 · 공간 위계(유역 ⊃ 소유역 ⊃ 행정구역) · 관측소 · 가공 방식 계열 · 출처 기관. 개념 간 관계와 동의어 |
| **인스턴스(A-Box)** | 실제 데이터셋·파일 엔티티를 개념에 건 링크 |
| **색인** | 개념·설명 임베딩 (그래프 탐색의 진입점) |

**A-Box는 D3(Catalog)의 사본이 아니라 참조다.** 데이터셋 본문은 D3에 있고, D9는 ID와 개념 링크만 든다. 사본을 두면 두 개가 갈라진다.

### 5.3 D10이 지키는 규칙

정본이 못 박은 것을 구조로 옮긴다.

| 정본 규칙 | 구조적 보증 |
|---|---|
| "확인한 것만 계보로 확정된다" | **D10에 D4 쓰기 Port를 주지 않는다.** 제안은 D10 소유 임시 저장소에 살고, 사람 확인 이벤트만 D4 커밋을 유발 |
| "[모두 승인] 버튼 없음" | 제안 API가 배치 승인 엔드포인트를 아예 노출하지 않는다 |
| 확신도는 **확실/애매/모름** 3단계, 퍼센트 금지 | 응답 스키마가 enum. 실수가 타입 오류가 된다 |
| 근거를 함께 낸다 | 제안·검색 응답에 근거 필드 **필수**(nullable 아님) |
| 못 찾으면 정직한 빈 상태 | 빈 결과가 정상 응답. 억지 제안 금지 |
| 검색 근거는 **한 줄 고정** | 응답 스키마에 길이 제약 |
| 뒤진 범위를 먼저 밝힌다 | 응답에 탐색 범위 필드 필수 |

### 5.4 모델 선택

**GPT 전면 통일 — staging·prod 동일** (`§9-㊷`, v1의 Claude 2티어 판정을 대체). ModelPort 뒤 OpenAI **API 키** 인증. 2티어 구성은 유지한다 — 헬퍼(질의 해석·의미 연결 등 하위 작업) = 경량 모델, 오케스트레이션(계보 제안·검색 응답 조립) = 중간 모델. 공급자 교체가 도메인 코드에 닿지 않아야 한다는 원칙은 그대로다 — Claude/Bedrock 어댑터는 휴면 보관하고, 국내 데이터 처리 요건이 걸리면 어댑터만 갈아 끼운다.

## 7. 스택

v2 기준으로 다시 고른다. v1의 판정은 **근거를 읽되 결론을 승계하지 않는다.** 도메인별 확정은 WU-D2에서.

| 계층 | 방향 | 제약 |
|---|---|---|
| core-api | Python 비동기 웹 프레임워크 + ORM | **geo 라이브러리 import 금지**(게이트) |
| pipeline-worker | Python 과학 스택 | 50GB급 스트리밍. 전체 메모리 적재 금지 |
| viz-render | COG 바이트 범위 타일 서버 + CDN | 인제스트 시 overview 선생성 |
| **ai-service** | Python + ModelPort | 그래프 저장소는 **WU-K1** |
| frontend | 타입 안전 라우팅 + 생성 클라이언트 | 손수정 금지 |
| DB | PostgreSQL + 공간·벡터·트라이그램 확장 | 메타·카탈로그·계보·권한만. 래스터는 객체 스토리지 |

## 8. AWS — 배포가 완료 조건이다

**개발 목표는 AWS 배포까지다.** 로컬 green은 중간 산물이며, WU의 완료 판정에 배포가 들어간다.

### 8.1 원칙 — walking skeleton을 먼저 올린다

기능을 다 만든 뒤 배포하지 않는다. **P0 직후, 빈 껍데기 상태에서 5개 배포 단위를 전부 AWS에 한 번 올린다**(WU-I2). 이후 모든 WU는 이미 서 있는 파이프라인 위로 배포된다.

이유 — 통합 지옥은 기능이 아니라 **배포 경로**에서 온다. 마지막에 몰면 그때 전부 터지고, 그 시점엔 되돌릴 시간이 없다.

```
P0 (도메인 뼈대)  →  I2 (빈 서비스 5종 AWS 배포)  →  이후 모든 WU가 배포까지 포함
```

### 8.2 환경 분리

| 환경 | 어디 | 용도 |
|---|---|---|
| **dev / test** | 로컬 컨테이너 | 도메인 구현·게이트 실행. AWS 불필요 |

### 8.3 토폴로지 (WU-I1에서 확정)

| 배포 단위 | 성격 | 요건 |
|---|---|---|
| core-api | 컨테이너 오케스트레이션, ALB 뒤, private 서브넷 | 지연 민감 → 상시 가동 |
| pipeline-worker | 배치·스팟. scale-to-zero | 중단 대비 체크포인트 + 온디맨드 폴백 |

### 8.4 배포에 반드시 들어가는 것

- **IaC 전량** — 콘솔 수작업 0. `plan`은 로컬에서 검증, `apply`만 계정 필요
- **비용 가드** — 예산 알람 + 태그 기반 귀속. 초기 규모에서 지배 항목은 DB 최소 용량·객체 스토리지·CDN 전송
- **데이터 레지던시** — 국내 리전 고정. AI 모델 호출의 처리 위치를 명시적으로 기록
- **복구** — 시점 복구 + 스토리지 버전 관리 + 복원 리허설 1회
- **롤백 경로** — 배포 실패 시 이전 이미지로 되돌아가는 경로를 I2에서 함께 증명
