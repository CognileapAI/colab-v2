## 3. 산출물 규격

### 3.1 목록 썸네일 — 128 px · stride · WEBP

| 항목 | 값 | 근거 |
|---|---|---|
| 긴 변 | 128 px, 짧은 변은 종횡비 유지 | 정본 §1.3 |
| 다운샘플 | **stride**(`arr[::s, ::s]`) | stride는 전 포맷 **0.0 ms**(뷰만 생성) — 정본 §5.2 |
| 포맷 | **WEBP q80** | WEBP가 PNG의 26~50 % — 정본 §5.5 |
| 생성 정책 | **전량 사전 생성** | 229장 4워커 **5.2 s** · 전량 **2.6 MB**(PNG면 6.0 MB) — 정본 §5.5 |
| 좌표 | **붙이지 않는다** | 목록에서 지도에 얹지 않는다 |

**썸네일에서 stride를 쓰는 것은 의도된 타협이다.** 128 px는 **형상 식별용**이라 누락을 허용한다. 상세에서는 허용하지 않는다(§3.2).

### 3.2 상세 — 1024 px · 블록평균 · PNG

| 항목 | 값 |
|---|---|
| 긴 변 | 1024 px |
| 다운샘플 | **블록평균**(`s×s` 블록의 유효값 평균. 결측 픽셀은 평균에서 제외하고, 블록 전체가 결측이면 결측) |
| 포맷 | **PNG RGBA** (결측 = 알파 0) |

**stride를 쓰면 안 되는 이유 — 실측.** HSR `202508131000` 대비 실험:

| 대비 | stride 3 | 블록평균 |
|---|---|---|
| 전역 강수 블록 | 69,568개 중 **4,031개 누락 (5.79 %)** | 누락 없음 |
| 산발 에코 360×360 확대 | 2,392개 중 **404개 누락 (16.9 %)** | 누락 없음 |

**점 형태 강수가 실제로 사라진다.** 전역 6 % · 국지 17 %다. 예시 이미지 — `hsr_bad_stride.png` vs `hsr_detail_blockavg.png`, 확대는 `hsr_crop_stride.png` vs `hsr_crop_blockavg.png`.

블록평균은 픽셀 수에 비례한 비용이 붙는다(bin 98.3 ms · tif 157.5 ms · hdf 87.5 ms · nc 2.1 ms — 정본 §5.2). **그 비용을 낸다.**

### 3.3 bbox 사이드카 JSON — 필드 스키마

**지도형 PNG 하나마다 같은 이름의 `.json` 을 나란히 둔다.** PNG 안에는 좌표를 적을 자리가 없다.

실물 한 벌 (`hsr_detail_1024_map.json`, 그대로 인용):

```json
{
  "name": "hsr_detail_1024_map.png",
  "crs": "EPSG:3857",
  "bbox_3857": [13568049.704, 3650897.322, 14867609.374, 5358243.368],
  "bbox_4326": [121.883864, 31.139640, 133.558007, 43.303245],
  "width": 1024,
  "height": 1346,
  "pixel_size_m": [1269.101, 1268.459],
  "source": "RDR_CMP_HSR_PUB_202508131000.bin.gz",
  "created": "2026-08-24T03:25:39"
}
```

| 필드 | 타입 | 필수 | 의미 | 규칙 |
|---|---|---|---|---|
| `name` | string | ✔ | 짝이 되는 PNG의 **파일명**(경로 아님) | 사이드카와 같은 디렉터리에 있는 파일을 가리킨다. 절대경로를 넣지 마라 |
| `crs` | string | ✔ | 이미지 픽셀 격자의 좌표계 | **`"EPSG:3857"` 고정.** 다른 값이 필요하면 warp 단계가 잘못된 것이다 |
| `bbox_3857` | number[4] | ✔ | `[minx, miny, maxx, maxy]` (m) — **이미지 바깥 모서리** | 픽셀 **중심**이 아니다. `.pgw` 와 반 픽셀 차이가 나는 이유가 이것이다 |
| `bbox_4326` | number[4] | ✔ | 같은 경계를 WGS84 경위도로. `[west, south, east, north]` | **소수 6자리.** 계약 `core-viz.yaml#/components/schemas/Bounds`(west/south/east/north)와 **같은 값·같은 순서**다 — 이 배열이 그 객체로 그대로 접힌다 |
| `width` | integer | ✔ | PNG 가로 픽셀 | 긴 변이 1024가 되도록 잡은 결과. 세로가 길면 `height` 가 1024다 |
| `height` | integer | ✔ | PNG 세로 픽셀 | |
| `pixel_size_m` | number[2] | ✔ | `[x 방향, y 방향]` 픽셀 크기 (m, **양수**) | 3857 미터 단위다. **지상 실거리가 아니다** — 메르카토르라 위도에 따라 늘어난다. 거리 계산에 쓰지 마라 |
| `source` | string | ✔ | 이 이미지를 만든 **원본 본체 파일명** | 파일명만. 계보·해시는 여기 담지 않는다(D4 소관) |
| `created` | string | ✔ | 생성 시각 ISO-8601 | 캐시 무효화 판단에 쓰지 않는다 — 그건 캐시 키가 한다(§8) |

**넣지 않는 것** — 위경도 배열, 격자 파일 경로, 스케일 범위·컬러맵(그건 범례가 나른다 — 계약 `Legend`), 원본 CRS 파라미터. **§10-3을 보라.**

4종 실측 bbox (EPSG:4326, 소수 6자리):

| 포맷 | 서 | 남 | 동 | 북 | 픽셀 | warp 전 원본 CRS |
|---|---:|---:|---:|---:|---|---|
| bin HSR | 121.883864 | 31.139640 | 133.558007 | 43.303245 | 1024 × 1346 | Lambert (헤더 아님 — 격자 파일에서) |
| nc GK2A | 114.054017 | 29.947443 | 137.605109 | 46.356057 | 1024 × 914 | Lambert (LCC, CF 속성) |
| tif HLS | 125.244880 | 36.911360 | 126.522658 | 37.925944 | 1024 × 1024 | UTM 51N (EPSG:32651) |
| hdf MODIS | 95.761867 | 19.984312 | 138.978668 | 40.012017 | 1024 × 552 | Sinusoidal |

### 3.4 월드 파일 `.pgw` — 6줄

**GIS 도구가 PNG를 바로 열게 하는 규격이다.** 사이드카 JSON의 대체가 아니라 **병행**이다 — JSON은 웹이 읽고, `.pgw` 는 QGIS·ArcGIS가 읽는다.

| 줄 | 값 (HSR 실물) | 의미 |
|---:|---|---|
| 1 | `1269.1012405929` | x 방향 픽셀 크기 (m) |
| 2 | `0.0000000000` | 회전 (행) — **warp 후라 항상 0** |
| 3 | `0.0000000000` | 회전 (열) — **항상 0** |
| 4 | `-1268.4591718509` | y 방향 픽셀 크기 (m). **음수다** — 이미지는 위에서 아래로 가고 좌표는 아래에서 위로 간다 |
| 5 | `13568684.2547301762` | **좌상단 픽셀 중심** x |
| 6 | `5357609.1382023031` | **좌상단 픽셀 중심** y |

**⚠ 5·6행은 픽셀 *중심*이고 `bbox_3857` 은 이미지 *바깥 모서리*다.** 반 픽셀 차이가 정상이다 — 검산 시 `line5 = bbox_3857[0] + |line1|/2`, `line6 = bbox_3857[3] − |line4|/2`. 두 값을 같게 만들려고 고치지 마라.
**`.pgw` 는 3857 좌표만 담고 CRS를 못 담는다.** 도구가 좌표계를 물으면 사이드카 JSON의 `crs` 를 쓴다. (`.prj` 를 함께 낼지는 **미결** — 정본에 근거 없음.)

## 5. HSR 특례 — 이 절을 건너뛰지 마라

**다섯 포맷 중 HSR 하나만 처리 순서가 다르다.** 나머지 넷은 파일이 격자를 주고, HSR은 밖에서 받아야만 한다.

### 5.1 왜 다른가

- 헤더 1024 B 중 **투영 파라미터 자리인 36~63 B가 실물에서 전부 0**이다 (✅확인 — 실물 바이트 판독).
- 헤더가 주는 것은 `nx=2305`·`ny=2881`·`dxy=500`·`map_code=1` 뿐이다. **크기·해상도는 있는데 투영을 세울 값이 없다.**
- 명세 기재값(Lambert · 표준위도 30/60 · 기준 N38.0 E126.0)으로 재현하면 dx가 499 m로 어긋나고, 최적 피팅해도 위도 **0.053°(≈5.9 km = 500 m 셀 11.8개)** 오차가 남는다 → **재현 불가**.
- **격자는 곡선 격자(curvilinear)다.** 픽셀마다 위경도가 따로 있는 2차원 배열 두 장이고, 규칙 격자가 아니다.
- 실증 — 격자 없이 3857로 warp 한 1차 시도가 **위도 26°로 밀렸다**(정본 §5.6).

> 이건 「코드가 막고 있다」가 아니다. **현행 `d5/grid.py` 가 HSR에 격자를 요구하고 못 찾으면 예외를 던지는 것은 옳은 동작이다.**

### 5.2 처리 순서

```
① 본체 .bin.gz 해제 → 헤더 1024 B 판독 → num_data × 파일길이 교차검증
② 블록 선택(기본 반사도) → <i2 → /100 dBZ → 결측 정확일치(−25000·−30000)로 마스크
   └ 여기까지로 ② 비지도형 미리보기가 나온다 (약 49 ms · 정본 §5.3)
③ 격자 npy 2장 로드 (위도·경도, 각 2881×2305 f32, 26.6 MB) — mmap
④ 곡선 격자 + 값 배열 → EPSG:3857 warp (규칙 격자로 편다)
⑤ 1024 px 격자 평균 리샘플 → PNG RGBA   ← ⭑ 개정 2026-09-03 · 〈308〉-㉰ — 「격자 평균」이 아니라 아래 두 단이다
⑥ bbox 사이드카 JSON + .pgw 생성
   └ 여기까지로 ③ 지도형 미리보기가 나온다
```

> ⭑ **⟨개정 2026-09-03 · `PLAN-SoT §9 〈308〉`-㉰ · `BF-2` · 커밋 `40844ea`·`5f6b75f`⟩ ③지도형 리샘플의 정의가 바뀌었다 — 「warp 후 격자 평균」 → 「축소 후 근사 최근접」.** 정본은 `preview.py` `warp_to_3857` docstring 이고 아래는 그 요지다.
> **왜 바꿨나** — 종전은 **전방 산란**(원본 셀을 출력 격자에 `np.add.at` 으로 던져 넣고 셀이 안 떨어진 픽셀은 결측)이라 **원본이 출력보다 촘촘할 때만** 옳았다. 출력 긴 변은 항상 1024 인데 원본은 그보다 성길 수 있고, 126×128 원본에서 채워진 픽셀이 **1.95 %** 로 떨어져 화면이 점 격자가 됐다(Ted 접수 B-1). 같은 해상도(1024×1024)에서도 lat→y 가 비선형이라 **전 결측 행 2줄**(가로 흰 줄)이 남았다 — lon→x 는 선형이라 세로 줄은 없었다.
> **지금은 두 단이다** — ⑴ **촘촘하면 먼저 줄인다**: 원본 긴 변이 `max_side` 를 넘으면 `block_average` 로 내린다(좌표는 평균하지 않고 `sample_centers` 로 집는다). **「촘촘 → 평균」 성질은 이 단계에서 지켜진다** — ②비지도형과 같은 사다리다. ⑵ **성기면 출력이 원본을 찾아간다**: 원본 셀을 씨앗으로 심고 2패스(행·열)로 가까운 씨앗의 값을 퍼뜨린다. **근사 최근접**이다 — 정확 최근접과의 일치율은 126×128→512 에서 약 **86 %**, 30×32→256 에서 약 **95 %**(브루트포스 대조 · advisor 게이트 ②). 판정 거리는 3857 위의 거리이고 3857 은 등각사상이라 픽셀 좌표 위의 거리와 같은 순서를 준다.
> **결측은 여전히 결측이다** — 값이 없는 원본 셀도 씨앗으로 자리를 잡으므로 이웃 값이 NoData 를 메우지 않는다. 씨앗이 원본 간격보다 멀리 있으면 채우지 않아 곡선 격자의 bbox 모서리는 발자국 밖으로 남는다.
> ⚠ **등재된 한계 둘** — ㉠ 근사 최근접이라 셀 경계가 1 px 들쭉날쭉할 수 있다(미리보기 배율에서 식별되지 않는다). ㉡ **「촘촘 → 평균」은 ⑴ 축소 단계에서만 성립한다** — 긴 변 ≤ `max_side` 이면서 발자국이 bbox 보다 작은 곡선 격자(크게 회전한 격자)는 한 출력 픽셀에 씨앗이 여럿 떨어져도 평균하지 않고 하나만 남는다. 현재 실원천(규칙 격자 · ≤1024)에는 이 부류가 없다.
> **캐시 키** — 다운샘플 라벨이 `warp+blockavg` → **`warp+nearest`** 로 바뀌어(`§7.2`) 배포 즉시 구 PNG 가 키에서 갈라진다. ⚠ 배포 순서는 **`BF-2` 배포 → 재굽기 1회**(`RC-1` 진입조건 · `〈308〉`-㉲).

**④를 지난 뒤로는 HSR도 다른 포맷과 완전히 같다 — 클라이언트가 받는 것은 PNG와 bbox 네 숫자뿐이다.**

### 5.3 npy는 서버에만 있다

| 항목 | 위경도 배열 2장 | bbox JSON |
|---|---|---|
| 전송량 | **53 MB** | 약 **400 B** |
| 차이 | | **13만 배** |
| 브라우저 부담 | float 수백만 개 역직렬화 + 메모리 상주 | 숫자 4개 읽기 |

**격자 npy는 ④ warp 시점에만 쓰이고 클라이언트로 내려가지 않는다.** 곡선 격자라는 사실은 서버 안에서 소멸한다. **위경도 배열을 API 응답·JSON·타일 메타 어디에도 싣지 마라**(§10-3).

|---|---|---|
| **가-1** | **디렉터리 범위** | 격자는 `04.Lat_Lon_info/` 또는 `#metadata/` 안에서만 찾는다. **본체 폴더를 뒤지지 마라** |
| **가-2** | **stem 대응** | 위경도 토큰(`lat`/`Lat`/`LAT`, `lon`/`Lon`/`LON`)을 **대소문자 무시하고** 제거한 나머지 stem이 같으면 한 쌍이다. `Lat_HSR`↔`Lon_HSR` · `lat2d_h27v05`↔`lon2d_h27v05` · `…v2.0_lat2d`↔`…v2.0_lon2d` |

| **가-4** | **형상 대조로 확정한다 — 이 단계를 생략하지 마라** | 격자 shape가 본체 shape와 정확히 일치해야 짝이다. 현행 `d5/grid.py` 의 `expect_shape` 가 이 일을 한다. **파일명이 맞아도 형상이 다르면 짝이 아니다** |

**⚠ 대소문자가 트리마다 다르다.** 같은 배열이 `02.File-format` 에서는 **`Lat_HSR.npy`**(첫 글자만 대문자), `01.level-data` 에서는 **`LAT_HSR.npy`**(전부 대문자)로 나온다 — 크기 26,562,948 B로 동일하다. **대소문자 구분 비교를 하드코딩하면 한쪽을 못 찾는다.** 항상 `casefold()` 후 비교한다. (현행 `d5/grid.py` 는 `name.lower().startswith("lat")` 라 이 함정은 이미 피해 있다.)

**⚠ `fortran_order` 도 트리마다 다르다.** 식생 `#metadata` 의 `LAT.npy`·`LAT_crop.npy`·`LON*` 은 `fortran_order: True` 로 저장돼 있고, 나머지 전부는 `False` 다. **C-order를 가정하면 축이 전치된 격자를 얻는다.** `np.load` 는 이걸 알아서 처리하므로 **직접 헤더를 파싱해 `reshape` 하지 마라.**

**⚠ HSR 정본 격자는 아직 미결이다** — `Lat/Lon_HSR.npy` 쌍과 `rdr_500m_latlon.nc` 가 **612 m(1.22 셀) 어긋난다.** `.nc` 도 표준위도가 없어 불완전하다. 정본 §9 U-1 — **사람이 정할 일이다. 구현이 관례로 고르지 마라.** 정하기 전까지는 `.npy` 쌍을 쓴다(`DATA-REFERENCE §1.1` 권고).



#### 5.4.2 축 판별 — 판별 사다리를 따른다

**순서를 고정한다. 위에서부터 내려가다 확신이 서면 멈춘다.**

| 순 | 규칙 | 실측 적중 | 판정 방법 | 깨지는 자리 |
|---|---|---|---|---|
| ① | **파일 내장 좌표·CRS** | — | 파일 안에 좌표 변수·투영 정보가 있으면 격자 파일 자체가 불필요 | nc·tif·hdf는 여기서 끝난다. **HSR은 여기가 비어 있다** |
| ② | **값 범위** | **14 / 14** | **절댓값 최대 > 90 → 경도.** 위도는 90을 넘을 수 없고, 한반도 경도는 114~144라 항상 넘는다 | 둘 다 90 이하면 판별 실패 |
| ③ | **쌍 정합** | — | 두 배열의 shape가 같고 본체 shape와 일치하면 **한 장은 위도·한 장은 경도**임까지는 확정된다 | 어느 쪽이 어느 쪽인지는 ②가 가른다 |
| ④ | **파일명** | 14 / 14 (현 샘플) | `lat*` / `lon*` 토큰 | **외부 반입 파일에서 가장 먼저 깨진다.** 그래서 맨 아래다 |

**쓰지 않는 규칙 — 축 변동 방향 (12 / 14).** 「행 방향으로 크게 변하면 위도」는 **MODIS 경도 2건에서 뒤집힌다**(행 방향 변동 14.3° / 15.8° > 열 방향 12.2°). 이 규칙은 **격자가 반듯하다**를 전제로 깔고 있고 sinusoidal은 반듯하지 않다. **사다리에 넣지 마라.**

**④까지 내려가도 확신이 없으면 판별 실패다. 그 파일만 거부하고 나머지 등록은 진행한다.** `linspace` 로 격자를 지어내지 마라 — PoC 1세대가 4곳에서 그렇게 하고 「성공」을 반환했다(`DR-9`).

**사용자에게 축을 묻지 마라.** 자기가 올린 npy가 위도인지 경도인지 사용자도 모른다. 서버가 판별하고, **등록 확정 전 지도로 보여주고, 틀렸으면 뒤집기 버튼 하나**로 정정하게 한다. (⚠ **축 수동 정정 경로가 계약에 아직 없다** — §11.)

### 5.5 격자가 아직 없을 때

| 상태 | 만드는 것 | 만들지 않는 것 |
|---|---|---|
| 격자 없음 | **① 썸네일 · ② 비지도형** (HSR 비지도형 약 **49 ms** — 정본 §5.3) | **③ 지도형 — 보류.** 실패가 아니라 보류다 |
| 격자 후주입됨 | **③ 지도형만 새로 생성** | **①②는 유지한다** — 원본도 렌더 파라미터도 안 바뀌었으므로 캐시 키가 같다(§8) |

- **후주입·교체는 정상 동작이다**(`〈58〉`·`〈59〉`). 잘못 붙인 격자를 바로잡는 것도 포함한다.
- 격자 교체 시 **계보는 접지 않는다**(`〈60〉`) — 바뀐 것은 과학 데이터가 아니라 좌표를 읽을 수단이다. 대신 `d8_activity` 에 `좌표계·격자 변경` 을 남긴다.
- 화면에는 **정밀도 배지**를 붙인다 — `동봉 격자 적용` / `투영 계산 격자`. 지금 보는 그림이 무엇을 근거로 그려졌는지 알 수 있게.
- **`withoutReferenceGrid` 를 HSR에 켜서 「그려 보기」를 시도하지 마라.** 계약에 이미 그렇게 적혀 있다(`core-viz.yaml`) — nc·tif·hdf에는 통하고 **Binary(HSR)에는 통하지 않으며, 합성 격자를 만들지 않고 실패로 끝낸다.**

### 5.6 결측 3값 — 정확일치

| 값 | 뜻 | 판정 |
|---:|---|---|
| **`−20000`** | 관측영역내 **표시 최소값** | **유효하다. 살린다** |
| `−25000` | 관측영역내 비관측 | 결측 |
| `−30000` | 관측반경 밖 | 결측 |

**`값 <= -20000` 으로 자르면 무엇이 사라지는가 — 실측** (HSR `202508131000`):

| 사라지는 것 | 개수 | 비율 |
|---|---:|---|
| 유효 `−20000` 픽셀 | 12 px | — |
| 그 아래 유효값 | **52,521 px** | 유효 709,256 중 **7.4 %** (미리보기 화면의 1.052 %) |

**부등호 판정은 약한 신호대를 통째로 지운다.** 예시 — `hsr_bad_fillcut.png`. `−25000`·`−30000` **둘만** 정확일치로 제외한다.

## 6. 공통 규칙 — 세 가지

### 6.1 결측은 정확일치로 판정한다

| 포맷 | 결측값 | 판정 |
|---|---|---|
| bin HSR | `−25000` · `−30000` | **정확일치.** `−20000` 은 유효 하한이다(§5.6) |
| nc GK2A | `_FillValue` = 65535 | **정확일치** |
| tif HLS | `nodata` = −9999 | **정확일치** |
| hdf MODIS | SDS별 `_FillValue`, `valid_range` 0~100 | **정확일치.** fill 255를 마스킹 없이 ×0.1 하면 25.5가 남는다 — `02.Results` 의 실제 버그다 |

**부등호로 자르지 마라.** 이 프로젝트는 같은 실수를 두 번 했다 — PoC가 `>= 249` 로 `256`·`1000` 을 함께 덮었고, HSR에서 `<= -20000` 이 유효값 52,521 px를 지운다(§5.6).
**결측 픽셀은 RGBA 알파 0으로 낸다.** 컬러맵의 색 하나를 결측에 배정하지 마라 — 그 색이 유효값과 구분되지 않는다.

### 6.2 스케일 범위는 데이터셋 단위 공통 고정

| 항목 | 규칙 |
|---|---|
| 산출 | **데이터셋 단위로 1회 산출한 뒤 고정한다.** 2–98 % 백분위 |
| 산출 비용 | **512 px 축약본 기준** — HSR 12파일 **884 ms** · nc 5파일 **204 ms** (전 해상도로 재지 마라) |
| 적용 | 그 데이터셋의 **모든 프레임·썸네일·상세·지도형에 같은 범위** |
| 갱신 | 범위가 바뀌면 **전 프레임 재생성** (§8) |

**프레임별 스트레치를 하지 마라 — 실측.**

| 데이터 | 개별 스트레치 vs 공통 범위 차이 | 판정 |
|---|---|---|
| nc LST 5프레임 | 평균 **2.9–26.8 DN**, **최대 42 DN**. p98이 **50분 만에 4.4 K 이동** | **재생 시 색이 튄다** |
| HSR 3프레임 | p98 폭 19.4, 평균 **0.8 DN** | 차이 미미 (5분 간격이라) |

**프레임별 스트레치는 값이 아니라 분포를 그린다.** HSR에서 차이가 작다고 규칙을 완화하지 마라 — nc 계열에서 즉시 깨진다. 예시 — `hsr_good_common_{0,1,2}.png` vs `hsr_bad_perframe_{0,1,2}.png`.

### 6.3 컬러맵

| 항목 | 값 |
|---|---|
| 기본 | **viridis** — 11앵커에서 보간한 **256엔트리 LUT**, 자체 구현(외부 의존 없음) |
| 결측 | RGBA 알파 0 |
| 사용자 선택 | **팔레트는 viz-render가 소유한다.** 이름을 계약·FE에 하드코딩하지 말고 `GET /palettes`(`core-viz.yaml` `listPalettes`)로 서빙한다 |
| 구간 수 | 3~9, 기본 6 (`RenderStyle.classCount`) — **범례에만 적용된다.** 미리보기 PNG 자체는 연속 LUT다 |

도메인별 컬러맵 후보는 `DATA-REFERENCE §6`(PoC `cmap_registry.py` 실측)에 있다.

## 7. 생성 시점과 캐시

### 7.1 언제 만드나

| 시점 | 무엇을 | 근거 |
|---|---|---|
| **첫 파일 도착 즉시** | **상세 1장을 동기로 렌더한다.** 전량을 기다리지 않는다 | ext4 기준 **30–334 ms** (정본 §10.2) · `/mnt/f` 비지도형 331–1374 ms |
| 그 직후 | 나머지 전량을 **백그라운드 큐 4워커** | 실측 speedup **3.06배 @4 vCPU** (정본 §2) |
| 데이터셋 단위 1회 | **공통 스케일 범위** 산출 (512 px 축약본) — 첫 장 렌더보다 **먼저** | §6.2 |
| 격자 후주입 시 | **지도형만** 재생성 | §5.5 |

**업로드와 처리를 파이프라이닝하지 마라.** 이득이 최대 1.4 s(nc·100 Mbps, 20 %)이고 나머지는 2~5 %다. **직렬로 두고 업로드를 병렬 멀티파트로 올리는 편이 낫다**(정본 §10.2).

### 7.2 캐시 키

**캐시 키 = 원본 해시 + 렌더 파라미터.** 렌더 파라미터에 들어가는 것:

| 파라미터 | 예 |
|---|---|
| 긴 변 | 128 / 1024 |
| 다운샘플 방식 | `stride` / `blockavg` / **`warp+nearest`** ⭑ ⟨개정 2026-09-03 · `〈308〉`-㉰ · `BF-2` · `5f6b75f`⟩ ／ 종전 ~~`warp+blockavg`~~ — 리샘플 알고리즘이 바뀌었는데 라벨이 그대로면 구·신 산출물이 같은 키를 쓴다(무효화는 키 자신의 일). 정의는 `§5.3` ⑤ 아래 주석 |
| 결측값 목록 | `[-25000, -30000]` |
| 스케일 범위 | `(min, max)` — 데이터셋 공통값 |
| 컬러맵 | `viridis` |
| 좌표계 | `none` / `EPSG:3857` |
| 변수·블록·밴드·SDS 선택 | `블록1` / `LST` / `B04` / `Lai_500m` |
| (지도형만) **격자 파일 해시** | 격자를 갈면 이 값이 바뀐다 |

**격자 파일 해시가 지도형 키에만 들어가므로, 격자 교체는 자동으로 지도형만 무효화하고 썸네일·비지도형을 살린다.** 무효화 규칙을 따로 코딩할 필요가 없다 — 키가 하게 하라.

| 사건 | 무효화 범위 |
|---|---|
| 격자 교체·후주입 | **지도형만.** 썸네일·비지도형 유지 |
| 공통 스케일 범위 갱신 | **전 프레임·전 산출물** |
| 원본 파일 교체 | 그 파일의 전 산출물 |
| 팔레트 변경 (사용자 조작) | 캐시 대상이 아니다 — 렌더 작업으로 새로 만든다 |

### 7.3 확대는 COG 실시간 타일

| 용도 | 판정 | 근거 (정본 §5.6~5.8) |
|---|---|---|
| 목록 | 128 px WEBP 전량 사전 생성 | 229장 4워커 5.2 s · 2.6 MB |
| 상세 (고정 배율) | 1024 px PNG + bbox — **이 문서의 ②③** | §2 |
| **확대 (연속 줌)** | **COG + 요청 시 실시간 타일** | 타일 1장 **4.1–72.0 ms** · COG 변환 장당 0.07–2.2 s |
| **타일 피라미드 전량 사전 생성** | **하지 않는다** | 167장 = 직렬 **9.4분 · 317 MB**(계산). tif 1장 최대줌이 **61.3 s · 28.0 MB** |

- **피라미드가 사 오는 것은 「연속 확대」 하나뿐이다.** 값 정확도는 나아지지 않는다(둘 다 픽셀 RGB).
- **hdf만 예외 — native CRS COG를 유지한다.** 3857로 변환하면 5.03 MB → **45.0 MB**로 부푼다. 재투영은 타일 응답에서 처리한다(정본 §7-14).
- tif는 **변환조차 필요 없다** — 원천 6건이 이미 유효 COG다. 단 **「타일만 있고 오버뷰 없는 tif 16건」이 실재한다** — 타일링만 보고 COG로 판정하면 오인한다(`DATA-REFERENCE §4`, 정본 무근거로 **미결**).
- 클라우드 스토리지 range 요청 **실지연은 `[미측정]`** (정본 §9 U-15). 위 타일 응답 값은 전부 로컬이다.

## 8. 성능 기대치

**⚠ 조건 없는 숫자를 이 절 밖으로 옮기지 마라.** 공통 조건 = AMD Ryzen 5 5600X, **WSL2 4 vCPU**, RAM 11 GB, Python 3.12.3, 반복 5~6회 중앙값, **전부 웜**(콜드는 `[미측정]`), 라이브러리 import 174~178 ms는 제외(서비스 상주 전제). 전체는 정본 §2.

### 8.1 1장 (§2.1 재게 — 조건: `/mnt/f`(9p), 웜, 1회, 단일 워커)

썸네일 25–207 ms · 비지도형 331–1374 ms · 지도형 861–2527 ms. **가장 느린 것은 tif다**(1374 / 2527).

### 8.2 데이터셋 규모 (조건: **ext4**, **4워커 병렬**, speedup 실측 3.06배)

| 데이터셋 | 메타만 | 전량 미리보기 | 첫 화면 1장 |
|---|---:|---:|---:|
| nc 141장 | 0.1 s | **4.3 s** | 30 ms |
| bin 12장 | 1 ms | **1.8 s** | 155 ms |
| tif 6장 | 4 ms | **2.0 s** | 334 ms |
| hdf 8장 | 4 ms | **1.7 s** | 220 ms |
| 식생 Lv.0 31장 | 19 ms | **1.3 s** | 43 ms |
| 식생 Lv.2 31장 | 6 ms | **2.7 s** | 87 ms |

**전 데이터셋 썸네일 일괄** — 229장 **직렬 14.2 s / 4워커 5.2 s**, 산출 **WEBP 2.6 MB**(`/mnt/f`, 정본 §5.5).

### 8.3 저장소가 지배한다

**`/mnt/f`(WSL 9p)가 ext4 대비 hdf 9.6배 · tif 2.6배 · 격자 로드 36배 느리다.** §8.1은 9p, §8.2는 ext4다 — **두 표의 숫자를 나란히 비교하지 마라.** 실서버 예측은 ext4 열로 읽는다.

HSR 격자 53 MB 로드가 `/mnt/f` 에서 **141.7 ms**, ext4에서 **4.8 ms** 다 — 9p에서는 이것이 단일 최대 병목이다. **시계열에서는 격자를 재사용해 상각한다**: HSR 12장이 격자 재사용 809.7 ms vs 매번 로드 2,760.9 ms → **3.4배**(정본 §5.4).

### 8.4 지배 구간은 업로드다

100 Mbps 기준 업로드 : 처리 = **tif 12 : 1 · 식생 Lv.2 23 : 1 · nc 4 : 1**. 미리보기 최적화로 사용자 체감을 바꾸려 하기 전에 **첫 파일 즉시 렌더**(§7.1)를 먼저 넣어라. **업로드 시간은 전부 (계산)이다** — 실효 대역폭 = 이론치 70 % 가정. **실측으로 인용하지 마라**(정본 §7-16).

## 9. 실패 처리

**원칙 둘.** ① **좌표를 지어내지 않는다**(`DR-9`) — 못 읽으면 `[미상]` 이고 실패다. ② **어느 단계에서 막히든 그 파일만 막고 나머지 등록은 진행한다.**

| 단계 | 실패 사례 | 처리 | 등록 |
|---|---|---|---|
| **감지** | 매직바이트가 알려진 것 중 없음 · gzip 안의 HDF5(미지원 조합) · `\x89HDF` 인데 netCDF4로 안 열림 | `format = null` → 파싱 불가. **확장자로 넘겨짚지 마라** | 그 파일만 실패, 나머지 진행 |
| **해독** | HSR 블록 잘림 · `TIME_SS` 판독 불가 · `pyhdf` 부재 · `StructMetadata` 못 찾음 | 예외. 부분 결과를 「성공」으로 반환하지 마라 | 〃 |
| 〃 | `num_data` ≠ 실블록 수 | **실패가 아니다.** 길이를 믿고 실재 블록만 읽되 **mismatch를 기록한다**. 조용히 버리지도, 넘겨짚지도 않는다 | 진행 |
| **격자 — 짝짓기** | 격자 shape ≠ 본체 shape | 짝이 아니다. **다른 후보를 찾거나 실패.** 리샘플로 맞추지 마라 | 그 파일만 실패 |
| **격자 — 축 판별** | 사다리 ④까지 내려가도 확신 없음 (둘 다 절댓값 90 이하 등) | **판별 실패 → 그 격자 쌍 거부.** `linspace` 합성 금지 | 격자만 거부, 본체는 등록 |
| **격자 — 부재 (HSR)** | 격자 파일이 아직 없다 | **실패가 아니라 보류.** ①② 생성하고 ③은 격자 후주입까지 대기 | 진행 |
| **격자 — 부재 (nc·tif·hdf)** | — | **해당 없다.** 이 셋에 격자 후주입을 요구하지 마라 — 파일이 격자를 준다 | 진행 |
| **warp** | 결과 bbox가 상식 밖(예: 위도 26°로 밀림) | **경계 위생 검사를 건다** — `bbox_4326` 이 `[-180,180]×[-90,90]` 안이고, 원본 CRS의 대략 범위와 겹치는지. 안 맞으면 지도형 실패 | 비지도형은 유지 |
| **렌더** | 유효 픽셀 0개 (전부 결측) | **실패가 아니다.** 전부 투명한 PNG를 낸다 — 빈 타일도 200 + 투명 PNG다(`core-viz.yaml`) | 진행 |
| **작업 전체** | 그리는 서버 연결 불가 · 시간 초과 · 알 수 없는 오류 | `RenderJob.status = "실패"` + `failure.code`. 정본 문구 3종을 그대로 쓴다 | — |
| **조각 일부** | 파일 여럿 중 일부만 못 읽음 | **`status` 는 `완료` 로 남고 `RenderResult.partialFailure` 를 채운다.** 읽힌 조각으로 그린다 | 진행 |

**조용한 실패가 제일 나쁘다.** 위경도를 바꿔 넣으면 위도 자리에 127이 들어가고, 지도 도구에 따라 **아무 경고 없이 빈 지도**가 나온다. 데이터는 멀쩡한데도 그렇다. **그래서 등록 확정 전에 사람이 지도를 한 번 보는 단계가 반드시 있어야 한다** — 값 범위 규칙이 14/14라 해도 마지막 확인은 눈이다.

## 10. 금지 사항 — 명령형

1. **npy 중간 산출을 필수 단계로 만들지 마라.** 원본 → PNG + bbox가 기본 경로다. npy 변환은 **반복 재생용 캐시로만** 쓴다. 손익분기가 1.0~1.4회로 낮지만 절대 차이가 작고(bin 23.6 → 1.7 ms), **bin·nc는 용량이 8~10배 팽창**하며, 변환하면 결측·스케일·헤더가 비가역으로 사라진다(정본 §6.3·§6.4).
2. **`02.Results` 변환본을 재사용하지 마라.** HSR 결측 3값이 NaN 하나로 붕괴해 91.13 %가 NaN이고, MODIS는 fill 255가 25.5로 남는다.
3. **위경도 배열을 클라이언트로 내려보내지 마라.** HSR 격자 2장이 53 MB인데 같은 일을 bbox 네 숫자(약 400 B)가 한다 — **13만 배**다. 곡선 격자는 warp 시점에만 필요하고 그 뒤로는 bbox로 덮인다(§5.3).
4. **파일명만으로 축(위도/경도)을 판정하지 마라.** 파일명은 사다리 **④, 맨 아래**다. 현 샘플 14/14지만 **외부 반입 파일에서 가장 먼저 깨진다**. 짝짓기(§5.4.1)와 축 판별(§5.4.2)을 혼동하지 마라 — 파일명이 통하는 것은 **짝짓기뿐**이다.
5. **값 범위로 결측을 자르지 마라 — 정확일치로 판정하라.** `값 <= -20000` 은 유효값 52,521 px를 지운다.
6. **상세 미리보기에 stride를 쓰지 마라.** 강수 블록 5.79 %(국지 16.9 %)가 사라진다. 블록평균을 쓴다. (썸네일 128 px에서는 stride가 **의도된** 선택이다.)
7. **프레임별 스트레치를 하지 마라.** 스케일 범위는 데이터셋 단위 공통 고정이다 — nc LST에서 최대 42 DN 차이가 실측됐다.
8. **HSR 헤더의 투영 파라미터로 격자를 계산하려 들지 마라 — 그 자리(36~63 B)는 0이다.** 명세 기재값으로 재구성해도 5.9 km(11.8 셀) 틀린다.
9. **HSR로 지도를 그릴 때 격자 파일을 선택 사항으로 두지 마라.** 격자가 없으면 **지도형은 보류**다. 비지도형만 허용한다. **`withoutReferenceGrid` 를 HSR에서 성공 경로로 쓰지 마라.**
10. **격자를 못 읽었을 때 `linspace`·합성 격자로 대체하지 마라.** PoC가 4곳에서 그러고 「성공」을 반환했다(`DR-9`). 못 읽으면 `[미상]` 이고 실패다.
11. **타일 피라미드를 전량 미리 굽지 마라.** 167장 = 직렬 9.4분 · 317 MB(계산). COG 실시간이 시간 20~50배 · 용량 5~10배 유리하다. 굽는다면 접근 빈도 높은 고정 레이어에만 선별한다.
12. **hdf를 3857 COG로 굽지 마라 — 45.0 MB로 부푼다.** native CRS COG(5.03 MB)를 유지한다.
13. **bin·nc·hdf를 격자·투영 확정 없이 3857로 warp 하지 마라.** 1차 시도에서 HSR이 위도 26°로 밀렸다.
14. **브라우저에서 전체 격자를 계산하지 마라** — tif 기준 204 MB · 1.8 초. FE에는 **bbox 네 숫자와 이미지 크기**만 내려준다.
15. **`/mnt/f` 에서 잰 값을 실서버 예측치로 쓰지 마라** — ext4 대비 최대 36배 느리다.
16. **사용자에게 「이 파일이 위도냐 경도냐」를 묻지 마라.** 사용자도 모른다. 서버가 판별하고 지도로 보여주고 뒤집기 버튼을 준다.
17. **grib 자리에 숫자를 채우지 마라 — 원본 `.grib` 이 없다.** `〈51〉` 로 범위 밖이다.
18. **확장자·폴더 이름·DB enum을 근거로 포맷을 확정하지 마라.** 세 번 다 거짓말을 했다 — 매직바이트로 감지하고, `\x89HDF` 는 try-open으로 가른다.
19. **`.npy` 헤더를 직접 파싱해 `reshape` 하지 마라.** 식생 격자는 `fortran_order: True` 다 — C-order를 가정하면 전치된 격자를 얻는다.
20. **PNG에서 원값을 읽으려 하지 마라.** PNG는 픽셀 RGB라 원값이 남지 않는다. 값 조회는 별도 경로이고 그 비용은 **`[미측정]`** 이다(§12).

### 11.3 계약 개정이 필요한 것

| # | 어긋남 | 현재 계약 | 필요한 개정 |
|---|---|---|---|
| K-1 | **결과가 타일 URL만 낸다** | `core-viz.yaml` `RenderResult.required: [tileUrlTemplate, bounds, legend]` · `additionalProperties: false` | **단일 이미지 + bbox 형태를 낼 자리가 없다.** 이 문서의 ②③이 계약에 안 실린다. `imageUrl`(+ 사이드카 URL)을 `tileUrlTemplate` 과 **택일**로 두거나, `oneOf` 로 가른다 |

| K-4 | **정밀도 배지를 나를 필드가 없다** | 없음 | `동봉 격자 적용` / `투영 계산 격자` 를 결과에 실어 화면이 근거를 표시하게 한다 |
