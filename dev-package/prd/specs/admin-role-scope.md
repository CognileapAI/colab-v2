# Spec: 시스템 관리자·교수 관리자 권한 일치
출처 intent: `dev-package/intent/2026-09-16-admin-full-access.md` (승인 2026-09-16, 「고고」)

## 문제 진술
- 전체 연구실 관리자의 GET 조회와 POST 미리보기의 스코프가 다르며 실패가 화면에서 숨겨진다.
- 교수 역할과 시스템 관리자 자격이 별도인데 화면과 기존 계정 전환이 이를 명확히 구분하지 않는다.

## 해법 개요
- 시스템 관리자는 모든 연구실, 교수 관리자는 자기 연구실의 기존 기능을 관리한다. 대상 연구실·실제 행위자를 유지하고 기존 상세/등록/편집 화면을 재사용한다.
- 신규 등록만 대상 연구실을 고른다. 기존 객체와 연구실 설정은 그 객체의 연구실 문맥을 사용한다. 일반 구성원의 권한은 확대하지 않는다.

## 사용자 스토리
1. 시스템 관리자로서 전체 연구실의 자료를 열고 변수·시각 조회 및 미리보기를 실행한다.
2. 시스템 관리자로서 타 연구실 자료를 수정·다운로드·삭제하고 원래 연구실에 결과와 이력을 남긴다.
3. 시스템 관리자로서 신규 자료·프로젝트의 연구실을 선택한다.
4. 교수 관리자로서 자기 연구실의 비공개 자료도 관리한다.
5. 교수 관리자로서 타 연구실 관리·시스템 관리자 지정은 거절받는다.
6. 일반 구성원으로서 기존 공개 범위 제한과 권한 안내를 받는다.
7. 운영자로서 기존 교수의 시스템 관리자 자격만 회수하고 데이터·소속·교수 역할을 보존한다.

## 구현 결정
- 기존 Subject, scope 커널, 도메인 접근 Port, 화면 권한 Provider를 재사용한다. 시스템 관리자 자격은 service_operator, 교수 관리자는 기존 교수 역할이다.
- 작업 대상 연구실은 서버가 기존 객체의 소속에서 유도한다. 신규 생성과 객체 ID가 없는 연구실 관리/미리보기 조회 문맥은 선택 연구실을 명시하고 서버가 시스템 관리자 신원·연구실 실존·기존 객체 일치를 검증한다. 임의 헤더만으로 일반 사용자의 연구실을 바꾸지 않는다.
- 미리보기·다운로드 티켓·비동기 등록에도 대상 연구실과 실제 행위자 ID가 유지된다. 시스템 관리자 여부는 클라이언트 주장으로 부여하지 않는다.
- 새 연구실 문맥은 관리자 전용 선택 헤더 `X-CoLAB-Target-Lab`을 사용한다. 기존 객체와 함께 온 헤더는 실소속과 대조한다. 미리보기 후속 조회에도 같은 문맥을 전달하며 전역 브라우저 상태로 암묵 전파하지 않는다.
- 다운로드 티켓과 미리보기 후속 조회는 소비 시 현재 신원·역할·대상 접근을 다시 확인한다. 발급 시 서명된 관리자 값만으로 권한 회수 뒤 접근을 지속시키지 않는다. 관리자 해제·교수 역할 변경 후 이전 권한으로만 가능했던 티켓/작업 접근의 거절을 시험한다.
- 교수는 자기 연구실 안에서 공개 범위·소유자·스위치 제한을 우회한다. 데이터 무결성 제약과 시스템 관리자 전용 계정 기능은 우회하지 않는다.
- 스키마: platform 0032_labless_operator 뒤 0033_admin_body_access로 관리자 본체 접근을 반영한다. 대상 발견과 전역 목록에서만 기존 SELECT 전 연구실 정책을 사용하고, 대상 연구실 확정 뒤에는 조회와 쓰기를 모두 해당 연구실로 좁힌다. 관리자 본체 접근은 인증 주체에서 설정한 별도 operator_manage 값으로 유지한다. AI 체인은 변경하지 않는다. 정본 schema와 Alembic 결과를 일치시킨다.
- API 계약: 연구실 선택 인자는 선택적 추가지만 시스템 관리자의 신규 생성에는 필요하다. 기존 일반 사용자 요청은 호환한다. 생성된 타입은 생성기로 갱신한다.
- 기존 교수 자격 전환은 dry-run 대상 목록과 명시 적용 절차로 분리한다. 목록의 회수/유지 충돌·마지막 관리자·상태 변동은 거절한다. 실제 DEV 전환과 배포는 실행하지 않는다.
- 미리보기 describe는 loading/ready/error를 구분하고 실패 메시지·재시도를 제공한다. 401 처리는 기존 인증 흐름, 403은 권한 안내, 404는 부재/비공개 안내, 서버 실패는 실패 안내다.

## 시험 결정
- 기존 FastAPI 실제 DB 시험과 프런트 컴포넌트 시험에서 실패를 확인하고 구현한다.
- 관리자 두 형태(무소속/소속)·교수·일반 구성원 × 자기/타 연구실 × 공개/비공개 자료를 검증한다. 조작 후 원본 연구실·감사 행위자·다시 읽은 값도 확인한다.
- 신규 생성 선택/미선택/잘못된 연구실/일반 계정 위조, 미리보기 생성→조회→그림, 다운로드 티켓→바이트, 교수 권한 회수/옛 세션 거절을 포함한다.
- 실제 브라우저는 격리된 로컬 계정/자료로 관리자 미리보기·수정·신규등록·교수/일반사용자 거절을 실행한다. DEV 계정 실패를 제품 검증 성공으로 세지 않는다.
- 게이트: contract-lint, contract-breaking, seam-consistency, generated-up-to-date, frontend-typecheck, frontend-test, service-tests-core-api, service-tests-viz-render, migration-single-head, migration-drift, schema-diff, rls-coverage, rls-effect, rls-effect-selftest, import-boundary, banned-import, work-item-consistency. 프런트 배포 빌드도 확인한다. 실제 변경에 따라 게이트 범위를 보완하고 제외·미실행을 기록한다.
- 검사 대상 수·종료코드·통과/판정실패/준비실패를 실제 실행에서 회수한다. 시험 0건·skip을 성공으로 대체하지 않는다.

## 정책 대조 (작성 시점 제약)
- 도메인 테이블 접근은 기존 Port와 조립 계층을 사용한다. 연구실 경계는 서버가 선택한 유효 대상 스코프로 주입하며 일반 사용자의 경계를 해제하지 않는다.
- 종전 관리자 읽기 전용·반출 제외 및 교수 공개 범위 제한은 승인 intent로 개정한다. 일반 구성원의 정책·무결성·비밀 무노출·생성물 직접 수정 금지는 유지한다.
- 계약 동결 해제: 사용자 「고고」가 승인한 연구실 선택 계약 추가와 권한 정책 변경 범위만 적용한다.

### 디자인 제약 확인
- 관리자 계정 표시, 데이터 상세/미리보기, 업로드/프로젝트 생성의 연구실 선택과 공개 범위 안내는 기존 select·버튼·메시지 컴포넌트와 tokens.css를 재사용한다.
- 글자 13px 이상·대비 4.5:1 이상, 카드 그림자 0, 간격은 컨테이너 소유. 새 애니메이션 없음, 기존 포커스·누름 피드백과 reduced-motion을 유지한다.
