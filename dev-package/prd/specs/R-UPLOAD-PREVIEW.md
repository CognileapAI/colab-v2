# Spec: R-UPLOAD-PREVIEW · HTML 기준 화면 재구성과 실제 미리보기
출처 intent: `dev-package/intent/2026-09-09-upload-layout-preview.md` (승인 2026-09-09 · 커밋 `25b7474`)

## 문제 진술
- 업로드·상세 화면의 정보 구조가 기획과 다르다는 사용자 보고가 있다. 기존 필드 구현 여부와 실제 화면의 구성 일치를 별도로 판정해야 한다.
- 포맷별 미리보기 실패를 실제 파일로 재현하고 파일 판별부터 이미지 표시까지 추적해야 한다.
- 업로드 상태 조회의 일반 오류 후 조회 중단, 렌더 조회 오류 후 이전 진행 상태 잔존은 코드상 위험 후보다. 아직 재현된 결함으로 단정하지 않는다.

## 해법 개요
- rev2 HTML의 화면을 기준으로 파일 선택, 분석, 입력 3단계, 상세, 확대, 수정과 오류 상태를 구성한다. rev1의 번호별 정책 65개를 추적 식별자로 사용하되 rev2에서 달라진 내용은 명시한다.
- 기존 저장·계보·다운로드 흐름을 재사용한다. 목업의 샘플 상태와 타이머를 실제 데이터·서버 상태로 바꾼다.
- 첫 미리보기는 입력에 필요한 참고 그림에 집중한다. 기존 보조 기능이 배치를 바꾸는 경우 위치와 진입 방식을 화면 비교표에 제안하고, 기능 삭제나 임의 숨김을 하지 않는다.
- 진행 상태는 전송, 분석, 렌더, 이미지 표시의 사실을 분리한다. 작업이 끝나지 않은 구간에서 안내가 사라지거나 완료로 보이지 않게 한다.

## 사용자 스토리
1. 연구자로서 파일 선택부터 시작해 무엇을 올리는지 분명히 알고 싶다.
2. 연구자로서 같은 확장자의 여러 파일을 하나의 데이터셋으로 묶고 제외된 파일을 알고 싶다.
3. 연구자로서 전송량과 분석 단계를 보며 기다리는 이유를 알고 싶다.
4. 연구자로서 분석 완료 뒤 다음 버튼으로 입력에 진입하고 싶다.
5. 연구자로서 왼쪽 미리보기를 보면서 오른쪽에서 분류·메타데이터·연결을 입력하고 싶다.
6. 연구자로서 단계 이동 때 입력값과 연결이 유지되기를 원한다.
7. 연구자로서 현재 파일명과 여러 파일의 개수·목록을 확인하고 싶다.
8. 연구자로서 포맷이 달라도 지원되는 실제 파일의 미리보기를 보고 싶다.
9. 연구자로서 그림을 확대·이동·초기화하고 좌표를 확인하고 싶다.
10. 연구자로서 선택한 변수·조각과 화면에 그린 대상이 일치하는지 알고 싶다.
11. 연구자로서 부분 실패와 미지원 형식을 정상 완료와 구분하고 싶다.
12. 연구자로서 통신 오류를 알림받고 입력을 잃지 않은 채 다시 시도하고 싶다.
13. 연구자로서 취소나 파일 교체 후 이전 요청이 새 화면을 바꾸지 않기를 원한다.
14. 연구자로서 이름·기간·설명·변수 표·출처를 저장하고 재접속해 확인하고 싶다.
15. 연구자로서 가공 전 데이터와 가공 방식을 연결하고 나중에 바로잡고 싶다.
16. 연구자로서 연관 프로젝트·논문을 연결하고 상세에서 그 활용을 확인하고 싶다.
17. 연구자로서 상세의 정보 표·설명·변수 표·계보를 일관된 순서로 읽고 싶다.
18. 연구자로서 연결된 계보 노드를 눌러 실제 데이터셋으로 이동하고 싶다.
19. 연구자로서 저장 내용을 편집하고 저장 실패와 성공을 명확히 구분하고 싶다.
20. 연구자로서 원본 파일을 내려받고 묶음의 파일이 빠짐없이 포함됐는지 확인하고 싶다.
21. 연구자로서 미리보기가 실패해도 등록·계보·다운로드를 계속 사용할 수 있기를 원한다.

## 구현 결정
- 모듈 · 인터페이스: 파일 전송, 분석 상태, 등록 폼, 계보 연결, 업로드·상세 미리보기, 이미지 표시의 기존 경계를 재사용한다. 미리보기 상태 표시와 오류 처리의 공통 규칙을 공유하고 화면별 폴링 정책의 차이를 제거한다. 불필요한 전면 재작성은 하지 않는다.
- 스키마 · 마이그레이션: 현재 단계에서 새 저장 구조나 마이그레이션을 확정하지 않는다. 실제 저장·재조회에서 값 유실이 재현될 때 원인을 좁힌다. 필요성이 확인되면 변경 전 별도 제안한다.
- API 계약: 기존 계약 내 비파괴 수정이 기본이다. 진행 정보를 임의 추정하지 않는다. 서버가 제공하지 않는 단계나 필드가 꼭 필요하면 계약 확장을 제안하고 구현과 소비 시험을 같은 작업에 포함한다.
- 화면: 파일 선택 전에는 드롭 영역을 중심으로, 분석 중에는 파일과 진행 안내를, 입력 중에는 좌측 미리보기·우측 3단계를 표시한다. 동작 버튼은 하단의 일관된 위치에 둔다. 정확한 폭·간격은 HTML과 동일한 뷰포트에서 측정하고 기록하며 추정 숫자를 확정하지 않는다.
- 상세: 헤더/편집/다운로드 → 기본 정보 표 → 설명 → 변수 표 → 소유·파일 정보 → 계보/미리보기/활용·접근 순서를 보존한다. 그래프는 실제 관계와 가공 방식을 사용하고 예제 데이터로 빈 상태를 채우지 않는다.
- 입력: 단계 변경 시 값 유지, 저장 중 중복 제출 차단, 실패 시 입력 보존, 실제 저장 성공 후 상세 이동. 종료 확인은 파일만 있는 상태·입력 변경·계보 연결 건수를 구분한다.
- 진행: 전송 완료는 분석 완료가 아니며 렌더 결과 수신은 브라우저 이미지 표시 완료가 아니다. 렌더 이후 이미지 로딩/오류도 다룬다. 이미지 로딩 이벤트 또는 동등한 실제 확인 뒤 준비 상태가 된다.
- 통신 오류: 재시도 가능한 오류는 제한된 간격 증가를 적용하고 복구 상태를 표시한다. 재시도 한계 후 실패와 사용자의 재시도 경로를 제공한다. 권한 오류·삭제된 업로드·지원 불가를 무한 반복하지 않는다. 구체적인 횟수는 기존 전송 정책과 함께 구현 계획에서 결정한다.
- 취소/교체: 진행 조회 타이머와 요청 세대를 정리하고 이전 응답을 무시한다. 존재하는 재개 업로드 보호를 유지한다. 화면 취소를 서버 원본 데이터 삭제로 간주하지 않는다.
- 포맷: 확장자와 실제 내부 구조를 함께 기록한다. NetCDF/HDF 계열 및 BIN의 구조·좌표 정보 요구를 검수 파일에 명시한다. GRIB은 현재 등록과 미리보기 지원의 차이가 확인됐으므로 전용 지원 가능성 조사 대상으로 둔다. 지원 제외 문구만으로 사용자의 미리보기 요구를 완료 처리하지 않는다.
- 느린 처리: 임의 퍼센트·남은 시간·성공 타이머를 만들지 않는다. 실제 측정 가능한 전송률과 서버 단계, 대기·재연결 안내를 제공한다.

### 2026-09-09 승인된 저장·조회 확장

- 대표 그림은 데이터셋 본체 파일이나 다시 만들 수 있는 렌더 산출물로 취급하지 않는다. 데이터셋별 별도 D3 메타데이터와 서버 생성 저장 키를 사용한다. 등록 요청 성공 뒤 이미지 업로드가 실패하면 생성된 데이터셋 ID를 보존하고 이미지 요청만 재시도한다. PNG/JPEG/WebP 실제 형식과 크기를 서버가 검사한다. 교체·삭제·자동 그림 복귀·재접속을 계약과 시험에 포함한다.
- 계보 후보 조회는 기존 카탈로그 행을 브라우저에서 전부 모으는 방식을 대체한다. 후보 전용 응답에 이름, 접근 가능한 본체 파일명·확장자, 분류, 기간, 출처, Lv와 주제를 포함한다. 이름/파일명 검색은 OR, 분류/기간은 AND, 기간은 겹치는 구간으로 판정한다. 서버 페이지와 안정 cursor를 사용한다.
- 사람이 적는 격자 설명은 자동 계산된 `grid`와 별도 nullable 값이다. 등록·상세·수정 계약에 포함하고, 표시는 사람 값 우선·자동값 보조다. 빈 값으로 지우면 자동값으로 복귀하며 좌표 계산에는 사용하지 않는다.
- platform migration은 현재 단일 head 다음 한 revision으로 만들고 schema 선언, RLS, downgrade와 생성 타입을 같은 변경에서 갱신한다.

### 디자인 제약 확인
- 공통: `frontend/src/shell/tokens.css`의 토큰을 사용한다. 파일별 전역 토큰 신설 없이 HTML 값을 매핑하고 맞지 않는 값은 차이표에 올린다. 본문·라벨 13px 이상, 대비 4.5:1 이상을 검증한다. 기존 승인된 예외는 근거를 남긴다.
- 파일 선택/분석 모달: HTML의 폭·패딩·드롭 영역·상태 위치를 비교한다. 카드 그림자 0, 컨테이너 소유 여백, 모달 표면/배경 처리 차이는 기획 대조에 포함한다. 키보드 초점과 닫기 복귀를 확인한다.
- 등록 입력: 좌우 열·카드·단계·하단 행동 줄을 유지한다. 팝오버의 그림자는 허용 범위에서 사용한다. 긴 내용에서도 입력과 진행 표시가 가려지지 않는다.
- 상세/계보: 정보 표·변수 표·섹션 내비·그래프의 계층과 순서를 맞춘다. 카드 그림자 0, 라벨 가독성, 가로 스크롤과 컨테이너 여백을 검증한다.
- 미리보기/확장: 좌표 표시·줌 조작·로딩/오류가 겹치지 않는다. 누름 즉시 피드백, 중단 가능한 전환, 움직임에 `prefers-reduced-motion` 분기, 키보드 조작을 확인한다.
