# Spec: 계보 단계와 데이터셋 기간의 사용자 입력 보존
출처 intent: `dev-package/intent/2026-09-16-issue-80-preserve-selected-level.md`, `dev-package/intent/2026-09-16-issue-76-preserve-period-precision.md` (승인 2026-09-16)

## 문제 진술
- 업로드 기본 가공 단계가 계보 선택에 따라 자동 변경되어 현재 선택값 기준의 부모 상한이 적용되지 않는다.
- 데이터셋 수정 폼이 기간의 시각을 날짜로 축약하며, 기간 변경 및 응답 전 표시에서 시각을 잃을 수 있다.

## 해법 개요
- 계보 선택 전후의 사용자 가공 단계를 유지하며, 기본값에도 부모 단계 상한을 적용한다.
- 등록에서 사용하는 기간 단위별 입력과 달력을 상세 수정에서도 재사용하고, 변경하지 않은 원본 기간을 보존한다.

## 사용자 스토리
1. 업로더로서 처음 보이는 Lv.0도 직접 선택한 값과 같은 제한이 적용되길 원한다.
2. 업로더로서 계보 연결과 해제 후에도 내가 선택한 단계가 유지되길 원한다.
3. 업로더로서 내 단계보다 높은 부모는 이유와 함께 연결 불가로 보이길 원한다.
4. 업로더로서 같은 단계 부모는 기존처럼 연결하길 원한다.
5. 업로더로서 연결 후 단계를 낮추면 연결을 잃지 않고 충돌을 해소하길 원한다.
6. 업로더로서 계산 단계 불일치는 안내로 확인하고, 유효한 부모 관계는 등록하길 원한다.
7. 편집자로서 기간 최소 단위가 분이면 분까지, 초이면 초까지 확인하고 수정하길 원한다.
8. 편집자로서 제목만 고친 저장이나 무변경 저장에서 기존 시각을 그대로 보존하길 원한다.
9. 편집자로서 저장을 기다리는 화면에서도 원래 시각을 잘못 표시하지 않길 원한다.
10. 편집자로서 종료 시점 없음과 기간 없음, 단위 미지정 데이터의 의미가 유지되길 원한다.
11. 편집자로서 등록과 수정에 같은 단위 축소 규칙이 적용되길 원한다.

## 구현 결정
- 업로드: 가공 단계 기본값은 Lv.0. 부모 계산값을 따라 선택값을 덮는 상태·효과·상한 예외를 제거한다. 계산값 안내는 유지한다.
- 부모 검증: 부모 단계 ≤ 자기 단계. 같은 단계 허용, 초과 후보 비활성 및 설명 유지. 기존 부모와 사후 충돌 시 자동 삭제 없이 등록 차단 유지.
- 기간: draft는 전체 시각을 보존한다. 기존 기간 팝오버와 문자열 자리 분해/조립을 재사용한다. Date 현지시간 변환은 도입하지 않는다.
- 기간 비교: 실제로 기간 입력이 바뀌었을 때만 period patch를 보낸다. 원본 기간과 응답 전 표시에서도 무변경 값은 보존한다.
- 팝오버 열기와 무수정 적용만으로 null 단위를 일 단위로 바꾸거나, 표시 단위 아래 원본 시각을 잘라내지 않는다. 사용자가 입력/단위를 명시적으로 바꾼 경우와 구분한다.
- 단위가 없는 기존 값은 임의로 일 단위로 저장하지 않는다. 단위 축소를 사용자가 명시한 경우에만 기존 등록 규칙으로 하위 자리를 정리한다.
- API 계약: 비파괴. DataPeriod 및 기존 등록·수정 요청을 유지한다.
- 스키마 · 마이그레이션: 없음.

## 시험 결정
- 재사용 seam: 실제 UploadModal·LineageStep 사용자 조작과 등록 요청, 실제 DatasetDetail 수정 동작과 요청/응답 및 applyDraft 경계. 단위 함수 시험만으로 화면 시험을 대체하지 않는다.
- 신설 seam: 없음. 로컬 실제 API·일회용 DB를 연결하는 기존 E2E 진입점에 이번 시나리오만 추가한다.
- #80: 미접촉 Lv.0에서 Lv.1~3 후보 비활성, Lv.0 허용; Lv.1에 Lv.1 연결·해제 후 Lv.1 유지; 단계 왕복; 연결 후 하향 시 카드 유지·등록 차단; 유효 등록값 보존.
- #76: 년~초 표시/입력, 분·초 변경, 무변경 patch 없음, 다른 필드만 변경 시 period 없음, 단위 null 기존값 유지, 응답 전 표시 보존, 단위 축소, 끝 null, 기간 삭제.
- 실패 시험을 구현 전에 실행하고 기대 불일치로 실패했음을 기록한다. 기존 승인 반전에 해당하는 시험 기대는 새 intent에 맞춰 개정한다.

- 실제 브라우저: agent-browser로 로컬 일반 연구원 계정의 등록·편집·저장·새로고침 확인. 서버 응답/DB 값도 대조한다. 모의 화면을 저장 E2E로 보고하지 않는다.
