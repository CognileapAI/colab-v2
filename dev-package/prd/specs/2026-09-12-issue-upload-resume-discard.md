# Spec: 미완결 업로드의 이어가기와 버리기 (bugfix 회차 · 레인 L1)
출처 intent: `dev-package/intent/2026-09-12-issue-upload-resume-discard.md` (승인 2026-09-12 · 커밋 `567b830`)

## 문제 진술
- 메인 화면 배너의 재개 버튼이 `openUpload({ resumeUploadId })` 까지만 값을 옮기고, `UploadEntry` 가 그 값을 `UploadModal` 로 전달하지 않아 재개 무장이 서지 않는다(`#33` ㉠).
- 업로드 닫기 확인 모달의 버튼이 둘(`UPLOAD_CLOSE_KEEP`·`UPLOAD_CLOSE_LEAVE`)이고, 미완결 항목 기억을 함께 지우는 선택지가 없다(`#34`).
- 메인 배너 행에 재개 버튼만 있고 폐기 버튼이 없다. 같은 폐기 버튼이 모달 안 배너(`up-discard-*`)에는 존재한다(`#32` 안 A).

## 해법 개요
- 사용자 행위 셋을 기존 흐름 위에 세운다 — ⑴ 배너에서 「이어서」를 누르면 모달이 그 업로드로 무장된 채 열린다 ⑵ 업로드 창을 닫을 때 「이 브라우저에서 감추기」를 고를 수 있다 ⑶ 메인 배너 행에서 바로 버릴 수 있다.
- 신규 화면·신규 개념 0. 재개는 이미 있는 배너 재개 경로(`resumeRef`·`resumeFromRef='banner'`·`resumeArm`)를 그대로 쓰고, 폐기는 이미 있는 모달 안 배너 폐기 버튼의 동작을 공통 헬퍼로 올려 세 자리가 같은 것을 부른다.
- 폐기의 뜻은 「이 브라우저의 기억 삭제」다. 서버 접수 행은 24시간 만료 스윕(`U-2`)이 정리한다. 문면이 그 사실을 그대로 말한다.

## 사용자 스토리
1. 연구실 구성원으로서 파일 전송이 끊긴 업로드를 메인 배너에서 이어가기를 원한다, 처음 화면부터 다시 밟지 않기 위해.
2. 연구실 구성원으로서 「이어서」를 누른 직후 모달이 그 업로드를 대상으로 무장했음을 화면에서 확인하기를 원한다, 내가 고른 항목이 맞는지 알기 위해.
3. 연구실 구성원으로서 업로드 창을 닫을 때 「계속하기」·「닫고 나가기」 외에 올리던 것을 정리하는 선택지를 보기를 원한다, 남겨 둘지 버릴지를 그 자리에서 정하기 위해.
4. 연구실 구성원으로서 그 세 번째 선택지가 무엇을 지우는지 문면으로 알기를 원한다, 서버에서 즉시 사라진다고 오해하지 않기 위해.
5. 연구실 구성원으로서 세 번째 선택지를 누른 뒤 메인 배너에서 그 항목이 사라지는 것을 보기를 원한다, 정리됐음을 확인하기 위해.
6. 연구실 구성원으로서 메인 배너 행에서 바로 버리기를 원한다, 버리려고 업로드 창을 여는 왕복을 없애기 위해.
7. 연구실 구성원으로서 메인 배너의 폐기와 닫기 확인의 폐기가 같은 결과를 내기를 원한다, 자리마다 결과가 갈리지 않기 위해.
8. 연구실 구성원으로서 폐기 뒤 배너가 비면 카드 자체가 사라지기를 원한다, 빈 카드가 자리를 차지하지 않기 위해.
9. 연구실 구성원으로서 폐기가 등록을 마친 데이터셋에 닿지 않기를 원한다, 끝낸 일이 지워지지 않기 위해.
10. 다음 회차 개발자로서 폐기 동작이 한 곳에 있기를 원한다, 세 자리가 서로 갈리지 않기 위해.
11. 다음 회차 개발자로서 재개 배선을 실물 렌더 시험이 지키기를 원한다, 컨텍스트 스텁만 보는 시험이 같은 결함을 다시 통과시키지 않기 위해.

## 구현 결정
- 모듈 · 인터페이스
  - 업로드 진입 컴포넌트 = 바깥 열기 요청의 재개 식별자를 모달로 전달한다. 모달 props 에 선택 필드 1개를 추가하고, 같은 요청 일련번호가 다시 오면 다시 무장한다(`seq` 기준 기존 규약 유지).
  - 업로드 모달 = 전달받은 식별자로 기존 배너 재개 무장 3종(`resumeRef`·`resumeFromRef`·`resumeArm`)을 세운다. 새 재개 상태를 만들지 않는다. 무장 후 표시는 기존 배너의 `is-armed` 표시와 `up-resume-hint` 를 그대로 쓴다.
  - 폐기 공통 헬퍼 = 미완결 기억 저장소 모듈(`pendingStore`)과 같은 계층에 함수 1개를 둔다. 인자 = 연구실 식별자 · 업로드 식별자. 동작 = 브라우저 기억 삭제 1회. 서버 호출 0.
  - 닫기 확인 모달 = 버튼 3개. 세 번째 버튼은 헬퍼 호출 후 모달을 닫는다. 판정식은 기존 `requestClose()` 한 곳을 그대로 둔다.
  - 메인 배너 = 접수 완료 행에 폐기 버튼 1개를 추가하고 같은 헬퍼를 부른 뒤 목록 상태에서 그 행을 제거한다. 버튼은 기존 `.ub-btn` 클래스를 재사용한다(신규 CSS 규칙 0 목표 · 미달 시 우려 항목 4).
  - 문면 = 문자열 상수 모듈(`toastCopy`) 한 곳에 세 번째 버튼 라벨과 보조 문장을 둔다. 화면이 문장을 짓지 않는 기존 규약 유지.
- 스키마 · 마이그레이션: 0건. Alembic revision 무접촉.
- API 계약: 비파괴 · 변경 0건. `contracts/` 무접촉이 상태 증거다(`git status --porcelain contracts/` 0행을 병합 전 확인).
- 서버 즉시 삭제 창구는 만들지 않는다. 접수 행의 서버 몫은 24시간 만료 스윕이 진다.
- 재개 무장 상태 (기존 코드에서 확인한 형태 · 신설 아님)

```
armed = { id: string, from: 'banner' | 'failure', arm: number }
from='banner'  → 파일 선택이 바뀌어도 무장 유지
from='failure' → 파일 서명이 바뀌면 무장 해제
```

## 시험 결정
- 외부 행위 기준 검증 항목 (구현 세부 미검증 · 화면에 보이는 것과 저장소 상태만 본다)

  2. 닫기 확인의 세 번째 버튼 존재 · 라벨 축자 대조.

  6. 폐기 뒤 남은 행이 0이면 카드 자체가 렌더되지 않음.
