# Spec: UI 결함 4건 — 원천 블록 노출 · 미리보기 조작부 배치 · 계정 생성 폼 · 지도용 선택지
출처 intent: `dev-package/intent/2026-09-17-issue-97-lv0-source-visibility.md`, `dev-package/intent/2026-09-17-issue-93-preview-viz-controls-position.md`, `dev-package/intent/2026-09-17-issue-84-account-create-form.md`, `dev-package/intent/2026-09-17-issue-92-map-options-renderable.md` (모두 승인 2026-09-17)

## 문제 진술
- 업로드 등록 화면의 `원천 · 연구실 밖 출처` 블록 노출 판정이 `Lv.0 또는 상위 0건`이라, Lv.0에 상위 데이터를 연결해도 블록이 남아 이미 계보가 말하는 출처를 다시 적으라고 읽힌다.
- 업로드 중 미리보기 패널에서 팔레트·구간 수가 기본 닫힘 `<details>` 안에 있어, 접기를 펼치기 전에는 지도 표현을 바꾸는 수단의 존재가 화면에 없다.
- 계정 관리 화면의 생성 폼이 탭·버튼 문면·요소 순서·체크박스 기본값·세로 정렬에서 주 동작(일반 사용자 계정 생성)과 어긋나고, 칸별 `data-testid`가 없다(#54).
- 미리보기를 그릴 수 없다고 서버가 판정한 파일에서도 지도용 선택지(팔레트·구간 수·격자 업로드)가 그대로 보여, 그릴 수 없는 조작을 시도하게 된다.

## 해법 개요
- 원천 블록의 노출 조건을 상위 0건 단일 조건으로 통일하고, 그 블록에 걸린 등록 전 형상 검증도 같은 조건으로 좁힌다. 등록 흐름 자체는 기존 그대로다.
- 팔레트·구간 수·미리보기 그리기를 접힌 메뉴 밖, 파일·변수 고르개 줄 바로 아래로 옮긴다. 상태 배선과 동작은 그대로다.
- 계정 생성 폼의 문면을 `사용자 생성`으로 통일하고, 관리자 여부 체크를 폼 맨 위로 올려 체크 시 연구실·역할 선택을 비활성·값 비움으로 만들고, 기본값을 꺼짐으로 바꾸고, 세로 가운데 정렬을 수식 클래스로 덮는다. 칸 7개에 `data-testid`를 세운다.
- 서버가 주는 기존 계약 필드를 읽어, 그릴 수 없다고 **확정된** 경우에만 지도용 선택지를 숨긴다. 판정 전에는 지금과 같다.

## 사용자 스토리
1. 업로더로서 Lv.0 데이터에 상위 데이터를 연결하면 원천·연구실 밖 출처 블록이 사라지길 원한다, 출처는 상위 계보가 이미 말하기 때문에.
2. 업로더로서 상위 데이터가 0건인 Lv.0에서는 출처 주소·내려받은 날 칸이 그대로 보이길 원한다, 그 경우 출처를 말할 다른 자리가 없기 때문에.
3. 업로더로서 원천 블록이 숨은 상태에서 등록 버튼을 누르면 등록이 진행되길 원한다, 보이지 않는 칸 때문에 막히면 되돌릴 방법이 없기 때문에.
4. 업로더로서 블록이 숨는 순간 그 칸의 값이 서버로 실려 가지 않길 원한다, 화면이 숨긴 값을 전송하면 화면과 저장이 어긋나기 때문에.
5. 업로더로서 Lv.1 이상·상위 0건에서는 기존과 같은 블록을 보길 원한다, 이번 변경이 내 기존 흐름을 바꾸지 않기 때문에.
6. 업로더로서 상위 데이터를 붙였다 떼면 원천 블록이 즉시 다시 나타나길 원한다, 조작의 결과를 바로 확인하고 싶기 때문에.
7. 업로더로서 미리보기 화면을 열자마자 팔레트와 구간 수가 보이길 원한다, 지도 표현을 바꿀 수 있다는 사실을 알기 위해.
8. 업로더로서 팔레트·구간 수가 파일·변수 고르개 바로 아래 있길 원한다, '무엇을 그릴지 → 어떻게 그릴지' 순서로 읽히기 때문에.
9. 업로더로서 옮긴 뒤에도 팔레트를 바꾸고 구간 수를 고쳐 미리보기 그리기를 누르면 같은 결과가 나오길 원한다, 배치 변경이 동작을 바꾸면 안 되기 때문에.
10. 업로더로서 접힌 메뉴 안의 나머지 미리보기 설정은 그대로 접힌 채 남길 원한다, 한 번에 전부 펼쳐지면 화면이 다시 복잡해지기 때문에.
11. 업로더로서 대표 그림 고르개가 기존 자리에 남길 원한다, 이번에 옮기기로 한 것은 두 조작과 그리기 버튼뿐이기 때문에.
12. 운영자로서 계정을 만드는 탭과 제출 버튼이 모두 `사용자 생성`으로 읽히길 원한다, 한 화면에 '초대'·'관리자 등록'·'사용자 생성'이 섞이면 무슨 일이 일어나는지 알 수 없기 때문에.
13. 운영자로서 관리자 여부 체크가 폼 맨 위에 있길 원한다, 그 선택이 아래 칸을 채울 필요가 있는지를 결정하기 때문에.
14. 운영자로서 관리자 여부를 체크하면 연구실·역할 선택이 비활성이 되고 값이 비워지길 원한다, 채울 필요가 없음이 화면으로 드러나야 하기 때문에.
15. 운영자로서 아무 조작 없이 제출하면 일반 사용자 계정이 만들어지길 원한다, 권한이 기본값이 되면 안 되기 때문에.
16. 운영자로서 폼 내용 길이가 바뀌어도 제출 버튼이 세로로 튀지 않길 원한다, 누르려던 자리가 움직이면 잘못 누르기 때문에.
17. 사용자로서 로그인 화면과 비밀번호 변경 화면의 세로 가운데 정렬이 그대로 유지되길 원한다, 그 두 화면은 이번 변경 대상이 아니기 때문에.
18. 개발자로서 생성 폼의 칸 7개를 `data-testid`로 직접 짚을 수 있길 원한다, 문면·배치가 바뀌어도 자동화가 따라 깨지지 않기 때문에.
19. 개발자로서 기존 `account-create` 구역 testid가 유지되길 원한다, 그것을 쓰는 기존 검사가 살아 있기 때문에.
20. 업로더로서 문서 파일처럼 지도로 그릴 수 없는 파일에서는 팔레트·구간 수·격자 업로드가 보이지 않길 원한다, 할 수 없는 조작을 시도하지 않기 위해.
21. 업로더로서 아직 분석 중인 파일에서는 지도용 선택지가 그대로 보이길 원한다, 숨겼다가 다시 나타나는 화면 흔들림을 겪지 않기 위해.
22. 업로더로서 그릴 수 있다고 판정된 파일의 화면이 지금과 같길 원한다, 이번 변경이 정상 경로를 건드리지 않기 때문에.
23. 업로더로서 그릴 수 없다고 판정돼도 등록은 끝까지 진행되길 원한다, 계약이 그렇게 정했기 때문에.
24. 업로더로서 지도용 선택지가 숨은 화면의 안내 문구가 '설정을 열어 그려 보라'고 말하지 않길 원한다, 열 설정이 화면에 없기 때문에.

## 구현 결정
- 모듈 · 인터페이스 (#97): 등록 영역 컴포넌트와 업로드 모달이 각자 들고 있는 원천 블록 노출 판정을 **상위 연결 0건 단일 조건**으로 통일한다. 레벨 값은 판정에서 빠진다. Lv.0이 연결할 수 있는 상위는 Lv.0뿐이라 이 단일 조건은 승인 intent가 말한 'Lv.0에 상위 연결' 조건과 동치다. 두 곳의 식은 문자 그대로 같은 형태가 되도록 맞춘다.
- 모듈 · 인터페이스 (#97, 동반 필수): 업로드 모달의 등록 전 검사 중 원천 주소·내려받은 날 필수 검사와 내려받은 날 형상 검사를 같은 노출 판정으로 좁힌다. 이 동반 수정이 빠지면 숨은 칸을 대상으로 한 초점 이동이 실패해 등록이 영구히 막힌다. 숨김과 검증 축소는 한 커밋에 함께 간다.
  **식 형태 — AND 추가이지 치환이 아니다.** `UploadModal.tsx:1153`·`:1161`의 `level === LV0 && …`를 `sourceVisible && level === LV0 && …`로 만든다. `sourceVisible`(상위 0건)은 Lv.1 이상에서도 참인데 Lv.1에는 내려받은 날 칸이 없으므로(`RegisterArea.tsx:1041`), `level === LV0`를 `sourceVisible`로 **바꿔치기하면 Lv.1 등록이 막힌다.** 이미 `:1058-1060`이 `if (sourceVisible) { … if (level === LV0 …` 중첩을 쓰므로 같은 형태를 따른다.
- 모듈 · 인터페이스 (#93): 미리보기 패널에서 팔레트·구간 수·미리보기 그리기를 담은 설정 묶음을, 접기 요소 밖·미리보기 틀 위 고르개 줄 컨테이너 안, 파일·변수 고르개 줄 바로 아래로 옮긴다. 대표 그림 고르개와 나머지 설정은 접기 안에 남는다. 상태는 전부 이 패널의 지역 상태이므로 배선을 바꾸지 않는다. 이동을 계기로 상태를 상위로 올리지 않는다.

- 모듈 · 인터페이스 (#84): 관리자 여부 체크를 폼 첫 요소로 올린다. 체크 상태면 연구실·역할 선택을 비활성으로 두고 값을 비운다. 체크박스 초기 상태를 꺼짐으로 바꾼다.
  **「값을 비움」의 수단**: 연구실·역할 select는 현재 uncontrolled(`AccountAdminPage.tsx:204-210, 229-230` — `name`만 있고 state 없음, FormData로 읽음). `disabled`만 붙이면 FormData에서 자동 제외되어 **전송은 비지만 화면 값은 남는다.** 시험 ⑶「값이 빔」을 실제로 만족하려면 체크 시 두 select의 `value`를 `''`로 되돌리는 처리(ref reset 또는 controlled 전환)가 필요하다. controlled로 바꾸면 기존 시험 `account-admin.test.tsx:165`「등록 탭에 입력한 값은 목록 탭을 다녀와도 유지된다」를 깨지 않아야 한다 — 가장 작은 수단은 **ref reset**이다.
  **러너 영향(드러냄)**: 러너는 연구실·역할을 고른 뒤(`runner.py:312-315`) 관리자 체크(`:316`)를 한다. 체크 시 비활성·비움이면 `admin: true` + `lab` 조합 엔트리(`tests/test_runner_plan_mapping.py:239`)가 연구실 없이 생성된다. 현재는 `:216-218`이 operator와 labId를 함께 보낸다. Ted 결정(관리자는 연구실·역할 없음)과 일치하는 변화이므로 spec은 이를 결함이 아닌 **의도된 seed 결과 변화**로 기록한다. 러너 계획 수정은 범위 밖.
- API 계약 (#84): 비파괴. 전송 본문은 관리자 여부가 참일 때 연구실·역할을 생략하는 기존 형태를 그대로 쓴다. 비활성 시 값을 비우므로 「연구실과 역할을 함께 지정하거나 함께 비우라」는 기존 폼 검증과도 충돌하지 않는다.
- 레이아웃 (#84): 로그인 계열 공용 클래스를 직접 고치지 않는다. 같은 클래스를 로그인 화면과 비밀번호 변경 화면이 공유하므로, 계정 관리 화면에만 수식 클래스를 덧붙여 최소 높이와 배치 기준점만 덮는다.
- 시험 식별자 (#54): 생성 폼의 칸 7개(이름·이메일·연구실·역할·초기 비밀번호·관리자 체크·제출)에 `data-testid`를 부여한다. 기존 생성 구역 testid는 유지한다. 명명은 기존 업로드 화면의 `<화면접두>-<칸>` 관행을 따른다.
- 폼 `name` 유지 (#54, 필수): 칸의 기존 `name` 속성(`name`·`email`·`labId`·`role`·`initialPassword`·`operator`)을 **지우거나 바꾸지 않는다.** dev-seed 러너 `dev-package/tools/dev-seed/runner.py:111-118`이 `[data-testid="account-create"] input[name="…"]`·`select[name="…"]`로 이 폼을 짚는다. testid는 덧붙이는 것이지 `name`을 대체하는 것이 아니다. 러너를 testid로 갈아타는 일은 범위 밖이다. 체크박스 기본값 변경은 러너에 안전하다 — 316행이 토글이 아니라 `["check", …, entry["admin"]]`로 원하는 값을 지정한다.

- red → green 순서 (#97): 상위 1건 연결 시 블록이 사라짐을 요구하는 시험을 먼저 추가해 red를 확인하고, 숨김 조건을 고친 뒤 green으로 간다. 숨김만 고치면 '숨은 상태에서 등록 제출' 시험이 초점 이동·차단으로 red가 되어야 하며, 그 red를 확인한 뒤 검증 축소를 넣어 green으로 간다. 두 red를 모두 실제로 관측한 기록을 남긴다.

- red → green 순서 (#92): 그릴 수 없음 확정 시 세 블록이 없음을 요구하는 시험을 먼저 추가해 red를 확인한 뒤 노출 조건을 씌운다. #93 커밋 위에서 작업하므로 red 확인 시점의 기준 트리는 #93이 들어간 뒤여야 한다.
- green-by-skip 방지 (#97): 대상 0건이 아님을 **상위 연결 1건이 실제로 붙은 상태에서만 사라진다**는 양성·음성 쌍으로 보인다. 같은 시험 안에서 연결 전에는 블록 조회가 성공하고 연결 후에는 실패함을 둘 다 단언한다. 등록 제출 경로는 요청 호출 수와 본문에 원천 두 키가 없음을 함께 센다. 「요청이 0건」으로 통과하는 형태를 쓰지 않는다.
- green-by-skip 방지 (#93): 옮긴 두 조작의 **실제 부모 노드**와 형제 순서를 단언하고, 접기 요소의 자손 집합에 두 조작이 없음을 별도로 단언한다. 조회 실패(0건)로 통과하지 않도록 두 조작이 화면에 존재함을 먼저 단언한다. 팔레트·구간 수를 실제로 바꾸고 그리기 요청이 한 번 더 도는 것을 센다.
- green-by-skip 방지 (#84·#54): testid 7개를 **목록으로 돌며 각각 1건씩** 조회되는지 센다. 총계만 세는 형태를 쓰지 않는다. 관리자 체크 기본값은 체크 안 됨을 단언한 뒤 실제 제출까지 보내 요청 본문에 관리자 키가 없음을 센다. 비활성 단언은 체크 전 활성 → 체크 후 비활성 양쪽을 본다.
- green-by-skip 방지 (#92): 계약 필드가 3상태이므로 **거짓 · 값 없음 · 참** 세 경우를 각각 별도 케이스로 돌리고, 세 경우 모두에서 세 블록의 존재/부재를 각각 단언한다. 값 없음 경우는 '보인다'는 양성 단언이라 조회 실패로 통과할 수 없다. 거짓 경우는 세 블록이 부재함과 동시에 등록 버튼이 **여전히 존재**함을 함께 단언해, 화면 전체가 비어 통과하는 형태를 막는다. 세 경우가 모두 실행됐음을 시험 수로 확인한다.
- 실제 브라우저: UI 변경이므로 `agent-browser`로 업로드 등록 화면·업로드 미리보기 패널·계정 관리 화면을 실제로 조작해 확인한다. 읽기 전용 시각 검사를 사용자 여정 검증으로 보고하지 않는다. 환경·계정 선택은 완료 전 검증 스킬을 따른다.
- 준비 실패와 미실행을 green으로 세지 않는다. 게이트 3계수(green / red 판정 / red 준비)와 종료코드를 그대로 회수한다.

- 글자: 옮길 묶음의 라벨은 현재 13px이고 상위 접기 컨테이너도 13px이다. 새 부모(고르개 줄 컨테이너)로 옮기면 접기 컨테이너가 주던 글자 크기 상속이 끊길 수 있다. **그 경우 상속에 기대지 않고 옮긴 묶음에 13px을 명시한다.** 실제 상속 결과는 `frontend-visual`의 실화면 계측으로 확인한다.
- 대비: 옮긴 뒤에도 배경이 바뀌지 않는지 실화면에서 잰다. 접기 컨테이너에는 위쪽 구분선이 붙어 있는데, 묶음을 그 밖으로 빼면 구분선과의 관계가 달라진다. **새 구분선을 추가하지 않고, 남는 접기 컨테이너의 구분선만 유지한다.**
- 그림자: 0 유지. 이 묶음에 그림자를 붙이지 않는다.
- 여백: 묶음이 자기 바깥 여백을 갖지 않게 하고, 고르개 줄 컨테이너가 자식 간 간격을 소유하게 한다. 현재 묶음에 걸린 접기 자손 전제의 위쪽 여백 규칙은 컨테이너 소유 원칙에 맞게 정리한다.
- 인터랙션: 셀렉트·수치 입력·버튼 모두 기존 요소를 그대로 옮기므로 pointer-down 피드백·키보드 접근이 유지된다. 새 전환·새 움직임을 만들지 않는다. 배치가 바뀌므로 **탭 순서**가 파일·변수 → 팔레트 → 구간 수 → 그리기로 읽히는지 실화면에서 확인한다.
- 판정: **조건부 통과.** 글자 크기 상속과 구분선 관계 두 가지는 실화면 계측 결과로 확정한다 — 아래 우려 항목에 올린다.

**③ 계정 관리 화면 — 생성 폼 (#84·#54)**
- 토큰: 신규 수식 클래스는 최소 높이와 배치 기준점 두 가지 레이아웃 속성만 덮는다. 색·간격·글자에 새 값을 넣지 않는다. 파일별 전역 선언을 신설하지 않는다.
- 글자: 폼 라벨은 캡션 토큰(13px), 카드 안내는 본문 소 토큰(14px)이다. 문면만 바꾸므로 크기는 그대로다. **하한 13px을 지킨다.**
- 대비: 문면 변경뿐이라 색 조합이 바뀌지 않는다. 다만 **비활성된 연구실·역할 선택의 대비**는 새로 생기는 상태다. 브라우저 기본 비활성 회색이 4.5:1을 밑돌 수 있으므로 실화면에서 재고, 미달이면 토큰 색으로 명시한다.
- 그림자: 카드 그림자 0 유지. 수식 클래스가 그림자를 도입하지 않는다.
- 여백: 폼 간격은 지금처럼 폼 컨테이너가 소유한다. 체크박스를 맨 위로 옮겨도 자기 바깥 여백을 갖지 않게 한다.
- 인터랙션: 체크 시 아래 두 선택이 비활성으로 바뀌는 것은 즉시 반영한다. 이 전환에 애니메이션을 넣지 않으므로 `prefers-reduced-motion` 분기가 새로 필요하지 않다. 비활성 전환 시 **초점이 비활성 요소에 남지 않도록** 확인한다.
- 수식 클래스 범위: 계정 관리 화면 최상위에만 붙인다. 로그인 화면·비밀번호 변경 화면은 공용 클래스만 유지한다 — 두 화면의 세로 가운데 정렬이 그대로인지 실화면에서 확인한다.
- 판정: **조건부 통과.** 비활성 선택의 대비와 두 공유 화면 무변경 두 가지를 실화면 계측으로 확정한다 — 아래 우려 항목에 올린다.

**④ 업로드 미리보기 패널 — 지도용 선택지 노출 (#92)**
- 토큰: 신규 스타일 0건. 블록이 통째로 렌더되지 않을 뿐이다.
- 글자·대비·그림자: 변경 없음. 남는 안내 문구는 기존 자리 선점 틀 안의 기존 스타일을 그대로 쓴다.
- 여백: 세 블록이 사라진 뒤 남는 자리에 빈 여백이 뜨지 않는지 실화면에서 본다. 여백은 지금처럼 바깥 패널이 소유한다.
- 인터랙션: 판정 전에는 노출을 유지하므로 값이 도착해도 화면이 흔들리지 않는다(참·값 없음 → 참인 경로). 값 없음 → 거짓 경로에서는 블록이 사라지므로 **그 전환에 애니메이션을 넣지 않는다.**
- 판정: **통과.** 새 시각 결정이 없다.
