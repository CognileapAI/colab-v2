# Spec: 승인된 대표 디자인의 전체 화면 확장
출처 intent: `dev-package/intent/2026-09-12-design-consistency.md` (2026-09-12 승인).
대표 방향 확인: 전체 확장 질문에 Ted “와 너무좋은데”. 동일 대화의 전체 디자인 작업 승인과 함께 대표안 긍정 확인으로 수용한다.

## 문제 진술
- 대표 화면에만 적용된 글자 위계·여백·두 테마를 제품 전체에 연결해야 한다.
- 화면별 하드코딩 색상·중복 토큰·기본 컨트롤이 공통 기준을 깨뜨리지 않아야 한다.

## 해법 개요
- 대표안의 서체·타이포·여백·색상·모바일 방식을 실제 제품 공통 스타일로 승격한다.
- 화면별로 목록·정보·입력·빈 상태의 구조를 유지하면서 동일 표현 기준을 적용한다.
- 기기 테마를 기본으로 따르고 사용자의 밝게·어둡게 선택은 로컬에 저장한다. 로그인 전후 동일하게 적용한다.

## 사용자 스토리
1. 연구원은 어떤 화면에서도 같은 제목·본문·보조 정보 위계로 내용을 읽는다.
2. 데이터 작업자는 표의 정보를 비교하고 좁은 화면에서 표 내부를 스크롤한다.
3. 모바일 사용자는 기존 메뉴·기능·폼과 마지막 실행 버튼에 도달한다.
4. 사용자는 원하는 테마를 선택하고 다시 방문해도 같은 테마를 본다.
5. 키보드 사용자는 테마 선택과 기존 필터·모달을 조작한다.
6. 오류·대기·잠김·성공 상태를 사용하는 사람은 두 테마에서 그 의미를 같은 방식으로 구분한다.
7. 저장소 접근이 차단된 브라우저에서도 사용자는 현재 창의 테마를 바꾸고 앱을 사용한다.

## 구현 결정
- 모듈 · 인터페이스: 승인된 대표 CSS를 공통 스타일로 연결하고, 화면별 토큰 및 상태색은 토큰 정본에 정의한다. 기존 화면의 비즈니스 인터페이스는 유지한다.
- 테마 선택은 시스템/밝게/어둡게 세 상태이며 기본은 시스템이다. OS 변화는 시스템 선택일 때만 반영한다. 다른 탭의 저장 변경도 반영한다.
- 초기 HTML에서 저장된 선택 또는 OS 선호를 적용해 첫 렌더의 테마 깜빡임을 줄인다. 저장 실패는 앱 기능을 막지 않는다.
- 공통 여백과 typography는 대표안 값 유지. 페이지별 정보 밀도·테이블 내부 스크롤·모달 본문 스크롤을 유지한다.
- 스키마·마이그레이션: 없음. API 계약: 비파괴·변경 없음.

## 시험 결정
- 테마 동작 테스트를 먼저 실패시키고 선택·지속성·OS 연동·저장 불가·탭 동기화·접근성 동작을 구현한다.
- 기존 화면 회귀 테스트와 실제 컴포넌트 시각 fixture를 사용한다. 공통 셸과 로그인에도 새 테마 기능을 연결한다.
- 필수 게이트: frontend-typecheck, frontend-test, frontend-fixture-reach, frontend-visual. 추가로 production build와 실제 브라우저 테마 변경/새로고침 지속성을 검사한다.
- 모든 routes 및 업로드·승인·설정·모달을 포괄하는 상태 목록을 source에서 작성하고 375/768/1440px × 두 테마를 계측한다. 상태별 대상 수와 누락/미실행을 보고한다.
- 실제 서버 데이터 저장 경로는 변경하지 않는다. 이번 실제 지속성 검증은 새 테마 저장 동작이며 기존 업무 기능은 프론트엔드 행위 회귀 테스트로 검증한다. fixture를 실제 서버 저장 E2E로 보고하지 않는다.
- 대상0건 성공 방지: 장면 목록과 캡처·probe 수를 대조하고 렌더 실패/콘솔 오류/작은 글자/낮은 대비/페이지 넘침을 실패로 기록한다.

### 디자인 제약 확인
| 화면 | 토큰·타이포·대비 | 표면·여백 | 동작 |
|---|---|---|---|
| 셸·로그인·없는 경로 | tokens.css, 13px 이상, 대비4.5 이상 | 카드 그림자0, 부모 여백 | 테마 접근·포커스·반응형 내비 |
| 연구실·데이터셋 | 승인 대표안과 동일 | 목록과 안내 밀도 구분 | 필터·모달·행 이동 유지 |
| 프로젝트 목록·상세 | 같은 토큰과 합격선 | 카드·표·정보 위계 통일 | 생성·수정·닫기·오류 보존 |
| 데이터 상세·계보 | 같은 토큰과 합격선, 의미 색상 유지 | 표·그래프 내부 스크롤 | 잠김·승인·파일 작업 보존 |
| 검색·미리보기 | 같은 토큰과 합격선 | 결과·빈/오류·파일 표시 간격 | 기존 검색과 표시 방식 보존 |
| 업로드·승인 | 같은 토큰과 합격선 | 단계·본문·푸터 여백 구분 | 처리·실패·취소·모달 키보드 보존 |
| 설정·구성원 | 같은 토큰과 합격선 | 폼·목록 여백 통일 | 권한별 노출·편집 보존 |
모든 변경 컨트롤은 pointer-down 피드백과 focus-visible을 갖고 reduced-motion을 지킨다.
