# AI 검색 근거의 제품 저장·갱신 설계안

출처: `intent/2026-09-12-ai-search.md`, 사용자 전체 실행 지시, 실제 D3 구조 조사.
상태: 2026-09-13 사용자 지시로 WSL stage 테스트 직전까지 로컬 구현한다. dev 배포와 stage 운영 스택 변경은 하지 않는다.

## 사용자가 하는 일

자료 등록 또는 기존 자료 수정에서 설명서를 근거로 파일의 역할과 자료의 적용 범위를 확인한다. 검색은 확인된 사실을 인용하고 미상·불일치를 구분한다. 설명서 추출 자체가 사실 확인이나 교수의 Verified 승인이 되지는 않는다.

입력 방식은 현재 모델 보류와 양립하는 설명서 원문 수집+사람 입력·확인으로 구현한다. 자동 의미 추출은 향후 같은 초안 입력 계약에 연결할 수 있다. 현재 DOCX 본문 수집은 모델 호출도 의미 추출도 아니다.

## 기존 구조를 재사용하는 범위

| 정보 | 기존 경로 | 재사용 한계 |
|---|---|---|
| 기간 | `d3_dataset_autometa.period_start/end/granularity`, 사람 메타 PATCH | 기간 경계만으로 결측 없음·연속 관측을 보장하지 않음 |
| 원천 | `d3_dataset.source_label/source_url/source_downloaded_on` | 특정 주장과 설명서 절/hash를 연결하는 근거 버전은 없음 |
| 격자 | `d3_dataset_grid_profile` bbox, `human_grid_description` | bbox와 지역명 일치를 근거 없이 추정하지 않음 |
| 파일 | `d3_file`, 파일 등록·교체·삭제 경로 | kind는 본체/기준 격자 접근 구분이며 모델 역할로 재사용 금지 |

## 추가 구조 제안

- 파일 역할은 별도 다대다 근거로 보관한다. 첫 역할 후보는 현재 출처로 확인한 model_input, auxiliary_input, validation, prediction, index다. 설명서와 분석 코드를 관측 자료로 오인하지 않도록 documentation, analysis_code도 구분한다. 다른 역할을 강제 추정하지 않는다.
- 최소 바인딩은 연구실·데이터셋·파일 ID, 주장 종류/값, 설명서 ID·절/문단·내용 hash, 확인자·확인 시각·상태다. 임의 로컬 경로를 제품 출처 URL처럼 노출하지 않는다.
- 후보 초안과 확인된 근거를 분리한다. 상태는 draft→reviewed, 대상 파일 내용 교체 시 stale이다. 저장 원문은 수집 당시의 텍스트 사본이며 외부 DOCX 변경을 제품이 자동 감지하지 않는다. 원문 편집 후 초안 저장은 draft, 확인하고 저장은 현재 사용자의 명시적 재확인이다. 이전 검토자를 자동 추출 결과의 확인자로 재사용하지 않는다.
- 저장된 원문 hash와 대상 파일 내용 버전에 연결된 최신 reviewed 근거만 검색에 사용한다. 파일 교체가 ID를 유지하더라도 내용 의존 근거는 stale로 돌린다. 단순 파일명 변경과 실제 내용 교체를 구분한다.
- 파일 삭제는 FK cascade로 연결 근거를 제거한다. 다른 자료의 동일 파일명에 근거를 전이하지 않는다.
- 파일 근거는 `d3_file`의 연구실+본체 접근 규칙을 따른다. 잠긴 카드에서는 파일명·역할·근거 문단을 노출하지 않는다. 공개 가능한 데이터셋 메타로의 승격은 별도 정책이다.
- 새 문서가 현재 DB 설명과 충돌하면 양쪽 출처를 보존해 재검토 대상으로 표시한다. 자동으로 기존 원장을 덮어쓰지 않는다.

## 검색 연결 순서

1. D3가 접근 가능한 자료와 최신 reviewed 근거만 조회한다. AI 서비스에 다른 연구실/잠긴 파일의 본문을 전달하지 않는다.
2. 질문 조건을 해석하고 supported/contradicted/unknown을 근거 단위로 판정한다. 여러 파일의 서로 다른 기간을 하나의 범위로 합쳐 주장하지 않는다.
3. 명확히 충족한 결과와 조건 미확인/불일치의 관련 결과를 구분하는 계약을 먼저 정의한다. 현재 단일 목록에 필터를 뒤늦게 적용해 총건수·이어보기를 깨뜨리지 않는다.
4. 기존 한 줄 rationale에서 출처가 뒷받침하는 내용만 설명한다. 검증 자료 역할과 자료 품질 검증을 구별한다.
5. 새 계약·소비자·권한·갱신 시험을 함께 구현한다. 기존 K4 판정 미결을 임의로 통과 처리하지 않는다.

## 독립적으로 완료한 수집 단위

`eval/k4-search/reference_evidence.py`는 원 DOCX 문단과 hash를 수집하고, 기존 연구 주석을 실제 snapshot 데이터셋/파일 ID와 연결한다. 동일 이름 설명서가 복수이거나 대상 파일이 없으면 임의 선택하지 않는다. 원문 변경·삭제를 검출한다. 제품 저장이나 자동 의미 확인은 수행하지 않는다.

## 다음 구현에서 반드시 검사할 것

- 추가→확인→검색 반영, 원문 수정→draft 또는 명시적 재확인, 대상 내용 교체→stale→재확인, 삭제→참조 제거.
- 다른 연구실, 잠긴 자료, 수정 권한 없음, 동일 파일명 충돌, 오래된 버전으로 확인하는 경쟁 요청.
- 기간 없는 파일과 관측 파일 혼합, 파일별 복수 역할, 설명서/DB 충돌, 미확인 조건.
- 전체 후보 필터·순위·Verified·총건수·다음 페이지 일관성, 기존 HTTP 장애/해석 저하.
- 기존 A층 및 새 골든셋 의미 판정, 실제 화면 등록/수정→검색→근거→상세 여정.

새 마이그레이션 번호는 구현 시 체인 HEAD를 확인해서 정한다. 이 문서에서 번호나 main 반영 승인을 발급하지 않는다.

## 구현 범위의 명확화

현재 DB 설명과 신규 출처 텍스트는 별도로 보존한다. 이는 모든 근거 편집 이력의 영구 보관을 뜻하지 않는다. 파일별 현재 근거 한 건을 버전 번호로 갱신하며 오래된 화면의 수정은 충돌로 거절한다. DOCX 변경 검사는 stage 입력 묶음을 다시 만들 때 수집 hash와 대조한다. 자료 품질이나 기간 내 연속성은 근거 없는 한 미상이다. 복합 부정 및 복수 월 날짜처럼 현재 해석기가 안전하게 판정하지 못하는 조건은 확정 필터로 사용하지 않는다.
