# Spec: 2026-09-12 · 등록 화면의 설명문 규약과 부모 찾기 재현
출처 intent: `dev-package/intent/2026-09-12-issue-register-hints-parent-picker.md` (승인 2026-09-12 · 커밋 `567b830`)

## 문제 진술
- 업로드 등록 ② 메타데이터 카드의 안내 문단(`fieldnote`·`axis-note`)이 칸마다 다른 자리에 그려진다 — 기간 칸만 컨트롤 앞, 나머지 셋은 컨트롤 뒤(`CognileapAI/colab-v2#31`).
- 배치 규약이 코드·정책 문서 어디에도 없어 칸마다 인라인 JSX 로 개별 작성됐다. 순서를 만드는 자료구조가 없으므로 결함은 작성 시점 배치 불일치다.
- 등록 ③ 계보 부모 찾기 모달의 결과가 0행인 화면이 첨부됐고, 조회 결함인지 후보 부재인지 재현되지 않았다(`CognileapAI/colab-v2#30`).

## 해법 개요
- 사용자 관점 = 등록 화면에서 칸마다 「설명이 입력칸 위에 있다가 아래에 있다」로 갈리는 것을 한 순서로 맞춘다. 기존 폼 요소를 그대로 두고 그리는 순서만 바꾼다 — 새 화면·새 개념을 추가하지 않는다.
- 채택 규칙 = **라벨 → 입력 컨트롤 → 설명문**. 설명문은 자기 칸의 입력 컨트롤 뒤에 온다.
- 문면은 유지한다. 「한 시점이면 비워 둬요」는 PRD-40 판정 ⓐ 의 산출물이라 삭제가 판정 재개봉에 해당한다.
- 부모 찾기 모달은 이번 회차에 코드를 고치지 않는다. dev 실물에서 0행이 재현되는지와 그 원인 후보 셋(후보 실재 · 연구실 경계 · 자기 제외)을 측정 회차에서 기록하고, 그 기록을 후속 판정 입력으로 남긴다.

## 사용자 스토리
1. 데이터를 등록하는 연구자로서 메타데이터 카드의 설명이 항상 입력칸 아래에 있기를 원한다, 칸마다 눈이 위아래로 옮겨 다니지 않게 하기 위해.
2. 데이터를 등록하는 연구자로서 기간 칸의 「한 시점이면 비워 둬요」가 달력 버튼 아래에 있기를 원한다, 다른 칸과 같은 순서로 읽히게 하기 위해.
3. 데이터를 등록하는 연구자로서 종료 시점이 없는 자료를 비운 채 저장할 수 있다는 안내가 사라지지 않기를 원한다, 종료를 억지로 채우지 않기 위해.
4. 데이터를 등록하는 연구자로서 격자 설명·공개 범위·데이터 유형 칸의 현재 설명 위치가 그대로 유지되기를 원한다, 이미 익숙한 자리가 바뀌지 않게 하기 위해.
5. 화면을 검수하는 사람으로서 설명문 배치가 시험으로 고정되기를 원한다, 다음 회차에 같은 불일치가 다시 들어오지 않게 하기 위해.
6. 데이터를 등록하는 연구자로서 부모 데이터 찾기 창에서 0행이 보일 때 그것이 결함인지 후보 부재인지 판정되기를 원한다, 등록을 계속할 수 있는지 알기 위해.
7. 판정자로서 0행 관측에 후보 실재 여부·연구실 경계 적용·자기 제외 동작이 각각 기록되기를 원한다, 다음 조치를 근거로 고르기 위해.
8. 판정자로서 재현 회차가 데이터를 지우거나 바꾸지 않기를 원한다, dev 상태를 되돌릴 필요가 없게 하기 위해.
9. 개발 담당자로서 이 회차가 계약·DB 를 열지 않기를 원한다, 동결 해제 서명 없이 병합되게 하기 위해.
10. 개발 담당자로서 등록 카드 수정 레인이 미리보기 레인과 같은 파일을 만지지 않기를 원한다, 두 레인을 동시에 돌리기 위해.
11. 판정자로서 부모 찾기 창의 화면 형태 재구성이 이번 범위에서 빠지기를 원한다, 범위가 조용히 늘지 않게 하기 위해.

## 구현 결정
- 모듈 · 인터페이스
  - 수정 대상 = 업로드 등록 카드 컴포넌트 하나(`frontend/src/components/upload/RegisterArea.tsx`). 기간 칸의 안내 문단을 달력 열기 버튼 뒤로 옮긴다. 문면 상수·`data-testid`·클래스는 무변.
  - 스타일시트 미접촉 — 갈래 ⓐ 한정. `.fieldnote` 규칙은 `margin-top` 만 두고 순서를 결정하지 않으므로 DOM 순서 변경만으로 화면 순서가 바뀐다.
  - 부모 찾기 모달 컴포넌트·조회 훅·계보 후보 조회 경로는 **읽기 전용**. 이번 회차 변경 0.
- 배치 규칙의 근거
  - 카드 안 안내 문단 4건 중 3건이 이미 컨트롤 뒤다 — 격자 설명(textarea 뒤) · 공개 범위(select 뒤) · 데이터 유형 정의 줄(셀렉트·정의 줄 뒤). 기간 칸 1건만 컨트롤 앞이다.
  - PRD-40 은 위치를 「기간 입력 옆에 안내 한 줄」로만 적고 앞/뒤를 지정하지 않는다 — 다수 배치와 충돌하지 않는다.
  - 규약 자체를 정책 문서에 한 줄로 적는 것은 후속 항목(이번 회차 밖).
- 부모 찾기 0행 재현 (측정 항목 · 코드 변경 0)
  - 재현 절차 = dev 실물 로그인 → 업로드 등록 ③ 계보 단계 → 「가공 전 데이터 직접 찾기」 모달 열기 → 필터 전부 비운 상태 1회 → 분류·주제 각 1값 적용 1회 → 가공 단계 필터 적용 1회.
  - 데이터 선행조건 = 같은 연구실에 등록 완료 데이터셋이 최소 2건 실재하고, 그중 1건 이상이 등록 중인 데이터셋 자신이 아닐 것. 실재 여부는 데이터셋 목록 화면 건수로 먼저 확인한다.
  - 기록 항목 = ⑴ 계보 후보 조회 요청의 질의 파라미터 전부와 응답 본문(행 수 · 다음 커서 유무) ⑵ 응답 0행일 때 화면이 낸 빈 상태 문면 두 갈래 중 어느 쪽인지 ⑶ 요청 주체의 연구실 식별자와 목록 화면이 같은 주체로 낸 데이터셋 건수 ⑷ 자기 제외 파라미터의 전달 여부와 값 ⑸ 등록 중 데이터셋의 가공 단계 기준값.
  - 판정 규칙 = 같은 주체·같은 연구실에서 후보가 실재하는데 후보 조회가 0행이면 조회 결함 ⟹ 신규 `BF-` 항목 등재 대상으로 보고한다. 후보가 실재하지 않거나 필터 값이 결과를 비운 것이면 사용법으로 닫고 항목을 등재하지 않는다. 자기 제외로만 0행이 되는 경우도 사용법으로 닫는다.
  - 첫 가설 = 연구실 경계 자동 주입(RLS)이 요청 주체의 연구실 밖 데이터를 거른 결과. 경계 동작은 관찰만 하고 바꾸지 않는다.
