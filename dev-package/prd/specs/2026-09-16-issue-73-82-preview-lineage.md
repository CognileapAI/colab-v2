# Spec: 미리보기 선택칸과 계보 선언 표시
출처 intent: `dev-package/intent/2026-09-16-issue-73-upload-preview.md`, `dev-package/intent/2026-09-16-issue-82-lineage-help.md` (승인 2026-09-16)

## 문제 진술
- 긴 GRIB 선택값의 최소 폭이 패널을 밀며, 서로 다른 표현층인 썸네일/지도 차이가 데이터 차이처럼 보인다.
- 부모 연결 후 비활성 선언 행이 실패 메시지처럼 읽힌다.
## 해법 개요
- 공용 선택칸의 축소·줄배치를 허용하고 전체 값 확인 경로를 유지한다.
- 확정 부모가 있으면 기록 없음 선언만 숨긴다.
- 실제 GRIB 원본으로 지도와 썸네일을 각각 검증하고 같은 렌더 선택값에 대응하는지 확인한다.
## 사용자 스토리
1. 업로드 사용자로서 긴 변수명을 선택해도 화면 안에서 조작하고 싶다.
2. 상세/확장보기 사용자로서 같은 선택 규칙을 사용하고 싶다.
3. 업로드 사용자로서 그림이 현재 고른 데이터를 나타내는지 알고 싶다.
4. 대표 그림을 직접 고른 사용자로서 내 선택을 유지하고 싶다.
5. 부모 데이터를 연결한 사용자로서 불필요한 기록 없음 선언을 보지 않고 싶다.
6. 연결을 해제한 사용자로서 이전 선언 선택을 다시 사용하고 싶다.
## 구현 결정
- 공용 미리보기 선택칸 CSS의 최소 폭/최대 폭, 라벨 비줄바꿈, 선택값 전체 표시 보조 속성을 사용한다. 새 컴포넌트 없음.
- 계보 선언 가시성은 기존 자기 단계 조건에 확정 부모 수 0 조건을 추가한다. 선언 상태나 등록 payload 로직을 변경하지 않는다.
- 렌더 계약은 유지한다. 큰 지도와 좌표 없는 썸네일의 투영 차이를 강제 제거하지 않는다.
- 실파일 조사에서 극점 ±90의 Mercator 변환이 세로 범위를 폭증시켰다. 기존 지도 투영 안에서 유효 위도를 처리하되 좌표 밖 값을 경계로 몰거나 축소 평균에 섞지 않는다. 배열·bbox·sidecar 지리 범위를 일치시킨다.
- 스키마 · 마이그레이션: 없음. API 계약: 비파괴.
## 시험 결정
- 기존 계보 시험에서 연결 시 숨김·해제 후 복원·Lv0 숨김·payload 생략·확정 여부를 검증한다.
- 공용 선택칸 시험은 긴 값의 전체 표시와 선택 이벤트 원본 ID 보존을 검증한다.
- 실제 agent-browser로 1440px/390px 화면에서 컨테이너 넘침과 선택 조작을 확인한다. CSS 치수는 jsdom만으로 통과 판정하지 않는다.
- 실제 surface.grib 렌더에서 원본 값/좌표 범위와 두 산출물을 대조하며 설정 변경 전후 선택값 대응을 확인한다.
- 위도별 서로 다른 값 fixture로 값/위치 대응, NoData 유지, 지역 격자 회귀, 전부 Mercator 범위 밖인 입력의 명시적 실패를 확인한다.
- 재사용 seam: 기존 vitest·agent-browser·viz-render 시험/실제 렌더. 신설 seam 없음.
- 게이트: frontend-typecheck, frontend-test, frontend-visual 및 CSS 정적 검사. 서버 수정이 확인되면 해당 viz 시험을 추가한다.
- green-by-skip 방지: 수집/통과 건수, 실제 화면 치수/스크린샷/원본 hash와 렌더 설정을 기록한다. 미실행은 명시한다.
## 정책 대조 (작성 시점 제약)
- 도메인/불변 규칙 저촉 없음. AI 없이 직접 연결 유지. 연구실 경계·기존 저장 계약 유지.
- 범위 확대 금지: 지도 정상 여부는 실측으로 판정하며 썸네일 계약/투영 재정의는 하지 않는다.
- 계약 동결 해제 필요: 아니오.
### 디자인 제약 확인
- 업로드·확장·상세 선택칸 및 계보 선언: 기존 tokens.css 토큰 재사용, 새 전역 토큰/그림자 없음.
- 글자 13px 이상·대비 4.5:1 이상 유지, 여백은 컨테이너 소유.
- 기존 native select/button 피드백 유지. 새 전환/애니메이션 없음; 기존 reduced-motion 유지.
