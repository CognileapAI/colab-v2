제품 기능의 상태 원본 `work-items.yaml`을 대체하거나 제품 stage·완료 조건을 변경하지 않는다.

## 구성과 원본

기존 공통 본문은 `.claude/skills`, `.claude/agents`, `CLAUDE.md`에 유지한다.
`.agents/skills`와 `.codex/agents`는 참조와 도구별 차이만 담는다.
실제 도구 대응과 실행 명령은 `docs/development/dual-agent.md` 한 곳에 둔다.
새 도구를 지원한다는 이유로 동일한 정책·판정 스크립트를 복제하지 않는다.

## 수용 기준

| 범위 | 통과 증거 |
|---|---|
| 실행 환경 | 기본 CLI와 프로젝트 진입점의 Astra 대응 버전 확인, WSL cwd·PATH·exit 전달 확인 |
| 스킬·역할 | 실제 런타임에서 연결 스킬과 네 역할 발견 확인, 역할별 제한을 확인하는 최소 실행 |
| 공통 검증 | 기존 검사 재사용, 잘못된 증거 거절, 미실행·준비 실패를 성공으로 취급하지 않음 |
| 자동 훅 | 지원 이벤트·payload·trust를 확인한 등록, 안전 명령 허용·금지 동작 차단을 실제 호출로 증명 |
| 로컬 eval | 같은 fixture·기대 결과를 사용한 Claude/Astra 실행 결과를 각각 기록, 미실행 과제를 명시 |
| E2E | agent-browser로 선언된 테스트 환경에서 실제 행동·저장·조회·지속성·거절 흐름 검증 |
| 보관 | 원본 보존·미커밋·미병합·worktree·경로 참조 확인 후 경로표를 갖춘 보관. 삭제 없음 |
| 최종 인수 | 위 결과와 남은 한계 검토. 전체 필수 단계가 통과하거나 사용자가 범위를 변경해야 완료 |

## 경계

`frontend-visual`은 읽기 전용 시각 검사다. 사용자의 쓰기 E2E로 바꾸지 않는다.
브라우저 about:blank 기동은 환경 점검이며 제품 E2E 통과가 아니다.
TOML 파싱은 파일 검사이며 에이전트 등록·권한 강제의 증명이 아니다.
명시적 guard 호출은 모든 Codex 명령을 자동 가로채는 훅이 아니다.
Codex 신뢰 설정을 읽기만 한 결과를 신뢰 등록 완료로 보고하지 않는다.

## 권한과 중단 조건

프로젝트 trust·hook trust는 2026-09-09 사용자 승인으로 이 PC에 등록됐다. 기존 승인을 반복 요청하지 않는다.
운영 데이터 대신 격리된 테스트 환경을 사용한다. 환경·계정·시나리오가 준비되지 않으면
기존 자료와 코드에서 확보할 수 있는 것을 먼저 조사하고 필수 입력만 묻는다.
차단된 단계 외의 실행 가능한 단계가 있으면 전체 작업을 종료하지 않는다.

## 2026-09-09 사용자 정정 — Codex 동작 동등성 필수 인수

요청: 「코덱스에서 완전히 돌아가게 만들고, 검증해서 똑같이 돌아가게 … 계획잡아」.
실행 뷰: `dev-package/prd/rounds/R-CODEX-PARITY.md`. 기존의 등록·최소 호출 기준만으로 완료하지 않는다.
동등성은 동일 입력에 대한 요구사항·승인 경계·산출물·허용/차단·검증·인계의 일치다.
모델의 문장, 내부 도구 이름이나 모델 구조가 같아야 한다는 뜻은 아니다.

1. 기존 모든 스킬·역할·규칙·훅·명령·참조 리소스·게이트를 목록화하고 동등성 증거를 각각 연결한다.
   미지원 명령은 동등한 실행 경로를 구현하고 실제 실행한다. 이름 대응표만으로 완료하지 않는다.
2. 사용자가 쓰는 Codex 데스크톱의 새 작업과 프로젝트 CLI에서 각각 진입·스킬 발견·훅·작업 실행을 검증한다.
   외부 CLI의 성공을 현재 데스크톱의 성공으로 옮겨 적지 않는다. 개인 절대경로 의존도 제거·검증한다.
3. intent → 질문/조사 → 사용자 확인 → spec → 계획 → 격리 구현 → 검토 → 게이트 → 인계를 완주한다.
   기획 미승인은 정상 대기이며 구현 허가로 간주하지 않는다. 승인 후에는 정상 종료까지 이어져야 한다.
4. 각 보호 규칙은 정상 허용과 금지 차단을 모두 검증한다. 무관한 기존 미추적 파일로 읽기 전용 조사자를
   막는 경우와 다른 레인의 보고서를 참조하는 경우는 원인과 공통 계약을 고쳐야 할 인수 결함이다.
   H7의 깨진 증거·준비 실패 관대 처리도 완료 검증에서 실제로 거절되는지 확인한다.
5. 정상 종료를 위해 훅을 끄거나 증거를 조작하지 않는다. 공유 정책 결함은 공통 원본에서 고치고 Claude 회귀를 검사한다.
6. 동일 코드 스냅샷·fixture·판정부에서 Claude와 Codex의 H01~H20을 각각 새로 2회 실행한다.
   각 40/40, 준비 실패·미실행 0을 인수 기준으로 삼는다. 과거 결과 합산·사후 재판정은 참고 증거만 된다.
   정답 문구 주입·판정부 완화는 금지한다. 모호한 과제 계약 수정은 양쪽에 동일 적용하고 전체 재실행한다.
7. 격리된 작은 개발 과제로 실제 변경·실패 테스트·수정·리뷰·검증·인계를 양쪽에서 확인한다.
   브라우저가 필요한 스킬은 실제 사용자 행동까지 검증한다. 제품 전체 배포 완료와는 별도로 판정한다.
8. 최종 실패·준비 실패·미실행·필수 미지원은 0건이어야 한다. 재시작과 새 격리 사본에서도 재현해야 한다.
   미충족 항목이 있으면 전체 상태는 진행 중이며 부분 성과를 최종 완료로 보고하지 않는다.
