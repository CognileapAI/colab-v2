# Spec: 전체 디자인 일관성 — 대표 화면 선행
출처 intent: `dev-package/intent/2026-09-12-design-consistency.md` (승인 2026-09-12, “엉 그렇게해봐”)

## 문제 진술
- 스타일 복구만으로 시각적 완성도를 판정할 수 없다. 글자 위계·컨테이너 여백·화면별 밀도의 공통 기준을 실제 화면으로 확인해야 한다.

## 해법 개요
- 기존 React 화면과 fixture source를 사용하는 로컬 미리보기에서 데이터셋 목록·연구실 대시보드·새 프로젝트 입력 모달을 선행 정비한다.
- 같은 데이터로 기존 복구 화면과 제안 화면을 전환하고, 밝음·어두움 및 모바일·태블릿·데스크톱에서 비교한다.
- 대표 화면의 사용자 확인 뒤 전체 화면으로 확장한다. 이번 대표 화면 인계는 전체 intent 완료가 아니다.

## 사용자 스토리
1. 연구원으로서 목록의 이름과 메타데이터를 명확하게 구분해 빠르게 비교하고 싶다.
2. 연구원으로서 필터를 읽고 조작하기 편한 크기로 사용하고 싶다.
3. 연구원으로서 대시보드에서 연구실 상태와 내 일을 구분해 보고 싶다.
4. 새 구성원으로서 빈 연구실의 다음 행동을 읽고 실행하고 싶다.
5. 프로젝트 작성자로서 필수 이름·설명·기간·성과 연결을 구분해 입력하고 싶다.
6. 모바일 사용자로서 기능을 숨기지 않고 사용할 수 있기를 원한다.
7. 어두운 화면 사용자로서 내용과 상태를 밝은 화면과 동등하게 구분하고 싶다.
8. 키보드 사용자로서 필터·행·모달의 포커스와 종료 동작을 유지하고 싶다.
9. 검토자로서 같은 내용의 이전 화면과 제안을 비교한 뒤 전체 적용 방향을 판단하고 싶다.

## 구현 결정
- 모듈 · 인터페이스: 기존 데이터셋·연구실·프로젝트 모달과 데이터 source 인터페이스를 재사용한다. 별도 미리보기 제어 화면에서 기존 시각 fixture를 iframe으로 연다. 제안 스타일은 명시적인 preview body class에서만 적용한다.
- 서체: 기존 Pretendard Variable 유지. 본문 15px/1.6, 목록 14px/1.5, 보조 13px/1.5, 구획 제목 16px/600, 페이지 제목 28px/700을 제안한다. 본문 자간 0, 제목 -0.02em.
- 공간: 페이지 최대폭 1280px, 데스크톱 외곽 32px·모바일 16px, 카드 내부 24px·모바일 20px, 기본 조작 높이 40px·모바일 44px. 표 행은 내용에 따라 높이를 늘리고, 제목과 상태 메타데이터는 두 줄로 구분한다.
- 색상: 기존 파랑 행동·중립 바탕을 유지한다. 크림슨/바이올렛은 검색 AI 행동만 사용한다. 어두운 테마의 배경·글자·경계·상태색은 preview 범위의 토큰으로 제안한다.
- 토큰은 공통 토큰 파일 한 곳에서 선언하되 preview 범위만 바꾼다. 기존 화면 CSS 전역 소유권 재편은 대표 화면 확인 뒤 별도 실행 단계로 다룬다.
- 미리보기는 예시 데이터임을 표시한다. 서버 호출·영구 저장 없이 기존 유효성 검사와 로컬 모달 조작만 확인한다.
- 모바일 표 필터 메뉴는 화면 하단의 고정 팝오버로 표시해 표 내부에서 잘리지 않게 한다. 메뉴 내용·선택·정렬 기능은 유지한다.
- 스키마 · 마이그레이션: 없음.
- API 계약: 비파괴, 변경 없음.

## 시험 결정
- 외부 행위 기준: 네 상태(목록·채워진 연구실·빈 연구실·입력 모달)를 375/768/1440px 및 밝음/어두움에서 총 24장면 검사한다.
- 재사용 seam: 기존 fixture source 및 실제 React 컴포넌트, agent-browser 사용자 조작, 기존 frontend 테스트. 신설 seam: 없음. 사용자는 실제 대표 화면 확인 후 전체 확장하는 시험 흐름을 승인했다.
- 목록 필터가 결과를 바꾸는지, 모달 빈 이름 오류·유형 전환·Escape·포커스 복귀를 실제 조작한다. 샘플 저장 시 서버 저장 성공으로 표현하지 않는다.
- 해당 서비스 단독 게이트: frontend-typecheck, frontend-test, frontend-fixture-reach, frontend-visual.
- 별도 미리보기 진입점은 기본 typecheck 포함 여부를 확인하고 Vite 변환 및 브라우저 런타임 오류 검사를 추가한다.
- green-by-skip 방지: 장면별 DOM·폰트·넘침·대비 및 캡처를 남기고 24건 존재를 확인한다. 기본 시각 게이트가 대표 미리보기를 대상으로 실행됐는지 URL을 기록한다.
