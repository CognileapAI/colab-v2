# Spec: 2026-09-12 bugfix 회차 — 미리보기 상자의 조작 자리

출처 intent: `dev-package/intent/2026-09-12-issue-preview-controls.md` (승인 2026-09-12 · Ted 확인 문장 "좋아 전부권고안으로" · 판정 기록 `dev-package/reports/issues/2026-09-12-ted-decisions.md` ⑤·⑥·⑦·⑩)

## 문제 진술

- 업로드 인라인 미리보기의 지도 자리(`.mapcanvas` · `data-testid="up-preview-map"`)가 64×64 축소본(`data-testid="up-preview-thumb"`)과 본 그림(`data-testid="up-preview-viewport"`)을 함께 그린다. 같은 축소본이 대표 그림 고르개(`data-testid="up-thumb-img"`)에도 실린다(`CognileapAI/colab-v2#26`).
- 파일·변수·시각 고르개(`PreviewPickRow`)가 4:3 틀(`.pv-frame` · `overflow: hidden`) 안쪽 스크롤 영역(`.pv-frame-in` · `overflow: auto` · `justify-content: center`)의 첫 자식이라, 그림이 렌더되면 스크롤 위로 밀려 화면에서 빠진다(`#25` ⑵).
- 같은 스크롤 영역의 마지막 계열 자식인 확대 줄(`.pv-zoom` · `data-testid="up-preview-zoom"`)이 아래로 밀려 스크롤 없이는 보이지 않는다(`#27`).
- 확장보기 본문(`.modal-b.pvx-b`)이 `display:flex` 이고 방향 선언이 없어 기본 `row` 가 적용되며, 그림 폭 상한이 없어 확대 줄이 오른쪽 열에서 눌리고 버튼 글자가 두 줄로 접힌다(`#28`).
- 확장보기에서 기간 라벨·「달력에서 고르기」가 그림 위에 보인다는 보고가 있고 재현 회차 0건이다(`#29` ⑴).

## 해법 개요

- 사용자 관점 행위는 무변 — 파일을 고르고, 그림을 보고, 파일·변수·시각을 바꾸고, 확대·축소한다. 새 화면·새 조작·새 문면을 만들지 않는다.
- 축소본은 사라지지 않는다 — 지도 자리에서 빼고 접히는 자리(`<details className="up-preview-options">` 안 대표 그림 고르개 옆)에서 표시한다. 표시 자체는 유지되므로 결정 `〈88〉` 묶음 3 의 표시 목적이 남는다.
- 고르개 줄은 4:3 틀 **밖** 고정 줄로 올라간다 — 렌더 상태와 무관하게 같은 자리에 서고 틀 안 스크롤에 실리지 않는다. 두 마운트 자리(업로드 인라인 · 데이터셋 상세)가 **같은 부품·같은 이음매 하나**를 쓴다.
- 확대 줄은 자리를 옮기지 않는다 — 접힘·가림만 해소한다. 틀 안 세로 흐름에서 그림 자리가 줄어들고 확대 줄이 줄지 않도록 배분을 정하고, 확장보기 본문은 방향을 세로로 선언하며 그림 폭 상한을 준다.
- 기존 흐름 재사용 = 공용 부품 `PreviewPickRow`·`PreviewZoomControls`·`PreviewSlot` 을 그대로 쓰고 신설 부품 0건. 배치 소유만 이음매 한 곳으로 모은다.

## 사용자 스토리

1. 데이터를 올리는 연구자로서 미리보기 그림이 한 장만 보이기를 원한다, 두 장이 보이면 무엇을 그렸는지 흐려지기 때문에.
2. 데이터를 올리는 연구자로서 대표 그림으로 쓰일 축소본을 접히는 설정 자리에서 확인하기를 원한다, 등록 뒤 목록에 무엇이 실릴지 미리 알기 위해서.
3. 데이터를 올리는 연구자로서 자동 축소본과 내가 고른 그림이 같은 자리에서 갈리기를 원한다, 어느 쪽이 저장될지 한 자리에서 판단하기 위해서.
4. 데이터를 올리는 연구자로서 그림이 다 그려진 뒤에도 파일 고르개가 보이기를 원한다, 조각을 바꿔 다시 그리기 위해서.
5. 데이터를 올리는 연구자로서 변수 고르개가 렌더 전·렌더 중·렌더 후 같은 자리에 있기를 원한다, 상태마다 조작 위치를 다시 찾지 않기 위해서.
6. 데이터를 올리는 연구자로서 시각 고르개가 스크롤 없이 보이기를 원한다, 시점이 여럿인 자료에서 시점을 바로 바꾸기 위해서.
7. 데이터셋 상세를 보는 연구자로서 상세 화면의 고르개가 업로드 화면과 같은 자리에 있기를 원한다, 화면마다 다른 조작을 배우지 않기 위해서.
8. 데이터를 올리는 연구자로서 확대·축소·기본 배율 버튼이 스크롤 없이 보이기를 원한다, 조작 자리를 찾기 위해 상자를 굴리지 않기 위해서.
9. 확장보기를 여는 연구자로서 세 버튼의 글자가 한 줄로 읽히기를 원한다, 두 줄로 접힌 글자를 해독하지 않기 위해서.
10. 확장보기를 여는 연구자로서 그림이 폭을 다 먹고 버튼이 눌리지 않기를 원한다, 큰 화면에서 조작이 좁아지지 않기 위해서.
11. 화면 낭독기를 쓰는 연구자로서 고르개 줄이 그림 앞 순서로 읽히기를 원한다, 조작을 먼저 만나기 위해서.
12. 키보드를 쓰는 연구자로서 고르개 줄과 확대 줄의 초점 순서가 세 화면에서 같기를 원한다, 이동 횟수를 예측하기 위해서.
13. 좁은 창을 쓰는 연구자로서 고르개 줄이 접힐 때 줄바꿈으로만 접히기를 원한다, 가로 스크롤이 생기지 않기 위해서.
14. 다시 그리기를 반복하는 연구자로서 고르개가 렌더 중 잠기되 자리를 지키기를 원한다, 자리가 사라져 상자 치수가 흔들리지 않기 위해서.
15. 데이터셋 상세를 보는 연구자로서 확대 줄의 문면이 업로드·확장보기와 같기를 원한다, 같은 조작을 다른 이름으로 배우지 않기 위해서.
16. 판정자로서 축소본 이동이 종전 결정의 어느 부분을 바꾸고 어느 부분을 유지하는지 기록으로 남기를 원한다, 다음 회차가 같은 논쟁을 다시 열지 않기 위해서.
17. 판정자로서 고르개 줄의 배치 규약 개정이 라운드 문서와 부품 주석 양쪽에 반영되기를 원한다, 코드와 문서가 갈리지 않기 위해서.
18. 다음 회차 담당자로서 확장보기 겹침 보고의 재현 결과가 측정 회차 기록에 남기를 원한다, 그 항목의 등급을 값으로 가르기 위해서.
19. 개발자로서 세 화면의 배치가 이음매 한 곳에서 갈리기를 원한다, 한 화면만 고쳐 공유 규약이 깨지는 일을 막기 위해서.
20. 개발자로서 축소본이 없는 응답에서 자리째 사라지는 현행 동작이 유지되기를 원한다, 빈 상자를 새로 만들지 않기 위해서.

## 구현 결정

### ㉮ 축소본의 자리 (`#26` · 판정 ⑤ ⓑ)

- 모듈 = 업로드 미리보기 화면 부품 1개. 성공 경로에서 지도 자리 안에 놓인 축소본 `<img>` 를 접히는 설정 블록(대표 그림 고르개와 같은 블록)으로 옮긴다. 삭제하지 않는다.
- 조건 무변 — 축소본 주소가 없으면 자리째 없다(현행 조건부 렌더 유지).
- 대표 그림 고르개는 사람이 고른 그림이 있으면 그것을, 없으면 자동 축소본을 이미 표시한다. 옮긴 축소본은 그 옆에 「자동 생성 축소본」으로 병립하며, 고르개의 표시 규칙을 바꾸지 않는다.
- 지도 자리 전용 CSS 규칙(`.mapcanvas .thumb`)은 옮긴 자리의 규칙으로 대체한다 — 치수 64×64 · `object-fit: contain` · `image-rendering: pixelated` 는 그대로 승계한다.
- 범위 밖 = 구제(salvage) 경로의 축소본. 같은 시험 표식을 쓰는 별개 블록이며 이번 회차에서 만지지 않는다.

### ㉯ 고르개 줄의 자리 (`#25` ⑵ · 판정 ⑥ ⓐ)

- 이음매 = **4:3 틀 부품이 「틀 위 고정 줄」 자리를 프로퍼티로 갖는다.** 부품 내부는 그 자리를 `.pv-frame` **바깥**, 같은 컨테이너 안, 틀보다 앞 순서로 렌더한다.
- 두 마운트 자리(업로드 인라인 미리보기 · 데이터셋 상세 미리보기)는 고르개 부품을 틀의 자식에서 그 프로퍼티로 옮긴다. 부품·프로퍼티 값·문면은 무변.
- CSS 이음매 = `preview.css` 의 고르개 줄 규칙 한 곳. 고정 줄 컨테이너 규칙 1건을 같은 파일에 신설하고 화면별 재정의를 만들지 않는다. 여백은 컨테이너(`.mapstage` gap · 상세 컨테이너 gap)가 계속 소유한다.
- 틀 안 치수 규율 유지 — 고르개가 빠져도 틀 자체의 비율·치수는 네 상태에서 불변이다(`PreviewSlot` 무변).
- 확장보기에는 고르개가 마운트돼 있지 않다(실물 대조 = 확장보기 자식은 뷰포트와 확대 줄 둘뿐). 확장보기에 고르개 줄을 신설할지 여부는 「우려 항목 1」의 판정 대상이며, 판정 전에는 신설하지 않는다.

### ㉰ 확대 줄의 접힘·가림 (`#27`·`#28` · 판정 ⑦ ⓐ)

- 배치 소유를 옮기지 않는다 — 확대 줄은 지금과 같이 세로 흐름의 형제로 남는다. 절대 배치·고정 배치·뷰포트 안 이동은 하지 않는다.
- 인라인(`#27`) = 틀 안 세로 흐름에서 그림 자리는 줄어들 수 있고 확대 줄은 줄지 않도록 배분을 선언한다. 고르개 줄이 틀 밖으로 나가 한 줄이 비므로, 배분 선언과 합쳐 기본 상태에서 스크롤이 발생하지 않는다.
- 확장보기(`#28`) = 오버레이 본문에 세로 방향을 선언하고, 그림 폭 상한을 주어 확대 줄이 남은 폭으로 눌리지 않게 한다. 확대 줄 자체에 줄바꿈 금지를 선언해 버튼 글자가 접히지 않게 한다.
- 세 화면이 같은 확대 줄 부품과 같은 `.pv-zoom` 규칙을 계속 공유한다 — 화면별 확대 줄 사본을 만들지 않는다.
- 부모 컨테이너의 방향에 따라 확대 줄이 두 자리로 갈리는 구조 자체는 이번에 고치지 않는다(범위 밖 · 후속 항목).

### ㉱ 기간 입력 겹침 (`#29` ⑴ · 판정 ⑩ ⓐ)

- 이 spec 은 코드를 바꾸지 않는다. 재현은 측정 회차(레인 L4 · 코드 변경 0)에서 수행하고, 기록 항목은 겹침 재현 여부 · 촬영 뷰포트 폭 · 1열 접힘 해당 여부다.
- 실물 소유자는 등록 폼 부품의 문자열 1곳이며 미리보기 부품 소유가 아니다. 수정이 필요하다고 판정되면 등록 폼 레인 뒤 별도 레인으로 연다(같은 파일 공유 · 병렬 금지).

### 스키마 · 마이그레이션

- 0건. Alembic revision 무변.

### API 계약

- 비파괴 · 변경 0건. `contracts/` 무접촉. 동결 해제 서명 불요.
- 근거 = 조사 C 각 5절 축자 「`contracts/` 변경 = 없음. DB 마이그레이션 = 없음. 동결 해제 서명 불요.」

### 종전 판정의 개정 기록 (구현과 같은 회차)

- 결정 `〈88〉` 묶음 3 = **재판정 기록 1건**. 원문 대조 결과 그 항의 축자는 응답 필드 신설에 대한 것이다 — 축자 「①②가 **항상 함께 구워지는데** 성공 응답 자리가 `imageUrl` 하나뿐이라 **렌더가 성공할수록 썸네일이 안 보였다**」. 화면 배치를 지정한 문장은 그 항에 없다 `[추론]`. 개정 대상은 **화면 주석이 그 결정에 붙여 둔 표시 자리**이며, 응답 필드·계약은 무변이다.
- 규약 R-C-2 = **개정 기록 1건**. 대상 축자 둘 — 부품 머리 「WU-C3 ⑵ — 틀 **안**의 컨트롤 줄: 파일 · 변수 · 시각 세 고르개.」 · 라운드 문서 ⑵ 항 「틀 안 컨트롤 줄에 파일·변수·시각 드롭다운 3개」. 두 곳의 문면을 같은 회차에 고친다.
- 원장 = `PLAN-SoT §9` 에 〈N〉 행 1건. 번호는 병합 직전 재실측으로 발급하고 같은 행에 「`〈88〉`-3 화면 표시 자리 재판정 · R-C-2 고르개 줄 배치 개정」을 적는다.

## 시험 결정

- 외부 행위 기준 검증 항목 (전부 red 선행):
  1. 렌더 완료 상태에서 지도 자리(`up-preview-map`) 안의 그림 요소 수 = 1. 현행 2 로 red.
  2. 접히는 설정 블록 안에서 자동 축소본이 조회된다. 현행 미존재로 red.
  3. 축소본 주소가 없는 응답에서 옮긴 자리도 자리째 없다(회귀 · 대상 0건 방지용 대조군).
  4. 업로드 인라인에서 고르개 줄이 4:3 틀(`up-preview-slot`)의 자손이 아니다. 현행 자손이라 red.
  5. 데이터셋 상세에서 고르개 줄이 4:3 틀(`dt-preview-slot`)의 자손이 아니다. 현행 자손이라 red.
  6. 두 화면 모두에서 렌더 전·렌더 후 고르개 줄이 같은 부모의 자식으로 남는다(상태 2종 대조).
  7. 확대 줄이 세 화면 모두에서 같은 부품(같은 클래스·같은 버튼 문면 3종)으로 렌더된다(공유 규약 회귀).
  8. CSS 원문 계측 — 틀 안 세로 배분 선언 존재 · 확대 줄 줄바꿈 금지 선언 존재. 현행 부재로 red.
