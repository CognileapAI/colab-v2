# Stage 2 편의 기능 묶음 — J-1

출처: 대장 `J-1.completion_def`, `sessions/S1-PLAN-REFOUND.md §J`, 사용자 2026-09-10 승인 경계.

## 범위와 원칙

- 이 라운드는 유효 9건 `J-1`~`J-6`, `J-8`~`J-10`을 함께 세운다. `J-7` 자동 무효화는 `Y-1` 소유다.
- `J-10` 폴더 드롭의 구현 소유는 이미 완료된 `F-3`이다. 여기서는 같은 파일 분류·축 판별·3개 이상 거절이라는 수용 증거를 재사용한다.
- 지도 좌표·형상·해시·남은 시간은 화면이나 core-api가 추측하지 않는다. 파일을 읽는 pipeline-worker와 실제 관측 표본이 만든 값만 쓴다.
- Google 로그인과 계정 백오피스는 Stage 1/2에 넣지 않는다. 백오피스 계정 추가는 Stage 3 최우선 `BO-1`이다.
- 로컬 코드·시험·문서는 계속 집행한다. main push, dev/staging 배포, 실제 S3/캐시 삭제, 실제 인프라 apply는 실행 직전 사용자 승인을 받는다.

## 저장 모델

현행 체인 head `0023_upv_image_grid` 다음 `0024_s2_grid_convenience` 한 건으로 아래 자리를 세운다.

- `d5_upload_grid_profile`: 업로드의 본체 형상, 격자 형상·SHA-256·형식 서명, 예상 경계, 지도 상태, 격자 출처를 보관한다. D3 식별자를 참조하지 않는다.
- `d3_dataset_grid_profile`: 등록 전환 뒤 같은 사실을 데이터셋에 승계한다. 근거가 없는 기존 행은 만들지 않아 `아직 모름`으로 남긴다.
- `d3_lab_default_grid`: 연구실당 기본 격자 데이터셋 0~1건. RLS와 dataset FK를 함께 건다.
- `d5_upload_transfer.early_preview_upload_id`: 프리사인드 전송에서 첫 본체로 만든 별도 임시 업로드를 멱등하게 재사용한다.

프로필의 지도 상태는 `지도 있음`, `지도 없음`, `아직 모름` 세 값이다. `지도 있음`은 파이프라인이 실제 좌표로 지도 산출물을 만들 수 있었던 경우, `지도 없음`은 본체는 읽었지만 좌표/격자가 없었던 경우, 나머지는 `아직 모름`이다. 카탈로그와 상세의 판정 근거를 이 한 값으로 맞춘다.

## 사용자 여정

### J-1 · J-2 격자 가져오기와 기본 격자

1. 좌표 없는 본체의 분석이 끝나면 화면이 현재 업로드의 본체 형상과 같은 `d3_dataset_grid_profile.grid_shape`만 후보로 조회한다.
2. 후보는 같은 연구실 RLS 안에서만 보인다. 요청에 다른 연구실 datasetId를 손으로 넣어도 404다.
3. 기본 격자가 후보에 있으면 맨 위에 `연구실 기본 격자`로 제시한다. 사용자가 `가져오기`를 눌러야 복제되며 자동 적용하지 않는다.
4. 서버는 원본 격자 1~2개의 바이트를 새 fileId와 현재 uploadId 키로 정확히 복제하고, 축 배정과 프로필을 승계한 뒤 파이프라인을 다시 연다. 같은 바이트 다이제스트이므로 직접 올린 경우와 지도형 내용 키가 같다.
5. 등록 전환 때 `격자 가져오기` 활동 한 줄을 새 데이터셋에 남긴다. 계보 edge·unknown 상태는 건드리지 않는다.
6. 교수는 격자를 가진 데이터셋 상세에서 `연구실 기본 격자로 지정`할 수 있다. 연구원은 같은 요청을 보내도 403이며 화면에 조작이 없다.

### J-3 · J-4 불일치와 예상 영역

- 직접 올린 격자와 연구실 기준 후보의 형식 서명 또는 SHA-256이 다르면 순수 경고를 보인다. 경고는 등록·미리보기·`맞습니다`를 막지 않는다.
- 거리에는 상수를 넣지 않는다. 두 프로필의 경계 상자 네 꼭짓점 차이와 화소 크기 차이를 쌍마다 계산한 최댓값을 사용한다. 어느 재료든 없으면 `거리 [미상]`이다.
- 파이프라인이 실제 좌표로 만든 COG의 경계 네 값이 있으면 격자 적용 전 `예상 영역`으로 표시한다. 읽지 못하면 `[미상]`이며 좌표를 합성하지 않는다.
- 렌더 완료 뒤 받은 `RenderResult.bounds`는 예상 영역과 같아야 한다. 차이는 시험 red다.
- `R-4` 완화의 근거가 이 경고임을 세션 증거에 남긴다.

### J-5 지도 상태 배지·필터

- 카탈로그 이름 칸에 `지도 없음` 또는 `아직 모름` 배지를 표시한다. `지도 있음`은 별도 경고 배지가 없다.
- 필터 바의 `지도 상태`는 `전체`, `지도 있음`, `지도 없음`, `아직 모름` 네 선택지를 제공한다.
- 서버 필터는 RLS가 적용된 목록 질의 안에서 같은 `d3_dataset_grid_profile.map_state`를 사용한다. 프로필 부재도 `아직 모름`으로 센다.

### J-6 팔레트·구간 수

- 등록 전 미리보기와 데이터셋 상세 모두 `listPalettes` 응답만 선택지로 사용한다. 팔레트 이름을 화면에 하드코딩하지 않는다.
- 데이터셋 상세의 컨트롤은 `업로드·편집` 권한자에게만 존재한다. 팔레트나 3~9 구간 수를 바꾸면 고른 값이 `RenderStyle.palette/classCount`로 새 렌더 요청에 간다.
- 서버 목록 3종 × 구간 수 7종으로 조합은 21개다. 목록이 3종이 아니면 UI가 임의로 자르거나 보충하지 않고 오류로 드러낸다.

### J-8 남은 시간

- 브라우저가 완료된 단계의 실제 소요 시간을 단계명별로 보관하고 중앙값을 계산한다. 평균과 고정 상수는 쓰지 않는다.
- 해당 단계 표본이 하나도 없으면 남은 시간을 자리째 그리지 않는다.
- 전송 중에는 전송 단계 중앙값과 실제 바이트 진행률로 남은 시간을 계산한다. 렌더 단계는 완료한 단계 표본을 다음 요청에만 사용한다.

### J-9 첫 파일 임시 미리보기

- S3 프리사인드 전송에서 첫 본체 파일의 객체 검증이 끝나는 즉시, 서버는 그 파일만 정확히 복제한 별도 임시 D5 업로드를 만들고 `upload.accepted`를 발행한다.
- 전체 전송 원장과 최종 uploadId는 그대로다. 임시 업로드는 등록할 수 없도록 화면이 최종 접수 완료 전 등록 조작을 잠근다.
- 첫 파일 미리보기에는 `먼저 도착한 파일 기준`과 전체 파일 뒤 바뀔 수 있음을 미리 말한다.
- 전체 전송 완료 뒤 최종 uploadId로 갈아타고 같은 미리보기 흐름을 다시 돈다. 수렴 알림은 한 번만 낸다. 경계가 바뀌면 바뀌었다고, 같으면 전체 기준 확인 완료라고 말한다.
- local multipart 폴백은 단일 HTTP 본문이라 첫 파일 완료 사건이 없다. 거짓 조기 완료를 만들지 않고 기존 전량 접수 뒤 흐름을 유지한다.

### J-10 폴더 드롭

- 폴더 드롭은 같은 파일들을 직접 다중 선택한 것과 같은 `PickedFile[]`·`relativePath`를 만든다.
- 위도/경도는 계속 서버가 두 파일을 함께 읽어 판정한다. 화면에 축 질문을 만들지 않는다.
- 격자 후보가 3개 이상이면 서버 계획 단계에서 이유를 포함해 거절한다.
