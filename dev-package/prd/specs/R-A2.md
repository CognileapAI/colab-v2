# Spec: R-A2 — rev2 증분 5 WU (프론트 중심 · 계약 0 · 스키마 0 · 마이그레이션 0)
출처 intent: `dev-package/intent/2026-09-06-r-a2.md` (승인 2026-09-06 · 커밋이 승인)

## 문제 진술

- R-A 14/14 의 완료 범위가 rev2 개정 이전 판정이라, rev2 ＋ 전수 감사가 만든 증분 6건이 코드에 없다.
- 증분 근거 PRD-41~45 가 레포 사본에 0건이었다 — 이 spec 과 함께 사본을 2026-09-06 판본으로 동기했다.
- 증분 6건 중 A6(기간 달력 팝오버)은 R-B `WU-B3` 으로 이관하고, 남은 5 WU 가 이 회차다.

## 해법 개요

- 공통 토스트 컴포넌트를 **먼저** 세우고(A13R), 문면을 쓰는 WU 가 그 하나를 호출한다 — 문면 하드코드 중복 0건이 수용 기준이다.
- 나머지는 기존 흐름 재사용이다 — 확인 모달·연관 영역·상세 편집은 기존 컴포넌트 자리에서 문면·판정 조건·배치만 바뀐다(사용자 관점 동일 행위는 기존 흐름 재사용 · `rules §6-1`).
- 서버 변경은 방어선 2건뿐이다 — 확장자 2종 400(PRD-32) · 같은 연구실 이름 중복 거절(PRD-42).

## 사용자 스토리

1. 올리는 사람으로서 확장자가 섞인 묶음을 놓았을 때 무엇이 빠졌는지 한 줄로 알고 싶다, 목록을 다시 세지 않기 위해.
2. 올리는 사람으로서 파일 분석이 끝나기 전에 `다음` 을 누르지 못하게 하고 싶다, 반쯤 읽힌 파일로 등록을 시작하지 않기 위해.
3. 올리는 사람으로서 미리보기 위에서 커서를 움직이며 위경도를 읽고 싶다, 클릭할 지점을 고르기 전에 범위를 훑기 위해.
4. 올리는 사람으로서 연관 프로젝트와 논문을 한 표에서 보고 싶다, 빈 패널 두 개가 화면을 먹지 않게 하기 위해.
5. 올리는 사람으로서 같은 이름의 프로젝트를 두 번 만들지 않게 막히고 싶다, 나중에 목록에서 고를 때 헷갈리지 않기 위해.
6. 올리는 사람으로서 닫을 때 무엇이 사라지는지(계보 몇 건인지) 듣고 싶다, 실수로 닫지 않기 위해.
7. 올리는 사람으로서 아무것도 안 적었으면 되묻지 않고 닫히기를 원한다, 빈 모달에 확인을 두 번 하지 않기 위해.
8. 고치는 사람으로서 편집 중에는 다운로드가 아니라 `취소`/`저장` 이 그 자리에 오기를 원한다, 편집 상태를 화면이 말해 주기 위해.
9. 고치는 사람으로서 저장 뒤 헤더 칩과 공개 범위 설명이 같은 값으로 다시 그려지기를 원한다, 새로고침 없이 결과를 보기 위해.
10. 올리는 사람으로서 좌표계 칸이 선택 항목임을 라벨에서 알고 싶다, 다른 선택 칸과 같은 규칙으로 읽기 위해.

- 모듈 · 인터페이스

  - `core-api` — 업로드 조각 확장자 2종 이상 400 · 프로젝트 생성 시 연구실 경계 안 이름 중복 거절. 도메인은 D3(Catalog) · D6(Project) 자기 테이블 범위다.
  - HUD 는 `mousemove` 핸들러 1개 ＋ 역산 함수 2개(`pvLatOf` / `pvLonOf`) ＋ 문면 2종(`커서를 지도 위로` · `지도 밖`). **서버 왕복 0.**
- 스키마 · 마이그레이션: **0.** Alembic revision 체인 무접촉(`0013` 이 head 그대로).
- API 계약: **비파괴 · 변경 0.** `contracts/` 를 열지 않는다 — 계약 동결 해제 회차를 쓰지 않는다.
- 유형 배지는 저장값 `kind` 에서 읽는다. 이름 문자열 정규식 판정을 쓰지 않는다.
- 종료 확인 판정 대상 = ①②③ 사람 입력 필드 전부 ＋ 확정 계보 부모 건수 ＋ **담은 프로젝트 건수** ＋ **대표 그림 교체 여부**. 자동 채움값(확장자·용량·`Lv2`·`연구실 구성원 전체`)은 세지 않는다.
