출처: `stage1-stage2-closeout.md`, `sessions/20260910-stage12-decisions.md` Q4/Q5/Q7.

## 범위

- core-viz의 실제 경계 호출 5건(createRender/getRender/createScreenshot/lookupValue/describeTarget)에 연구실 헤더를 선언하고 경계 부재 400을 계약에 반영한다.
- ScreenshotRequest.layers는 1~8건이다. 빈 목록/9건은 거절하며 이미 구현된 런타임 상한을 바꾸지 않는다.
- 서비스 토큰 인증, 서명된 타일 조회, 연구실과 무관한 팔레트 목록은 기존 경계를 유지한다.
- 현행 로그인 제한은 그대로 두며 CI 준비 로직은 현재 구현과 실패 픽스처로 대조한다.
- 실제 전달 IP/여섯 번째 실패 429, 배포 SHA/healthy, 회수 관측은 실행 직전 승인 후 검증한다.

## 확인이 필요한 경계

서버 동작까지 승인안에 맞춘다. 빈값·공백도 누락과 같으며 연구실 소유 판정은 유지한다.
아래는 확인 전 이력이다.

Q4 승인 기록과 원 계약 델타 초안은 연구실·계정 헤더를 모두 필수로 적었다.
그러나 `colab_viz/app/deps.py::tenant_scope`는 연구실만 필수이며 계정 누락은 허용한다.
계약 가산 승인 당시의 '이미 그렇게 동작한다' 전제가 실물과 다르다.
계정 누락까지 HTTP 400으로 바꾸는 동작 변경은 당시 확인 전 집행하지 않았다.
연구실 헤더와 스크린샷 상한은 이 모순과 독립적으로 구현·시험한다.
