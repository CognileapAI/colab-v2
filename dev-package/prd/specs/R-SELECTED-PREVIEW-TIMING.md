# Spec: 선택 미리보기와 개별 시간 측정
출처 intent: `dev-package/intent/2026-09-16-selected-preview-timing.md` (승인 2026-09-16)
## 문제 진술
- mount·선택 변경이 전체 본체 렌더를 만든다. 413 폴백은 사용자가 고르지 않은 첫 파일로 대상을 바꾼다.
- 비동기 POST의 응답 시간은 작업 시간과 다르고, 브라우저 polling 간격도 섞여 있다.
## 해법 개요
- 기존 파일·변수·시각 선택 줄과 ‘보기’ 버튼을 사용한다. 선택 초안과 현재 결과를 구분한다.
- 목록 조회 후 선택 파일의 후보만 기존 describe API(fileIds)로 조회한다. 후보 준비 전 실행하지 않는다.
- 보기 한 번에 `fileIds:[선택ID]`와 유효한 변수·시각만 전송. 413으로 다른 파일을 대신 그리지 않는다.
- 진행 중 선택/버튼을 잠그고 성공·실패 종료 뒤 해제한다. 이전 응답으로 새 선택의 결과를 덮지 않는다.
- 서버 queue/worker 시간을 monotonic으로 측정하고 기존 로그에 남긴다. 브라우저는 클릭부터 실제 이미지 decode/표시까지 독립 측정한다.
## 사용자 스토리
1. 계보·정보만 조회할 때 렌더 작업을 만들지 않고 싶다.
2. 고른 파일·변수·시점만 보고 요청과 결과를 구별하고 싶다.
3. 실행 중 중복 요청 없이 종료 후 새 선택을 보고 싶다.
4. 요청별 대기·처리·화면 관측 시간을 구분해 느린 원인을 확인하고 싶다.
5. 검사도 한 건씩 실행하고 미측정을 성공으로 집계하지 않기를 원한다.
## 구현 결정
- 기존 PreviewPickRow, DatasetPreviewSource, 렌더 폴링/이미지 구성 재사용. 업로드 정책은 유지한다.
- describe는 기존 fileIds 지원으로 선택 파일에 한정한다. 후보가 없는 변수·시각은 생략하며 지어내지 않는다.
- API/DB 변경 없음. 기존 관측커널로 event `render.timing`: `render_id,target_id,file_ids,variable,instant,queue_ms,processing_ms,status,failure_code` 기록. 인증값·서명URL·원본 경로 제외.
- 다른 프로세스의 monotonic 값을 빼지 않는다. 복원 작업의 이전 큐 대기는 unknown으로 표시하고0으로 대체하지 않는다.
- 화면 총 시간은 서버 처리 시간이 아니라 network/poll/decode를 포함한 사용자 체감 관측값이다. 새 요청 시 초기화한다.
- 같은 상세 화면에서 한 요청만 진행한다. 화면 이동은 취소가 아니며 제출된 서버 작업은 종료까지 실행될 수 있다. 새 화면 자동 실행은 없앤다.
- 통신 오류는 서버 terminal이 아니다. renderId 확보 후 조회 실패는 같은 작업 조회만 재개하며 새 create를 막는다. create 응답 유실로 ID를 모르면 ‘결과 불명’을 표시하고 자동/즉시 재생성을 막는다. 이 상태를 성공·실패 완료로 꾸미지 않는다.
- 이미지 경로는 실제 decode 완료, 타일 경로는 최초 화면에 필요한 타일들의 로드/decode 완료를 표시 완료로 삼는다. 실패/미측정 시간은 성공 표시 시간과 구분하며 이전 성공값을 재사용하지 않는다.
- 계보 검사에서는 렌더를 만들지 않는다. 미리보기 검사는 파일을 명시 선택·보기 후 terminal/decode를 판정한다. timeout 뒤 다음 요청을 쌓지 않는다.
## 시험 결정
- mount/선택변경 POST0; 보기1회→정확한 단일file payload1회; 진행중 중복0; 후보갱신·오래된값제거; 다른file폴백0; decode전 완료시간 확정0.
- 서버 manual/thread 큐 대기·처리 독립 측정, 실패시간, 복원unknown, job별 로그와 선택대상 일치.
- 네트워크 실패와 서버 실패 구분, 같은job조회재개, create응답유실시 중복생성0, 이미지/타일의 실제 표시완료 및 실패·미측정 시계 시험.
- 도구 명시적 실행/순차대기, 미지원/실패/미측정 구분.
- 기존 frontend source 주입·DOM 시험, viz JobStore 시험, runner helper 시험 재사용. 로컬 브라우저에서 실제 클릭·요청·표시 확인.
- 게이트: frontend-test, frontend-typecheck, service-tests-viz-render, product-reseed-selftest. 타일 높이의 최소 CSS 수정에 따라 CSS 정적 검사와 frontend-visual도 실행한다.
- green-by-skip: 시험 수/실패/준비 실패를 기록한다. 빈 측정·실패를 성공 표본으로 쓰지 않는다.
