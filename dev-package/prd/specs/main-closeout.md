2026-09-10 원격 `main`은 `09e2b9b2db1ae7cd32619f9d52cbf56375a4faf8`이고 최신 CI 실행은 성공했다. 그러나 현재 로컬 체크아웃은 원격보다 28커밋 뒤이며 추적 변경 57개와 미추적 항목 59개가 있어, 이 체크아웃을 병합·배포·대장 수정의 기준으로 사용할 수 없다.

1. 깨끗한 `origin/main` 기반 작업 사본에서 모든 판정을 수행한다.
2. `X-7`과 `WU-PREVIEW`를 최신 실물로 재측정하고, 대장 상태를 근거와 함께 바로잡는다.
3. dev 실행 SHA와 최신 `main`의 차이를 확정하고, 최신 두 업로드 진행 표시 수정을 배포할지 한 번의 go/no-go로 판정한다.
4. 배포를 승인받아 실행한 경우 staging 리허설과 dev 배포를 분리하고, dev에서 `deploy_doctor` 15/15 한 번의 실행과 실제 업로드 여정을 확인한다.
5. 대장에 남은 현재 단계 항목을 의존 순서로 다시 계산해 다음 두 독립 라운드 후보를 확정한다.
   - 배포·운영 준비: `IS4` → `I3` → `I4`
   - 미리보기 회수: `BF-12` → `TL-2`
6. stage 1·2의 완료 138건은 기능 묶음과 항목 집합으로 보존하고, 미완 20건은 재검증·승인·실제 개발·차단으로 나눈 최신 현황 지도를 남긴다.

## 판정 규칙

- 최신 `main` 전체 CI의 성공만으로 특정 서비스 시험 성공을 대신하지 않는다. 해당 job이 skip이면 로컬 단독 게이트를 실행한다.
- 기존 미추적 세션 기록은 참고 자료다. 경로·해시·원격 상태를 재확인해야 대장 근거로 채택한다.
- 배포 원천은 `origin/main`의 조상인 SHA만 허용한다.
- staging은 리허설이고 완료 판정처가 아니다. 완료 판정은 dev의 `deploy_doctor` 15/15 한 번의 실행이다.
- 배포는 별도의 사용자 GO 뒤에만 실행한다. 삭제는 이 사양이 승인하지 않는다.
- 검사 결과는 green, 판정 실패, 준비 실패의 세 계수를 유지한다. skip과 준비 실패를 green으로 합치지 않는다.
