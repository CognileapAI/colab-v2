## 1. 목표와 변경 경계

정상 경로뿐 아니라 통신 실패·지연 응답·여러 탭·만료·동시 요청에서도 로그인 주체와 저장 상태를 명확히 한다.

실패 제한은 기존 승인값(자격/클라이언트 각각5회/15분, 성공 초기화, 프로세스 메모리)을 유지한다. 분산 제한·모든 기기 로그아웃·비밀번호 찾기/재설정 신규 UI는 이번 범위가 아니다.

## 3. 서버 세션 모델

### 3.1 독립 세션과 만료

platform 체인에 `0026_login_sessions.py`를 추가한다(실행 전 최신 head 충돌 확인). 기존 계정 원장과 분리된 `account_admin.login_session`에 다음을 저장한다.

- `id ulid PRIMARY KEY`: 로그인 성공마다 새 session_id. 같은 브라우저의 탭은 이를 공유하며 다른 기기는 별개다.
- `account_id ulid NOT NULL REFERENCES d1_account(id)`, `lab_id ulid NOT NULL REFERENCES d1_lab(id)`.
- `issued_at timestamptz NOT NULL`, `expires_at timestamptz NOT NULL CHECK(expires_at > issued_at)`.
- `revoked_at timestamptz NULL`, `generation integer NOT NULL DEFAULT 1 CHECK(generation > 0)`.
- `revoke_digest text NOT NULL UNIQUE`: 무작위32바이트 종료 전용 자격의 SHA-256. 원문은 DB에 저장하지 않는다.
- INDEX(account_id), INDEX(expires_at). PUBLIC/일반 앱 롤 접근 금지, 제한된 인증 전용 연결로만 조회/삽입/갱신한다. 백업 역할의 새 표 읽기도 실제 검증한다.

현재 인증 전용 접속 역할을 재사용하되 해당 표의 SELECT/INSERT/UPDATE만 더한다. 운영자 등록부의 쓰기 권한은 늘리지 않는다. 만료 행 삭제 잡 신설은 별도이며 이번 배포에서 기존 데이터를 삭제하지 않는다.

새 서명 포맷 `ss1`의 payload는 sid/sub/lab/exp/generation, credential_kind(database|planted-code|legacy-file), purpose(normal|password-change)를 담는다. DB 자격은 credential_version이 필수이며 매 요청 현재 자격 version 및 must_change_password와 대조하고 제한 상태를 Subject에 전달한다. 다른 자격 종류로 위장해 DB 검증을 생략하지 못하도록 발급 시 종류와 제한 상태를 서버 session 행에도 저장·대조한다. MAC domain을 기존 v1/db1과 분리한다.
세션 Bearer로 인증하는 모든 보호 요청은 서명·만료와 DB session 행의 주체/연구실/만료/generation/revoked_at를 대조한다. DB 장애는503이며 legacy 인증으로 폴백하지 않는다. 이름·연구실 권한·운영자 권한은 DB에서 판정한다.
최초 로그인 시 expires_at=issued_at+12시간으로 고정한다. /me 조회·탭 전파·첫 비밀번호 변경은 연장하지 않는다.
첫 변경은 session 행과 credential 행을 일관된 순서로 잠그고 상태/version/만료를 재확인한 뒤 credential 갱신과 session generation 증가를 한 트랜잭션에 수행한다. 반환 자격은 잠금 중 읽은 값과 UPDATE RETURNING으로 구성하여 commit 뒤 find 재조회가 필요 없게 한다.

### 3.2 발급과 종료 API

- POST `/sessions`: 기존 로그인 두 형태를 엄격히 검증한 뒤 새 session을 생성한다. 응답 `token`, `expiresAt`, `sessionId`, `revocationToken`. `Cache-Control: no-store`. 인증 실패 응답에서 계정 존재를 구분하지 않는다.
- PUT `/me/password`: `newPassword`만 받는다. 응답 token/expiresAt/sessionId는 같은 session과 원래 만료를 유지한다. 기존 종료 자격은 계속 유효하다. 최초 변경 이외 사용403, 기존토큰재사용401, 초기암호재사용400.
- DELETE `/sessions/current`: 유효 현재 세션만 idempotent 종료하고204. 계정 전체 version을 증가시켜 다른 기기를 로그아웃시키지 않는다.
- POST `/sessions/revoke`: `{revocationToken}`만 받는 종료 전용 경로. 공개 인증 형식이나 capability 기반이며 조회/로그인/계정선택 권한이 없다. 32바이트 난수의 digest로 정확히 한 session만 종료한다. 이미 종료·만료·없는 값은 동일204, 잘못된 형태400, DB 장애503. 서버 오류 시 완료로 응답하지 않는다. 응답/로그/no-store 기준은 로그인과 같다.
- 종료 전용 자격은 URL·query·일반 Authorization에 넣지 않는다. request body 원문 로깅 금지. 기존 클라이언트 실패 제한을 재사용할 때 로그인 계정 버킷을 오염시키지 않는 별도 namespace를 쓴다.

### 3.3 기존 인증과 전환

파일 비밀번호 및 접속 코드의 로그인 입력 호환은 유지하되 발급되는 결과는 모두 서버 등록 ss1 세션이다.
사용자용 보호 API에서 기존 v1/db1 및 심어 둔 정적 토큰의 직접 bearer 접근을 계속 허용하면 로그아웃 정책을 우회하므로 전환 이후 거절한다. 실제 서비스 간 인증은 별도 서비스 자격 경로를 목록화해 유지한다. 시험 전용 주체 표를 운영 사용자 경로의 예외로 남기지 않는다.
기존 다운로드 티켓/서명 URL은 별도 10분 자격이며 이미 발급된 URL과 진행 중 다운로드까지 회수하는 것은 이번 범위가 아니다. 회수된 세션의 신규 티켓 발급은 거절한다.
기존 세션은 전환 시 한 번 재로그인이 필요하다. 화면은 토큰 형식을 근거 없이 성공으로 취급하지 않는다. stage의 사용자 비밀번호나 계정 행을 바꾸지 않는다.

## 4. 브라우저 세션과 오프라인 종료

`store.ts`의 문자열 token만 저장하는 구조를 버전이 있는 세션 상태로 옮긴다. 같은 origin의 탭은 storage 이벤트와 BroadcastChannel을 통해 상태 변경을 알리고, 최종 읽기는 공유 저장소를 기준으로 한다.
활성 상태는 token/sessionId/expiresAt/종료 전용 자격을 가진다. 토큰/자격이 로그·오류·분석 이벤트로 나가지 않게 한다.
모든 계정 전환은 단일 조정기를 통한다. Web Locks로 원자적으로 직렬화하고 각 탭의 작업 상태 확인 응답을 받은 뒤 적용한다. API 미지원이나 탭 응답 불명확 시 전환을 허용했다고 추정하지 않고 안내 후 막는다.
토큰 교체 순간 기존 account 렌더를 차단한다. /me 응답은 시작한 token+generation과 연결하고 현재 상태가 달라졌으면 버린다.
401 및 logout 완료는 해당 요청의 session/token과 현재값이 같을 때만 활성 상태를 제거한다. 이전 응답은 새 로그인을 끊지 않는다.

명시적 로그아웃 요청 시 미저장·진행 중 작업이 있으면 ‘돌아가기 / 작업 버리고 로그아웃’을 표시한다. 돌아가기는 세션과 작업을 유지한다. 로그아웃을 확정하면 모든 탭의 초안을 폐기하고 로컬 전송을 중단한다. 서버에 이미 접수된 작업의 취소를 보장하지는 않는다. 종료 전용 자격과 원래 expiresAt를 종료 큐에 넣은 다음 활성 token·account를 모든 탭에서 즉시 제거한다. 온라인이면 바로 종료 요청을 보내고, 실패하면 ‘이 기기에서는 로그아웃했지만 서버 종료를 확인하지 못했어요’ 상태를 남긴다.
종료 큐는 접근용 token 없이 revocationToken/sessionId/expiresAt만 보관한다. 새 로그인과 분리하며 새 세션으로 덮어쓰지 않는다. 앱 시작·online 이벤트·열려 있는 동안 지수 backoff(1초→최대60초, 중복 실행 방지)로 재시도한다.
204이면 큐 항목 제거,503/네트워크 실패는 유지,400은 자동 반복을 멈추고 오류 안내. 원래 expiresAt가 지나면 서버의 고정 만료에 따라 접근이 끝났다고 구분하며 ‘종료 응답 확인’으로 꾸미지 않는다.
저장소 쓰기 실패 시에도 메모리의 접근 토큰을 제거하고, 큐를 보존하지 못해 창을 닫으면 자동 재시도가 불가능하다는 안내를 한다. 서버 종료가 확인되지 않았다는 사실을 숨기지 않는다.

## 5. 작업 중 계정 전환과 만료 복구

각 탭에 `workGuard`를 두고 미저장 작성 내용·진행 중 제출·선택된 업로드 파일·업로드 전송을 등록한다. 사용자 입력이 없는 초기 상태는 dirty가 아니다. 성공 저장·명시 취소로 해제한다.
만료 후 같은 계정의 재인증은 미저장 초안이 있어도 허용한다. 이는 다른 계정으로의 전환과 구분한다. 다른 계정으로 로그인하려면 기존 작업을 명시적으로 폐기해야 하며, 폐기 전에는 이전 초안을 유지하고 다른 계정의 화면을 열지 않는다.
계정 전환 요청은 모든 열린 탭의 safe 응답을 기다린다. dirty/진행 중/응답 불명은 차단하며 어느 탭의 작업을 마치거나 취소해야 하는지 표시한다. 하트비트 유실만으로 다른 탭의 작업을 완료 처리하지 않는다.
12시간 만료는 작업이 있어도 연장하지 않는다. 화면을 인증 대기 상태로 가리고 새 쓰기 요청을 막는다. 현재 탭의 `draftVault`에 accountId+화면+폼 키로 비밀이 아닌 초안과 필요한 File 참조를 메모리에 보관한다.
비밀번호·초기 비밀번호·접속 코드·세션 토큰은 초안 보관 대상이 아니다. 다른 계정 로그인에는 복원하지 않는다. 탭 종료·새로고침 후 영구 복구를 약속하지 않는다.
업로드가 서버에 접수됐으면 uploadId만 추적하여 같은 계정 재로그인 후 조회한다. 사용자 확인 없이 자동 재업로드·자동 제출하지 않는다. 만료 전에 이미 인증되어 처리 중인 서버 요청은 완료될 수 있으므로 성공/취소를 추정하지 않는다.
보호 대상은 계정 발급, 프로젝트 생성·수정, 데이터셋 메타 수정, 연구실 정보, 구성원 권한, 업로드·등록, 파일 추가·교체, 대표 그림, 계보 편집, 접근요청 거절·검증취소 사유다. 실행 계획은 이 범위를 실제 파일에 연결한다. 구현 시 `onSubmit`, `FormData`, mutation 호출 전체 검색으로 빠진 쓰기 표면을 확인하고 미포함 폼을 남긴 채 ‘모든 작성 보호’라고 완료 보고하지 않는다.

| LH-6 | accountName+password 또는 accessCode 단독. 다른 방식의 비어 있지 않은 필드가 하나라도 섞이면400. 기존5회/15분 두 버킷 유지. |

## 7. 검증과 운영 완료 정의

단위/통합/실브라우저를 구분한다. 기존 전체회귀 green만으로 신규 요구를 통과 처리하지 않는다.
실제 두 브라우저 문맥·두 탭, 시간 경계, 지연/응답 유실, 재시작·DB 장애를 격리 환경에서 시험한다. 시험 환경의 시간을 바꾸며 stage 시스템 시간은 변경하지 않는다.
서버 저장소 장애 시 인증503·로그아웃미확인, 만료토큰401·일반사용자권한403, 동일계정동시변경 성공1/version증가1을 구분한다.
새 migration은 platform 체인만 추가하며 schema/드리프트/RLS allowlist·실효 권한·백업 복원 증거가 필요하다.
stage 외 배포·실제 사용자 비밀번호 변경·데이터 삭제·커밋/push는 이번 문서가 승인하지 않는다.
되돌리기는 새 session 조회·회수·ss1 검증을 유지하는 호환 이미지로만 한다. 예전 무상태 이미지로 돌아가 종료된 세션을 되살리는 경로는 금지한다. 호환 되돌림 이미지와 격리 리허설이 없으면 전환을 시작하지 않는다.

## 8. 후속 검토에서 확정한 사용자 동작

승인 근거: 세 질문과 권고안에 사용자 “좋아 그렇게해”. 기존 intent의 8개 정책을 다음과 같이 구체화한다.

| 상황 | 확정 동작 | 수용 시험 |
|---|---|---|
| 작성 중 직접 로그아웃 | ‘돌아가기 / 작업 버리고 로그아웃’. 확정 시 모든 탭의 초안 폐기와 즉시 로그아웃 | 돌아가기는 초안·세션 유지, 확정은 모든 탭 접근 제거·초안 제거. 오프라인도 같은 로컬 결과이며 서버 종료 미확인 안내 |
| 만료 후 재로그인 | 같은 계정은 초안이 있어도 재인증·복구 허용. 다른 계정은 기존 작업의 명시적 폐기 후 허용 | 같은 계정 복구가 작업 보호에 막히지 않음. 다른 계정 선택만으로 초안 폐기·노출 없음. 폐기 확정 뒤 다른 계정 표시 |
| 비밀번호 변경 결과 불명 | 새 비밀번호로 먼저 재로그인 안내. 인증 거절 시 기존 초기 비밀번호로 직접 시도 안내. 기존 값이 통하면 최초 변경 화면 | 자동 로그인·자동 변경 재전송0. 변경이 commit된 경우 새 값 성공, commit되지 않은 경우 기존 값 성공 후 변경 화면. 연결 실패·429는 암호 거절로 오인하지 않음 |

위 동작은 확정 사양이다. 실행 계획은 이 spec을 기준으로 다시 대조한 뒤 확정하며, 이번 승인으로 구현·검증이 완료됐다고 표시하지 않는다.
