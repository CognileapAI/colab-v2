## 범위와 완료 기준

- 제품 범위·상태의 정본은 `dev-package/work-items.yaml`이다. stage 3·보류 항목을 임의로 이번 릴리즈에 넣지 않는다.
- 미완료 stage 1/2를 실제 코드·최근 검증과 대조해 구현, 검증 대기, 결정 대기로 나눈다.
- 최신 main CI 실패를 재현하고 준비 결손을 해결한다. 검사 범위를 줄여 통과시키지 않는다.
- 모델 eval은 사용자 요청대로 로컬 실행을 기본으로 한다. CI의 명시 면제 모드에 API 키를 요구하지 않는다. 모델 미실행은 결과에 남긴다.
- agent-browser로 격리된 사용자 여정을 실행한다. 스크린샷·도구 기동을 E2E 통과로 세지 않는다.
- 제품 최종 완료는 기존 정의인 dev 배포 green과 deploy_doctor 15/15 단일 실행이다. 배포 전 코드·검증 결과를 검토 가능한 상태로 만든다.
- 운영 데이터 변경, 기존 미커밋 작업 덮어쓰기, trust 우회는 범위 밖이다.
