# 클라이언트 요구 기반 검색 재설계

2026-09-13 · 사용자 직접 요청으로 실행 · codex/ai-search-next

## 목표와 경계

실무자의 일곱 검색 의도를 핵심 골든셋으로 고정한다. 기존 참조 데이터 골든셋은 회귀 검사로 유지한다.
문장 답안을 암기하는 검색 대신, 유형이 있는 온톨로지 조건 → 현재 접근 가능한 근거 → 조건 판정 → 답변으로 재구성한다.
기존 변경 원장·일일 갱신·파일 버전·온톨로지 버전 구조를 유지한다. 제품 DB 삭제/이관, 배포, main 통합은 이번 실행에 포함하지 않는다.
실제 Sonnet 호출 평가는 기존 보류 상태다. 결정적 API 검사는 모델 평가와 구분한다.

## 원문 해석 결정

- 사용자 확인: 질문의 서울 강수량·공간자료를 우선한다. CSV와 NPY는 단순 저장 포맷이며 동일 공간자료를 표현할 수 있다. `.npy`는 괄호 안 예시이므로 필수 포맷 조건이 아니다. 명시적으로 형식을 제한한 질문에서만 포맷을 걸러낸다.
- 지표면 온도와 기온은 다른 관측량이다. 월평균 최고/최저기온을 LST와 자동 동치로 만들지 않는다.
- NPY는 배열 저장 형식이다. 공간자료 여부는 별도 검토된 표현 유형으로 확인한다.
- 예시의 5건·2건·1종, 제품 이름, 날짜는 실제 보유 현황이 아니다. 테스트 픽스처의 현재 행에서 산출한다.
- 어제 받은 자료는 열람 자료와 다르다. 현재 다운로드 이력은 티켓 발급 기록이므로 완료를 주장하지 않는다.
- 작년/이번 달/어제는 서버 기준 Asia/Seoul 달력으로 해석한다. 관측 기간과 업로드 시점을 구분한다.
- 플랫폼에 등록되고 현재 주체에게 허용된 범위만 검색한다. 전 세계 위성 제품 전수 조사를 주장하지 않는다.

## 구조와 인터페이스

`contracts/search/semantics.json`을 변수·지역·통계 유형의 정본으로 삼아 두 서비스의 동일 상수를 생성한다.
AI 온톨로지 manifest에 의미 규칙 해시를 포함하여 일일 변경 감지와 연결한다. 기존 D9 개념 사전은 후보 확장 역할을 유지한다.
Core의 typed plan은 의도·강제 조건·정렬·질문할 항목을 보유한다. DB는 후보 메타와 현행 검토 근거만 읽고 파일 본문을 읽지 않는다.
서로 다른 파일의 속성을 합쳐 거짓 적합 판정을 만들지 않는다. 확정/불일치/미확인을 구분하고 추천은 명시한 연구 조건에 한정한다.
기존 `/dataset-searches`에 선택적 연구/참조 문맥과 조건 판정 응답을 추가한다. 일반 검색은 기존 동작을 유지한다.
프런트엔드는 추가 질문·검색 범위·비교 근거를 보여준다. 다운로드나 미리보기는 사용자가 선택한다.
