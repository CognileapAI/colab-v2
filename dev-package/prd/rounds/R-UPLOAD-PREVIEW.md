- 산출 예정: `dev-package/reports/upload-layout-preview/policy-map.md`, `screens/`.
- 비교 상태: 빈 파일 선택, 단일/다중 파일 분석, 등록 분류/메타데이터/연결, 필수 오류, 닫기 확인, 미리보기 생성/완료/실패, 확장, 상세, 상세 편집, 계보 수정/기록 없음.

## 2. 포맷·진행 재현
- 산출 예정: `dev-package/reports/upload-layout-preview/format-matrix.md`, `progress-cases.md`.
- 파일은 기존 데이터 참조와 테스트 자산에서 찾는다. 실사용 파일이 없으면 합성 fixture와 구분해 기록하며 합성만으로 실사용 검증을 대체하지 않는다.
- 최소 분류: NetCDF 계열, GeoTIFF/tiff, HDF 계열(내부 구조 구분), BIN(배열·좌표 구조 구분). 현재 추가 등록 포맷과 GRIB 제외 경로도 조사한다.
- 표 열: 파일 식별·해시, 확장자, 실제 구조, 좌표/결측, 크기·조각 수, 분석, 렌더, 이미지 표시, 확장, 상세 재조회, 결과·근거.
- 재현 후보 A: `frontend/src/components/upload/UploadModal.tsx`의 상태 조회 catch — 일반 통신 오류 후 안내·재조회 여부.
- 재현 후보 B: `frontend/src/components/upload/PreviewPanel.tsx`의 poll catch — 오류 이후 drawing 잔존·spinner·입력 비활성 여부.
- 비교 대상: `frontend/src/components/preview/usePreviewRender.ts`의 상세/별도 뷰어 오류 복구.
- 실제 지연을 전송/분석/렌더/이미지 로딩에 각각 주고 상태가 사용자에게 보이는지 확인한다. 영구 실패·권한·삭제·부분 실패는 따로 검증한다.

## 3~4. 구현 경계
- 화면 후보: `frontend/src/components/upload/UploadModal.tsx`, `FileDropCard.tsx`, `RegisterArea.tsx`, `PreviewPanel.tsx`, `PreviewExpandOverlay.tsx`, `upload.css`; 상세·계보·공통 미리보기는 대응표에서 실제 소유 파일을 확정한다.

- 기존 백오프·전송 재개·오래된 응답 차단을 재사용하고, 오류 상태와 진행 상태의 상호 배타성을 검증한다.
- 필요한 의미 있는 재현 시험을 먼저 마련한다. CSS 수치 자체를 복제하는 시험을 만들지 않는다.
- 기능 삭제, 권한 변화, 계약 확장 필요가 드러나면 구체적인 대안까지 만든 뒤 해당 변경만 판정 대상으로 남긴다. 독립 작업은 계속한다.

## 5~6. 최종 검증
- 한 파일의 그림 성공을 다른 포맷 성공으로 확대하지 않는다. 화면 비교는 같은 상태로 수행한다.
- 실제 등록 → 새로고침/재접속 → 편집 → 계보 연결·수정 → 노드 이동 → 원본 다운로드를 잇는다.
- 파일 묶음은 개수·내용 해시를 대조한다. 미리보기에서 일부 조각을 사용하면 사용자 안내와 실제 대상이 일치해야 한다.
- 사용자 입력을 보존한 재시도, 취소 후 늦은 응답 무시, 전송 100% 이후 분석 안내, 이미지 로딩 실패를 확인한다.
- 변경 범위에 맞는 frontend·core-api·pipeline-worker·viz-render 게이트를 실행하고 결과를 남긴다. 환경 준비 실패는 통과가 아니다.
- 산출 예정: `dev-package/reports/upload-layout-preview/verification.md`에 실행 환경·소스 기점·시험/미실행/실패·시각 비교·잔여 항목·배포 준비 여부를 기록한다.

## 격리·변경 관리
- 이 라운드는 사용자 전용 별도 작업 사본의 `codex/upload-layout-preview-plan`에서 시작한다. 공유 루트·다른 세션의 대장·DB·서버·배포 환경을 변경하지 않는다.
- 작업대장 등록은 기존 항목과 중복을 확인하고 현재 사본에서만 수행한다. 다른 세션과 합칠 때 상태 기록의 충돌도 검토한다.
- 기본 직렬 한 레인, 동일 사본 쓰기 주체 하나. 독립 조사 에이전트는 읽기 전용으로 활용한다.
- 브랜치 push·병합·배포 완료를 이번 계획 작성과 혼동하지 않는다.
