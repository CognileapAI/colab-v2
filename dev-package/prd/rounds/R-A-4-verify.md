### §B-2 · WU-A14 · 조각 수 표기 (PRD-38) — 크기 S · 레인 `p3-part-count` · **의존 WU-A12**

- **원천**: `P-5` 축자 「목업의 예시 업로드는 데이터 파일 1개인데 등록후에는 데이터 조각 4개라고 표현되고 있습니다.」
- **판정 정정 (PRD 축자)**: 종전 PRD 는 이 항목을 부록 A 「이미 적용됨」으로 닫고 근거를 `file_count` 트리거·`files.count minimum 1`·`test_file_count_drift.py` 로 들었다. **그 근거는 저장값의 정합이고, pdf 의 지적은 화면 표기다.** ⟹ 부록 A 에서 「표기는 미적용」으로 갈라 이 요구로 옮겼다.
- **현재 코드**: 상세 레코드 줄이 `파일 조각 {n}개` 를 보인다. **실측 1건 — 상세 픽스처는 이미 응답값을 쓴다**: `frontend/src/components/detail/fixture.ts:78` `files: { count: row.fileCount, … }`(하드코드가 아니다). 남은 확인은 **목록 카드와 상세 렌더가 그 값을 그대로 읽는지 한 곳**뿐이다.
- ⚠ **결과가 「없음 → 0 작업」일 수 있다.** 실측에서 하드코드가 **0건**이면 **고칠 것이 없고 작업량은 0 이다** — 그 사실과 근거 `path:line` 을 판정으로 남기고 **회귀 시험 1건만 붙이고 닫는다.** ⛔ **없는 결함을 고치지 않는다.**
- **변경 — 프론트만** (하드코드가 있을 때만): 조각 수 표기의 값을 **응답의 `files.count`(＝`d3_dataset.file_count`) 하나로만** 잡는다. 화면 상수·목록 길이·목업 잔재를 쓰지 않는다. 표기 문면 = `파일 조각 {n}개 · 합계 {용량}`(rev1 축자).
- **변경 — DB·계약·서버**: 없음. ⛔ **`file_count` 를 새로 저장하지 않는다** — 저장은 이미 맞다. **기존 데이터**: 해당 없음.
- **수용 기준**
  - Given 조각 1개인 데이터셋, When 상세 조회, Then 표기가 `파일 조각 1개` 이고 **다른 수가 보이지 않는다**.
  - Given 조각 4개인 데이터셋, When 상세·목록 조회, Then 두 화면의 수가 같고 `files.count` 와도 같다.
  - Given 조각 수 표기, When 코드 확인, Then **값의 출처가 응답 한 곳이다**(하드코드 0건).
