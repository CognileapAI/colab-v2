# AI 검색 — WSL stage 테스트 준비까지 실행

**Goal:** 출처가 있는 파일 조건을 저장·확인·검색·화면에서 사용할 수 있게 개발하고 로컬 검증한다.
**Architecture:** 기존 D3 파일과 접근 경계를 재사용한다. 새 근거 저장은 파일의 내용 버전에 연결하고 변경 후 재확인을 요구한다. 모델 평가 보류는 유지한다.
**Tech Stack:** PostgreSQL/Alembic, 기존 FastAPI/core-api, React/Vitest, disposable PostgreSQL와 agent-browser.

사용자 최신 지시: “dev배포는 하지말고 완성된걸 stage에 테스트할건데(wsl) 이 직전까지 개발 완수해라.”
종료 범위는 개발·로컬 검증·stage 실행 준비다. dev 배포·stage 스택 재시작·원격 DB 쓰기·main 반영은 수행하지 않는다. 전체 제품 대장의 배포 완료 정의와 이번 개발 완료를 구분한다.

## 실행 순서

- [x] 1. 계획 독립 검토: 새 근거의 접근/버전/조건 검색/계약 충돌을 검토하고 구체 계약 확정.
- [x] 2. 격리 backend 사본: 파일 내용 버전 및 근거 저장 migration/schema, 입력 검증·읽기/수정 API, RLS·stale·삭제·경쟁 수정 시험.
- [x] 3. 검색 연결: 실제 권한 내 reviewed 근거 조회, 조건별 사실 설명, 파일 역할 검색과 기존 후보/순위/이어보기 계약 검증.
- [x] 4. 상세 화면: 기존 수정 권한을 사용해 파일별 근거 입력·검토·저장·재확인 상태 표시, 실패/저장 후 새로고침 시험.
- [x] 5. 레퍼런스 실제 파일 ID에 연결하는 stage용 입력 초안 생성. 모델 없이 이미 검토한 근거를 입력하며 원문 hash·충돌·누락을 보존.
- [x] 6. 골든·기존 회귀·스키마/계약/서비스/화면 검사, 실제 로컬 입력→저장→검색→상세 여정. 실패는 해결하거나 개발 미완으로 표시.
- [x] 7. WSL stage 테스트 실행 순서·필수 입력·마이그레이션·검증·복구 절차를 준비하고 실제 미실행을 명시. 현재 코드 hash와 시험 근거를 대장·인계에 기록.

한 단위 완료를 종료 지점으로 삼지 않는다. 파일 역할은 학습/보조/검증/예측/지수의 복수 역할, 기간·지역·주기·보간·직접관측·모델은 출처가 있는 선택적 조건이다. 빈 값은 미상이다. 자동 확인·Verified 승격·DB 설명 자동 덮어쓰기는 없다.

## 검증 진행 기록

- 독립 검토: 기간 축약 범위 방어까지 수정 후 approve. 원문은 수집 snapshot, DB 기존 설명 별도 보존.
- core 전체 1152/1152 통과(미실행0, e2e표식6 제외). 이후 기간 방어11/11 및 레퍼런스97건 저장+12문항 실제API 통합 재검증 통과.
- 실제 로컬 브라우저: browser-evidence-06에서 초안→확인→새로고침→검색→상세·로그아웃 exit0. 좌표 클릭이 전달되지 않은 초기 시험은 실패로 보존하고 실제 키보드 조작으로 검증.
- 프런트 타입검사·빌드, schema diff·migration단일head·RLScoverage·seam·생성물·import경계 통과. 전체 화면 시험은 최초 실행 중단(exit143); WSL 내부 동일 소스 사본에서 전체105파일1261건 통과. 중간 안내문 기대값1건은 실제 stale 정의에 맞춰 수정 후 전체 재실행 통과.
