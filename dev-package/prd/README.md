# `dev-package/prd/` — 개발 투입물 (에이전트용)

**이 폴더가 개발 세션이 여는 첫 파일이자 마지막 파일이다.** 세션 하나 = 라운드 파일 하나.

## 왜 이 폴더가 있나

개발 세션이 매번 `03-HANDOFF.md`(607 KB) · `PLAN-SoT.md`(1.17 MB) · `work-items.yaml`(513 KB) · `WORK-UNITS.md`(138 KB)를 읽고 시작했다. **네 파일 합이 2.4 MB 다.** 세션이 그 자리에서 무거워지고, 정작 요구사항은 레포 밖 기획 폴더에 있었다.
⟹ **자립형 라운드 파일 ＋ 명시적 읽기 금지 규칙.** 라운드 파일 하나에 그 세션이 필요한 전부가 들어 있다 — 확정 결정 · 요구 문면 축자 · `path:line` · 규약 명령 · 완료 판정.

## 읽기 규칙 (모든 라운드 파일 §0 과 같은 규칙)

> ⛔ **아래 4개를 통째로 열지 않는다.**
> `dev-package/03-HANDOFF.md` · `dev-package/PLAN-SoT.md` · `dev-package/work-items.yaml` · `dev-package/WORK-UNITS.md`

- **허용된 접근은 세 줄뿐이다.**
  1. 결정 번호 최대값 — `bash dev-package/prd/tools/max-decision.sh`
  2. 대장에서 항목 하나 — `grep -n -A14 '^  - id: <WU-키>' dev-package/work-items.yaml`
  3. 게이트 이름 확인 — `sed -n '12,30p' gates/run.sh` (`ALL_GATES` 배열)
- `03-HANDOFF.md` · `CLAUDE.md` · `RESTART.md` 는 **머리 부분만** 읽는다. 본문 통독 금지.
- 요구사항 정본은 라운드 파일과 `PRD-260905-적용전기획.md` 다. 더 필요하면 PRD 사본에서 **해당 `#### PRD-xx` 절만** 읽는다.
- **코드 파일은 고칠 때만 연다.** 현황 정찰·grep 스윕·다수 파일 읽기는 **서브에이전트에 위임**하고 결론만 회수한다 — 메인 컨텍스트에 파일 덤프를 들이지 않는다.
- 못 읽으면 `[미상]` 이고 실패다. 지어내지 않는다.
- **세션은 `03-HANDOFF.md` 를 직접 고치지 않는다.** 라운드 파일 §4 의 **5줄 이하** 갱신문을 오케스트레이터에 넘긴다.

## 세션이 자기 파일을 고르는 법

1. 오케스트레이터가 **라운드 파일 경로 하나**를 준다. 그것만 연다.
2. 지정이 없으면 아래 상태표에서 **`status` 가 `대기` 인 첫 행**을 고른다.
3. 파일 §0 의 「선행」 줄을 먼저 확인한다 — **선행 WU 가 green 이 아니면 그 파일부터 돈다.**
4. 착수 = ⑴ `work-items.yaml` 등재(§3-㉯ 의 YAML 블록) → ⑵ 레인 워크트리 → ⑶ 실패 테스트 red 확인 → ⑷ 구현 → ⑸ 단독 게이트 green.

### 파일 순서와 두 개의 선행 예외

기본 순서는 **DB → 서버 → 프런트 → 실측**(입력이 먼저 서게). 다만 계획서의 의존이 두 곳에서 이 순서를 가로지른다 — **파일 번호보다 아래 선행이 우선한다.**

| 선행 | 이유 |
|---|---|
| **WU-A12**(R-A-4) → WU-A9 · WU-A10(R-A-3) · WU-A14(R-A-4) | 같은 화면을 고치는 WU 가 rev1 유지 항목 방어선 **위에서** 돈다 |
| **WU-A3**(R-A-3) → WU-A4(R-A-2) · WU-A6(R-A-1) 의 **FE 부분** | 수정 화면 골격이 서야 새 필드를 받는다. **계약·서버 부분은 WU-A3 없이 먼저 갈 수 있다** |

⟹ 권장 착수 순서: **A1 · A2 → A12 → A3 → A13 · A4 → A5 · A6 → A7 · A8 · A9 · A10 → A11 · A14 → R-A 종료 검증.**

## 「41 폴더 없음」 규칙

> **이 폴더가 개발 투입물의 원본이다. `40 COLAB-기획` 은 기획 정제다.**

- 개발이 참조할 기획 산출물을 담는 **`41` 번대 형제 폴더를 만들지 않는다.** 만들면 같은 문서가 세 곳(`40` · `41` · 레포)에 놓이고 어느 것이 정본인지 사라진다.
- `40 COLAB-기획/` 은 **읽기 전용 · 기획 정제 공간**이다. 개발 세션은 고치지 않고, 고칠 것이 있으면 **제안만** 낸다.
- 개발이 코드로 따르는 판본은 **이 폴더의 사본**이다. 두 사본 머리의 3행(원본 경로 · 판본 · 「이 사본이 코드가 따르는 판본」)이 그 사실을 적어 둔다.
- 원본이 개정되면 **별건 회차로 사본을 다시 옮기고 그 사실을 원장에 적는다.** 조용히 덮어쓰지 않는다.
- 문서·주석에 **절대경로를 적지 않는다** — 레포 밖은 `<작업공간>` 표기로만 가리킨다(`CLAUDE.md §3-8`).
