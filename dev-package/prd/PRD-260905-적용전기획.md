# PRD — 「적용 전」 기획 3건의 코드 반영 (2026-09-05)

## 0. 문서 정보

### 0.1 목적

- `40 COLAB-기획/10_적용전/` 의 기획 문서 3건을 CoLAB v2 코드베이스에 반영하기 위한 요구사항 정본이다.
- 이 문서는 **별도 개발 세션에 그대로 넘긴다.** 원천 문서(docx·pdf·html)를 다시 열지 않고도 구현할 수 있도록 값 집합·문면·수용 기준을 여기에 적었다.
- 현재 코드 사실의 출처는 `20_검토/260905_적용현황조사/_조사_적용현황_적용전문서_260905.md`(이하 **적용전조사**) · `_조사_적용현황_SoT_260905.md`(이하 **SoT조사**) 두 건과, 이 PRD 작성 시 직접 실측한 파일이다. 두 조사에 없는 코드 주장은 `path:line` 으로 실측 근거를 적었다.

### 0.3 우선순위 원칙 (Ted 판정 2026-09-05)

1. **기획자 문서가 임시 개발분을 이긴다.** 코드가 문서와 다르면 이 PRD 는 문서 쪽을 사양으로 적는다.
2. 두 기획자의 문서가 서로 다르면 **Ted 가 판정해 확정값을 적는다**(`결정서_Ted_260905.md` — 2026-09-05 에 16건 판정 완료). 판정 규칙 = **연구실 경계 RLS 보안 모델을 고치지 않아도 되는 쪽**을 고른다. §1 이 그 확정표이고, 개발 세션은 그 값대로 구현한다.
3. **이미 판정된 것은 다시 열지 않는다.** 로그인은 `PLAN-SoT §9 〈188〉` 로 비밀번호 방식을 유지하고, 구글 IdP 는 `〈122〉` 로 stage 1 완료 후다. 이 PRD 는 로그인을 건드리지 않는다.
4. **모든 스키마·값 집합 변경은 이미 저장된 행의 처리를 함께 적는다.** 자동 매핑 규칙이거나 「재선택 필요」이며, 재선택 필요면 그동안의 화면 표기까지 적는다.

#### PRD-07 · 부모 Lv ≤ 자기 Lv (같은 레벨 허용)

- **현재 코드**: 규칙의 방향이 반대다. 자기 Lv 를 `max(부모 Lv)+1` 로 **시스템이 계산**하고 사람이 담을 자리가 없다(PRD-03 참조).

#### PRD-10 · 파생 Lv 병존 — 계산은 유지, 불일치는 경고

- **원천**: 미결-2 ⓐ 확정(Ted 2026-09-05). `〈194〉`(파생 전용)와 `P-9`(사람 선택)를 봉합하는 자리다.

  - Given 사람 값 NULL 행, When 조회, Then `mismatch=false` 이고 안내가 뜨지 않는다.

- **상태 전이표 — 이것이 정본이다.** 종전 2값에서는 `잠김` 인 채로 grant 를 받는 것이 정상이었고(P6 접근 요청 경로 · 마이그레이션 `0010`), 3값이 되면 `잠김`(허용 목록이 비어 있다)과 `지정 공개`(허용 목록에 사람이 있다)가 갈리므로 **승인이 상태를 옮겨야 한다.**

| 현재 상태 | 사건 | 다음 상태 |
|---|---|---|
| `열림` | 접근 요청 | 요청 자체가 성립하지 않는다 — 이미 볼 수 있다(현행 유지) |
| `잠김` | 접근 요청 | `잠김` (요청은 **허용된다** — 요청 경로를 막지 않는다) |
| `잠김` | 요청 승인 | **`지정 공개`** — grant 를 쓰는 같은 트랜잭션에서 상태를 올린다 |
| `잠김` | 요청 거절 | `잠김` |
| `지정 공개` | 접근 요청 | `지정 공개` (요청 허용) |

| 어느 상태든 | 소유자가 `잠김` 으로 내림 | `잠김` **＋ 유효 grant 를 전부 만료 처리**한다. 이것이 「`잠김` = 허용 목록이 비어 있다」를 지키는 유일한 자리다. 화면이 「지금 볼 수 있는 사람 {n}명의 접근이 끊깁니다」로 되묻는다 |

- **불변식을 어디서 지키나 — 서버다.** `잠김` ∧ 유효 grant ≥ 1 이 성립하지 않게 하는 검사를 서버에 둔다. DB CHECK 로는 못 건다(`d2_dataset_access` 와 `d2_dataset_access_grant` 두 표에 걸친 조건이라 행 단위 CHECK 의 사정거리 밖이다). 트리거도 쓰지 않는다 — **상태를 바꾸는 쓰기 경로가 둘뿐**이고(`decide_access_request` · `updateDataset` 의 `accessState`) 둘 다 D2 안에 있어, 한 도메인 함수에 모아 두는 편이 규칙을 두 곳에 적지 않는다(`CLAUDE.md §3`). 불변식 위반을 **게이트 테스트로 잰다** — 승인 후 상태 조회 · `잠김` 내림 후 grant 잔여 0건.
- **변경 — 계약**: `DatasetCreate`·`DatasetUpdate` 에 `accessState: [string,"null"]` 추가. NULL = 연구실 기본값 적용(현행 의미 유지). 승인 응답(`decideAccessRequest`)에 바뀐 상태를 실어 화면이 되읽지 않게 한다.
- **변경 — 서버**: 등록 시 값을 `d2_dataset_access` 에 쓴다. `지정 공개` 는 grant 판정을 그대로 타므로 **접근 판정 함수를 고치지 않는다** — `잠김` 과 같은 경로다(`d2_access.py:120` `body_accessible = open_ or granted`). 바뀌는 것은 판정이 아니라 **승인이 상태를 함께 올린다**는 점 하나다(`d2_access.py:337-359` `decide_access_request` — 지금은 grant 만 쓰고 `d2_dataset_access` 를 건드리지 않는다).
- **변경 — 프론트**: 등록 ② 메타데이터 단계 부가 정보에 셀렉트(rev1 배치). 상세 헤더의 `accessState` 표시(`DetailHeader.tsx:72`)를 3값 표기로 교체.
- **기존 데이터**: **자동 매핑한다.** `열림` → `열림`(표기 `연구실 구성원 전체`). `잠김` 이고 유효 grant 0건 → `잠김`(표기 `나만 보기`). `잠김` 이고 유효 grant 1건 이상 → `지정 공개`(표기 `지정한 사람만`). NULL → NULL 유지(연구실 기본값). 재선택을 요구하지 않는다.
- **수용 기준**
  - Given 마이그레이션 적용, When 유효 grant 를 가진 잠김 데이터셋 조회, Then 상태가 `지정 공개` 이고 그 사람의 접근이 **종전과 같이 허용된다**(음성·양성 둘 다 잰다).
  - Given `나만 보기` 로 등록, When 같은 연구실 다른 사람이 본체 요청, Then 거절된다.
  - Given 공개 범위를 고르지 않고 등록, When 조회, Then 연구실 기본값이 적용되고 화면이 그렇게 표시한다.
  - Given `나만 보기` 데이터셋에 접근 요청이 올라옴, When 소유자가 승인, Then 상태가 `지정 공개` 로 바뀌고 그 사람의 본체 접근이 열린다. 같은 트랜잭션이라 「상태는 잠김인데 볼 수 있는 사람이 있다」가 나오지 않는다.
  - Given `지정 공개` 이고 유효 grant 2건, When 소유자가 `나만 보기` 로 내림, Then 되묻는 문면에 `2명` 이 뜨고, 확인 후 grant 2건이 만료되며 두 사람의 접근이 끊긴다.
  - Given 어느 시점이든, When `state='잠김'` 인 데이터셋의 유효 grant 를 셈, Then **0건이다**(불변식 회귀).
  - Given `나만 보기` 데이터셋, When 다른 구성원이 접근 요청, Then 요청이 **접수된다**(3값 도입이 요청 경로를 막지 않는다 — 마이그레이션 `0010` 회귀).
  - Given 연구실 밖 계정, When 어느 상태의 데이터셋이든 조회, Then 보이지 않는다 — **3값 도입이 RLS 경계를 열지 않았음을 cross-tenant 음성 테스트로 증명한다.**
- **영향 범위**: `rls-effect` 게이트 · `d2_access.py` 접근 판정 · **접근 요청 승인 경로(`decide_access_request`)와 P6 화면** · `d1_lab_profile.default_visibility` 를 읽는 연구실 설정 화면 · 상세 헤더 · 검색 카드·카탈로그 행의 잠김 칩(3값 표기로 갈린다).

  - **ⓑ 기각 — 트리거로 갱신하는 별도 `tsvector` 컬럼을 세우는 안.** 생성 컬럼을 일반 컬럼으로 바꾸는 스키마 개정이 선행하고, 갱신 누락이 조용히 색인을 비게 만드는 형태로 회귀하며, `variables` 배열이 더는 안 채워져 되돌림 경로가 사라진다. 얻는 것은 미러 한 벌을 안 두는 것뿐이다.
  - **미러의 방향은 한쪽뿐이다** — 사람·API 가 쓰는 정본은 `d3_dataset_variable` 이고 `variables` 는 그 그림자다. `variables` 를 직접 쓰는 경로(파이프라인 자동 채움 · `AUTOMETA_FROM_EVENTS`)가 남아 있으므로, **등록·수정 경로에서는 `variables` 를 직접 쓰지 않는다**(트리거만 쓴다). 두 곳이 같은 칸을 쓰면 순서에 따라 값이 갈린다.
- **수용 기준 — 색인**

  - Given 변수 행을 `runoff` 로 수정, When 검색어 `runoff`, Then 그 데이터셋이 나오고, 종전 이름으로는 나오지 않는다(트리거 갱신 확인).
  - Given 변수 행 1개를 삭제, When `SELECT variables FROM d3_dataset_autometa`, Then 그 이름이 배열에서 빠져 있다.
- **영향 범위**: 검색 `d3_dataset_autometa.search_vector` 가 `d3_search_join(variables)` 로 변수명을 물고 있다(`schema.sql:409-415`) — **새 표로 옮기면 그 색인이 비게 되므로 위 ⓐ 트리거 미러로 함께 옮긴다.** 이것이 이 요구의 가장 큰 위험이다. `autometa-loss` 게이트 · `contract-breaking` 게이트 · 파이프라인의 `variables` 자동 채움 경로(`AUTOMETA_FROM_EVENTS`)와 트리거의 쓰기 순서.

- **기존 데이터**: 기존 `기록 없음` 행은 그대로 둔다 — 자동으로 붙은 것이라 어느 쪽이었는지 사후에 알 방법이 없다. 종전 규칙 아래에서는 부모 0건 행에 `d4_lineage_unknown` 행이 **빠짐없이** 붙어 있으므로, 개정 판정식을 적용해도 그 행들은 ⑶ 을 타 **종전과 같이 `기록 없음`** 이다(화면 값이 바뀌는 기존 행 0). 새로 등록되는 것부터 갈린다. **이 사실을 마이그레이션 전에 실측한다** — `부모 0건 ∧ d4_lineage_unknown 행 없음` 인 데이터셋 건수가 0 임을 세고, 0 이 아니면 그 행들이 `확인 필요` 로 넘어감을 보고한다.

  - Given 부모 ≥1, When 조회, Then 판정이 종전과 같다 — 부모가 있는 경로는 이 개정이 건드리지 않았다.

#### PRD-37 · 「조건부 공개」 — 뷰와 다운로드를 가른다 — **§4 범위 밖 (미결-1 ⓐ 확정)**

- **답이 ⑵(외부 기준 3값)일 때** — 뷰 축과 다운로드 축이 **둘로 갈린다.** `d2_dataset_access` 에 뷰 상태와 다운로드 상태를 따로 두고, RLS 의 연구실 경계 정책 개정 ＋ 외부 열람 라우트 신설이 선행한다. 이 경우 **PRD-11 전체를 다시 쓴다**(미결-1 되돌림 비용 열의 「WU 3~4개 신설」이 이 자리다).

#### PRD-38 · 조각 수를 화면에서 정직하게 적는다

- **원천**: `P-5` 축자 「목업의 예시 업로드는 데이터 파일 1개인데 등록후에는 데이터 조각 4개라고 표현되고 있습니다.」
- **판정 정정**: 종전 PRD 는 이 항목을 부록 A 「이미 적용됨」으로 닫고 근거를 `file_count` 트리거·`files.count minimum 1`·`test_file_count_drift.py` 로 들었다. **그 근거는 저장값의 정합이고, pdf 의 지적은 화면 표기다.** 트리거가 정확해도 목업 문면이 고쳐졌는지는 다른 사실이다 — **부록 A 에서 이 항목을 「표기는 미적용」으로 갈라 이 요구로 옮긴다.**
- **현재 코드**: 상세 레코드 줄이 `파일 조각 {n}개` 를 보인다. **실측 1건 — 상세 픽스처는 이미 응답값을 쓴다**: `frontend/src/components/detail/fixture.ts:78` `files: { count: row.fileCount, … }` 로 행의 조각 수를 그대로 옮긴다(하드코드가 아니다). 남은 확인은 목록 카드와 상세 렌더가 그 값을 그대로 읽는지 한 곳뿐이다.

- **기존 데이터**: 해당 없음.
- **수용 기준**
  - Given 조각 1개인 데이터셋, When 상세 조회, Then 표기가 `파일 조각 1개` 이고 다른 수가 보이지 않는다.
  - Given 조각 4개인 데이터셋, When 상세·목록 조회, Then 두 화면의 수가 같고 `files.count` 와도 같다.
  - Given 조각 수 표기, When 코드 확인, Then 값의 출처가 응답 한 곳이다(하드코드 0건).
- **영향 범위**: 부록 A `P-5`·`R-05` 행 · PRD-32(조각이 한 종류인 전제).

### ③ 연결

- 카드 둘이 이 단계에 함께 있다.
- **계보 카드**
  - 상단 안내 — `지금 이 데이터는 Lv{n} · Lv0~Lv{n} 가공 전 데이터만 연결할 수 있어요. 분류에서 바꾸기` (Lv0 이면 범위가 `Lv0`). 색은 정보색(파랑), 위치는 버튼 **위**(`R-20`).
  - `+ 가공 전 데이터 추가` → 찾기 모달. 모달에 가공 단계 필터. 자기 Lv 초과 후보는 보이되 선택 불가 + 사유(PRD-08).
  - 확정 항목 목록. 사후 충돌 항목에 `확인 필요` 칩(PRD-09). 항목마다 `가공 방식` 입력 1칸(선택) — **이미 서 있다**(`LineageStep.tsx:350-356` · 부록 A `H-50` · PRD-30). 이 PRD 가 더하는 칸이 아니다.
  - `가공 전 데이터를 못 찾았어요 — 기록 없이 등록할게요` 체크박스 — 확정 부모가 1건 이상이면 비활성이고 사유 한 줄이 붙으며, 가공 단계가 Lv0 이면 보이지 않는다(PRD-27 · 미결-6 ⓐ).
  - **원천 표기** — 가공 단계와 무관하게 늘 보인다(PRD-19 · 미결-11 ⓐ). 가공 단계가 **Lv0 일 때만** 그 아래 `출처 주소`(선택) · `내려받은 날`(선택) 두 칸이 열리고 안내 `원시 데이터라 부모가 없어요. 대신 어디서 언제 받았는지를 남겨요.` (PRD-19)
- **연관 프로젝트·논문 카드**
  - 제목 `연관 프로젝트·논문 등록` · 부제 `어디에 쓰나요?` · 우측 `선택 · 여러 개`
  - `국가과제` 패널 / `논문` 패널 두 개. 각 패널 안은 행이 위에서 아래로 쌓인다(PRD-23). `+ 새 프로젝트 만들기` 는 두 패널 공통으로 맨 아래 한 곳이다.
- 검증 — **`데이터셋 만들기` 를 막는 것**
  - ① 의 세 값 중 빈 것이 있다 (화면에서는 기본값 때문에 성립하지 않고, API 경로의 방어선이다)
  - ② 의 이름 · 설명 · 기간 · 변수 1행 중 빈 것이 있다
  - `확인 필요` 연결이 1건 이상이다
  - ⚠ **게이트 범위는 rev1 정책문서 쪽을 따랐다.** rev1 코드 `makeDataset()` 는 4종(이름 · 설명 · Lv0 출처 2칸 · 확인 필요)만 검사하고, rev1 정책문서는 기간을 `VAL-006` 필수로 적는다 — **rev1 안에서 코드와 정책문서가 어긋난다.** §0.3-1(기획 문서가 임시 개발분을 이긴다)에 따라 정책문서를 택해 기간·변수 1행을 게이트에 올렸다. Lv0 출처 2칸은 반대로 **게이트에서 뺐다** — PRD-19 가 pdf 원문 근거로 선택 항목으로 되돌렸다.
- **막지 않는 것**: 계보 부모 0건(기록 없음·확인 필요로 등록된다) · 사람 Lv 와 파생 Lv 의 불일치(경고만 — PRD-10) · 공개 범위 미선택(연구실 기본값) · 관측 간격 미기재 · **Lv0 의 출처 주소·내려받은 날 미기재**(PRD-19) · **연결의 `가공 방식` 미기재**(현행 유지 · 부록 A `H-50`) · 단계 표시기로 앞 단계 건너뛰기(PRD-12).
