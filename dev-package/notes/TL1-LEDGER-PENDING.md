타일에는 소유 필드도 사이드카도 없으므로 「누구 것인가」가 아니라 **「지금의 주체가 낳는 이름인가」**

주체의 본체를 못 열면 그 주체가 낳을 키를 모르고, 조용히 빼면 그 주체가 가리키던 타일이
**고아로 둔갑한다**(`DATA-REFERENCE §0 M-9` 의 그 오판). ⟹ **계산 불가 ≥ 1 이거나 주체 0건이면
판정을 시작하지 않는다**(`ReaderNotReady` · 진입점 종료 코드 **78 = red(준비)**). **㉱ 첫 참값

`BEGIN READ ONLY` 조회 — `d3_file 133`(본체 **125**) · `d5_upload_file 133` · `d5_upload 17`
**전건 등록 전환**(`registered_at IS NOT NULL` 17/17) ⟹ **보류 업로드 0** · **주체 125**.
자리·접수분은 **`viz-render` 컨테이너 안에서 읽었다**(접수분은 `ro` 마운트 · 컨테이너 파일시스템에도
쓰지 않았다 — 판독기 원본과 주체 목록을 **표준입력**으로 물렸다 · `RC-1` 과 같은 선). 결과 축자 =
`지도 타일 생존 — 자리의 타일 2벌 · 살아 있다 2 · 접수분에만 닿는다 0 · 고아(못 닿는다) 0 · 판정 불가 0 · 계산 불가 0`.
주체 125가 낳은 후보 키 **157**. **가장 오래된 못 닿는 벌 = 없다.** ⭑ **다주체 공유가 실물에서
확인됐다** — 둘째 타일(`tile-e63939cc…`)을 **서로 다른 데이터셋 파일 둘**이 낳는다. 완료 정의 ⑴ 의
「첫 주체가 지워져도 산다」가 픽스처가 아니라 staging 실물에 실재한다. **㉲ 이 0 을 「결손이 없었다」로
읽지 않는다** — 종전에는 **세는 자리 자체가 없었고** 값은 `0` 이 아니라 **`[미확인]`** 이었다.
⛔ **`〈312〉` 가 지목한 stale 3벌은 `tile-` 벌이 아니다** — ③지도형 **렌더** 산출물(`.png`·`.pgw`·`.json` ·
키 규칙 `render_cache_key`)이고 이 판독기의 대상이 아니다(그 회수는 `CR-2` ⑶ 이 진다).
**타일 키가 갈리지 않은 이유** = `warp+blockavg → warp+nearest` 는 **렌더의 다운샘플**이고 지도 타일
키의 재료 여섯에 그 이름이 없다 · `MAP_TILE_KEY_VERSION` **1 무변**. ⚠ **모집단은 2벌뿐이다** —
검증된 것은 **규칙**이지 「타일이 많은 자리에서도 0」이 아니다. **㉳ 규칙을 두 곳에 적지 않았다** —
`candidate_tile_keys`·`file_digest` 를 판독기 쪽 한 자리로 옮기고 `value_lookup` 이 **재수출**한다
(값 조회와 생존 판독이 같은 이름을 지어야 한다 · 불변규칙 1). `ownership.py` 는 **한 글자도 고치지
