> 이 파일에 `§9` 를 대신하는 값을 두지 않는다 — 등재 시 아래 본문을 그대로 옮긴다.

## ⓐ 등재문 초안 — 「등록 화면에서 변수·좌표계·기간을 적는다」

**판정(Ted · 2026-09-02) = 등록 화면에서 변수·좌표계·기간 입력을 허용한다.** 그래서 **서버를
넓히고 화면을 연다.** 계약을 좁히는 갈래(14차 해제 · `〈138〉` 반전)는 채택하지 않았다.

**㉮ 서버 — `createDataset` 이 셋을 받는다.** `routes/ingestion.py` `_ALLOWED_CREATE_FIELDS`
7 → **10**. **계약 개정 0 · 동결 해제 0회 · 마이그레이션 0**(열은 `d3_dataset_autometa` 에
이미 있다 · head `0011` 그대로). 저장은 **`updateDataset` 이 쓰는 경로 하나**를 그대로 쓴다
(`d3_catalog.update_dataset`) — 쓰기 코드를 두 벌 두지 않았다.

**㉯ 검사기도 한 벌이다.** `routes/catalog.py` 에 `validate_human_metadata` 를 세우고
생성·수정 **두 경로가 같은 함수**를 부른다. 보는 것은 **형상뿐**이다 — 정본 `VAL-006` 이
셋을 「자유 입력 · 형식 검사는 하지 않는다」로 뒀다. 시험이 같은 어긋난 값에 **같은 400
문구**가 나오는 것을 못 박는다.

**㉰ 순서가 곧 규칙이다 — 사람 값이 사건보다 먼저 쓰인다.** 등록 전환은 보류된
`file.header-parsed` 를 같은 트랜잭션에서 반영한다(`〈190〉`). 사람 값을 **먼저** 쓰고
`apply_autometa` 의 「빈 칸만 채운다」(`COALESCE`)를 그대로 둔다. 뒤집으면 사용자의 입력이
화면에 아무 말도 남기지 않고 사라진다. 시험 = 같은 회차에 사람 값과 헤더 파싱 사건이 만나
**변수·좌표계·기간은 사람 값이 남고 `format`·`grid` 는 사건 값이 들어온다**(「사건을 통째로
버렸다」로 통과시키지 않는다).

**㉱ 빈 칸은 싣지 않는다.** 서버 `_human_metadata` 와 화면 `humanMetadata()` 가 같은 규율을
쓴다 — 빈 배열·빈 문자열·`null` 은 **안 보낸 것**이다. 저장하면 `_APPLY_AUTOMETA` 가 영영
막혀 그 칸이 **영구 공란**이 된다(`〈140〉`-㉱ 와 같은 실패형).

**㉲ 화면 — 세 칸이 읽기 전용 `자동` 에서 입력 칸으로 내려왔다.** `RegisterArea.tsx` 의
`파일에서 자동으로 읽었어요` 블록은 **포맷·용량·격자** 셋만 남는다. 근거 = 정본
`POLICY-20260825-001` 핵심규칙 1 「자동으로 읽는 값은 포맷과 용량뿐」 · UI 스펙 **18·19·20**
(변수·기간·좌표계 입력 · 전부 「자유 입력」).

**㉳ ⚠ 자동완성은 붙이지 않았다 — 정본에 없다.** 서버 op `listDatasetFieldSuggestions`
(`catalog.py:200` · `SUGGESTABLE_FIELDS`)는 서 있지만 **UI 스펙 18·20 은 자동완성을 한 글자도
적지 않는다**(`ui: "Input"` · 예시 안내 문장뿐). 지시는 「스펙이 다르면 스펙을 따르고 차이를
보고하라」였고, **스펙을 따랐다.** ⟹ 그 op 은 여전히 **프런트 소비자 0** 이다.

**㉴ ⚠ 정본과 어긋나는 자리 하나 — 기간의 입력 형태.** UI 스펙 19 는 기간을
「`2025-06 ~ 2025-09`」 **한 칸의 자유 문장**으로 그린다. 계약 `DataPeriod` 는
`start`·`end` 두 `date-time` (`required` ＋ `additionalProperties: false`)이고 DB 도
`period_start`·`period_end timestamptz` 두 열이다. **자유 문장을 담을 자리가 계약에 없다.**
계약 무변경이 이 회차의 전제라 화면이 **날짜 두 칸**으로 받는다. ⟹ **판정 대기** — ⓐ 화면을
스펙대로 한 칸 자유 문장으로 되돌리고 계약·DB 를 문자열로 넓히는가(동결 해제 ＋ 마이그레이션)
ⓑ 지금의 두 칸을 정본으로 승격하는가.

**㉵ ⚠ 격자는 열지 않았다.** UI 스펙 21 은 격자도 사람이 적는 선택 입력으로 그리는데 계약
`DatasetCreate`·`DatasetUpdate` 어디에도 `grid` 가 없다(`〈74〉` — 격자 파일을 붙인 뒤 서버가
세는 값). **이 회차의 대상이 아니었고 손대지 않았다.** 소유·처분 미정.

**㉶ ⭑ 부수 발견 — 수정 경로의 기간이 통째로 죽어 있었다.** `d3_catalog._UPDATABLE` 에
`period` 가 없어 `update_dataset` 의 대응표 순회가 `KeyError` 로 죽었다 ⟹
`PATCH /datasets/{id}` 에 `period` 를 실으면 **500**. `fff3034`(2026-08-27) 이래 열려 있었고
**시험이 0건이라 아무도 몰랐다.** 이번 회차에 고쳤고(순회에서 `period` 를 건너뛴다) 200 을
못 박는 시험을 세웠다. **없는 것은 diff 에 안 나온다**(`§4 #55`·`#62` 와 같은 실패형).

## ⓑ 기록만 하고 고치지 않은 것 — 동결 회차표의 결번

`sessions/X2-FREEZE-PROTOCOL.md §1` 회차표에 **`869ee64`(2026-08-27 · `〈138〉`·`〈140〉` ·
`DatasetCreate` 에 `processingLevel`·`variables`·`crs`·`period` 추가)의 해제 회차 번호가
없다.** 표는 1~13차이고 8차는 `〈180〉`(2026-08-28)이라, 그 앞의 계약 개방이 번호를 못 받은
채 남아 있다. **8차 누락**(`〈199〉`·`〈200〉` 이 사후 기재로 닫은 것)과 **같은 무늬**다.

⛔ **이번 회차에 고치지 않았다.** 회차 번호 발급은 오케스트레이터의 자리이고, 소급 번호를
레인이 지어내면 그것이 `§1-b-⑶` 이 금지한 그 사고다. **정할 것** = ⓐ 사후 번호를 발급하는가
ⓑ 「번호 없이 일어난 개방」으로 표에 기재만 하는가.
