## 2. 새로 드러난 것 — 배치 정본과 시험 조건이 어긋나 있었다

**시험이 본체를 원래 파일 이름으로 놓고 있었다.** 배치 정본(`contracts/storage/layout.json`
`keys.본체`)은 **`{uploadsPrefix}/{targetId}/{fileId}`** 이고 `fileId` 는 ULID다 — **확장자가 없다.**
즉 실운영에서 그리는 쪽이 여는 파일에는 이름도 확장자도 남지 않는데, E2E 는
`HLS.S30….tif`·`gk2a_….nc` 로 놓고 돌고 있었다.

**포맷 판정을 확장자에 조금이라도 기대는 자리가 하나만 있어도 E2E 는 전건 초록인데
실제 업로드는 한 장도 안 그려진다.** 이 레포에 이미 두 번 난 무늬다 — 확장자로 역할을 갈라
실파일 14건을 삼킨 `DATA-REFERENCE §0 M-1`, 시험이 자기가 놓은 자리에서 읽어 배치를 아무도
안 본 `03-HANDOFF §4 #20`.

**측정 결과 = 결함 0건.** 그리는 쪽은 확장자를 전혀 보지 않는다(전량 매직바이트 판정).
**그러나 그 사실을 지키는 시험이 없었다** — 그래서 회귀 시험으로 세웠다.

## 3. 이 회차가 세운 시험 — red 로 먼저 확인했다

두 본 다 **먼저 초록이 났다.** 초록이 곧 「이미 서 있었다」인지 「아무것도 안 보고 있다」인지
갈리지 않으므로, **변이(mutation)로 오라클을 증명했다** — 이 레포가 검사기에 요구하는 것과 같은 방법
(`CLAUDE.md §4` 「실패 픽스처로 증명한다」).

| 시험 | 건수 | 변이 | 변이 결과 |
|---|---|---|---|
| `services/core-api/tests/test_e2e_s3_real.py` | **6**(포맷 5 ＋ 목록 정본 대조 1) | 계보 **확인 호출을 건너뛴다** | **5 red** — 다섯 포맷 전건이 「확정으로 남지 않았다」로 떨어졌다 |
| `services/viz-render/tests/test_e2e_storage_layout_real.py` | **5** | 본체를 **앞 1,024 B 만** 놓는다 | **5 red** — 전건이 렌더 실패로 떨어졌다 |

⟹ **red 로 세운 시험 = 10건**(변이 실측). 빈 단언이 아니다.

**시험이 실제로 하는 것.**

- **계보 판** — 5종 **실파일 바이트**를 `createUpload` 로 올려(영수증의 `byteSize` 가 실파일
  `st_size` 와 같은지 대조 — 실물이 통과했다는 유일한 증거) 두 데이터셋으로 등록하고,
  부모를 붙이고, **확인 전에는 `확인 필요`** 인 것을 본 뒤 `confirmLineage` 로 **`확정`** 을 만든다.
  상세 응답과 계보 그래프가 **같은 값**을 말하는지, 그래프에 부모 노드가 있는지까지 본다.
  덧붙여 **core-api 가 포맷을 스스로 적지 않는다**(`d5_upload_file.detected_format` = NULL)를
  실파일로 음성 확인한다 — 확장자로 싸잡아 분류하지 않는다(`DR-3`·`M-1`).
- **배치 판** — 같은 실파일을 **ULID 한 개**(확장자 없음)로 놓고 5종을 다시 그린다.
  격자는 배치 정본이 이름을 보존하는 자리라 그대로 둔다.
- **목록 정본 대조** — 시험이 손으로 적은 다섯이 `gates/config/e2e-format-coverage.toml`
  `[required].formats` 와 **순서까지 축자로 같은지** 본다. 정본이 늘었는데 시험이 조용히
  다섯만 재고 통과하는 것을 막고, **GeoTIFF 가 첫 자리인 것**도 이 대조가 함께 지킨다.

⚠ **포맷 커버리지 표식(`e2e_format`)을 새 파일에 붙이지 않았다** — 커버리지 계수는
`test_e2e_real.py` 다섯 건이 지는 것이고, 또 붙이면 같은 포맷을 두 번 세게 된다.

## 4. 5종 각각의 완주 — 어디까지 가고 어디서 멈추나

**단위는 「업로드 → 헤더 파싱 → 좌표계 통일 → 미리보기 산출 → 화면 도달 → 계보 확정」이다.**

| 포맷 | 업로드 | 헤더 파싱·좌표·미리보기 산출(D7) | 화면이 받는 자리 | 계보 확정 | 완주 |
|---|---|---|---|---|---|
| **GeoTIFF** | ✅ 24,577,705 B | ✅ 동봉 격자 불요(파일 내부에서 계산) | ✅ | ✅ | ✅ |
| **NetCDF** | ✅ 397,448 B | ✅ 변수 자동 선택 `LST` · 단위 K · 200~400 대역 | ✅ | ✅ | ✅ |
| **Binary**(HSR) | ✅ 1,259,571 B | ✅ 동봉 격자 `.nc` 필요 — 다섯 중 **유일**(`§1.1`) | ✅ | ✅ | ✅ |
| **HDF4** | ✅ 9,731,088 B | ✅ Fpar 0~1 대역 | ✅ | ✅ | ✅ |
| **NumPy** | ✅ 6,553,728 B | ✅ 동봉 격자 `LAT_crop`·`LON_crop` 짝(형상 `(1280,1280)`) | ✅ | ✅ | ✅ |

**멈추는 자리 0건 — 다섯 다 완주한다.** 값(격자·dtype·COG 판정 기준)은 다시 재지 않고
`DATA-REFERENCE §1`·`§1.1` 과 `DATA-PIPELINE-MEASUREMENT` 의 실측을 찾아 썼다.

### 4-b. 「지원 목록 밖」과 「구현 결함」을 가른다 — 하나 나왔다

⛔ **`NumPy` 는 `pipeline-worker`(D5)의 헤더 파싱에서 멈춘다. 이것은 「지원 목록 밖」이 아니라
「구현 결함」이고, 에러 메시지가 그 둘을 뒤바꿔 말하고 있다.**

- **실측**(이 회차) — `Prediction_20230501.npy` 를 `d5/pipeline.run_file` 에 넣으면
  `detect_format` 은 **`NumPy`** 로 바르게 판정하는데, 바로 다음 단계가
  `파싱 실패(NumPy): 지원 목록 밖: NumPy` 로 떨어진다.
- **그런데 D5 자신의 선언은 지원한다고 말한다** — `d5/formats.py` `SUPPORTED_FORMATS` 에
  `NumPy` 가 있고(`〈77〉`), `d5/renderable.py` 의 `NOT_RENDERABLE_FORMATS` 는 `GRIB` 하나뿐이라
  **`NumPy` 는 `RENDERABLE_FORMATS` 에도 들어 있다.**
- **결함의 자리** = `d5/parse.py` `parse_metadata` 의 분기(`NetCDF`·`HDF4`·`GeoTIFF`·`Binary` 넷만
  받고 나머지는 `else` 로 떨어뜨린다) ＋ `d5/pipeline.py` 의 COG 분기(같은 모양).
- ⟹ **선언은 여섯인데 처리는 넷이다.** 메시지가 「지원 목록 밖」이라 **읽는 사람이 이것을
  정책으로 착각한다** — 실제로는 목록 안이고 구현이 없는 것이다. `M-6` 의 무늬(주석·문면이
  확인을 멈추게 한다)가 에러 메시지에서 되풀이됐다.

⚠ **이것이 `S3` 를 막지 않는 이유를 갈라 적는다 — 두 경로가 다르다.**
화면이 받는 미리보기는 **`viz-render`(D7)** 가 원본에서 직접 산출하고(`ports/source.py` 가
접수분 자리를 그대로 읽는다), **D5 의 COG 는 지도 타일 재사용용 별도 산출물**이다
(`contracts/storage/layout.json` `contentKeys` — 만드는 자리가 둘이고 키 규칙도 둘이라고
정본이 못 박는다). **`NumPy` 는 D7 경로로 완주한다** — 이 회차가 실파일로 다시 확인했다.
⟹ **이 결함의 소유는 `S3` 가 아니라 `D5`(`partial`)다.** 여기서 고치지 않았다(범위를 늘리지 않는다).
**새 블로커로 상신한다.**

## 5. `S3` 를 닫았는가 — **닫지 않는다.** 남은 조건 하나

**충족된 것 셋** — ㉮(5종 각각 그려짐 · 배치 정본 이름으로도) · ㉯(5종 실파일 계보 확정) ·
㉰(실패 목록 · 면제 0건) ＋ ㉱(GeoTIFF 우선을 기계가 대조).

⛔ **남은 조건 = 「시각화 **화면**에 그려진다」의 포맷별 실측이 없다.**

- **포맷에 의존하는 지점은 전부 `viz-render` 안에 있고 거기서 5/5 실측됐다.** 화면 구역의
  정본은 「**무엇으로 그릴지는 사람이 고르지 않는다. 격자·경계·점의 판정은 포맷이 하고
  viz-render 가 한다**」(`DatasetPreviewSection.tsx` 축자)이고, core-api 중계도
  「**중계는 해석하지 않는다**」다. ⟹ **화면은 구조상 포맷 무관**이다.
- **그러나 그것은 틀이지 측정이 아니다.** 공개 엣지 실측은 `〈241〉` 의
  **주 화면 13/13 = 200 ＋ `image/png`** 이 유일한데, **그 13건의 포맷 구성이 어디에도 적혀 있지 않다**
  (`sessions/P3-AB-DEPLOY-20260831.md §5` — 「데이터셋 13건」으로만 적는다.
  같은 문서의 「표본 25 · 포맷 5종」은 **게이트 `render-latency` 의 로컬 측정**이지 엣지가 아니다).
  ⟹ **「5종 각각이 공개 엣지에 도달했다」는 `[미확인]` 이다.**
- **증거는 확정으로, 틀은 잠정으로 적는다**(`M-5`). 틀만으로 v2 완주 조건 한 항을 닫지 않는다.
  **부분 완료로 닫지 않는다.**

**푸는 법(다음 회차 진입조건)** — staging 에서 **5종 각각 최소 1건**을 골라 공개 엣지 주 화면
자리를 왕복해 `200 ＋ image/png` 를 포맷 이름과 함께 적는다. **이 레인은 staging 무접촉
조건이라 재지 않았다** — 못 잰 것을 잰 것처럼 쓰지 않는다.
