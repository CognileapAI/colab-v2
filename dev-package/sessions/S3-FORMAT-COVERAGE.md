## 2. 실데이터 완주 — 무엇이 이미 통과하고 무엇이 없었나

**이미 통과하고 있었다.** 렌더 서비스의 실데이터 시험이 네 포맷을 각각 그려 보이고 있었고,
「그려졌다」의 판정이 200·PNG 매직에 머물지 않는다 — 경계 중심을 덮는 타일을 골라 **불투명 픽셀이
실제로 있는지**까지 본다(`test_e2e_real.py::_assert_drawn`). 값 자릿수도 함께 박혀 있다(반사도 상한 ·
Fpar 0~1 · 지표면 온도 200~400 K). **직전 회차 실측 = 원천 마운트 시 119 통과 · 마운트 없으면
fail-closed** — 이번에 다시 재지 않고 그대로 받았고, 기점 재확인 1회만 돌려 같은 값을 봤다.

**없던 것 셋.**

1. **다섯째 포맷의 실데이터 케이스** — 정본이 판정 목록에 `NumPy` 를 넣었는데 실파일 케이스가 0건이었다.
   합성 `.npy` 시험은 있었으나 **원천의 산출 값 배열**을 그려 본 자리가 없었다.
2. **커버리지를 세는 자리** — 「각각 최소 1건」이 사람 눈으로만 확인됐다. 케이스 하나가 지워져도
   시험은 그대로 green 이고 아무도 모른다.
3. **「조용히 건너뛰지 않는다」의 집행** — 실패·건너뜀을 **이름으로** 남기는 자리가 없었다.

## 3. 세운 것

### ㉮ NumPy 실데이터 렌더 케이스 ＋ 그 짝 음성

- 짝 = `01.level-data/02.vegetation/…/Lv.2/Prediction_*.npy` `(1280, 1280)` `<f4`
  ↔ `#metadata/LAT_crop.npy`·`LON_crop.npy` `(1280, 1280)` `<f8` (이 회차 실측 · 형상 일치).
- **격자 파일이 아니라 본체를 그린다** — `04.Lat_Lon_info` 의 `.npy` 는 좌표 기준 격자이고
  (`DATA-REFERENCE §1`), 그것을 그리면 「NumPy 를 그렸다」가 「격자를 그렸다」가 된다.
- **값 범위는 단언하지 않았다** — 이 산출물의 물리 단위를 말하는 정본이 없다. 근거 없는 상·하한을
  박으면 레인이 값의 정의를 관례로 정하는 것이 된다.
- **짝 음성을 함께 세웠다** — 같은 폴더의 `LAT.npy`·`LON.npy` 는 `(852, 1200)` 이라 짝이 아니다.
  붙이면 **리샘플로 맞추지 않고 거절**한다(`REFERENCE_GRID_MISSING`). 이 음성이 없으면 양성의
  「동봉 격자 적용」이 아무 것도 구분하지 못한 채 통과한다(`§0 M-4` 의 무늬).

### ㉯ 게이트 `e2e-format-coverage` ＋ selftest

- 세는 단위 = **포맷 표식이 붙은 시험 케이스 1건.** 파일 수로 세지 않는다 — 한 케이스가 원천 파일
  여럿을 읽는 자리가 있어 파일 수와 케이스 수는 애초에 같지 않다.
- 표식은 시험이 **명시적으로** 선언한다(`@pytest.mark.e2e_format("<포맷>")` → junit 속성).
  **케이스 이름으로 짐작하지 않는다** — 이름 규칙으로 세면 이름을 바꾸는 순간 대상이 조용히 0 이 되고
  게이트는 그것을 통과로 보고한다.
- 세 상태 — 케이스가 있으면 검사 · `gates/config/e2e-format-coverage.toml` 에 **포맷 이름으로**
  적히면 건수를 드러낸 채 통과 · 아무 말 없으면 red. **원천 마운트 미선언도 red(준비)**,
  **표식 붙은 케이스 0건도 red**.
- 실패·건너뜀은 **케이스 이름으로** 출력에 찍는다 — 「목록으로 남긴다」가 그 뜻이다.
- **판정 목록의 정본은 선언 파일 하나다.** 정본이 「그 목록으로 판정한다」고 적은 다섯을 그대로
  옮겼다. `S3` 의 이름이 「4종」인 것과 목록이 다섯인 갈림은 **여기서 고르지 않았다.**
- ⚠ **이 게이트는 `S3` 를 닫지 않는다.** 계보 확정 상태와 staging 배포 green 은 여기서 재지 않는다.

### ⚠ 대상 0건 함정을 어떻게 피했나

**이 게이트의 자연스러운 대상 수는 원천이 안 붙은 환경에서 0 이다** — CI 에는 원천 3.5 GB 가 없다.
0 을 통과로 세면 게이트가 아무것도 안 보면서 green 을 찍는다. 그래서 `TOTAL=0` 을 red 로 못 박고,
selftest 케이스 ⓕ 가 그 red 를 **픽스처로** 증명한다(표식 없는 junit 을 먹인다).
**본 게이트를 CI 에 넣지 않았다** — 원천이 없으면 상시 준비 red 이고, 그 red 는 입력 미선언이지
판정 실패가 아니다. **selftest 는 CI 에 넣었다** — 픽스처가 junit XML 과 선언 파일뿐이라 원천·DB·도커
없이 돈다.

## 4. `DATA-REFERENCE` 에서 **다시 재지 않고 가져다 쓴 값**

- **§1 격자 파일 형상·dtype 16건** — HSR `(2881,2305)` `<f4` · HLS `(3660,3660)` `<f8` ·
  MODIS `(2400,2400)` `<f8` · GK2A `(900,900)` `<f4`. 기존 실데이터 케이스의 짝이 이 값이다.
- **§1.1 격자를 어디서 얻는가** — **밖에서 받아야 하는 것은 HSR 하나**, 나머지는 파일 내부 계산.
  NumPy 케이스를 「동봉 격자를 붙이는」 갈래에 놓은 근거다(`.npy` 는 좌표를 말하지 않는다).
- **§2 HSR 스펙 전량**(헤더 1024 B · `<i2` · `/100` → dBZ) · **§6 `Fpar_500m` 0~1** — 기존 케이스의
  값 자릿수 단언이 이 값 위에 서 있고, 이번에 다시 재지 않았다.
- **§0 `M-1`(확장자로 싸잡지 않는다)** — 그래서 `.npy` 본체와 `.npy` 격자를 케이스에서 갈랐다.
- **§0 `M-4`(부분 검증 통과를 전체 통과로 착각한다)** — 짝 음성을 붙인 근거.
- **§0 「여덟 중 일곱이 에러 없이 그럴듯한 값」** — 커버리지를 사람 눈이 아니라 기계가 세게 한 근거.

**새로 잰 것 = `Prediction_*.npy` 와 `LAT_crop`/`LON_crop`/`LAT`/`LON` 의 형상·dtype 다섯 뿐**
(원천 목록에 없던 값이라 잴 수밖에 없었다).

## 7. 멈춘 자리 — 사람이 고른다 (이번에 결정하지 않았다)
