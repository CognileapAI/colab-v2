> **범위** `contracts/schemas/common.json` 한 파일. seam(`contracts/seams/`)·이벤트(`contracts/events/`)는 이 조각에 없다.
> **근거 규칙** `CLAUDE.md §3-6`(정규 ID 타입은 common.json 에서만 정의) · `PLAN-SoT §9-⑲`(값 집합은 DB가 강제한다) · `§9-⑳`(파생값 2종 미저장) · `§9-㉖㉗`.

## 1. 판단 — enum 값 표기

**확정 = 정본 한국어 표기를 값 그대로 쓴다.** 속성 이름만 영문(기술 어휘), enum 값은 한국어(도메인 값 집합).

근거 셋.

1. **정본이 한국어로만 열거한다.** `DataModel_공통_기반 v1.8` 에 영문 코드값이 한 건도 없다. 영문 코드를 만들면 **정본에 없는 어휘를 우리가 새로 만드는 것**이고, 그 어휘의 정본이 어디인지 다시 정해야 한다.
2. **매핑 테이블을 만들지 않는다** — `PLAN-SoT §9-㉗` 이 `데이터 공개 범위`를 2값으로 좁힌 것과 같은 논리. 코드값·라벨을 나누면 코드↔DB↔화면 세 곳이 갈라질 자리가 생기고, 그것이 정확히 v1 이 당한 드리프트다.
3. **`CLAUDE.md §3` 이 이미 값으로 못 박았다** — "확신도는 `확실 | 애매 | 모름` enum". 이 문장을 그대로 타입으로 옮기면 해석이 개입하지 않는다.

대가(알고 받는다) — 쿼리스트링·경로에 한국어가 실리면 퍼센트 인코딩이 붙는다. 값이 다국어로 늘어나면 그때 라벨 층을 **추가**하는 것이지, 지금 없는 화면을 위해 미리 갈라 두지 않는다.

### 지킨 제약

- **⑳ 파생값 2종** — `LineageState`·`ProcessingLevel` 에 `readOnly: true` 를 걸고 description 에 "쓰기 타입에 두지 않는다"를 명시했다. seam 작성자가 요청 바디에 이 둘을 넣으면 계약 리뷰에서 걸린다.
- **AI 규격** — 확신도는 enum이고 **숫자·퍼센트 필드를 만들지 않았다.** `AiRationale` 은 nullable 이 아니다(`type: string` 단독). **배치 승인 개념의 타입을 만들지 않았다** — `AiSuggestion` 배열·`approveAll` 류를 여기 두지 않는다.
- **값 집합 9종 전수** — `PLAN-SoT §9-⑲` 가 센 9종(역할2·권한스위치4·파일종류2·부모역할2·만들어진경로2·계보상태4·접근상태2·프로젝트상태2·프로젝트유형2)이 전부 들어갔다. P0 의 DB CHECK/enum 은 이 파일에서 생성한다.

| 1 | **가공 방식 어휘** | **정본 무근거 — enum 을 만들지 않았다.** `DataModel §4.2` 는 "어떻게 만들었는지 **한 줄**"(자유 문장, 예시 하나)이라고만 한다. 열거값이 없다. `DOMAINS §3-③`·`PLAN-SoT §9-㉚` 은 이 어휘가 **개발 판단이 아니라 수문학 도메인 소유자(HYD) 협의 사항**이라고 못 박았다 | HYD 협의 → 별도 WU. 그때까지 자유 문자열 |

## 4. 다음 조각의 진입조건

- `contracts/seams/` 는 이 파일의 `$defs` 만 `$ref` 로 참조한다. **seam 안에서 enum 을 다시 선언하면 계약 게이트 red 로 잡아야 한다** — 게이트 규칙은 아직 없다(D2 남은 조각).
- `㉑` D4→D3 읽기 Port(`계보요약(데이터셋ID) → {부모역할별 최대 Lv, 최근 확인 시각, 원천 여부}`)를 OpenAPI 로 옮길 때, 반환의 Lv 는 `ProcessingLevel`, 상태는 `LineageState` 를 쓴다. **값 자체를 다시 열지 않는다.**
