## 수정과 검증

실험 코드만 수정했다. 다른 날짜를 같은 달로 대체, 한글 월 무시, 부모를 검증자료로 오인, 복수 주제 미지원 숨김의 네 실패 시험을 먼저 확인했다. 수정 후 기존 포함 **18개 단위 시험 통과**.

[두 번째 실행](../reports/stage3-ai-search-plan/structured-probe-02.json): 기존12는 자동9통과/1실패/2해당없음, 추가6은5통과/1실패. 실행 종료코드1은 실제 후보 누락 판정이며 준비 실패가 아니다. 실패는006/P2다. 종전10+6 통과는 첫 실행 이력으로 보존하되 현재 결과로 재사용하지 않는다. 코드·시험 파일·질문·snapshot hash를 결과에 기록했다. LLM 호출0, DB/제품 코드 변경0.

## 이어갈 작업 단위와 순서

1. **파일 역할 근거 표**: 9묶음의 검색 핵심 파일에 역할·출처 문단·확인 범위를 기록한다. 특히 rn15 검증과 HLS 검증을 부모 간선에서 추정하지 않는다. 완료 조건:006/P2의 근거 있는 회수와005/007/009의 파일 구분 시험.
2. **기간·지역 증거 표**: 파일명 기간, 실제 시간축, 설명서 범위, 등록 요약을 별도 값으로 보관한다. 완료 조건:4월/5월·특정일·12월31일·지역 충돌에서 충족/불일치/근거없음 구분.
3. **조건 판정 결과 형식**: 후보별 조건·판정·근거·관련 후보 사유를 반환한다. 품질 미확인과 직접관측 불일치를 다른 상태로 표현한다. 완료 조건:011/012를 완전 일치로 표시하지 않는 시험.
4. **미공개 질문 평가 후 사양 작성**: 실험 코드를 고정한 뒤 별도 질문을 받고 수정 없이 최초 결과를 기록한다. 실패 수정 후 같은 질문은 개발셋으로 전환한다. LLM 선택/평가는 사용자 지시대로 보류한다.

이는 승인된 intent 안의 실험 작업 분해이며 제품 API·화면·배포 결정은 아니다.

1번 착수 결과: [파일 역할 근거 표](../../eval/k4-search/file-role-evidence.json)에 핵심10파일의 역할과 설명서 출처를 기록했고 파일명10개 모두 snapshot과 일치함을 검사했다. 기존 레퍼런스 조사에서 옮긴 수동 주석이며 자동 추출 결과가 아니다. 전체108파일 전수 주석도 아니다. 다음 재개 지점은 이 근거를 실험 검색에 연결하고 파일별 역할·포함/제외를 시험하는 것이다. 아직 두 번째 실행의006/P2 실패를 해소했다고 보고하지 않는다.
