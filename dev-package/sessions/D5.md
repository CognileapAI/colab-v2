### 실측으로 새로 확정한 것 (문서에 없던 값)

**HSR `RDR_CMP_HEAD` 필드 오프셋** — 실파일 대조로 확정 (값 일치 검증):
`TIME_SS(관측)@3`(파일명 시각과 일치) · `TIME_SS(생성)@10` · `nx@20`(=2305) · `ny@22`(=2881) · `nz@24` · `dxy@26`(=500) · `num_data@32` · `data_code[16]@33`. 바이트 0~2·17~19 는 미판독 — 쓰지 않는다.
**⚠ 원천 배포본은 헤더가 `num_data=3`(code 1·2·3)을 선언하면서 1블록만 담는다** — 파서는 실크기와 대조해 `block_count_mismatch` 로 기록하고 실재 블록만 읽는다 (가정도, 조용한 버림도 없음).

**⚠ HSR 헤더에 투영 파라미터가 없다 (2026-08-23 추가 실측 · `DATA-REFERENCE §0 M-8` 으로 등재).**
투영 파라미터가 들어갈 자리인 **36~63 B 가 전부 0** 이다. 명세 기재값(Lambert·표준위도 30/60·기준 38/126)으로 재현하면 위도 **0.053°(≈5.9 km = 500 m 셀 11.8 개)** 오차가 남는다 → **HSR 은 다섯 포맷 중 유일하게 기준 격자 파일이 필수인 포맷**이고, **이 모듈이 격자 파일을 요구하고 못 찾으면 FAILURE 로 끝내는 것은 옳은 동작이다.** 옛 `DATA-REFERENCE §1.1` 이 반대로(「헤더가 직접 준다 ✅확인」) 적혀 있던 것은 근거가 **포맷 명세 PDF 였고 실물 바이트가 아니었기** 때문이다. 나머지 4종(nc·tif·hdf·grib)은 파일 내부 정보로 격자가 계산된다(오차 1.3e-5°~0.0). 정본 = `DATA-PIPELINE-MEASUREMENT.md`.

### 라이브러리 — DATA-REFERENCE §5 대비 이탈 1건

HDF4: PoC 방식(rasterio+GDAL HDF4 드라이버)은 **pip 휠에 드라이버가 없어** 불가(§5 가 이미 경고). **`pyhdf`(manylinux 휠) 채택** — 실물 MOD15A2H 판독 E2E 로 검증. 컨테이너 빌드 시 conda 없이 pip 만으로 선다. 나머지는 §5 대로(netCDF4 · rasterio · rio-cogeo · h5py · pyproj).

작은 이미지(한 타일 이하) 산출물은 rio-cogeo 가 오버뷰 0단을 만들어 판정 정본(타일+IFD≥2)에 미달하므로 **최소 1단을 강제**했다 — 판정 규칙을 느슨하게 푸는 쪽은 택하지 않았다.
