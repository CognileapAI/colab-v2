## 0. 30초 요약 — 판정 전에 알아야 할 세 줄

1. **정본은 그래프를 한 번도 말하지 않았다.** 정본 전체에서 `온톨로지` 는 **히트 1건**이고 그 1건은 `백로그.md B-04`(**1차 범위 밖**)의 인용문이며, `지식 그래프` 는 **0건**이다 (§4.1 실측).
2. **따라서 `ONTOLOGY-SCOPE §③` 의 10건은 지금도 대부분 `[정본 무근거]` 다.** 정본은 `㊸` 승인(2026-08-23) 이후 이 영역에서 **개정되지 않았다.**
   **정본이 값으로 답하는 항목 = 0건** · **부분 인용이 가능한 항목 = 3건**(변수 3쌍 · 좌표계 3표기 · 원천 표기 별칭 1~2쌍) · **완전 무근거 = 6건** · **정본이 아니라 Ted 선행 판정으로 이미 닫힌 것 = 1건**(§③-10).
3. **그러므로 G8b 의 실질은 「정본을 뒤져 채우기」가 아니라 「값을 만들 채널을 여는 것」이다.** 그 채널을 여는 질문이 §1-Q1 이고, **나머지 넷은 Q1 이 닫히기 전에는 답할 수 없다.**

## Q3 방법용어 13개의 **동의어 그룹**을 지금 저작하는가

`ONTOLOGY-SCOPE §③-2` 가 지목한 자리이고 `DOMAINS §3-③` 이 명시적으로 물은 질문이다 — **「리샘플과 보간이 같은 가공인가」에 정본은 답하지 않는다.** 정본은 `리샘플` 이라는 말 자체를 쓰지 않는다(쓰는 말은 `재격자화`·`다운스케일`).
**이것이 검색에서 가장 크게 바뀌는 자리다** — §3.2 예시 2 참조. 실측 시드 데이터의 가공 방식(`Nearest`·`Bilinear`·`IDW`·`Co-Kriging`, `SEED-DATA §3.1` D-03~D-06)과 정본 어휘 13개는 **한 글자도 겹치지 않는다.**

| | 내용 |
|---|---|
| **(가)** ★ | **13개를 지금 그룹으로 묶는다.** Ted 가 한 번 앉아 대략 **5~7 그룹 · 엣지 8~15개**를 적는다 `[추정]`. 값의 자격은 Q1 이 정한다 |
| (나) | 묶지 않는다. `K4-b` 는 E1 을 **주제·지명에만** 쓴다 |

**→ 판정:** (가) / (나). (가)면 **덧붙일 질문 하나** — `목업 E-04` 의 「`Lv1 (격자 보간·품질검사)`」 같은 **목업 문자열을 근거로 쓸 수 있는가?**
`㊸-④-2` 에서 Ted 는 주제 목록에 대해 **「목업 주제목록은 목업」**(= 예시이지 정본이 아니다)이라 판정했다. **같은 규칙을 방법용어에도 적용하면 13개 중 상당수의 근거가 흔들린다.**
`ONTOLOGY-SCOPE §④-2` 는 이 판정이 **주제 목록에 한정**되며 방법용어는 「후보일 뿐 닫힌 값이 아니라 지위가 흔들리지 않는다」고 적었다 — **그 해석이 유효한지 한 줄로 확인해 주면 이 자리가 닫힌다.** ★ 유효하다(후보 용도에 한해 목업을 근거로 인정).

# ③ `K1b` 가 곧바로 물을 네 가지

## 3.1 노드 종류와 엣지 종류

**규율 — 정본이 쓰지 않은 어휘를 들여오지 않는다.** 정본에 `클래스`·`인스턴스`·`상위 개념` 같은 말은 **없다**. 그래서 이름을 정본의 말로 짓는다.

**노드 3종 — 이미 표가 있다** (`db/ai/schema.sql`, 실측 §4.2)

| 노드 | 실물 | 정본 어휘 |
|---|---|---|
| **방법 용어** | `d9_method_term (term PK, source_note, created_at)` | 「가공 방식」(`DM §4.2`) |
| **주제** | `d9_topic_synonym.topic` (4값 CHECK) | 「주제 \| 고정 목록에서 선택」(`P04 §5`) |
| **지명** | `d9_place_alias.place_name` | 「'낙동강 유역'은 공간」(목업 E-02) |

> **후보 노드 2종은 열지 않기를 권고한다** — **변수**(#3: 자동 추출이라 D9 의 것이 아니다) · **원천 표기**(#8: Q5 가 예여도 **노드가 아니라 별칭 행**으로 족하다).

**엣지 — Q2 의 E1~E4.** ★ 권고는 **E1「같은 말이다」 한 종류**이고, 그 한 종류가 세 노드 종류 안에서 각각 돈다(방법↔방법 · 질의어↔주제 · 별칭↔표기).
**모양의 함의** — E1 하나면 `K1b` 는 새 표 하나(`d9_term_synonym` 류)면 되고, 기존 3표의 자연키·`source_note NOT NULL`·RLS 면제 판단(`schema.sql` RLS 절)을 그대로 물려받는다. **E2 를 열면 방향 있는 표가 하나 더 필요해진다** — 별칭은 대칭이고 포함은 아니다.

## 3.2 그래프가 검색에서 **실제로 바꾸는 것** — 실물로 짠 예시 3개

전제 — `〈72〉-㉮`: **LLM 은 질의를 검색어·필터로 해석하는 데까지**, **매칭·순위는 `tsvector` + 사전 3종**이 정한다. 그래프는 **해석 결과를 확장하는 자리**에만 들어간다(순위에 들어가지 않는다 → §3.3).
사전 실측값 = 방법 **13** · 주제 동의어 **5** · 지명 별칭 **4** = **22행** (§4.2). 데이터셋은 `SEED-DATA §3.1` 의 제안 15건.

### 예시 1 — 「25년도 낙동강 유역 **강우** 데이터 찾아줘」

- **지금(tsvector + 사전 3종)**: 주제 동의어 표에 있는 것은 `강우데이터`(정본이 준 유일한 동의어)와 주제 표기 4개 항등 행뿐이다. 질의어가 `강우` 로 **한 글자 짧으면 매칭이 없다** → **주제 필터가 안 걸린다.** 남는 것은 데이터셋 이름 문자열 매칭뿐이다.
- **그래프(E1)**: `강우 ≡ 강우데이터 ≡ 강수` → 주제 `강우·강수` 확정 → `D-07`·`D-08`·`D-15` 로 좁힌다.
- **정직한 부분** — 시드 15건에 **낙동강 데이터가 없다.** 공간 축은 그래프가 있어도 **0건이고, 그것이 정답이다**(`P02 §3.3` 0건 안내 — 「우리 연구실 데이터 128개를 뒤졌지만 … 없었어요」). **그래프는 0건을 없애 주지 않는다.**

### 예시 2 — 「**재격자화**한 NDVI 자료」 ★ 가장 크게 바뀌는 자리

- **실물 대조**: 시드의 `D-03`~`D-06` 은 같은 NDVI 를 `Nearest`·`Bilinear`·`IDW`·`Co-Kriging` **네 방법**으로 만든 파생 데이터셋이다(`SEED-DATA §3.1`). 정본 어휘는 `재격자화`·`다운스케일`·`보간 방식(선형/최근접)` 이다.
- **지금**: `재격자화` 와 `Bilinear` 는 **공통 문자가 없다.** tsvector 는 **0건**을 낸다.
- **그래프(E1)**: `재격자화 ≡ 다운스케일 ≡ 보간` 그룹 + `보간 방식(선형/최근접)` 에서 `최근접 ≡ Nearest` · `선형 ≡ Bilinear` → **4건이 잡힌다.**
- **⚠ 이 예시가 Q3 을 필요로 하는 이유** — 위 그룹은 **정본에 없다.** `[정본 무근거]` 이고, **Ted 가 적어야 존재한다.**

### 예시 3 — 「**유럽중기예보센터** 강수 자료」

- **지금**: 결과 카드의 원천 표기는 `ECMWF 재분석`(목업 E-02) 이다. 질의어와 **한 글자도 겹치지 않아 0건**이다.
- **그래프(E4)**: `유럽중기예보센터 ≡ ECMWF` → 잡힌다. `GK2A ≡ 국가기상위성센터` 는 **`DM §4.1` 이 한 표기 안에 함께 적어 두어 정본 근거가 있다**; ECMWF 쪽은 Ted 판정이 필요하다(Q5).

### 반례 — 그래프가 **안 바꾸는** 자리 (범위를 늘리지 않기 위해 적는다)

「충청권 지형 자료」 → 시드 `D-02` 의 이름이 `DEM 100 m 충청권` 이라 **tsvector 가 그냥 잡는다.** 지명 별칭에 `충청권` 이 없어도 된다.
「한강 데이터」 → `한강 상류`·`한강 유역` 은 **접두가 같아 tsvector 가 상당 부분 잡는다.** **E2(위계)의 실이득이 여기서 작아진다** — Q4 권고의 근거다.

## 4.2 `db/ai` 실측 (파일 기준)

- 표 **3개** — `d9_method_term(term PK, source_note NOT NULL, created_at)` · `d9_topic_synonym(synonym PK, topic CHECK 4값, source_note, created_at)` · `d9_place_alias(alias PK, place_name, source_note, created_at)`. **관계·그래프 테이블 0개.**
- 시드 적재 **22행** — 방법 **13** + 주제 동의어 **5**(항등 4 + `강우데이터` 1) + 지명 별칭 **4**. 전 행 `ON CONFLICT DO UPDATE` 로 멱등.
- 커버리지 기준 파일은 **21항목**(방법 13 + 주제 4 + 지명 4). 적재 22 와 수가 다른 이유는 시드 파일이 스스로 적어 두었다(주제는 기준 4값 vs 적재 5행).
- 마이그레이션 **3개** — `0001_p0_ai` · `0002_k1_ontology` · `0003_k2_ontology_seed`. 체인 상태 표는 `alembic_version_ai`(체인 분리의 실물).

> ⚠ **이 수는 시드 SQL 파일을 `cat -n` 으로 센 값이지 `SELECT count(*)` 가 아니다.** DB 에 접속하지 않았다.
> `S1-PLAN §4.3` K4-a 행이 인용한 **13·5·4 = 22 는 파일 기준으로 일치**한다.
> (`DATA-REFERENCE §0` — 측정 안 한 것을 측정된 것처럼 인용하지 않는다.)

## 4.3 이 문서가 하지 않은 것

- **값을 만들지 않았다.** 동의어 한 쌍도 초안 값으로 적지 않았다 — 적는 순간 `㊴-②` 위반이다.
- **DB·게이트를 돌리지 않았다.** 읽기 전용 조사다.
- **기존 문서를 고치지 않았다.** `ONTOLOGY-SCOPE`·`PLAN-SoT`·`03-HANDOFF` 갱신은 **판정이 내려진 뒤** 승인 세션의 일이다(`CLAUDE.md §6`).

## 4.4 판정 뒤에 이어지는 것

1. `PLAN-SoT §9` 에 새 결정(Q1~Q5 의 값과 근거)을 적는다 — **HANDOFF 에는 링크만.**
2. `ONTOLOGY-SCOPE` 에 `§⑥` 다음 절로 2차 범위를 얹고, `§③` 표의 처리 칸을 갱신한다.
3. `K1b` 진입조건 = **Q1·Q2 에 값이 적혀 있을 것.** Q3~Q5 는 `K2b`(적재) 진입조건이다 — **스키마는 엣지 종류만 알면 세울 수 있고 값을 기다리지 않는다.**
4. `K4-a` 는 **이 판정 어느 것도 기다리지 않는다**(`〈71〉-㉱` — 진입조건은 `K4-infra` 하나뿐).
