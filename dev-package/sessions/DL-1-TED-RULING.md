| **집합 D 래퍼** | `deletion_plan(produced, deleted_file_ids=D, …)` 신설 — stale 조건 = `sidecarVersion≥2 ∧ baked_for 있음 ∧ sources≠∅ ∧ sources⊆D ∧ not tile-`. 그 밖은 전부 `kept` |
| 원장 등급 재사용 | 위 이유로 **아무것도 안 지운다** — 조용한 no-op |

**고르면 달라지는 것** — 래퍼는 「없는 필드를 근거로 지우면 오삭제」를 조건에 박아 둔다
(사이드카 부재·구판·일부만 D·`tile-` 은 전부 kept). 계산기 신설은 0 —
`reclaim_plan` 과 같은 모양으로 `keep_keys` 를 계산해 기존 `plan()` 을 부른다.
**한계(정직하게)** — 로컬 루트에서 사라진 산출물(`work` 볼륨 소실 · `down -v` · 인스턴스 교체)의
S3 키는 viz 가 못 찾는다. 그 잔여는 **`U-2` 형제 WU 「미리보기 고아 정리」**(목록 → 사람 확인 →
명시 삭제 · `〈354〉`-㉰ 방식)로 간다. CloudFront `/previews/*` 캐시 **300초 잔존은 수용**
(무효화 선례 0 · IAM 없음 · `〈354〉`-㉱ 「미리보기는 재생성된다」).
**권고 — 승인(집합 D 래퍼 · `tile-` 무접촉 · CloudFront 300초 수용).**
**되돌리는 비용** — 함수 하나 삭제. 지운 바이트는 재생성되므로 데이터 손실이 아니다.

## ⓔ 확인 모달 문면 = 계약 산문 축자

**배경** 사용자가 말한 문면은 「계보 등 연관관계가 있으면 확인 알림 — **관계가 끊어진다**」였다.

**현재 상태** 계약 산문은 **정반대**를 적는다 — 「파일·미리보기만 지우고 이름·주제·Lv·
**계보 관계·프로젝트 연결·Verified 는 남긴다**」. `DeletionImpact` 세 칸의 설명 축자도 같은 축이다 —
「이 데이터로 만든 데이터 N건의 **계보에 자리가 남아요**」 · 「교수 승인이 붙은 데이터예요」 ·
「대기 중인 접근 요청 N건이 자동으로 닫혀요」.

**선택지의 뜻**
| 갈래 | 뜻 |
|---|---|
| **계약 산문** | 「자리가 남아요」. 사용자 표현은 채택하지 않는다 |
| 사용자 표현 | 「관계가 끊어진다」. 정본과 반대라 계약 산문 개정이 먼저 |

**고르면 달라지는 것** — 계약 산문을 쓰면 모달이 **거짓말을 하지 않는다**(관계는 실제로 남는다).
사용자 표현을 쓰면 화면이 남아 있는 것을 없다고 말한다.
**권고 — 계약 산문.** **되돌리는 비용** — 모달 문자열 3줄 ＋ 그것을 잠그는 vitest 3건.
（낱말 축 — 정본 낱말은 **「삭제」**다. 「휴지통」은 레포 0건이라 글리프만 휴지통이고
접근명·버튼 글자는 「삭제」다.）

## ⓕ 「대기 접근 요청 자동 닫힘」의 상태 전이

**배경** 계약 산문 = 「대기 중인 접근 요청은 **자동으로 닫힌다** (§9)」.

**현재 상태 (스키마 실측 · `db/platform/schema.sql`)**
- `d2_dataset_access_request.state` CHECK = **`('검토 대기', '승인됨', '거절됨')` 3값.**
  **「닫힘」 상태가 없다.**
- 짝 CHECK 셋이 함께 걸려 있다 —
  `(decided_by_account_id IS NULL) = (decided_at IS NULL)` ·
  `(state='검토 대기') = (decided_at IS NULL)` ·
  **`(state='거절됨') = (rejection_reason IS NOT NULL)`.**
  ⟹ 「사유 없이 거절」은 DB 가 막는다. 닫으려면 **사유 문자열이 반드시 있어야 한다.**

**선택지의 뜻**
| 갈래 | 뜻 | 비용 |
|---|---|---|
| **`거절됨` ＋ 고정 사유** | `rejection_reason = '데이터가 지워져서 요청이 닫혔어요.'` ＋ `decided_by = 지운 사람` ＋ `decided_at = now()` | 마이그레이션 **0** |
| 4번째 상태 신설(`닫힘`) | CHECK 3개를 함께 고쳐야 한다 | 마이그레이션 1 ＋ 전이표 개정 ＋ 화면 라벨 신설 |

**고르면 달라지는 것**
- `거절됨` → ⚠ **요청자에게 「거절」로 보인다.** P-26(「거절 사유는 요청자에게 그대로 전달된다」)에
  따라 위 문장이 그대로 전달되므로 **왜 닫혔는지는 읽힌다.** 다만 상태 낱말은 「거절」이다.
- `닫힘` 신설 → 전이표(정본 §7.2)가 3값에서 4값이 된다. 정본 개정이 먼저다.
- ⚠ 고정 사유 문자열 `데이터가 지워져서 요청이 닫혔어요.` 는 **`[정본 무근거]`** 다.

**권고 — `거절됨` ＋ 고정 사유.** 마이그레이션 0 이고, 정본이 「닫힘」이라는 **상태**를 만들라고
적지 않았다(「닫힌다」는 동작 서술이다).
**되돌리는 비용** — 나중에 `닫힘` 을 신설하면 이 회차에 `거절됨` 으로 닫힌 행을 소급 이관해야
한다. 지금 대기 요청이 몇 건인지는 `[미측정]` — prod 계수를 재고 판정하는 편이 안전하다.
