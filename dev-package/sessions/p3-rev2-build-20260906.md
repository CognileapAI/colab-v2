## 4. 자기 표시 (판단한 것 · Ted 확인이 필요한 것)

1. **분석 단계를 3개로 정한 근거** — rev1 `pbStatus` 는 문면 **4개**(`파일 올리는 중…` · `파일 읽는 중…` · `확장자·용량 확인 중…` · `분석 완료 · 확장자와 용량을 읽었어요`)를 갖고, 라운드 파일은 「3단계」로 적었다. 화면이 실제로 아는 상태는 셋(전송 중 / 접수됨·미준비 / 준비됨)이라 **`파일 읽는 중…` 을 세우지 않았다** — 넷째 상태가 없는데 문면만 늘리면 화면이 거짓을 말한다. 나머지 3문면은 rev1 축자 그대로다. **판정 필요 = 4문면을 요구로 읽어야 하면 상태 하나(헤더 파싱 시작)를 서버가 실어야 한다.**
2. **⑫ 안내 3문면의 단계 이름 불일치** — rev1 축자 `분류를 고르고 다음에서 데이터 정보를 입력하세요` 는 rev1 의 ① 이 **분류**일 때의 말이고, 코드의 ① 은 `자동 메타데이터 확인`이다. 「판정 없이 고치지 않는다」에 따라 **축자를 그대로 두고 고치지 않았다.** ② 재편(등록 3단계 재편 = WU-B3)이 이 자리를 다시 정한다. **판정 필요.**
3. **⑩ 을 `UsageSection`(접근·다운로드 구역)에 둔 근거** — 상세에 접근·공개 범위 구역 자체가 없다는 것이 PRD-39 실측이다. rev1 원문에서 이 문장이 붙은 자리는 접근·다운로드 카드의 「공개 범위」 값 아래다. **공개 범위 값 칸은 R-B 의 몫**(라운드 §2-⑤ 「R-B 가 더하는 필드 … 그리지 않는다」)이라 값을 지어내지 않고 **출처 문장만** 그 구역에 세웠다. R-B 가 값 칸을 세우면 문장이 그 아래로 붙는다.
4. **HUD 를 `zoom` 없이도 세운 것** — `result.bounds` 만 있으면 역산이 성립하고, 배율이 없으면 항등 변환이다. S-08(미등록 미리보기)에서도 좌표가 읽히므로 rev1 뷰어와 같은 위상이 된다. 서버 왕복은 0이다.
5. **HUD 에 `aria-live` 를 걸지 않았다** — 커서를 따라 초당 수십 번 바뀌는 값을 읽어 주면 보조기술 사용자가 다른 것을 듣지 못한다. 그 사용자의 길은 클릭 기반 값 조회다(존치 6종).
6. **`ValueLookupPanel` 의 `<dt>값</dt>` 을 `셀값` 으로 바꿨다** — 라운드 축자 「출처를 라벨로 갈라 적는다」의 집행이다. 패널·경로·시험은 그대로다(존치 규칙 위반 0).
