⭑ **여기서 실물 결함 둘이 잡혔다. 「기동이 안 선다」로 뭉뚱그리지 않고 값으로 적는다.**

1. **`postgresql://` 로 접속 URL 을 쓰면 세 단위가 기동 루프에 빠진다.**

   ⚠ **이 실패는 헬스에 안 보인다** — `Restarting (1)` 로만 보이고 `/healthz` 는 응답조차 못 한다.
2. **`CREATE DATABASE` 를 한 `-c` 에 둘 넣으면 둘 다 실패한다.** psql 이 묶어 보내 트랜잭션 블록이 되기 때문이다.
   그 실패가 조용히 넘어가 4단까지 갔다 — 그래서 각 단계의 stderr 를 세 줄씩 남기게 고쳤다.

### 2.3 완-비3 — 로그인 200 · cross-tenant 음성 (**닫혔다**)

**`D3b` 의 자세를 따랐다 — 음성이 먼저고, 양성은 음성이 뜻을 갖게 하는 대조군이다.**

```
PASS 완-비3-a 로그인 201 (재발급 자격 파일로 세션이 섰다)
PASS 완-비3-b 음성① 토큰 없는 조회 401
PASS 완-비3-c 음성② 표에 없는 토큰 401
  연구실 A 데이터셋 12건 · B 0건
PASS 완-비3-d 양성 — 자원 보유 연구실 토큰이 12건을 본다
PASS 완-비3-e **cross-tenant 음성㈎** — 다른 연구실 토큰의 목록 0건
PASS 완-비3-f **cross-tenant 음성㈏** — 다른 연구실 토큰으로 id 직접 조회 = 404
```

| 검사 | 값 | 뜻 |
|---|---|---|
| `POST /api/v1/sessions` (재발급 `credentials.json`) | **201** | 계약이 `201` 이다. 「200」은 완료 정의의 표기이고 실물은 201 |
| 토큰 없는 `GET /datasets` | **401** | 인증 없는 표면이 없다 |
| 표에 없는 토큰 | **401** | 재발급으로 **옛 토큰이 죽는다**의 실물 |
| 자원 보유 연구실 토큰 | **12건** | 양성 대조군 |
| 다른 연구실 토큰 목록 | **0건** | cross-tenant 음성㈎ |
| 다른 연구실 토큰 · id 직접 조회 | **404** | cross-tenant 음성㈏ — **목록만 가리는 구현을 걸러낸다** |

⚠ **양성 대조군을 안 세웠다면 이 음성은 거짓이었다.** 실측상 **데이터셋 12건이 전부 한 연구실(`…HYMETS`)에 몰려 있어**,
아무 두 연구실이나 집으면 **양쪽 다 0건**이 나오고 그 0을 「경계가 막혔다」로 읽게 된다. 실제로 한 번 그렇게 읽혔다.
그래서 스크립트가 **원장에서 데이터셋 수를 세어 「자원 보유 연구실」을 A 로 고른다.**
⚠ 그리고 목록 항목의 키는 `id` 가 아니라 **`datasetId`** 다. `id` 로 읽으면 `KeyError` → 0건 → 같은 오독이 된다.
**둘 다 「0건이니 안전하다」로 보이는 실패**였고, 둘 다 이번에 값으로 잡혔다.

## 3. `green-by-skip` — 무엇이었고 어떻게 고쳤나 (`〈170〉-㉮`)

> **`CLAUDE.md §4` 가 존재하는 이유가 이 실패다** — 「v1 CI 가 DB 없이 돌아 RLS 테스트를 green-by-skip 했던
> 실패를 구조적으로 막는 장치」. **그 장치 안에서 같은 실패를 다시 지었다.**

### 3.1 진단

- `verify-volume-artifact.sh` V5 는 오라클 이름이 **빈 값이면 `SKIP`** 하고, 요약줄은 그냥 `결과: GREEN` 이었다
- 실 설정 파일(홈의 `0600` env)에 `COLAB_VOLBACKUP_*` 키가 **한 개도 없었다** — `config.example.env` 에만 있었다
- 그 위에서 `rehearsal.sh` 4단과 `preflight.sh` P3 가 **조건 없이** 「원장 오라클 포함 GREEN」이라 찍었다
- 셀프테스트는 **스스로 키를 세워** 돌기 때문에 전건 GREEN 이었다 — **테스트가 실환경을 안 대변했다**

### 3.2 처치 — 넷

**⑴ 오라클은 코드가 쥔다.** `volume-lib.sh::load_volume_config` 에 기본값을 박았다.
`COLAB_VOLBACKUP_ORACLE_uploads=d3_file` · `_previews=none` · `MIN_FILES` 67·19.
`:=` 는 **미설정과 빈 값을 모두** 덮으므로 실 설정에 무엇이 있든(없든) 오라클이 켜져 있다.
**「손으로 켠 GREEN 은 기구가 아니다」의 유일한 해법은 값을 사람 손에서 빼는 것이다.**

**⑵ 미선언은 RED 다.** `volume_oracle` 의 값이 **세 상태**가 됐다.

| 값 | 뜻 | V5 |
|---|---|---|
| `<테이블명>` | 오라클 있음 | 돈다 |
| `none` | **명시적 면제** — 사람이 「대조 기준이 없다」고 **적은 것** | 승인된 SKIP |
| 빈 값·미설정 | **선언 자체가 없다** | **RED** |

두 상태(있다/없다)로 두면 「선언을 잊은 것」과 「없다고 판단한 것」이 같은 값이 된다. 그 구분 없음이 이 사고였다.

**⑶ SKIP 은 요약줄에 반드시 드러난다.** `lib.sh` 에 `skip_ack` ＋ `verdict` 를 신설하고 **모든 요약줄을 거기 모았다.**
승인된 SKIP 이 있으면 요약줄이 `GREEN (전부 통과 · **승인된 SKIP N건** …)` 이 되고, 0 이면 `GREEN (SKIP 0 — 모든 항목이 실제로 돌았다)` 이다.
**SKIP 건수를 숨긴 GREEN 을 쓸 수 있는 자리를 없앴다.**

**⑷ 같은 결함을 전수 조사했다 — 둘이 아니라 다섯이었다.**

| # | 자리 | 종전 | 지금 |
|---|---|---|---|
| 1 | `verify-volume-artifact.sh` V5 | 오라클 없으면 `SKIP` → `결과: GREEN` | 미선언 = **RED** · `none` = 승인된 SKIP · 요약줄에 건수 |
| 2 | `rehearsal.sh` 4단 | 조건 없이 「아카이브 검사 GREEN(**원장 오라클 포함**)」 | 검사기 **요약줄을 그대로 옮기고** 오라클 이름을 설정에서 읽어 적는다 |
| 3 | `preflight.sh` P3 | 조건 없이 「P3 볼륨 … GREEN (**원장 오라클 포함**)」 | 같은 처치 |
| 4 | `verify-restored.sh` ⑦ 헬스 | `--base-url` 없으면 `SKIP` → 최종 「복원 검증 GREEN」 | **RED.** 일부러 빼려면 `--no-health` 로 **명시**한다 |
| 5 | `verify-restored.sh` 최종 요약 | 「복원 검증 GREEN — **단, ③-보 와 ⑤ 는 손으로**」이면서 `exit 0` | **`exit 3` = 미완.** 손검사를 돌고 `--manual-ok` 를 줘야 GREEN |
| — | `verify-artifact.sh` C6 · `verify-restore.sh` | `--skip-age` SKIP 이 요약에 안 보였다 | `skip_ack` ＋ `verdict` 로 건수가 실린다 |

⭑ **4·5 는 이번에 처음 발견됐다.** 지시받은 둘(V5·P3)만 고쳤으면 「헬스를 한 건도 안 재고 GREEN」과
「손검사 둘을 안 돌고 GREEN」이 그대로 남았을 것이다. **한 종류의 결함은 대개 한 곳에 있지 않다.**

전 패턴으로 보관처와 그 상위 디렉터리를 훑었다.

**삭제 계 = 1건 · 633 B.** ⚠ **내용은 열지 않았고 값은 어디에도 기록하지 않았다**(`〈121〉-㉰` 계열).
같은 이유로 sha256 도 이 문서에 남기지 않는다 — 사본의 지문은 사본의 존재를 증명하는 데 필요 없다.

**그 밖에 걸린 것 0건.** 보관처의 나머지 102 파일은 전부 산출물(`*.sql.gz` · `vol-*.tar.gz` · `.manifest.tsv` · `.pair` · `.sha256`)이다.
상위 디렉터리의 `LAST-SUCCESS.txt` · `staging-backup.log` 둘은 **보관처 밖**이고 비밀이 아니다(스케줄 표식 · `run-scheduled.sh`).

⚠ **왜 이 한 건이 중요한가** — `〈152〉-㉱` 는 픽스처 토큰 폐기를 **401 로 증명**했다.
그 증명 옆에 폐기 전 사본이 평문으로 남아 있으면 **증명이 무른다.** 사본 하나가 401 을 되돌린다.

### 4.2 재발 방지 기구 — 주석이 아니라 검사

**⑴ 보관처 허용 목록** (`lib.sh::backup_dir_offenders`).
보관처에는 **산출물만** 있어야 한다 — `<프로파일>-<stamp>.sql.gz` · `vol-*.tar.gz` · `.manifest.tsv` · `.pair` · `.sha256` · `.inflight-*`.
그 밖의 파일이 하나라도 있으면 RED. **배제 목록이 아니라 허용 목록이라 「아직 생각 못 한 모양의 비밀」도 걸린다.**
배제 목록은 언제나 뒤늦는다 — 이번 사본도 「subjects 라는 이름을 미리 배제했다면」 막혔을 물건이 아니다.

거는 자리 **셋**:

| 자리 | 언제 | 무엇을 한다 |
|---|---|---|
| `backup-full.sh` **0단** | 매 백업 시작 전 | 규약 밖 파일이 있으면 **백업을 시작하지 않는다**(`exit 1`) |
| `latest-check.sh` | 주간 재검사 | 같은 질문을 다시 던진다 — 흘러든 것을 늦게라도 잡는다 |
| `preflight.sh` **P10** | 복원 직전 | 사전조건 RED. 사본을 안은 채 복원에 들어가지 않는다 |

**⑵ 이름 모양 판정기** (`lib.sh::secret_shaped`).
허용 목록을 못 쓰는 자리(볼륨 트리)에서 쓴다. `backup-volume.sh` 가 **매니페스트를 만든 직후** 이것으로 훑고,
비밀 모양 경로가 하나라도 있으면 **아카이브를 만들지 않는다.**
⚠ **조용히 제외하지 않고 실패시킨다.** 제외하면 아카이브와 원장이 어긋나 오라클이 거짓 RED 를 내고,
사람이 그 RED 를 「원래 그렇다」로 읽게 된다. **볼륨에 비밀이 들어간 것 자체가 사고**이므로 선다.

**⑶ 값은 어디에도 안 남긴다.** 세 자리 전부 **이름과 건수만** 찍는다. 내용을 여는 코드 경로가 없다.

**⑷ 일회용 스택의 재발급본도 남기지 않는다.** `throwaway-stack.sh` 는 비밀 7종을 `0700` 임시 디렉터리에 만들고
**`trap EXIT` 에서 지운다.** 보관처에 놓는 경로가 없다.

### ㉰ 이번 회차가 잡은 실물 결함 넷 (`throwaway-stack.sh` 를 세우다 나온 것)

## 7. 안전 경계에 걸려 못 한 것

- **crontab 재설치를 하지 않았다** — 시스템 설정이고 본 레포 경로를 가리킨다. 위 `§6` 에 남겼다
- **살아 있는 staging 을 재기동하지 않았다** — `§4.6-④`(복원 전후 digest 동일성)의 실사고 버전은 재기동을 요구한다
- **살아 있는 비밀 파일을 열지 않았다** — 재발급 절차는 **새 값으로** 재현했다. `P6` 는 존재·권한만 본다
- **`cloudflared` 를 일회용 스택에 안 띄웠다** — 같은 터널 토큰의 두 번째 커넥터가 실트래픽을 가로챈다.
  그래서 기동 시간이 **7 컨테이너 값**이고, 그 사실을 값 옆에 적었다
