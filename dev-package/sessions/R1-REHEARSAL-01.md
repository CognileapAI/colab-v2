## 3. `subjects.json` 재생성 — 형식은 닫혔고 기동은 안 닫혔다

**형식 (레포에서 읽었다 · 값은 지어내지 않았다)**

- 정본 근거 = `services/core-api/tests/fixtures/subjects.json` 실물 ＋ `services/core-api/src/colab_core/kernel/auth.py` 의 `SubjectRegistry.from_file`
- 구조 = **평평한 한 겹 맵**. `{"<토큰문자열>": {"accountId": "<ULID>", "labId": "<ULID>"}}`
- **키가 곧 베어러 토큰**이다 — `bearer_token()` 이 `Authorization: Bearer <키>` 에서 뽑은 문자열을 그대로 `resolve()` 에 넣는다
- 값의 두 키는 **필수**다. `accountId`·`labId` 둘 다 `Ulid(...)` 로 강제 파싱되므로 **ULID 가 아니면 적재 시점에 터진다**
- 만료·역할·스코프 필드가 **없다**. 파일이 곧 발급대장이고, 끊는 수단은 **키를 지우는 것뿐**이다
- ⚠ `labId` 를 요청에서 받지 않는다 — **연구실 경계가 오직 이 파일에서 나온다**(`auth.py` 머리말)
- ⚠ **레포 픽스처 값을 staging 에 올리지 않는다.** 그렇게 배포된 적이 있다(`RESTART §2-1`). 토큰은 새로 만든다(`openssl rand -hex 32`)

**완-비2 「재발급본으로 기동이 선다」 — 이번에 못 닫았다. 무엇이 없어서 못 닫았나 (정확히)**

1. `rehearsal.sh` 에 **컨테이너를 띄우는 단계 자체가 없다.** 6단은 형식을 화면에 찍을 뿐이고, 일회용 인스턴스는 `postgres:16-alpine` **하나**다 — `core-api` 이미지를 기동하는 경로가 스크립트 어디에도 없다
2. `core-api` 를 띄우려면 **DB 접속 URL 파일이 있어야 한다.** 지금 있는 5종은 전부 **살아 있는 staging DB** 를 가리킨다. 그것을 일회용에 물리면 「일회용에만 쓴다」가 깨진다 — 그래서 시도하지 않았다
3. 일회용에 물릴 URL 을 새로 쓰려면 **일회용 pg 에 소유자·앱 롤을 세우고**(`services/core-api/ops/app-role.sql`) 그 값으로 `0600` 파일 5개를 만들고, `compose` 의 `:?` 13키를 **일회용 프로젝트명으로 갈아** 띄워야 한다. 이것이 `§5-2` 「별도 compose 프로젝트명으로 전체 기동」이고, **2회차 범위**다
4. 즉 결손은 **「기구가 안 선 것」**이지 「돌렸는데 실패한 것」이 아니다. 필요한 물건 = `rehearsal.sh` 에 붙는 **일회용 compose 프로젝트 기동 단(段)** 하나

> **형식을 안 것과 기동이 선 것은 다르다.** `REHEARSAL.md` 가 미리 그렇게 적었고, 실행 결과가 그 문장을 그대로 확인했다.

- 실해(實害) = **없다.** 전부 셸 에러로 끝났고 SQL 이 DB 에 닿지 않았다. 다만 **단계 제목이 잘려 나갔다**(「§5-1 — → 재적재」처럼)
- ⚠ **위험한 성질** = 백틱 안에 파괴적 명령을 적은 주석을 넣으면 그것이 **실행된다.** 지금은 우연히 무해할 뿐이다
- 고칠 자리 = `step()` 에 넘기는 문자열을 홑따옴표로 바꾸거나 백틱을 이스케이프. ⚠ **`infra/staging/**` 이라 이번에 안 고쳤다**

### ㉰ `preflight.sh` 1차 RED 4건 — 셋은 설계대로, 하나는 순서 문제

| 항목 | 1차 | 2차(리허설 뒤) | 판정 |
|---|---|---|---|

### ㉱ 보관처에 비밀 사본이 하나 있다 — `§7` 판정과 어긋난다

- 백업 보관처에 `subjects-20260827T051347.json`(633 B · `0600`)이 놓여 있다
- `R1-RESTORE-DRAFT §7`(Ted 판정 `〈163〉-㉲`) = **비밀 7종을 백업하지 않는다.** 사본이 원본과 같은 머신 1대 위에 놓이기 때문이다
