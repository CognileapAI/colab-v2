## 4. 지속적 통합의 의존 설치 단계 — 실물 확인

`.github/workflows/ci.yml` 전문을 읽었다.

- **`npm`·`yarn`·`pnpm` 문자열이 파일 전체에 0 건이다**(`grep` 결과 비어 있음).
- 계약 게이트 잡(`contract-gates`)과 자기검사 잡(`gate-selftest`) 은 `actions/cache@v4` 로 **`contracts/node_modules` 와 `gates/tools/node/node_modules` 를 복원만** 한다. **채우는 단계가 없다.** 캐시가 비면 영구히 빈다.
- **`frontend/` 는 캐시 대상에도 없다.** 설치도 복원도 없다.
- `generated-up-to-date` 게이트의 등기부 첫 항목이 요구하는 명령은
  `frontend/node_modules/.bin/openapi-typescript contracts/seams/fe-core.yaml -o {OUT}`
  (`contracts/codegen/manifest.toml`). **이 경로가 없으면 게이트는 red 다.**
- 파이썬 쪽은 다르다 — `dormant-tests` 잡은 `pip install -r requirements.txt` 를 **실제로** 돌리고, 게이트 가상환경은 `gates/tools/_venv.sh` 가 스탬프 대조로 스스로 다시 짓는다. **끊긴 것은 노드 쪽뿐이다.**

**앞선 회차의 추정은 맞다.** 원인은 `frontend/node_modules` 의 부재이고, 그 부재의 원인은 지속적 통합 잡에 설치 단계가 없는 것이다.

**로컬 실측 (2026-08-28)** — `./gates/run.sh generated-up-to-date` = **green** (「등기부 4건 전부 재생성 일치, 등기부 밖 자칭 생성물 0건」). 로컬에는 `contracts/node_modules`·`frontend/node_modules`·`gates/tools/node/node_modules` 셋이 다 있다. **즉 로컬 green 은 지속적 통합의 상태를 말해 주지 않는다.**

`[미확인]` — **지속적 통합의 실제 실행 결과**. 이 조사는 워크플로 정의와 게이트 코드만 읽었고 GitHub Actions 실행 로그를 보지 않았다. 푸는 것 = 최근 실행의 `contract-gates`·`gate-selftest` 잡 로그 1 회 조회.
