## 1. 재현 — **재현됨. 원인 지점 = LLM 질의 해석**

### 1.1 실행 조건

- 대상 = staging `ai-service` 컨테이너의 `POST /searches` (`services/ai-service/src/colab_ai/app/main.py:61`)
- 방법 = 컨테이너 내부에서 동일 본문으로 연속 호출. 간격 = 즉시 연속(수 초 이내). DB 무변동 상태(적재 병행 없음 — §2-ⓐ)
- 관측 값 = 응답의 `interpretation.terms` · `topic` · `source` · `isDataQuery` · `expansions`

### 1.2 「강수량」 10회 — `terms` 가 3종으로 갈림

| 회차 | terms | 빈도 |
|---|---|---|
| 1·2·3·4·6·7·8·9·10 중 8회 | `('강수량',)` | 8/10 |
| 5 | `('강수량', '강수')` | 1/10 |
| 0 | `('강수량', '강수', '강우')` | 1/10 |

- 10회 전부 `source='llm'` · `degraded=False` · `topic='강우·강수'` · `expansions=()`
- DB 대조(§1.4) — `('강수량',)` 는 **1행**, `('강수량','강수','강우')` 는 **3행+**. 평가셋의 3건↔1건 진동과 일치

### 1.3 「다운스케」 10회 — `isDataQuery` 판정 자체가 갈림

| 회차 | isDataQuery | terms | 빈도 |
|---|---|---|---|
| 0·2·3·4·7·9 | `true` | `('다운스케',)` | 6/10 |
| 1·5·6·8 | `false` | `()` | 4/10 |

- `isDataQuery=false` 이면 core-api 가 검색을 아예 돌리지 않음 (`services/core-api/src/colab_core/app/routes/catalog.py:252` — `answer["isDataQuery"] and answer["terms"]` 조건) → **0건**
- `('다운스케',)` 이면 접두 질의 `다운스케:*` 가 설명의 `다운스케일링` 토큰에 맞음 → DB 대조 **3행** (§1.4)
- 평가셋의 0건↔3건 진동과 일치

### 1.4 DB 층 대조 — 고정 검색어로는 **완전 결정적**

- `_SEARCH` (`services/core-api/src/colab_core/domains/d3_catalog.py:210`) 와 동형의 SQL 을 검색어 고정
  `ARRAY['강수량','강수','강우']` 로 staging `colab_platform` 에 **5회 반복** → 결과(식별자·rank·순서) md5 **5회 전부 동일**
  (`10ae63c2e8090de88ae0609636f7a620`)
- 동점 3행(rank 2.2 동일)도 식별자 오름차순으로 **매회 같은 순서**
- 단일 검색어 대조 — `ARRAY['강수량']` = 1행 · `ARRAY['다운스케']` = 3행. §1.2·§1.3 의 건수 진동을 검색어 차이만으로 전부 설명

### 1.5 패턴 판정

- 시간 경과 종속 아님 · 호출 순서 종속 아님 · **호출별 무작위** — 같은 입력의 연속 호출에서 확률적으로 갈림
- 발생 지점 = LLM 응답 두 값: ① `terms` 의 표기 변형 개수 ② `isDataQuery` 판정

## 3. 결정성 판정 기준

`PLAN-SoT §9-〈72〉` 원문 근거 — 「LLM 이 순위를 정하면 **같은 질의가 때마다 다른 순서를 내고** 근거 한 줄이 사후 정당화로 전락하며, **평가셋으로 회귀를 잡을 수 없다**」. `〈89〉-㉮③` — 「넷 다 DB 가 낸 결정적 값이라 **같은 질의가 같은 순서를 내고** 평가셋이 회귀를 잡을 수 있다」.

| 층위 | 요구 | 근거 |
|---|---|---|
| ① 결과 집합 동일 | **요구됨** | 순서 동일의 전제. 평가셋 판정 단위가 집합(건수·구성)이다 |
| ② 순서 동일 | **요구됨** | `〈72〉`·`〈89〉` 원문이 「순서」를 명시 |
| ③ 관련도 값 동일 | `[정본 무근거]` | 정본은 순서까지만 말한다. 다만 §1.4 실측상 rank 값도 동일했고, `relevanceBar` 는 rank 의 정규화라 ①·②가 서면 따라온다 |
| 적용 범위 (동일 질의 = 자연어 원문 기준인가, 해석된 검색어 기준인가) | **정본이 답하지 않음 — Ted 판정 필요** | `〈72〉` 는 LLM 을 해석에 한정하며 순위 결정성을 세웠으나, 해석 자체의 진동으로 **자연어 원문 기준의 종단 결정성은 현재 구조에서 성립 불가**(LLM API 는 `temperature=0`·`seed` 지정으로도 결정성 미보장 — 공급자 무보증) |
