# 이태헌 님께 — 1차 검증 회신

> **발송본 · 데이터 재투입·검증 완료 뒤 Ted 발송**

이태헌 님, 1차 검증 16건을 받아 화면과 코드에 하나씩 대조했습니다. 14건은 이번 작업에 반영했고, 나머지 2건은 코드 변경 없이 아래와 같이 정리했습니다.

## 1. 「할 일 함」 표기

- 오탈자가 아니라 기획 정본에서 정해 둔 용어입니다.
- 쓰이는 곳 — 화면 두 곳의 글자 · 화면과 서버가 주고받는 규격 문서의 설명 · 권한 원칙과 기능 구분 문서 · 기획 정본의 개정 기록.
- 다른 표기(「할 일함」·「할일함」·「할 일 목록」)는 문서와 코드 전체에서 0건입니다.
- 현 표기를 유지합니다.
- 바꾸기를 원하시는 경우의 순서입니다.
  1. 기획 정본의 용어를 먼저 고칩니다. 원하시는 표기를 알려 주시면 정본 개정안을 드립니다.
  2. 그 뒤 목업, 규격 문서의 설명, 화면 두 곳을 한 번의 작업으로 함께 바꿉니다.
  3. 정본보다 화면을 먼저 바꾸면 문서와 화면이 서로 다른 말을 하게 되므로, 이 순서로만 진행합니다.

## 2. 로그인 실패 뒤 이메일 칸이 비는 현상

- 코드 확인 결과 — 로그인에 실패하면 비밀번호 칸만 비웁니다. 이메일 칸을 비우는 동작은 코드에 없습니다.
- 보신 현상은 브라우저 자동완성이나 비밀번호 관리 확장 프로그램이 칸의 값을 바꾼 것일 가능성이 큽니다.
- 화면 쪽 결함은 확인되지 않아 이 건은 코드 변경 없이 마무리합니다.

## 3. 나머지 지적에 대한 이번 반영 요약

1. 상단 — 눌러도 동작이 없던 연구실 표기와 이름 옆 화살표를 누를 수 없는 표시로 정리했고, 휴대전화에서는 「더보기」 목록에서 기능 이름을 글자로 확인할 수 있게 했습니다.
2. 계정·구성원 — 계정 관리 화면의 표 좌우 이동 안내·초기 비밀번호 자동완성·본인 비활성화 버튼 잠금을 고쳤고, 비활성 계정은 구성원 권한 표에서도 「비활성」으로 보이고 권한 편집이 잠기도록 했습니다. 연구실 설정 화면의 제목 단계도 바로잡았습니다.
3. 목록·등록·검색 — 프로젝트 카드를 키보드로 열 수 있게 했고, 빈 데이터셋 표에 안내를 넣었으며, 승인 대기 칸을 한국어로 표시했고, 가공 단계는 계보 계산값을 기본으로 삼아 다르면 표식과 이유를 보여 주도록 했으며, 검색 범위 줄이 실제로 찾은 범위와 건수를 말하도록 고쳤습니다.

- 이번에 넣지 않고 다음으로 미룬 것 — 한 연구실만 골라 보는 전환 · 사용자 이름 메뉴 · 가공 단계를 계산값과 다르게 고를 때 사유를 적는 절차 · 표 줄 전체를 키보드로 여는 나머지 자리. 순서가 정해지면 다시 공유드립니다.
- 반영된 화면은 dev 에 2026-09-14 반영했습니다. dev 데이터 재투입이 끝난 뒤 확인하실 수 있습니다(발송 시점 기준 완료).

이번에 화면에 새로 넣은 안내 글자는 아래 여섯 가지이며, 표기에 의견이 있으시면 알려 주세요. 의견이 없으면 이대로 확정합니다.

1. 「승인 전」 — 승인 대기 칸
2. 가공 단계가 계산값과 다를 때의 한 줄 — 「고른 가공 단계는 LvN이고, 연결한 데이터로 계산하면 LvM이에요(사람이 고른 값 / 주입력 부모 중 최대 Lv＋1 · 부모가 없으면 Lv0). 그대로 두어도 등록돼요.」
3. 「계산값과 다름」 — 목록 표식
4. 「자기 계정은 비활성화할 수 없어요」
5. 「비활성 계정은 권한을 바꿀 수 없어요」
6. 가공 단계가 계산값을 따라가는 동안 부모 선택 단계에 안내를 둘지 여부 — 현재 = 두지 않음
