## ① `연구실 설정 > 구성원·권한` — 권한 값의 원천

**출처**: `에픽/E-01_역할과_권한/documents/Policy_역할과_권한.md` v1.3, §3(52행)·§5(71,81행)·changelog(168행)
> "권한 스위치는 `연구실 설정 > 구성원 · 권한`에서 고친다" / "고치는 자리는 `연구실 설정 > 구성원 · 권한` 한 곳이다. 구성원을 행, 권한 네 가지를 열로 놓은 표에 칸마다 체크박스를 둔다"

**의존**: 도메인 D2(Access & Policy, 주) + D1(Identity & Lab, 연구실·구성원 목록). 선행 화면 없음 — 자립 화면. 데이터 의존: D1의 구성원 레코드, D2의 권한 스위치 4종.

**현재 상태**: 순서표 어디에도 없다. P0는 "권한 게이트 틀"(소비 장치)만 있고 **값을 바꾸는 화면은 없다.** P8은 "화면별 적용 지점 표"(E-01 §7, 정책 문서)일 뿐 이 화면과 다르다.

**배정 제안: P1**
- P0는 스캐폴드(셸·게이트 틀)만 닫는 단계라 값 편집 UI를 얹기엔 이르다.
- P6(승인 처리)이 `승인 위임`·`연구실 설정` 위임 값을 실제로 소비하므로, 그 전에 값을 켜고 끌 화면이 있어야 한다.
- P1은 이미 "읽을 화면을 먼저 세운다"는 원칙 아래 카탈로그·데이터셋 헤더를 넣는 단계다. 구성원·권한 화면도 읽기/쓰기 화면이라 P0 직후 결이 같다.
- WU-G4 원문 제안 범위(P0~P1)와 일치 — P1로 확정 제안.

## 판단이 필요한 지점 (본 세션에서 결정하지 않음)

1. **P1 행에 D2·D1을 추가하면 §7 T-P 도메인 열의 의미가 바뀐다** — 지금까지 "주 도메인" 1개만 적던 관례(P0만 예외로 복수)를 P1에도 확장하는 것. 표기 규칙을 먼저 정할지 확인 필요.
2. ①을 P1에 넣으면 P1의 "*읽을 화면을 먼저 세운다*"라는 단계 취지 문구를 수정할지(권한 편집은 "읽기"가 아니라 "쓰기") — 문구 그대로 둘지 판단 필요.
3. G4 행 자체의 완료 판정("순서표 갱신")을 이 제안 반영 시점에 닫을지, 아니면 실제 표 편집까지 별도 승인을 받은 뒤 닫을지 — 이번 세션은 편집하지 않았으므로 미결.
