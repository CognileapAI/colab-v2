## 2. 테이블 3개 — 컬럼과 정본 근거

인용 표기는 `ONTOLOGY-SCOPE.md` 상단과 같다(`DM`=DataModel v1.8, `P04`=Policy 업로드와 계보 확정 v2.2, `목업`=해당 에픽 mockups).
세 표 모두 **`lab_id` 컬럼이 없다.** 그것이 §3 판단의 물리적 근거다.

### 2.1 `d9_method_term` — 가공 방식 후보 어휘

| 컬럼 | 형 | 정본 근거 |
|---|---|---|
| `term` **PK** | `text`, `btrim(term)=term`, 길이 **1~120** | 어휘 목록의 출처는 `ONTOLOGY-SCOPE §2.6-⑴` 의 정본 인용표 13개(`격자 보간`·`유역 평균`·`재격자화`·`편의 보정`·`다운스케일`…). 길이 상한 120 은 **가공 방식 한 줄의 정본 상한** 그대로 — `P04 §5` 「1자 이상 120자 이하」 |
| `source_note` | `text` NOT NULL, 공백만 불가 | **이 표의 핵심 방어장치다.** 어휘마다 정본 출현 위치를 강제로 적게 해 `[정본 무근거]` 어휘가 조용히 섞이지 못하게 한다 (`§9-㊴-②` · `DOMAINS §7` 규칙 4) |
| `created_at` | `timestamptz` DEFAULT now() | 레포 관례 |

**값을 닫는 표가 아니다.** `㊸-④-1 (다)` — 저장·계약은 자유 문자열 유지, 이 13개는 **제안 문장·자동완성 후보**로만 쓴다.
근거: `DM §4.2` 「어떻게 만들었는지 **한 줄**」 · `P04 §5` 자유 문장. `DM §4.2` 의 예시(`일 단위 평균 후 유역 경계로 잘라냄`)는 어떤 enum 값에도 들어가지 않는다.

**두지 않은 컬럼** — 동의어 그룹·정규형 컬럼. `재격자화 ≡ 리샘플` 판정은 정본이 답하지 않았고(`§③-2`), 컬럼을 두면 그 자리를 발명이 채운다.

### 2.2 `d9_topic_synonym` — 주제 동의어

| 컬럼 | 형 | 정본 근거 |
|---|---|---|
| `synonym` **PK** | `text`, 1~120 | 정본이 든 유일한 증거 — 「'강우데이터'는 강수 주제로 일치」(목업 E-02, `§2.2-⑴`). **PK 를 질의어에 둔 이유**: 다의어 처리 규칙이 정본에 없다(`[정본 무근거]`). 규칙 없이 1:N 을 열면 "어느 주제를 고르나"를 구현이 발명하게 된다 |
| `topic` | `text` NOT NULL, **CHECK 4값** `강우·강수 / 식생·NDVI / 지형·DEM / 토지피복·LULC` | `P04 §5` 입력값 규칙 + `㊸-④-2` **(가) 문서가 정본.** Ted 판정 원문 「목업 주제목록은 목업」 — 홈 데이터 맵 목업의 `유출·수문` 은 반영하지 않는다. 이 CHECK 가 그 판정을 DB 층에 굳힌 것이다 |
| `source_note` | NOT NULL | 위와 같다 |
| `created_at` | | |
| 인덱스 `d9_topic_synonym_topic_idx (topic)` | | 주제 → 동의어 역방향 조회 |

**주제 값 자체의 소유는 D3 다**(`§2.2-⑶`). D9 가 갖는 것은 매핑뿐이다.
4값을 여기에도 적은 이유: 체인이 분리돼 있어 카탈로그 목록을 FK 로 참조할 수 없다(`CLAUDE.md §3-3`). **두 곳이 각각 같은 정본(`P04 §5`)을 옮겨 적는 것**이지, D9 가 값을 소유하는 것이 아니다.
> 비대칭 하나를 명시해 둔다 — 기록 쪽 `topic` 컬럼에는 CHECK 가 없다(자유 text). 이 세션은 기록 쪽을 건드리지 않았다. 두 곳을 맞출지는 D3/P1 의 판단이고 K1 의 범위가 아니다.

### 2.3 `d9_place_alias` — 지명 별칭

| 컬럼 | 형 | 정본 근거 |
|---|---|---|
| `alias` **PK** | `text`, 1~120 | 「'낙동강 유역'은 공간」(목업 E-02). 별칭이 키다 |
| `place_name` | `text` NOT NULL, 1~120 | 정본이 쓴 표기 — `낙동강 유역` · `한강 상류` · `금강 하굿둑`(`§2.4-⑴`). 별칭 = 표기인 행(자기 자신)도 허용 |
| `source_note` | NOT NULL | 위와 같다 |
| `created_at` | | |
| 인덱스 `d9_place_alias_place_idx (place_name)` | | 표기 → 별칭 역방향 |

**위계가 아니라 별칭만이다**(`㊸`·`§2.4-⑶`). 부모 컬럼·유역 코드·좌표·행정 대응을 두지 않았다 — 정본에 포함 관계를 정의한 곳이 없다(`§2.4-⑵`). 두면 정본에 없는 위계를 발명하는 것이다.

### 2.4 ID 정책 — ULID 를 쓰지 않았다

기록 쪽은 `ulid` DOMAIN 을 쓴다. 여기서는 **자연키**를 썼고 이유는 셋이다.

1. 사전의 정체성은 어휘 그 자체다 — 같은 어휘가 두 번 들어오면 그것이 곧 중복이다
2. 이 행을 밖에서 id 로 가리키는 곳이 없다 — 소비자는 D10 하나이고 오가는 값은 문자열이다(`§⑥-3` 읽기 전용 Port)
3. K2 시드 적재가 어휘 기준으로 멱등해진다 (`ON CONFLICT (term)`)

`contracts/schemas/common.json` 의 `Ulid` 는 여전히 **정규 ID 타입의 유일한 정의처**다(`CLAUDE.md §3-6`). 여기서 그 타입을 안 쓴 것이지, 다른 ID 타입을 새로 만든 것이 아니다.

## 3. RLS 판단 — **연구실 무관(면제)** 이고, 그 판단의 근거

세 표 전부 **테넌트 데이터가 아니다.** `allow_no_rls` 에 이름을 하나씩 올렸다. 근거는 넷이다.

| # | 근거 | 출처 |
|---|---|---|
| 1 | D9 는 **연구실 공통 지식**이고 테넌트별로 갈리지 않는다 | `DOMAINS.md` D9 · `db/ai/schema.sql` 원 헤더 주석(P0 이 미리 적어 둔 판단) |
| 2 | **값의 출처가 기획 정본 인용뿐이다.** K2 시드가 넣는 것은 §2.6 표의 13개 + 주제 4값 + 지명 4개이고, 이건 어느 연구실의 데이터도 아니다 | `ONTOLOGY-SCOPE §⑥-4` |
| 3 | **되먹임 루프를 1차에 만들지 않는다.** 사람이 고쳐 쓴 가공 방식 문장은 기록 쪽에 저장되고 **D9 로 돌아오지 않는다**. 즉 연구실 데이터가 이 표에 들어올 경로 자체가 없다 | `ONTOLOGY-SCOPE §2.6-⑷` · `§⑤-5`(되먹임은 미채택 제안) |
| 4 | 주제 고정 목록은 「연구실이 항목을 추가할 수 없다 — 항목 추가는 운영팀이 한다」로 못 박힌 **전역 값**이다. 그 위에 다는 동의어도 전역이다 | `P04 §5` |

**반대 방향의 실패도 검토했다.** 공유 어휘를 RLS 로 밀어 넣으면 `lab_id` 없는 행이 모든 연구실에서 안 보이게 되어(`current_lab_id()` = NULL 비교 → 기본 거부) 사전이 통째로 못 쓰게 된다. 그래서 면제가 편의가 아니라 **사실**이다.

**뒤집히는 조건을 명시해 둔다** — 이 표에 연구실 데이터가 한 줄이라도 들어오게 되는 날(예: `§⑤-5` 되먹임 채택, 연구실별 사용자 사전), 그 표는 `allow_no_rls` 에서 내려가고 `lab_id` + `lab_boundary` 정책을 받는다. 이 문장을 allow-list 주석에도 같이 적었다.

### 게이트 설정을 고친 것에 대하여

`gates/` 편집은 원칙적으로 하지 않는다. `rls-allowlist.toml` 은 예외로 판단했고 근거는 **그 파일 자신의 주석**이다.

- 파일 첫 줄: 「rls-coverage 게이트의 **유일한 정의처**. 스크립트는 목록을 갖지 않는다」 → 판정 **로직**이 아니라 **사실 선언**이다
- `[ai]` 섹션에 P0 이 미리 적어 둔 안내: 「접두사가 아니라 **이름을 하나씩 적는다.** 접두사 면제는 나중에 아무 테이블이나 숨는 문이 된다」 → **테이블이 생길 때마다 이 파일에 판단을 한 줄 남기는 것이 설계된 흐름**이다
- 검사 대상을 줄인 것이 아니다. 오히려 세 이름이 목록에 오르면서 「목록에만 있고 DB 엔 없는 테이블도 red」 규칙의 감시 대상이 셋 늘었다

게이트 우회·비활성화·검사 축소는 하나도 없다.

## 5. 게이트·왕복 증명

검증 DB 는 **일회용**이었다 — 컨테이너 `c1_pg` 1개, **호스트 포트 publish 0개**, PGDATA tmpfs, 검증 후 `docker rm -f` 로 제거. staging 컨테이너(`colab_v2_staging_*`)는 건드리지 않았다.

### 5.1 게이트 (2026-08-23 실측)

| 게이트 | 결과 | 출력 요지 |
|---|---|---|
| `migration-single-head` | **green** | `db/platform: 리비전 1건 · head 1개` / `db/ai: 리비전 2건 · head 1개 (0002_k1_ontology)` |
| `rls-coverage` | **green** | 조사한 테이블 **24건**. `d9_method_term`·`d9_place_alias`·`d9_topic_synonym` = `RLS 면제(allow-list)`, 그 밖 전부 `rls=on force=on` |
| `schema-diff` | **green** | `db/platform green — 드리프트 없음` · `db/ai green — 드리프트 없음` · `두 체인 각각 선언 = 적용`. 체인별 변수 `COLAB_APPLIED_DB_URL_PLATFORM`·`_AI` 둘 다 지정 |
| `ai-no-lineage-write` | **green** | `L3 체인층 db/ai 마이그레이션 4건 · db/platform 3건` → 세 층 모두 쓰기 경로 없음 |

절차: ① `db/ai/schema.sql` 을 빈 postgres 에 적용 → OK ② `db/ai` 체인을 `applied_ai` 에 `upgrade head` ③ `db/platform` 체인을 `applied_platform` 에 `upgrade head` ④ 위 게이트 실행.
**선언과 마이그레이션이 서로 다른 경로로 만든 스키마가 정확히 같다**는 것이 `schema-diff` green 의 내용이다.

### 5.2 예시 인스턴스 왕복 (`WORK-UNITS §8` K1 완료 판정)

마이그레이션으로 만든 `applied_ai` 에 직접 넣고 읽었다.

| 단계 | 결과 |
|---|---|
| ① 삽입 | `d9_method_term` 3행 · `d9_topic_synonym` 2행 · `d9_place_alias` 2행 — 전부 성공 |
| ② 읽기 | 세 표 모두 값·`source_note`·`created_at` 왕복 확인 |
| ③ 소비 질의 | K3 자동완성: `term LIKE '격자%'` → `격자 보간` · K4 주제축: `synonym='강우데이터'` → **`강우·강수`** · K4 공간축: `alias='낙동강'` → **`낙동강 유역`**. 정본의 검색 근거 문장 두 줄이 그대로 재현된다 |

**음성 3종도 실제로 거부됐다** (제약이 장식이 아님의 증명).

| 시도 | DB 응답 |
|---|---|
| 목업의 `유출·수문` 을 주제로 삽입 | `ERROR: violates check constraint "d9_topic_synonym_topic_check"` — `㊸-④-2` 판정이 DB 층에서 강제된다 |

| `강우데이터` 를 두 번째 주제에도 매핑 | `ERROR: duplicate key ... d9_topic_synonym_pkey` — 다의어를 구현이 임의로 고르는 일이 생기지 않는다 |

## 6. `[정본 무근거]` 로 남긴 것 · 못 정한 것

### 6.1 채우지 않은 자리 (`ONTOLOGY-SCOPE §③` 10건을 그대로 승계)

K1 은 이 중 **하나도 채우지 않았다.** 채우려면 기획 정본 개정이 먼저다(`§⑥-5`).

| # | 없는 것 | K1 의 처리 |
|---|---|---|
| 1 | 가공 방식 **enum** | 표를 만들되 값을 닫지 않았다. 계약·기록 쪽 자유 문자열 무변경 |
| 2 | `리샘플 ≡ 보간` 동일성 판정 | 동의어 그룹 컬럼을 **두지 않았다** |
| 3 | 변수 사전 (`유출`·`수위` 포함) | 테이블 없음 |
| 4 | 유역 위계·코드·소유역 | `d9_place_alias` 에 부모·코드 컬럼 **없음** |
| 5 | 행정구역 목록·유역↔행정 대응 | 테이블 없음 |
| 6 | 관측소 명부(ID·좌표·기관·항목) | 테이블 없음 |
| 7 | 좌표계 목록 · 비-EPSG 표기(`GK2A 정지궤도 격자`) 처리 규칙 | 테이블 없음 |
| 8 | 기관 마스터(ECMWF·국가기상위성센터) | 테이블 없음 — 정본은 원천을 **표기**로 남긴다(`DM §4.1`) |
| 9 | 주제별 동의어 **값** | 표만 만들었다. 값은 K2 |
| 10 | 주제 목록 정본 내부 불일치(`토지피복·LULC` vs 목업 `유출·수문`) | `㊸-④-2` 로 닫혔다 — 문서가 정본. **목업 쪽 불일치는 기획 정본 갱신 대상으로 남아 있다**(레포가 고칠 것이 아니다) |

### 6.2 K1 이 새로 만난 `[정본 무근거]` 2건

| 무엇 | 이 세션의 처리 |
|---|---|
| **다의어 규칙** — 한 질의어가 두 주제/두 지명에 걸릴 때 무엇을 고르는가 | 정본에 없다. **1:1 로 닫았다**(PK 를 질의어에) — 규칙 없이 1:N 을 열면 구현이 발명한다. 정본이 규칙을 주면 PK 를 바꾸는 마이그레이션 한 건이다 |
| **별칭 매칭 방식** — 정확 일치인가, 부분·정규화 일치인가 | 정본에 없다. **스키마는 어느 쪽도 강제하지 않는다**(문자열 컬럼 + 인덱스). 매칭 전략은 K4 의 판단이고, 필요해지는 시점에 근거와 함께 정한다 |

### 6.3 K1 이 하지 않은, `§⑥` 이 적어 둔 나머지

- **읽기 전용 Port 시그니처**(`§⑥-3`) — 이 세션은 저장 형태까지다. Port 코드가 놓일 자리는 `services/ai-service` 이고, 그쪽은 다른 레인이 동시에 만지고 있다. **K2 또는 K3 착수 시점에 계약 없이 코드가 앞서지 않도록 함께 놓는다**
- **K2 커버리지 기준**(`§⑥-4`)은 이미 확정돼 있다 — 핵심 어휘 = §2.6 정본 인용 **13개 + 주제 4값 + 지명 4개**. 세 표가 그 셋을 정확히 하나씩 받는다
