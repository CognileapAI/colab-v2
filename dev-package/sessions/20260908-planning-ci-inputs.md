## 현재 공급 경로

- `planning/README.md`는 원본을 제품 저장소에 복사하지 않고 형제 `40 COLAB-기획`을 참조한다.
- 해당 형제 폴더에서 `git rev-parse --show-toplevel`은 저장소가 아니라는 오류를 반환했다.
  폴더 전체의 `.git` 항목 검색도 0건이었다. 따라서 이 폴더의 Git remote는 존재하지 않는다.
- 제품 Git은 `planning/README.md`와 `dev-package/prd/planning-applied.yaml`을 추적한다.
  형제 기획 원본은 제품 checkout에 포함되지 않는다.
- `.github/workflows/ci.yml`의 `planning-gates`는 ubuntu-latest에서 제품 checkout과 PyYAML 설치 후
  두 게이트를 실행한다. 기획 저장소 추가 checkout, artifact 다운로드, 원본 URL 설정은 없다.
  워크플로 전체에서도 download/upload-artifact·repository 지정·COLAB_PLANNING 설정은 발견되지 않았다.
- 기획 README에는 CI용 Git/artifact/S3 원격 주소가 없다. 과거 Drive 동기화 언급만으로는
  실제 접근 가능한 원격 원본 경로·권한·버전이 증명되지 않는다. 외부 계정 저장소는 조사하지 않았다.

## 안전한 해결 선택

- **원본 위치를 유지하는 로컬 검증:** 기존 COLAB_PLANNING_HOME/ROOT 입력으로 원본을 직접 읽고
  실제 게이트를 실행한다. 즉시 가능하지만 GitHub-hosted CI 입력 부재 자체를 해결하지는 않는다.
- **관리되는 별도 비공개 기획 원본 저장소:** 원본의 정본 위치를 명시적으로 결정하고 버전 고정 후
  CI가 읽기 전용 checkout하도록 연결한다. 제품 저장소 안에 또 다른 편집용 사본은 만들지 않는다.
  새 원격 저장소·외부 반출 대상과 접근 권한 결정이 필요하다.
- **버전 고정된 불변 CI artifact:** 원본에서 생성한 배포물임을 명시하고 전체 목록/해시 및 제품
  매니페스트 연결 버전을 검증한다. 원본을 대신하는 편집 장소로 사용하지 않는다.
  현재 artifact 저장 위치가 확인되지 않았으므로 임의 업로드는 할 수 없다.
- **관리된 로컬/self-hosted 검사:** 기존 원본을 읽을 수 있으나 임의 PR 코드가 실행되는 runner에
  사용자 작업공간을 직접 노출하지 않는 격리가 선행돼야 한다. 현 호스트를 곧바로 runner로 등록하지 않는다.

원본이 없는데 selftest만 통과시키거나 planning-freshness를 면제하는 것은 해결이 아니다.
현재 증거로는 기존 CI 공급 저장소가 없으므로 외부 저장 위치 결정을 제외한 로컬 검증은 계속할 수 있다.
