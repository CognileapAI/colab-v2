## 2. 절차를 어떻게 재현했는가

`DRIFT3-MEASURE §3.1` 이 적은 2단을 그대로 옮겼다.

| 단 | 무엇 | 어디서 |
|---|---|---|
| 1단 | 고정 검색어를 `SqlDictionaries.expand` 에 넣어 사전·그래프 확장을 얻는다 | staging `ai-service` 컨테이너 **실호출** |
| 2단 | 확장된 검색어로 `_SEARCH` → (0건이면) `_SEARCH_TRGM` | staging `colab_platform` · `topic` 필터 `NULL` · 롤 `postgres`(RLS 우회) |

**2단 SQL 을 베껴 적지 않았다.** `run.py` 가 `services/core-api/src/colab_core/domains/d3_catalog.py` 에서
`_PREFIX_TSQUERY`·`_SEARCH`·`_SEARCH_TRGM`·`TRGM_THRESHOLD` **원문을 읽어** 파라미터만 묶는다. 베껴 두면
제품이 바뀌었을 때 **평가셋만 옛 규칙을 재게 된다.** 제품 SQL 의 조립 모양이 바뀌면 실행기는 조용히 옛
SQL 로 돌지 않고 `못 쟀다`(rc 2)로 끝난다.

이름 ↔ `D` 코드 대응도 적지 않았다 — **`infra/staging/manifest-s2.json` 이 정본**이고 실행기가 그것을 읽는다.
매니페스트 12건과 실물이 어긋나면 실패로 끝난다.

## 5. green-by-skip 을 만들지 않았다 — **실패로 끝나는 것을 실증했다**

종료 코드는 **판정이 아니라 「잴 수 있었는가」**다. `0` = A층 16건 전건 실행 · `2` = 못 쟀다.

| 실증한 상황 | 관측 |
|---|---|
| `ai-service` 컨테이너 부재 | `⛔ 못 쟀다 — … No such container` · **rc 2** |
| `pg` 컨테이너 부재 | `⛔ 못 쟀다 — … No such container` · **rc 2** |
| 표가 없는 DB 를 가리킴 | `⛔ 못 쟀다 — … SQL 실패` · **rc 2** |
| **표는 있는데 대상 0건** | `⛔ 못 쟀다 — 대상 데이터셋 0건 — 잴 것이 없다. **0건은 통과가 아니다**` · **rc 2** |
| 정상 | **rc 0** |

「대상 0건」 실증은 **일회용 인스턴스**로 했다 — `--rm` ＋ tmpfs ＋ `PGDATA` 지정 ＋ 호스트 포트 미공개
(`RESTART.md ④` 방식), 빈 두 표만 만들어 재고 **즉시 정지·제거**했다. 운영 스택은 건드리지 않았다.

같은 문에서 함께 실패로 끝나는 것 — 1단 사전 미배선(`dict_db_url` 없음) · 1단이 일부 질의를 안 냄 ·
매니페스트 12건과 실물 불일치 · 항목 수 ≠ 16 · 제품 SQL 조립 모양 변경.
**기본값이 관대한 쪽으로 떨어지는 자리를 두지 않았다** — 검사 대상이 없으면 통과가 아니라 실패다.
