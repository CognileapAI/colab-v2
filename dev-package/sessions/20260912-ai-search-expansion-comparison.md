## 비교 조건

- 기존12문항·문항별 후보 범위를 그대로 사용했다. 정답을 변경하지 않았다.
- expanded: dev AI 컨테이너의 실제 SearchService + LiteralInterpreter(BY_DESIGN) + SqlDictionaries를 사용한다. 기능어 제거·사전·그래프 확장·주제 선택·검색어 상한을 포함한다.
- 사전5표는 한 번의 읽기 전용 일관된 트랜잭션으로 읽은 뒤 그 스냅샷을 12문항에 재사용했다. 제품의 질의별 재조회와 차이가 있으며 결과에 사전·그래프 내용을 보존한다.
- AI DB는 AI 컨테이너만 조회하고 core DB는 core 컨테이너만 조회했다. 전달한 것은 검색어·주제다.
- LLM·HTTP·화면·계정 로그인·배포·제품 데이터 변경은 수행하지 않았다. 확장이 degraded로 돌아오면 준비 실패로 처리한다.
- 주제 제거 실험은 같은 확장 검색어에서 SQL topic 인자만 None으로 둔 진단이다. 제품 코드·사전·운영 설정을 바꾸지 않았다.
- 세 실행 사이 후보25건의 설명·검색 벡터 및 D3 검색 코드 hash가 동일함을 대조했다. 확장/주제제거 사이 사전·그래프·해석 결과도 동일했다.

## 원인과 설계에 반영할 사실

1. `tif→파일 포맷 예제` 동의어가 질문 속 파일 확장자를 주제 필터로 만든다. 확장 검색어는 유지하고 필터만 제거하자 004 정답이 다시1위로 나왔다. 사전의 검색어 확장과 엄격한 주제 제한을 구분해야 한다.
2. `U-Net으로` 같은 토큰은 공백·구두점 분리만으로 기본 명칭과 연결되지 않는다. 이는 LLM 필요성을 곧바로 입증하지 않으며, 해석·표현 정규화 비교 대상이다.
3. 010은 ‘가뭄’과 ‘U-Net 예측’을 동시에 충족해야 한다. 주제만 거르고 나머지를 낱말 OR로 찾으면 없는 산출물에도 후보를 반환한다. 부정 표현뿐 아니라 긍정 조건의 결합도 검토해야 한다.
4. 이번 입력에서 그래프 확장 기록은 3건이다(001·002의 충청권 영문 표기, 004의 GK-2A). 49노드·19간선 전체의 품질 평가가 아니다.
5. 모든 주제 필터를 제거하면 010의 잘못된 후보가1→5로 늘어난다. 004가 나아졌다는 이유로 필터 전체 제거를 제품 해법으로 채택하지 않는다.

코드 근거: `services/ai-service/src/colab_ai/domains/d9_ontology.py`의 `expand`, `domains/d10_ai_services.py`의 `SearchService`, `app/interpret.py`의 `_tokens`, `services/core-api/src/colab_core/domains/d3_catalog.py`의 `_SEARCH`.

- [확장 원자료](../reports/stage3-ai-search-plan/expanded-baseline-01.json), [주제 제거 진단](../reports/stage3-ai-search-plan/expanded-no-topic-01.json).
- 결과에 사전13기법·18주제동의어·4지역별칭, 그래프49노드·19간선 및 실제 코드 hash를 기록했다. 비밀값은 기록하지 않았다.

- 조사자의 원인 검토는 읽기 전용 반환이며, 공유 사본 변경으로 H6 종료 검증 exit2가 발생했다. 독립 게이트 통과로 세지 않고 실제 분리 실험으로 결론을 확인했다.
- 다음 비교 후보: 포맷 단서를 엄격 주제 필터로 쓰지 않는 해석, 조사 결합 표현 정규화, 역할·기간·지역의 조건 일치 확인. 모두 골든 기대값은 유지한다.
- LLM의 모델 선택·호출 평가는 사용자 지시에 따라 보류한다. 전체 방식 선택과 사양 확정은 아직 완료되지 않았다.
