# 완료 변경 통합·배포

사용자 승인: “완료된건 브랜치 올리고 메인에 붙여서 푸시/배포 까지하자”. 기존 사용자 수정은 원본에 보존하고 격리 사본에서 수행한다.

범위: 실행 완료4건의 대장·근거, 실패 업로드3건 삭제 근거, 미구현2건의 단계 미정 백로그 이동과 검사기 지원. I4는 미완료 유지. 비밀 SQL·백업·.codex/artifacts는 공개 커밋에서 제외한다. 제품 서비스·DB 마이그레이션·배포 코드는 변경하지 않는다.

기준 main c329c32d2f6d469deb12d64f6cb89e60994b1d3d, dev d56428d6945d677cae013d6bff25cb61727f3166, staging c329. 관련4게이트/18개 셀프테스트와 이전 제품 전체61/0/0의 적용 범위를 구분한다.

| 순서 | 완료 조건 | 상태 |
|---|---|---|
| 공개 자료·변경 검토 | 비밀 제외, I4 open 유지, 독립 go | 진행 |
| 브랜치 커밋·push | 관련4게이트, 공개 파일 명시, 원격 SHA 확인 | 대기 |
| main 통합·push | 최신 main 재확인, ff-only, 동일 후보 고정 | 대기 |
| dev 배포 | 후보 ARM64 5이미지, main 조상, 반입·기동·단일 doctor | 대기 |
| staging 자동배포 | 기존5분 cron이 후보 감지, 최종 실행/실제서비스 검증 | 대기 |
| 인계·정리 | release 태그·배포 증거·브랜치 정리, 사용자 변경 보존 | 대기 |

staging 배포용 사본은 clean c329에 그대로 두고 main push 후 기존 예약 실행을 관측한다. dev는 기존 build/ship/up 절차를 따른다. 직전 정상 이미지와 설정을 보존하고 실패 시 기존 rollback 절차로 복구한다. 마이그레이션 변경0이므로 DB downgrade는 수행하지 않는다. 실제 삭제는 이미 완료된 작업이며 재실행하지 않는다.
