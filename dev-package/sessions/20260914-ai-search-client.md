# 클라이언트 핵심 골든셋과 유형 기반 검색

요청 2026-09-13, 구현·검증 2026-09-13~14. 브랜치 codex/ai-search-next.
실행 정본: [R-AI-SEARCH-CLIENT](../prd/rounds/R-AI-SEARCH-CLIENT.md).

## 클라이언트 기준

핵심 7문항은 `eval/k4-search/client-golden.json`. 기존 `golden-cases.json` 12문항은 회귀로 유지한다.
원문 답변의 예시 건수·제품명은 보유 사실로 사용하지 않는다. 합성 API 픽스처의 정답 행과 방해 행으로 검증한다.
사용자 후속 확인: CSV/NPY는 저장 포맷이며 공간자료의 동일 내용을 담을 수 있다. ‘예: .npy’는 필수 포맷이 아니다.
서울 강수량·공간 표현이 본 조건이며 ‘NPY 형식만’처럼 명시한 질문에서만 확장자/형식을 제한한다.

## 구현 구조

1. `contracts/search/semantics.json`: 관측 변수·지역·통계 유형 정본. LST와 기온을 분리한다. core/AI 동일 상수를 생성하고 manifest discovery 해시에 포함한다.
2. 기존 D9 사전과 연결은 보존한다. 새 의미 규칙은 코드 배포로 버전 관리되는 유형 계층이며, D9 제품 DB의 개념/관계 행을 자동 확정하거나 교체하지 않았다.
3. 기존 파일별 검토 근거에 공간 표현·관측 기반·제공 기관·단위·통계·형식을 추가한다. 기존 editor가 추가 속성을 삭제하지 않고 읽기/편집/검토 저장한다. 변경 원장·파일 revision·일일 갱신은 기존 경로를 유지한다.
4. `/dataset-searches`는 지원하는 유형 질문을 계획으로 바꾸고 같은 현행 본체 파일에 모든 강제 조건을 적용한다. 명시적 조건은 SQL에서 LIMIT 전에 적용한다. 데이터셋별 대표 근거 1개, 후보 최대 200개와 초과 표식으로 본문/전체 파일 근거 읽기를 피한다.
5. 일반 검색은 기존 해석/온톨로지 후보 확장 경로다. 새 유형 경로는 결정적 규칙과 검토 근거를 사용하며, LLM을 호출했다고 표시하지 않는다. 알 수 없는 연구 정보를 추측하지 않는다.
6. 연구 변수·지역·기간은 이번 요청에서 사용자가 직접 제공한다. 월평균/일최고/일최저/일최고값의 월평균을 별도로 표현한다. 자료를 단 하나로 최적이라 단정할 근거가 없으면 조건을 충족하는 후보와 미확인 속성을 보여준다.
7. 참조 검색은 사용자가 선택한 현재 접근 가능한 본체 파일의 검토 기간/지역에 맞춘다. ‘어제 수신 완료’를 이력으로 추정하지 않는다. 다른 연구실/접근 불가 기준 파일은 404, stale 근거는 추가 확인 대상이다.
8. 화면은 검색 범위·해석 조건·출처·비교 속성·연구 입력/기준 선택을 제공한다. clarification을 ‘데이터 0건’으로 표시하지 않는다. 상세 이동은 사용자 클릭으로 수행한다.

## 알려진 범위

- 추천은 명시한 조건을 만족하는 등록 자료 후보 추천이다. 연구 내용 자동 기억, 세계 위성 제품 전수 조사, 임의 품질 점수는 구현한 것으로 주장하지 않는다.
- 지역 어휘는 서울/제주/한반도부터 시작한다. 공간 포함 관계의 GIS 연산이나 행정구역 전체 포괄 검증은 하지 않는다.
- 자료 근거가 없거나 stale이면 확정 결과에서 제외한다. `unknownCount`는 DB 후보 이후 판정 불일치/미확인 수이며 전체 카탈로그의 미확인 자료 총수가 아니다.
- 200개 초과는 partial이다. 전수 건수 또는 최적 자료 확정을 하지 않는다. 데이터셋 기준 건수와 대표 파일을 명시한다.
- 자연어 파서는 제한된 문법이며 임의 자연어 전체 품질 평가를 통과한 것이 아니다. 실제 Sonnet 호출/평가는 사용자 기존 보류 유지.
- 제품 DB 변경·배포·main 통합은 수행하지 않는다. 운영 가동이나 실자료 추천 품질 완료로 보고하지 않는다.

## 최초 intent와 이번 요청의 대조

- O1: 이번 일곱 의도와 제한된 지역·기간 문법을 구현했다. 임의 자연어 및 실제 모델 품질 전체 완료는 미달이며 Sonnet 평가는 사용자 보류 중이다.
- O2: 현행 파일의 검토 속성·조건별 판단·출처를 비교한다. 원자료/모델 등 기존 역할 근거를 유지한다.
- O3: 미확인 근거와 연구 문맥 부재를 확정 정답으로 만들지 않는다. 후보 한도 또는 조회 중 변경은 partial로 표시한다.
- O4: 상세 이동 UI 및 단위 테스트는 구현·통과했다. 실제 브라우저 저장→검색→상세 여정 판정은 별도 기록한다.
- O5: 기존 식생 첫 문항과 참조 12문항을 유지했다. 클라이언트 7문항의 우선순위 추가는 이번 사용자 요청에 따른 확장이다.
- 승인 없는 범위 초과 0건. 기존 K4 전체 완료·운영 품질·배포 완료로 확대 해석하지 않는다.


## 브라우저 원인 분리

- 마우스 자동 클릭 뒤 열림/저장/이동이 반영되지 않는 구간은 키보드 focus/Enter로 실제 UI를 조작했다. 날짜는 native input setter와 input/change 이벤트를 함께 전달하고 값 조회로 확인한다. 서버 API로 저장을 우회하지 않았다.
- `browser-search` 실행에서 근거 확인 저장·새로고침·연구 문맥 입력·검색 결과·출처/공간 CSV 비교까지 확인했다. 마지막 상세 링크의 자동 마우스 이동이 실패하여 전체 여정은 당시 실패로 기록했다.
- `research-result`는 일회용 합성 DB 화면이다. 원래 픽스처 제목 ‘A 강우 원자료’에 이번 시험용 LST 근거를 입력한 것이며 실제 등록 제품의 과학적 추천을 뜻하지 않는다.
