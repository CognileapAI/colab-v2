**무엇을 위한 화면인가** (정책 §1.3-3 · §8.1)
> 「보기만 하고 나가면 **미등록 파일 미리보기 화면(S-08)**으로 간다. 미리보기는 온전히 주고, 등록해야 생기는 것만 빈 자리로 남긴다.」
> 「등록하지 않아도 파일을 제대로 열어볼 수 있어야 한다.」 (README_E-04 · 목업 주석 동일 문장)

**누가 여는가** (정책 §1.2)
> 「**`업로드·편집`이 켜진 구성원**: 데이터를 올릴 때, 파일 내용을 등록 없이 확인할 때」
사람이 주소를 쳐서 오는 화면이 아니라 **업로드 모달에서 「보기만 할게요」를 눌러야 도달**한다 (§7.2 전이표).

**무엇이 보이는가** (정책 §8.1 전 행)
| 요소 | 정본 문구 |
|---|---|
| 화면 귀속 | 「탭 귀속은 `데이터셋`이다」 |
| 휘발 고지 | 「"연구실에 등록하지 않은 파일이에요 / 여기서 얼마든지 열어 볼 수 있어요. 다만 이 화면을 벗어나면 사라지고, 다른 사람은 볼 수 없어요."와 `연구실에 등록 →`을 한 줄에 둔다. **남은 시간을 숫자로 적지 않는다**」 |
| 기본정보 | 「**파일 헤더에서 읽은 값만** 세운다 (포맷·크기·좌표계·기간·변수·격자). 헤더에 없는 항목은 자리째 뺀다」 |
| 미리보기 | 「업로드 모달에서 그린 미리보기를 그대로 이어서 보여준다」 |
| 계보·족보 | 「빈 자리로 둔다: "등록하면 AI가 가공 전 데이터를 찾아 줘요"」 |
| 검색·공유·승인 | 「빈 자리로 둔다: "등록하면 연구실이 이 데이터를 찾을 수 있어요"」 |
| 나가기 | 「`← 데이터셋 목록` 클릭 → 파일을 버리고 목록으로 돌아간다」 · 「"등록하지 않아서 파일이 사라졌어요"」 |
| 수명 | 「화면을 벗어나지 않았더라도 **일정 시간이 지나면** 파일과 미리보기 결과를 서버에서 지운다. 지운 뒤 그 주소로 들어오면 없는 것으로 답한다」 · 「"이 파일은 더 이상 없어요. 다시 올려 주세요."」 |

**빈 상태·실패 상태** — 정책 §9 가 그리는 쪽 실패 문구를 준다.
> 「그리는 서버에 연결 못 함 → "지금 미리보기를 만들 수 없어요. 잠시 뒤 다시 시도해 주세요."」
> 「그리다 시간 초과 → "그리는 데 너무 오래 걸려요. 조각 하나나 좁은 기간으로 다시 해 보세요."」
> 「헤더에서 메타데이터를 읽지 못함 → "파일에서 정보를 읽지 못했어요…"」 (등록 단계 쪽 문구다 — 이 화면 전용 문구는 아니다)

**정본이 말하지 않은 것** — 이 화면에서 팔레트·구간 수를 바꿀 수 있는가는 §8.1 에 **없다**. `정본 무근거`.

## 2. 사용자 여정에서의 자리

```
데이터셋 탭 → [업로드] 전체 화면 모달(S-04) → 파일 놓기 → 미리보기 그리기
                                   │
             ┌─────────────────────┴─────────────────────┐
    「연구실에 등록」                              「보기만 할게요」
     ① 자동 메타 → ② 프로젝트 → ③ 계보 확정        모달 닫힘
     → 데이터셋 생성 → 데이터셋 상세(S-05)          → **이 화면(S-08)**
                                                       ├ 「연구실에 등록 →」 → 모달을 다시 열고 등록 단계까지 펼친다
                                                       ├ 「← 데이터셋 목록」 → 파일을 버린다
                                                       └ 수명 초과 → 서버에서 지운다 → 다시 들어오면 「없다」
```

**확인** — 질문의 전제 「업로드했지만 데이터셋으로 등록하지 않은 파일의 미리보기 화면」은 **정본과 일치한다.**
근거 = 정책 §7.1 상태표 「미등록 미리보기 — 모달을 닫고 …화면에 있는 상태 · **저장 안 됨**. 그 화면을 벗어나면 사라진다」 · §4 용어 「등록하지 않은 파일을 여는 전용 화면」 · PRD §4.2-2.
**보태야 할 한 가지** — 바이트는 이미 서버에 올라가 있다. 「저장 안 됨」은 **카탈로그에 데이터셋 행이 생기지 않는다**는 뜻이지 파일이 브라우저에만 있다는 뜻이 아니다 (그래서 §8.1 에 서버 쪽 수명·삭제 규칙이 따로 있다).

**도달 가능하게 만들려면 없는 것 — 정확히 셋**
1. `routes.tsx` 에 화면 `import` 한 줄 + `<Route path="/datasets/preview/:uploadId" …>` 한 줄. 경로 문자열은 이미 `handoff.ts` 의 `PREVIEW_ROUTE_PATH` 에 있다.
2. **업로드 모달의 「보기만 할게요」가 이 화면으로 가지 않는다.** `frontend/src/components/upload/UploadModal.tsx:365` 에서 그 버튼은 `requestClose` 만 부른다 — **모달만 닫히고 파일은 버려진다.** `handoff.ts` 의 `previewNavigation()` 은 만들어져 있으나 **어디에서도 호출되지 않는다**. 즉 정본 §7.2 의 「열어보는 중 → 미등록 미리보기」 전이가 제품에 없다.
3. 되돌아오는 길 — 이 화면의 `연구실에 등록 →` 은 데이터셋 목록으로 이동하며 「등록하려고 모달을 열어라」는 열쇠만 state 로 건넨다. **그 열쇠를 받아 모달을 등록 단계까지 펼치는 쪽은 아직 없다**(모달 소유 레인의 일).

**목업 대비 눈에 띄는 차이 2건** — 목업 상단의 **파일명 제목(`h1`)과 `등록 안 됨` 칩**이 코드에 없다. 팔레트 고르기 자리는 「고를 수 있는 팔레트 목록을 아직 불러올 수 없어요」로 비어 있고, 그 자리의 주석은 「팔레트 목록을 주는 서버 동작이 계약에 없다」고 적었는데 **그 주석은 이제 낡았다** — `contracts/seams/fe-core.yaml:1589` 에 `listPalettes` 가 있고 `services/core-api/.../routes/preview.py:47` 이 `GET /preview-palettes` 로 중계한다.

## 5. 완료 정의가 답해야 할 결정 목록

> 아래는 **질문 목록이다.** 어느 것도 여기서 고르지 않았다.

1. **도달 경로를 어디까지 이 항목이 책임지는가** — ㉮ 주소로 들어가면 화면이 뜬다까지 ／ ㉯ 업로드 모달의 「보기만 할게요」가 이 화면으로 보내는 것까지 ／ ㉰ 이 화면의 「연구실에 등록 →」이 모달을 등록 단계까지 다시 펼치는 것까지.
   · ㉮ 는 파일 한 개(라우팅 표) 수정으로 끝나지만 **사람이 도달할 길이 없어 제품에서는 여전히 없는 화면**이다. ㉯ 는 업로드 모달을 함께 만진다. ㉰ 는 모달 안 상태 복원까지 들어가 범위가 가장 크고 다른 레인과 파일이 겹친다.
2. **표현을 바꿀 수 있게 하는가** — ㉮ 그려진 그림을 보여 주기만 ／ ㉯ 구간 수 바꿔 다시 그리기까지 ／ ㉰ 팔레트 고르기까지.
   · 정본 §8.1 에는 컨트롤 이야기가 **없다**(`정본 무근거`). ㉰ 를 넣으면 팔레트 목록을 화면이 실제로 불러야 하고, 「팔레트 선택 화면」은 2단의 다른 항목·편의 묶음에 배정돼 있어 **경계가 겹친다**.
3. **확대·값 조회를 완료 조건에 넣는가** — ㉮ 넣지 않는다(1단 한계 그대로 · 못 하는 것을 화면이 말한다) ／ ㉯ 넣는다.
   · ㉯ 를 고르면 이 항목은 타일·값 조회 항목이 끝날 때까지 **닫을 수 없고**, 「병렬 가능」이라는 현재 진입조건이 깨진다.
4. **정본 §8.1 의 몇 행을 판정 기준으로 삼는가** — ㉮ 전 행(휘발 고지 문구·기본정보 자리 뺌·빈 자리 두 장·나가기·수명 안내까지 문구 단위 대조) ／ ㉯ 구조만(요소가 있는지).
   · 화면 시험(`frontend/test/preview.test.tsx`)은 이미 「§8.1 전 행 대비」를 표방한다. ㉮ 를 고르면 **그 시험이 실제로 전 행을 덮는지 재계수하는 일**이 완료 조건에 들어간다.
5. **목업 대비 검증을 별도로 세우는가** — ㉮ 목업 대비 항목 없음(현재 상태) ／ ㉯ 세운다.
   · ㉯ 를 고르면 **파일명 제목과 `등록 안 됨` 칩 부재**가 곧바로 미충족 2건이 된다.
6. **수명·만료를 어디까지 시험하는가** — ㉮ 화면이 「만료됨」 상태를 그린다까지 ／ ㉯ 서버가 실제로 지운 뒤 그 주소로 들어오면 「없다」로 답하는 것을 한 번 통과시키는 것까지.
   · ㉯ 는 정리기 쪽과 맞물려 시험 환경이 필요하다.
7. **어디까지 green 이어야 닫히는가** — ㉮ 화면 시험 통과 ／ ㉯ 전 게이트 통과 ／ ㉰ staging 에 배포돼 브라우저에서 실제로 뜨는 것까지.
   · 이 레포의 공통 규칙은 「로컬 green 은 완료가 아니다」이지만, **이 항목에 그 조항이 붙는지는 문서에 적혀 있지 않다** → 아래 `[미확인]`.
8. **권한을 어떻게 다루는가** — ㉮ 다루지 않는다 ／ ㉯ `업로드·편집` 이 꺼진 사람이 이 주소로 들어오면 막는다.
   · 정본은 「업로드 버튼 자체가 권한자에게만 보인다」까지만 말한다. **주소로 직접 들어오는 경우는 `정본 무근거`.**
9. **다른 사람이 이 주소를 열면 어떻게 되는가** — ㉮ 정하지 않는다 ／ ㉯ 「없다」로 답한다.
   · 정본 문장 「다른 사람은 볼 수 없어요」가 **화면 문구로만** 있고 서버 규칙으로 적혀 있지 않다.
