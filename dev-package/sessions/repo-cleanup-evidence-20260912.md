# 저장소 정리 근거 회수 실행 기록

## 목표와 승인 범위

- 사용자가 승인한 저장소 정리 판단표에서 `commit`으로 확정된 906개만 원본 작업 폴더에서 회수한다.
- 과거 성공·실패 판정은 당시 기록 그대로 보존하며 현재 제품 상태로 다시 해석하지 않는다.
- 원시 데이터베이스, 자격 증명, `retain_private`, 중복·구본·생성 중간물과 후속 작업 대상 8개는 반입하지 않는다.
- 이 레인은 보존 근거 커밋까지만 수행한다. `main` 병합·push·원본 삭제는 오케스트레이터가 담당한다.

## 단계와 의존

1. 기준 확인 — 지정 사본, 브랜치, 기대 HEAD `09b97a3499cbb88aa724cf01d7809fc9af53929c`와 clean 상태를 확인한다.
2. 원본 대조 — 판단표의 906개 경로가 모두 존재하고 SHA-256이 일치해야 반입할 수 있다.
3. 선별 회수 — 각 대상의 쓰기 guard를 통과한 뒤 경로를 유지해 복사한다. 기존 파일은 `docs/DEPLOY.md` 한 개뿐이며 판단표 해시와 일치하는 원본으로 갱신한다.
4. 안전 검사 — 반입 파일 목록이 판단표와 정확히 일치하는지 확인하고 텍스트 비밀정보 패턴 및 화면 근거의 민감 노출 가능성을 검사한다.
5. 검증·커밋 — 문서 게이트 3종을 한 번의 task 실행으로 통과시키고 논리 묶음별로 커밋한다.
6. 인계 — 커밋 후 source/destination 해시와 커밋 포함 파일 수를 다시 대조하고 lifecycle handoff를 발행한다.

## 완료 조건

- 판단표의 `commit` 906개가 누락·초과 없이 반입되고 SHA-256이 전부 일치한다.
- 제외 결정 파일과 원시 DB·자격 증명은 staged 파일에 없다.
- `contract-lint`, `work-item-consistency`, `planning-freshness`가 판정 실패 0, 준비 실패 0으로 끝난다.
- 보존 커밋의 경로·파일 수·해시와 검증 결과를 오케스트레이터에게 반환한다.
