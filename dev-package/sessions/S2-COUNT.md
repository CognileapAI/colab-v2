## STEP 2 — staging 실물 카운트 (읽기 전용)

접속: `docker exec colab_v2_staging_pg psql -U postgres -d colab_platform -c "..."` (컨테이너 목록에서 `colab_v2_staging_pg` 확인, 정지/재기동 없음). 비밀번호·접속 문자열은 어디에도 출력하지 않았다.

실행 SQL과 결과:

```sql
SELECT COUNT(*) AS dataset_all FROM d3_dataset;
-- 결과: 12

SELECT COUNT(*) AS file_all FROM d3_file;
-- 결과: 129

SELECT COUNT(*) AS lineage_all FROM d4_lineage_edge;
-- 결과: 6

SELECT kind, COUNT(*) FROM d3_file GROUP BY kind;
-- 결과: 기준 격자 파일 = 6, 본체 = 123  (합계 129)

SELECT COUNT(*) FROM d4_lineage_unknown;
-- 결과: 7  (별도 테이블 — 미확정/미해소 계보 후보. d4_lineage_edge 와 다른 개념)
```

스키마 확인(`\d d4_lineage_edge`)상 `confirmed_at`·`confirmed_by_account_id`가 NOT NULL 제약이라, 이 테이블에 들어있는 행은 정의상 전부 "확정" 상태다 — 즉 이 테이블 안에 미확정 계보 행은 존재할 수 없다(미확정 후보는 `d4_lineage_unknown`에 별도 보관). 따라서 "confirmed 계보" 필터를 걸어도 6에서 변하지 않는다.

`d3_dataset`, `d3_file`에는 소프트삭제 플래그 컬럼이 없었다(`\d`로 확인, `deleted_at` 등 없음) — orphan/soft-delete 배제 변형은 시도할 컬럼 자체가 없다.
