## 3. 일곱의 공통 모양

**전 회차에 참인 것 4개**

1. **Ted 승인이 있었다.** 예외 0건. 자기 판단으로 연 회차가 없다
2. **마이그레이션 0건.** 7회 중 스키마를 건드린 회차가 하나도 없다 — `〈94〉`·`〈95〉` 는 스키마로 푸는 안 셋을 **기각**하고 순서로 풀었고, `〈107〉` 은 세션 표를 두면 「중단 조건에 걸린다」고 스스로 적었다
3. **소비자 0건.** 7회 전부 「깨질 화면·서비스가 실재하지 않는」 표면이었다. 4회차는 그 극단 — 고치려던 op 이 **한 번도 불린 적이 없었다**
4. **게이트를 우회하지 않았다.** 7회차만 red 를 겪었고, 그 red 를 끄지 않고 **판정 사안으로 올려** 두 회차(`〈98〉` → `〈151〉`)에 걸쳐 닫았다

**갈리는 것 3개**

1. **가산 6 : 파괴 1.** 파괴는 7회차 하나뿐이고, 그것도 **미집행 약속의 회수**였다
2. **묶음 크기 8·1·2·11·1·1·1.** 「한 회차에 몰아 담기」는 1·4 회차만이고, 나머지는 단건이다
3. **점검 축.** 1~3 = 「응답이 무엇을 담는가」 · 4 = 「그 응답을 부를 op 이 있는가」 · 5·6 = 「사용자 행위가 계약에 있는가」 · 7 = 「계약이 낼 수 없는 것을 선언하고 있는가」. **회차가 늘어난 이유는 의지가 아니라 축의 누락이다**(`〈87〉-㉮` 진단 → `〈88〉` 이 실측으로 검증)

**규칙이 자동 승인했을 것 / 멈췄을 것**

- **자동 승인** — 2(필수 완화·소비자 0·마이그 0) · 3(선택 속성 추가) · 4 의 대부분(추가·중계 신설). ⚠ 7(`〈151〉`)은 **ERR 1 이라 자동 허용이 아니다** — ㉮-1 이 걸러 낸다
- **멈췄을 것** — 1(정본이 안 정한 설계 판단이 8항에 섞여 있다: 타일 존치·축 뒤집기 seam 선택·기각안) · 6-`〈107〉`(**범위 확대 · 정본 개정 · `[정본 무근거]` 8항**). 둘 다 계약 형태가 아니라 **제품 결정**이다

## 4. 게이트가 잡는 것 / 못 잡는 것

**잡는다**

- `contract-breaking`(oasdiff, 다이제스트 고정) — 기준 = **git HEAD 의 `contracts/`**, 대상 = 워킹트리. `--fail-on ERR`. 응답 상태 삭제·필수 강화·타입 축소 등 **구조적 파괴**. docker 부재·계약 0건도 red(green-by-skip 금지)
- `contract-lint`(spectral, `--fail-severity=warn`) — `operationId` 존재·유일 · 4xx/5xx 는 `ErrorEnvelope` `$ref` · ID 는 `Ulid` `$ref` · **숫자 확신도 금지** · **배치 승인 경로 금지** · 절대 URL 금지
- `generated-up-to-date` — `contracts/codegen/manifest.toml` 등기부 전건 재생성 후 byte-diff. 등기부 밖 자칭 생성물도 red
- `seam-consistency` — G-e(산문 위임 참조 실재) · G-b(`source` const 능력 주장) · ㉠ 정본 근거 대조 · ㉡ E-04 흐름 완주
- `event-lint` · `event-breaking` — `contracts/events/**` 전용

**못 잡는다 — 이것이 프로토콜이 존재하는 이유다**

1. **가산으로 보이는 의미 파괴.** 3회차의 「계약 산문이 구현과 반대」는 oasdiff 에 **0 error** 다. 2회차의 `bounds` 완화도 WARN 4·ERR 0 — 스키마는 넓어졌지만 **의미는 갈래가 둘로 쪼개졌다**
2. **op 의 부재.** 4회차 `listPalettes` 가 없어 `createRender` 가 도달 불가였던 것을 **어떤 게이트도 말하지 않았다**. 없는 것은 diff 에 안 나온다
3. **집행 없는 선언.** 7회차의 `202` — 계약이 낼 수 없는 응답을 들고 있어도 lint·breaking 전부 green
4. **기준이 HEAD 다.** 파괴적 변경도 **커밋과 동시에 green 이 된다.** 게이트는 「방금 깼는가」만 보고 「깬 적 있는가」는 못 본다 → 회차 기록이 곧 유일한 이력
5. **미구현 3종을 감추지 않는다** — `seam-consistency` 의 G-a(식별자 도달성)·G-c(짝 op 대칭)·G-d(공유 값 집합 재선언)는 아직 없다
6. **소비자 수·실서버 도달성.** 4회차가 실서버 실측으로 잡은 「토큰 미탑재로 전부 401」은 계약 게이트 밖이다

⚠ **탐지 범위를 줄이는 방향의 해법은 배제한다.** v1 CI 가 DB 없이 돌아 RLS 를 green-by-skip 한 것이 이 레포가 막는 실패 모드다. 프로토콜은 게이트 **위에** 얹히고, 게이트를 대체하지 않는다.

## 6. 동결 자체가 잘못 설계됐는가 — 판정

**부분적으로 그렇다. 「해제 횟수 상한」이 잘못이었고, 「동결」은 잘못이 아니다.**
**확정 = 상한을 폐기하고 3등급으로 간다** (Ted 2026-08-27 · `PLAN-SoT §9 〈163〉-㉮`).

- **잘못된 것 = 「1회」라는 수.** `〈80〉` 은 「두 번째 해제가 일어나면 이 결정은 실패」라고 못 박았고, 6~7회가 났다. **1회는 예측 가능한 세계에서만 성립하는 수인데, 회차마다 새 점검 축이 발견됐다**(응답 → op → 사용자 행위 → 집행 없는 선언). 축을 다 아는 상태가 애초에 없었으므로 **1회는 지킬 수 없는 약속**이었다
- **잘못이 아닌 것 = 동결.** 7회 전부 Ted 승인·마이그 0·게이트 준수였다. **동결이 없었다면 이 7건은 기록도 승인도 증거도 없이 흘러갔다.** 동결의 산출물은 「안 여는 것」이 아니라 **「열 때마다 근거와 증거가 남는 것」**이었고, 그 산출물은 실제로 나왔다
- **확정된 것 = 횟수 상한 폐기 · 등급 채택.** 「몇 번 여는가」가 아니라 **「무엇을 여는가」**로 판정한다 — §5 의 ㉮/㉯/㉰ 3등급이 **지금부터 규칙이다.** 상한이 사라지므로 「해제가 관례가 된다」는 위험은 **증거 요구(㉱ 7항)와 금지 6항**이 대신 받는다. ⭑ **그중 `㉰-6`(묶음 쪼개기로 자동 허용 만들기 금지)이 상한 폐기의 대가를 직접 받는 자리다** — 한 목적의 변경을 나눠 ㉮ 로 통과시키는 것은 **목적 단위 판정**으로 막는다
- **상품성 기준에서** — 지금의 산문 정당화는 회차마다 비용이 붙고 **판정이 사람의 기억에 의존**한다. 4회차가 「실서버에서 미리보기가 단 한 번도 안 그려졌다」를 세 회차나 지나서 발견한 것이 그 값이다. 등급 규칙은 **자동 허용을 열어 실작업을 안 막고**, 설계 판단·정본 개정·파괴는 **전부 사람에게 올린다**
- ⚠ **게이트 탐지 범위는 줄이지 않는다.** 이 프로토콜은 게이트가 **못 잡는 6종**(§4)에만 얹힌다. 장기 해법은 규칙 완화가 아니라 `seam-consistency` **G-a·G-c·G-d 구현**이고, **그 시점은 stage 2 이후로 확정됐다**(`〈163〉-㉱` · `WORK-UNITS §10.2` 목록 밖). 그때까지 6종은 **㉯ 사람 판정이 계속 받는다**
