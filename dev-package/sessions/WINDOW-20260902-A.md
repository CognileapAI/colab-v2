- 명령 = **`infra/staging/deploy.sh --target staging`** — 플래그 없음.
  ⛔ `--skip-backup`·`--skip-alias-reattach`·`--allow-dirty` 는 이 창에서 금지.
- 적용 마이그레이션 = `db/platform/versions/0011_lv1_drop_level_user_set.py`
  (`0010_p6_access_request` → `0011_lv1_drop_level_user_set`). `deploy.sh ⑧` 이 돌린다 — 손으로 DDL 을 치지 않는다.
- 떨어뜨리는 것 (스키마 문면 그대로):

```sql
ALTER TABLE d3_dataset
  DROP CONSTRAINT IF EXISTS d3_dataset_processing_level_user_set_range;
ALTER TABLE d3_dataset
  DROP COLUMN IF EXISTS processing_level_user_set;
```

- 되돌림의 한계 —
  ⑴ `rollback.sh --to-last-green` 은 **이미지만** 되돌린다. **스키마는 되돌리지 않는다**(`deploy.sh:14-16`·`rollback.sh:15-18` forward-only).
  ⑵ `deploy.sh ⑤` 가 부르는 것은 `backup/backup.sh` = **원장 덤프 2프로파일뿐**이다. 볼륨 짝이 없어 P5-b 를 못 채운다.
  ⑶ ⟹ 스키마까지 되돌리려면 **§2 의 짝 회차**로 `restore/restore-db.sh --yes-drop-schema` = **파괴적 복원**이다.
  이것이 단계 A 를 신설한 이유이고, 그 재료가 지금 확보됐다(§3).
