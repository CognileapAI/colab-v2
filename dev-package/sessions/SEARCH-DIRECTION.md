# 검색의 방향 — 온톨로지·지식그래프가 핵심인가, 일반 검색인가

> **작성** 2026-08-28. **읽기 전용 조사** — 코드·계약·게이트·운영 데이터 무변경.
> **값의 정본은 `PLAN-SoT §9` 다.** 이 문서는 인용만 한다.
> Ted 질문 = 「한국어 검색은 품질이 높을 필요 없다. 온톨로지와 지식그래프 기반의 AI 검색이 핵심 아니냐. 만약 그렇지 않다면 일반적인 검색을 제공하자.」

---

## 0. 직답

**절반만 그렇다. 그리고 갈리는 자리가 정본이 아니라 실물이다.**

- **정본은 「자연어 검색」을 요구한다 — 온톨로지·지식그래프를 요구하지 않는다.**
  `Policy_데이터_찾기 §1.2`(정본, `40 COLAB-기획/.../E-02_데이터_찾기/documents/`)가 두 길을 고정한다 — **자연어 검색은 AI 를 쓰고, 카탈로그는 안 쓴다.** 의존 전제는 `PRD §7` 의 「자연어 검색 엔진 — 질문 해석 · 관련도 · 근거 문장 생성」 한 줄뿐이다.
  **어떤 방식으로 그것을 하는지는 정본에 없다 — `[정본 무근거]`.** 온톨로지·지식그래프·임베딩·형태소 사전 중 무엇을 쓸지는 전부 개발 판정이다.
- **실물에서 온톨로지·그래프는 「검색어를 넓히는 층」이지 「찾고 순서를 매기는 층」이 아니다.**
  찾고 순서를 매기는 것은 **Postgres `tsvector` 하나**다. 온톨로지가 통째로 죽어도 검색은 낱말 그대로 돈다.
- **그러므로 「한국어 검색 품질에 투자하지 말자」는 지금 실물에서 성립하지 않는다.** 온톨로지가 넓힌 말도 **결국 `tsvector` 로 던져진다.** 매칭이 나쁘면 온톨로지가 데려온 말도 함께 못 맞는다.
- **다만 「한국어 형태소 사전(`T-1`)이 지금 실패의 원인이냐」는 별개이고, 답은 「거의 아니다」다** — 평가셋 실패 8건 중 형태소로 움직이는 것이 **최대 1건**이다(§3).

## 1. 배경 — 정본이 검색을 무엇으로 정의했나

| 자리 | 정본이 적은 것 |
|---|---|
| 두 길 | `Policy §1.2` — 자연어 검색(AI 쓴다·코랄 표시) / 카탈로그(AI 안 쓴다). **키워드 검색이라는 세 번째 길이 없다** |
| 입력 | `Policy §5` — 「검색 질문 : 1~200자. 자연어」 |
| 진입 | `Policy §1.3-2` — 홈 히어로 **한 곳** |
| 순서 | `Policy §5` — 「검색 : Verified 우선 + 관련도」. `§8 결과 헤드` — **정렬 선택 상자를 두지 않는다** |
| 근거 | `Policy §1.3-4` — 카드마다 「왜 이 결과?」 **한 줄**, 한계도 그 줄 안에서 |
| 0건 | `Policy §3.3` — 「우리 연구실 데이터 128개를 뒤졌지만 … 없었어요」 + 다음 행동 3종 |
| 관련도 | `Policy §4` — **막대 하나만.** 수치·등급 텍스트 금지 |
| 엔진 | `PRD §7` — 「자연어 검색 엔진 : 질문 해석 · 관련도 · 근거 문장 생성」. `Policy §10` — 「근거 생성이 안 되면 카드 구조 재검토」 |

**정본이 말하지 않은 것 (= `정본 무근거`)** — 온톨로지 · 지식그래프 · 임베딩 · 형태소 분석 · `ts_config` · 키워드 검색. **이 단어들은 정본 어디에도 없다.** 따라서 「온톨로지·지식그래프가 핵심이다」는 **정본이 지지하지도 반박하지도 않는다.**

## 2. 현재 상태 — 실제로 무엇이 도는가

### 2.1 검색 한 번에 실제로 일어나는 일

```
홈 히어로 (SearchHero.tsx)
  → /datasets/search?q=…  (SearchResultsPage.tsx)
  → core-api  POST /dataset-searches
      ├─ ① ai-service  POST /searches         ← 질의 해석 + 사전·그래프 확장. 결과 배열은 비어 있다
      └─ ② core-api    tsvector 질의 실행     ← 실제로 찾고 순위를 내는 자리
  → 근거 한 줄 조립 (dataset_search.py)       ← 템플릿이다. 문장 생성 모델이 아니다
```

- **ai-service 는 카탈로그를 못 읽는다.** `services/ai-service/src/colab_ai/domains/d10_ai_services.py` 서두 — *「카탈로그 커넥션이 없다. D3 를 읽지도 쓰지도 못한다 … 순위 규칙이 없다. 순서는 core-api 의 `ts_rank_cd` 가 낸다」*. 응답의 `results` 는 **항상 빈 봉투**이고, core-api 가 읽는 값은 `interpretation.terms` 하나다.
- **찾고 매기는 것은 `tsvector` 다.** `services/core-api/src/colab_core/domains/d3_catalog.py` — `phraseto_tsquery('simple', …) || ':*'` 접두 질의, 순위는 `ts_rank_cd`. `tsvector` 가 **0건일 때만** `pg_trgm` 유사도(임계 0.3)가 보조로 돈다.
- **`ts_config` 는 `'simple'` 이다.** `db/platform/schema.sql:246` — *「`ts_config` 는 `'simple'` 이고 이 값은 **`[정본 무근거]`** 다 — 소문자화·구두점 분리뿐, 한국어 형태소 분석이 없다(이미지의 `pg_ts_config` 29종에 한국어가 없다 — 실측)」*.
- **AI 근거 한 줄은 LLM 이 쓰지 않는다.** `services/core-api/src/colab_core/app/dataset_search.py` 가 **맞은 검색어와 그래프 엣지 이름을 템플릿에 끼워** 만든다. 정본의 「근거 문장 생성」은 **문장 생성 모델 없이** 충족되고 있다.

### 2.2 지금 배포에서 LLM 은 아예 돌지 않는다

- `infra/staging/compose.i2.yml:282` — `COLAB_AI_QUERY_INTERPRETATION: ${…:-literal}`.
  `infra/staging/compose.throwaway.yml:120` — `literal` 고정.
  `services/ai-service/src/colab_ai/kernel/config.py:86` — 기본값 `"literal"`.
- `app/main.py` — LLM 은 **스위치와 키가 둘 다** 있어야 선다. 지금은 스위치가 꺼져 있다.
- 즉 **오늘의 「AI 검색」은 = 질문을 공백·구두점으로 자르고 → 조사 걷어내고 → 온톨로지 사전·그래프로 넓히고 → `tsvector` 로 찾는 것**이다. 모델 호출이 한 번도 없다.

### 2.3 온톨로지·지식그래프는 실재한다 — 그리고 하는 일이 좁게 정해져 있다

| 것 | 실측 | 출처 |
|---|---|---|
| 사전 3종 (방법어·주제 동의어·지명 별칭) | **13 + 5 + 4 = 22행** | `d9_ontology.py` `Dictionaries` docstring · K2 시드 |
| 개념 그래프 | **노드 49 · 엣지 19** | `PLAN-SoT §9 〈165〉-㉮` (2026-08-27 staging 실측) |
| 관계 종류 | **3값** — `같은 말이다` · `~의 한 가지다` · `안에 있다` | `db/ai/schema.sql` CHECK |
| 확장 규칙 | 하향 전용 · **깊이 1** · 팬아웃 상한 6 · `expandable=false` 도착 금지 · **근거를 못 적으면 확장하지 않는다** | `d9_ontology.py` K4-b 절 (Ted `F-11` 승인) |

- **그래프는 검색어 집합만 넓힌다. 순위에 손대지 않는다** (`d9_ontology.py` 주석 그대로).
- **임베딩·벡터 검색은 없다.** `PLAN-SoT §9 〈81〉` — `postgres:16-alpine` 에 pgvector 가 **없다**(2방법 실측). `〈157〉-㉯` — **pgvector = stage 2 범위 밖.** 「검색은 키워드 ＋ 온톨로지 사전으로 버틴다.」
- 즉 **「AI 가 온톨로지로 답한다」가 아니라 「온톨로지가 검색어를 몇 개 더 만들어 준다」** 가 오늘의 실물이다.

### 2.4 그래프가 실제로 값을 바꾼 것 — 실측

`eval/k4-search/README.md` (2026-08-25 실측):

| 질의 | 그래프 없이 | 그래프 있음 |
|---|---|---|
| 재격자화한 NDVI 자료 | 8건 · 1위 `D-01` | 8건 · **상위 3이 `D-03`·`D-04`·`D-05` 로 바뀐다** |
| 전처리한 강우 자료 | 3건 | 3건 (금지 목록이라 확장이 시작되지 않는다) |

**읽는 법** — 그래프의 값어치는 대부분 **집합이 아니라 순위**에서 난다. 그리고 그 순위는 여전히 `ts_rank_cd` 가 낸다.

## 3. 「한국어 `ts_config` 가 지금 그대로면 무엇이 틀리는가」 — 증거

### 3.1 평가셋 실패 8건의 실제 원인 (검증됨)

`dev-package/sessions/S2b-SEARCH-EVALSET.md §2.10.2` (2026-08-26 재판정, 통과 8 · 실패 8 · 층 밖 2):

| 갈래 | 건수 | 질의 | ts_config 한국어화로 움직이나 |
|---|---:|---|---|
| ① 확장 경계 (사전·그래프가 너무 넓힌다) | **3** | Q-04 · Q-05 · Q-07 | **아니다** — 원인이 온톨로지 쪽이다 |
| ② 설명 적재 결손 (`summary` 가 `NULL`) | **2** | Q-12 · Q-13 | **아니다** — 색인할 글자가 없다 |
| ④ 매칭 규칙 | **2** | Q-01 · Q-11 | **아니다** — Q-01 은 검색어를 `' | '`(OR)로 잇는 것이 원인(`d3_catalog.py:207`), Q-11 은 §2.10.3 이 「매칭 규칙 개정으로 안 고쳐진다」로 개정 대상에서 뺐다 |
| ⑤ 기지 한계 (붙여쓰기 → `pg_trgm` 임계 0.3 미달) | **1** | Q-14 | **유일하게 가능성이 있다** — 형태소 분석기가 `HSR레이더합성반사도` 를 쪼개면 `tsvector` 가 잡을 수 있다. **재 본 적 없다 → `[미확인]`** |

**⇒ 사전(형태소) 교체로 확실히 고쳐지는 실패 = 0건. 가능성이 있는 것 = 1건(그것도 미측정).**
Ted 가 앞서 들은 「8건 중 6건은 사전이 바뀌어도 안 움직인다」는 **맞다.** 갈래별로는 ①3 + ②2 + ④의 Q-01 1 = 6 이고, 남은 둘(Q-11 · Q-14)도 사전으로 고쳐지는 건이 아니다 — **실제로는 8건 중 7건이 확실히 안 움직이고, 1건이 미측정이다.**

### 3.2 `ts_config` 가 그대로일 때 사용자에게 실제로 틀리는 것

**측정된 것 하나뿐이다** — `PLAN-SoT §9 〈81〉-㉲` : *「「강수량」이 한 토큰이 되어 「강수」로는 안 잡히고 접두 질의 `강수:*` 로만 잡힌다」*. **그런데 그 접두 질의는 `〈89〉` 로 이미 들어가 있다**(`d3_catalog.py` `_PREFIX_TSQUERY`). 즉 **`〈81〉` 이 예고한 손해는 `〈89〉` 가 이미 상당 부분 갚았다.**

남는 손해는 방향이 반대인 것 — **긴 말로 짧은 말을 못 부른다**(「강수량」으로 「강우」를 못 찾는다). `〈89〉` 가 스스로 적었다 — *「한계는 남는다 — 「강수량」으로 「강우」를 부르는 것은 여전히 **사전·그래프의 일**이지 매칭의 일이 아니다」*.
**⇒ 이 손해는 형태소 사전이 아니라 온톨로지가 갚는 손해다.**

### 3.3 ⚠ `T-1` 이 지금 이미지에서 실행 가능한지가 확인되지 않았다

- `PLAN-SoT §9 〈165〉-㉰` (2026-08-27 실측) — staging `pg_ts_config` **29 항목 전부 PostgreSQL 기본, 사용자 정의 0**. 한국어 설정이 **없다.**
- 한국어 형태소 `ts_config` 를 만들려면 **분석기 확장**(mecab-ko / textsearch_ko 계열)이 이미지에 있어야 한다. **`postgres:16-alpine` 에 그것이 있는지 재지 않았다 — `[미확인]`.**
- **없다면 `T-1` 은 pgvector 와 같은 종류의 비용이 된다** — 베이스 이미지 교체 + 재기동 + 전 행 재생성. 그리고 그 비용은 `〈157〉-㉯` 가 pgvector 에 대해 **이미 「지불하지 않는다」고 판정한 비용**이다.
- **푸는 법** — staging 컨테이너에서 읽기 전용 조회 1회: `SELECT name FROM pg_available_extensions WHERE name ~* 'mecab|korean|ko|bigm';` (`〈81〉` 이 pgvector 를 잰 것과 같은 방법).

## 4. 선택지의 뜻

### ㈎ 온톨로지·지식그래프를 검색의 핵심으로 승격한다 — `T-1` 의 형태소 부분은 뺀다

- **뜻** — `T-1` 완료 정의(`WORK-UNITS §389-390`) 넷 중 **ⓑ 온톨로지 어휘·관계 확장만 남기고 ⓐ `ts_config` 한국어 재작성 + 전 행 재생성을 뺀다.** ⓒ(`public` 밖 객체 재측정)는 ⓐ 를 빼면 함께 사라진다. ⓓ(평가셋 8건 재측정·보수)는 남는다.
- **고르면 달라지는 것**
  - 베이스 이미지를 건드리지 않는다 — 재기동 위험 0. `〈153〉` 사고(옛 이미지로 올려 ai-service 만 healthy, 사전 DB 가 조용히 빈 채 200) 재발 표면이 안 생긴다.
  - 실패 8건 중 **①3 + ④의 Q-01 1 = 4건**이 온톨로지·매칭 규칙 개정의 사정권에 들어온다. **②2건은 데이터 적재(`summary` `NULL`) 문제**라 어느 쪽을 골라도 별도로 고쳐야 한다.
  - **Q-14(붙여쓰기)는 미해결로 남는다** — 그리고 그것이 이 선택의 유일한 실제 손실이다.
- **되돌리는 비용** — 데이터셋이 12건인 지금 `ts_config` 를 바꾸는 것이 가장 싸다(`〈157〉-㉰`). 나중에 되돌리면 **그때 행 수만큼 비싸진다.** 지금 12건 → stage 2 말 `[미확인]`.

### ㈏ 정본대로 두고 `T-1` 을 원안대로 집행한다

- **뜻** — 형태소 `ts_config` 재작성 + 전 행 재생성 + 온톨로지 확장을 한 회차에.
- **고르면 달라지는 것** — §3.3 의 `[미확인]` 이 먼저 풀려야 한다. 분석기 확장이 없으면 **이미지 교체가 딸려 온다.** 그리고 §3.1 대로 **그 대가로 확실히 닫히는 평가셋 실패는 0건**이다.
- **되돌리는 비용** — `ts_config` 를 되돌리면 **다시 전 행 재생성**이고, `〈165〉-㉰` 의 `public` 밖 객체 목록과 복원 절차(`R1-RESTORE-DRAFT §4.3`)를 **두 번 고쳐야 한다.**

### ㈐ 「일반적인 검색」을 새로 제공한다

- **⛔ 정본이 막는다.** `Policy §1.3-1` — *「두 길의 역할을 넘나들지 않는다. 카탈로그에 자연어 입력을, 검색에 조건 패널을 두지 않는다」*. `§1.3-2` — 검색 진입은 홈 히어로 한 곳. **세 번째 길을 만들면 정본 개정이 먼저다.**
- **그리고 이미 있다.** 오늘 도는 것이 바로 그 「일반적인 검색」이다 — 모델 없이 낱말을 잘라 `tsvector` 로 찾는다(§2.2). Ted 가 원하는 「일반 검색」은 **새로 만들 것이 아니라 이미 배포된 상태**이고, 정본이 요구하는 「자연어 검색」의 옷을 입고 있다.
- 새로 만들 것이 있다면 그것은 화면이 아니라 **문구**다 — 검색 히어로가 이미 「적혀 있는 낱말 그대로 찾아요」로 말하고 있다(`interpret.py` `BY_DESIGN_REASON`).

## 5. 권고 — 하나

**㈎ 를 고른다. 단, §3.3 의 조회 한 줄을 먼저 돌린다.**

1. **읽기 전용 조회 1회** — staging 에서 한국어 형태소 분석기 확장이 이미지에 있는지 잰다(§3.3). **없으면 ㈎ 가 확정된다** — pgvector 와 같은 근거(`〈157〉-㉯`)로 같은 결론이 나온다.
2. **`T-1` 을 둘로 가른다** — `T-1a` 온톨로지 어휘·관계 확장(집행) / `T-1b` `ts_config` 한국어 재작성(보류, 근거를 `§9` 에 등재).
3. **평가셋 실패 8건은 갈래별로 다른 WU 에 붙인다** — ①3건·④Q-01 → `T-1a`+매칭 규칙 개정 / ②2건 → **데이터 적재**(`D-01`·`D-02` `summary` `NULL`) / ⑤Q-14 → 보류 기록.
4. **`〈157〉-㉰`(「`ts_config` 한국어 재작성 = stage 2 초반」)를 개정 표시로 정정한다.** 지우지 않는다.

**되돌리는 비용** — 문서 판정 하나. 코드·계약·마이그레이션 무변경. **되돌리기 가장 싼 시점이 지금이다** — `T-1` 이 아직 착수되지 않았고, 데이터셋이 12건이다.

## 6. 어느 쪽을 골라도 깨지는 것

| 것 | 왜 |
|---|---|
| **`K4`·`P4` 완료 판정** | 오라클이 「평가셋 대비」이고 `T-1` 뒤 재측정에 걸려 있다(`WORK-UNITS §390`). `T-1` 을 가르면 **어느 쪽에 거는지를 다시 정해야 한다** |
| **`〈157〉-㉰`** | 「stage 2 초반」이 개정된다 |
| **`〈164〉-㉮`** | 「온톨로지 확장을 `T-1` 과 묶어 재생성 1회로」의 근거가 사라진다 — 재생성이 없으면 묶을 이유가 없다 |
| **설명 적재 결손 2건** | 어느 선택지도 안 고친다. `D-01`·`D-02` 의 `summary` 가 `NULL` 인 것은 **업로드 경로의 문제**다 |
| **검색이 오타·음차를 못 잡는다** | `〈89〉` 가 「오타를 잡는다」고 말한 적이 없다(`S2b §4`). 정본도 요구하지 않는다. **이건 안 깨지는 것을 깨진 것으로 세지 않기 위해 적는다** |
