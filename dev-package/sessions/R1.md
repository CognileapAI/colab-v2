1. 원격 연결 + 첫 push
2. `main` 보호 (force-push·삭제 차단)
3. CI 1회 실행 확인 — **red가 정상**임을 확인하고 그 사실을 기록

- **CI를 green으로 만들려는 어떤 시도도 하지 않는다** — §5 참조

## 3. 절차

```bash
git remote add origin https://github.com/CognileapAI/colab-v2.git
git push -u origin main
```

**원격에 자동 생성 README가 있어 거절되면:**

```bash
git pull --rebase origin main
# 자동 생성 README.md가 우리 것과 충돌하면 우리 쪽(HEAD)을 채택한다
git push -u origin main
```

**`main` 보호** — 리뷰 필수는 걸지 않는다. 현재 CODEOWNERS가 1인 단일이라 셀프-락아웃이 난다(v1에서 겪은 문제).

```bash
gh api -X PUT repos/CognileapAI/colab-v2/branches/main/protection --input - <<'JSON'
{
  "required_status_checks": null,
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false
}
JSON
```

**CI 확인**

```bash
gh run list --limit 3
gh run view --log-failed | head -40
```

## 4. 완료 판정

| # | 판정 | 통과 기준 |
|---|---|---|
| 1 | 원격에 커밋 도달 | `git log origin/main --oneline` 에 스캐폴드 커밋 |
| 2 | 트리 일치 | `git status` clean, `git diff origin/main` 없음 |
| 3 | `main` 보호 | `gh api repos/CognileapAI/colab-v2/branches/main/protection` 에서 `allow_force_pushes.enabled=false`, `allow_deletions.enabled=false` |
| 4 | CI 실행됨 | 워크플로가 트리거되고, **`contract-gates` 잡이 "미구현 — red"로 실패**했음을 확인 |
| 5 | 상태 기록 | `03-HANDOFF.md` 의 R1 행 ✅, §2 스냅샷에 레포 URL·CI 상태 기입 |

## 5. 함정

| 함정 | 대응 |
|---|---|
| **CI가 red라서 고치고 싶어진다** | 고치지 마라. `gates/run.sh`는 미구현 게이트에 대해 **의도적으로** 실패한다. green으로 만드는 유일한 방법은 WU-D3에서 실제 검사를 구현하는 것이다. 임시로 `exit 0`을 넣는 순간 v1의 green-by-skip 실패를 그대로 재현한다 |
| 자격증명에 `workflow` 스코프가 없다 | `.github/workflows/ci.yml` 때문에 push가 거절된다. 스코프를 추가한다. 워크플로 파일을 빼고 push하지 않는다 |
| 원격 자동 README와 충돌 | 우리 `README.md`가 정본. rebase에서 우리 쪽 채택 |
| 리뷰 필수를 켜고 싶어진다 | 1인 CODEOWNERS 상태에서 켜면 본인이 잠긴다. **협업자 합류 시** 켠다 |
| `.gitignore`가 생성물을 무시한다 | 생성물은 **커밋 대상**이다 — `generated-up-to-date` 게이트가 diff로 검증하므로 추적돼야 한다 |
