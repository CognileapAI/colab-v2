## 1. 과제 A — `gates/run.sh all -j 6` 의 간헐 거짓 red

### 1.1 재현 — 잰 값

| 세는 기준 | 값 |
|---|---|
| `-j 6` 전 게이트 회차 (수정 전) | **11회** (`/tmp/j6-1..10`, probe 1회) |
| 그중 `rls-*` 가 뒤집힌 회차 | **0회** — 전 회차 red 는 `schema-diff` 하나뿐(시작 기준선과 동일) |
| **단독 게이트가 뒤집힌 회차** | **1회** — `-j 6` 루프가 **동시에 도는 중**에 `./gates/run.sh rls-effect` 를 치자 red |

축자 (2026-08-30T00:0x · 호스트 부하 load average 5.5~7.2 · 코어 **4**):

```
::error::rls-effect red — postgres 가 60초 안에 뜨지 않았다.
```

직후 같은 명령을 부하가 걷힌 뒤 다시 치자 **green**. 게이트 내용·커밋 무변경.

**⟹ 뒤집히는 자리는 게이트의 판정부가 아니라 「일회용 postgres 가 60초 안에 준비되는가」다.**
이 자리는 검사 내용과 무관하고, **호스트 부하에 따라 값이 달라진다.**

### 1.2 배제한 가설 둘 — 실측으로 죽였다

| 가설 | 실측 | 판정 |
|---|---|---|
| 컨테이너 **생성**이 도커 데몬 경합으로 실패 | 8개 동시 `docker run`(같은 옵션) → **8/8 성공 · 준비까지 2.7~3.0초** | **기각** — 60초 예산 대비 20배 여유 |
| CPU 기아만으로 DB 게이트가 red | 4코어에 busy-loop 8개를 걸고 `rls-coverage`·`rls-effect`·`rls-effect-selftest`·`db-selftest` 동시 실행 → **4/4 green** | **기각** — CPU 부하 단독으로는 안 뒤집힌다 |
| 이름·포트·임시경로 충돌 | 컨테이너명 `…_$$_${RANDOM}`(프로세스마다 다름) · 포트 publish **0** · `mktemp -d` 전건 | **기각** — 정적 대조 |

**⟹ 남는 것은 「동시에 도는 일회용 postgres 의 총량」이다.** `-j 6` 은 바깥 6 갈래에 더해
`rls-effect-selftest` 가 자기 풀(19케이스)을 돌리고 `db-selftest` 가 43케이스를 돈다 —
**한도가 어디에도 선언되어 있지 않았다.** 실측 동시 컨테이너 최대 **3개**(1초 간격 표본)지만
표본 사이의 첨두는 잡히지 않는다.

### 1.3 ⛔ 더 나쁜 것 — 그 red 가 **왜** 났는지가 기록에 없었다

- `_pg.sh` 의 `docker run … >/dev/null 2>&1` 이 **도커가 낸 말을 통째로 버렸다.**
  남는 것은 「띄우지 못했다」 한 줄이라, **사후에 귀속이 불가능**하다. 이번 회차가
  「같은 커밋에서 뒤집혔다」를 8회차나 뒤쫓아야 했던 이유가 이것이다.
- 60초 초과 메시지도 컨테이너 상태·부하·로그를 하나도 싣지 않았다.

### 1.4 고친 것

1. **일회용 postgres 의 동시성 한도를 선언한다** (`gates/tools/_pg.sh` · `pg_slot_acquire`).
   `flock` 슬롯 N개(`COLAB_PG_MAX_CONCURRENT`, 기본 **4**). `rls-effect.sh` 는 같은 함수를 **재사용**한다
   (두 벌로 두면 한쪽이 언젠가 관대해진다).
   - **게이트 목록·검사 내용·판정 기준은 한 글자도 바뀌지 않는다.** 바뀌는 것은 착수 시각뿐이다.
   - **기본 병렬도를 낮추지 않았다** · **재시도 없음** · **경합 시 skip 없음**.
   - ⚠ 슬롯을 `COLAB_PG_SLOT_WAIT`(기본 900초) 안에 못 얻으면 **red 다.** 무엇이 없었는지
     (「실행 슬롯」)를 함께 적는다. 거짓 red 를 거짓 green 으로 바꾸지 않는다.
2. **실패 사유를 싣는다.** `docker run` 의 stderr 를 red 메시지에 그대로 넣고, 60초 초과 시
   컨테이너 상태 · 호스트 부하 · 마지막 로그 3줄을 함께 적는다.

### 1.5 검증 — 수정 후 `-j 6` 5회 · `-j 2` 2회

§7 에 회차별 값.

### 1.6 이번에 세지 않은 판단기준 — 다음 회차 진입조건

- **`-j 6` 에서 `rls-*` 가 실제로 뒤집히는 빈도** — 11회차에 **0회**. 오케스트레이터가 관측한 1회는
  이 회차에 재현되지 않았다. `[미확인]` · **푸는 법** = 같은 호스트에서 `-j 6` 을 부하와 함께 20회 이상.

  호스트의 값은 재지 않았다.

## 6. `PLAN-SoT §9` 에 넣을 초안 — **아직 옮기지 않았다**

부하가 걷힌 뒤 재실행 green — **호스트 부하가 판정을 바꾼다**는 것이 실측으로 잡혔다.

`COLAB_PG_MAX_CONCURRENT` 기본 4) ＋ **실패 사유(도커 stderr·컨테이너 상태·부하·로그)를 red 에 싣는다**.
기본 병렬도 무변경 · 재시도 없음 · 경합 시 skip 없음 · 슬롯 미획득은 **red**.

**㉯ 이미지 digest 이력 기구를 놓았다 — 별칭 태그 이동이 이제 기록으로 남는다.**
`$HOME/colab-v2-releases/image-digest-ledger.tsv`(append-only · prune 없음)에
`deploy.sh` ⑫-a2 와 `rollback.sh` 가 별칭을 옮길 때마다 이미지 하나에 한 줄씩 적는다.
실측 불가는 `[미측정]` 으로 적히고 배포가 **멈춘다**.

**㉰ digest 대조를 세 상태로 만들었다.** 검사 대상의 정본이 대장이 아니라 `compose.i2.yml` 의 `image:` 다.
선언 → 대조 / `면제: <사유>` → 통과하되 요약줄에 건수 / 미선언 → **RED** / **사유 없는 면제 → RED**.
이로써 **배포되는데 대장에 없던 이미지 2건**(`colab-v2/migrator:i2` · `alpine:3.20`)이 드러났다 —
종전에는 검사 대상에서 조용히 빠져 있었다.

**㉱ 기존 5건 불일치는 값을 덮지 않는다 — 「이력 기구 부재로 소급 불가」로 기재했다** (Ted 판정 2026-08-29).
오늘 값으로 덮으면 불일치를 드러낸 **대조 기준 자체**가 사라진다.

**㉲ 같은 무늬의 형제 3건을 함께 고쳤다** — `preflight` P8 의 `|| true`(대조 RED 를 삼키던 자리) ·
