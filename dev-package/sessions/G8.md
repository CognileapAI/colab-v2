- 문서: `E-00 DataModel v1.8` 전문 · `E-02 Policy v1.8` + `PRD v1.1` 전문 · `E-04 Policy v2.2`(특히 §5 입력값 규칙) + `PRD v1.2` 전문 · `E-03 Policy`(발췌) · 루트 `사용자_핵심_시나리오.md` 전문 · `백로그.md`·`에픽_목록.md`·`IA_사이트맵.md`(발췌)

  - 기관·원천 스윕(`ERA5|GK2A|위성센터|유럽중기|기상청|K-water|관측소|지점`) → ECMWF·국가기상위성센터 둘뿐
  - 공간 스윕(`유역|소유역|행정|한강|금강|낙동강|위경도|공간 범위`) → 이름 4개, 위계 0
  - `<option>` 전수 추출 → 변수 3종(`tp/t2m/sp`)·Lv 라벨·주제 목록

### 이 방식을 고른 이유
정본의 **문서**는 저장 형태와 규칙을 말하고, **목업**은 실제 어휘를 말한다. `가공 방식 어휘`가 세 세션 연속으로 막힌 이유가 이것이다 — 문서만 읽으면 "자유 문장 한 줄"이라는 규칙만 나오고 값이 안 나온다. 값은 목업 HTML 안의 계보 화살표 라벨·AI 근거 문장·입력 도움말에 흩어져 있었다.

## 2. 판단 근거

1. **소비처가 이미 닫혀 있다.** `core-ai.yaml` 이 D9 가 떠받쳐야 할 표면을 두 오퍼레이션으로 고정해 뒀다. 그래서 "온톨로지가 무엇을 알아야 하는가"를 **`DOMAINS §2` 의 소유물 목록이 아니라 두 계약의 출력에서 역산**했다. `DOMAINS §2` 의 목록은 v2 1차 범위가 아니라 D9 라는 도메인의 성격 서술로 읽었다.
2. **계보 제안의 근거를 정본이 직접 열거해 뒀다** — 목업 E-04 의 AI 근거 문장이 실제로 쓰는 신호는 ① 헤더·이력 속성의 직접 참조 ② 같은 프로젝트 소속 ③ 격자 해상도 변화(0.25°→0.05°) ④ 이름 유사, 넷이다. **이 넷 중 온톨로지를 요구하는 것이 없다**는 것이 범위를 크게 좁힌 결정적 관찰이다.
3. **검색이 요구하는 해석축도 정본이 한 문장으로 준다** — `'25년도'는 2025년, '낙동강 유역'은 공간, '강우데이터'는 강수 주제`. 시간·공간·주제 3축이고, 이 중 사전이 필요한 것은 주제(동의어)와 공간(별칭)뿐이다.
4. **정본이 명시적으로 거부한 것을 되살리지 않았다** — 원천을 "데이터셋이 아니라 표기"로 못 박았으므로 기관 마스터를 만들지 않았다. 좌표계는 자동 추출 + 외부 표준이므로 D9 로 끌어오지 않았다.
5. **enum 을 만들지 않았다.** `P04 §5` 가 가공 방식을 자유 문장 1~120자로 확정했고, `DM §4.2` 의 예시 문장(`일 단위 평균 후 유역 경계로 잘라냄`)은 어떤 열거값에도 안 들어간다. 대신 **후보 목록 + 선택지 3개 + 각 대가**를 제시하고 결정은 Ted 에게 넘겼다.

## 3. 한계 — 다음 세션이 알아야 할 것

1. **목업 HTML 을 정본으로 인용했다.** 목업은 `links.ui_spec` 으로 정책 문서가 가리키는 정본 구성물이지만, 문서보다 낮은 층위다. 특히 §2.6 어휘 13개 중 대부분은 **정책 문서가 아니라 목업 문자열**에서 왔다. Ted 가 "목업 문구는 예시일 뿐"이라고 판정하면 §2.6 의 근거가 약해진다 — **이 판정 자체가 §④-1 결정에 포함된다.**
2. **정본 내부 불일치 1건을 발견했다** — 주제 고정 목록: `P04 §5` 는 `토지피복·LULC`, 홈 데이터 맵 목업은 `유출·수문`. 어느 쪽도 이 세션이 고를 수 없다(정본 수정 권한 없음). §④-2 로 올렸다.
3. **`DOMAINS §2` 가 D9 소유물로 든 `유출·수위`는 정본에 변수로 존재하지 않는다.** DOMAINS 의 그 열거는 수문학 예시이지 정본 인용이 아니다. 이 초안은 정본을 따랐다.
4. **정량 검증을 하지 않았다.** "이 어휘로 실제 제안·검색 품질이 나오는가"는 평가셋이 필요하고, 평가셋의 정답은 `DOMAINS §7` 규칙상 **정본이 값을 주지 않으면 만들지 않는다.** K3·K4 의 완료 정의(평가셋 대비 품질)가 이 문제를 다시 만난다 — **미리 보고해 둔다.**
5. **HANDOFF·PLAN-SoT·WORK-UNITS 를 갱신하지 않았다.** 이 WU 의 산출은 승인 대기 초안이고, 결정값이 없는 상태로 `PLAN-SoT §9` 에 적으면 결정 로그가 빈 껍데기가 된다. **§④ 에 Ted 의 값이 적히는 세션에서 함께 기록한다** — 그 세션의 진입조건을 `ONTOLOGY-SCOPE.md §⑥` 끝에 명시했다.
