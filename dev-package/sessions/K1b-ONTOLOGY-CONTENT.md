- **이것이 그래프가 사는 이유다** — 그리고 **네 행 전부 등급 ⑥ 이었다.** ⟨**판정** — 셋은 ✅(F-4a·4b·4c), 넷째는 ❌(F-4d). 개선은 4건에서 **3건**으로 줄었고 사라지지는 않았다⟩

### D-3. 「GK2A 위성 NDVI」

- **tsvector 단독**: `[미확인]`. `to_tsvector('simple','GK-2A NDVI 1 km 충청권')` 이 어떤 토큰을 내는지 **재지 않았다.** Postgres 기본 파서는 하이픈 낱말을 **전체 + 조각**으로 함께 내는 경향이 있어(`gk-2a`·`gk`·`2a`) `gk2a` 와 **안 만날 가능성**이 있다. 만나면 `D-01`·`D-03`~`D-06` 이 그냥 걸리고, 안 만나면 **0 건**이다.
- **재는 법 — 한 줄이다.** `SELECT to_tsvector('simple','GK-2A NDVI 1 km 충청권'), to_tsvector('simple','GK2A');` **`K1b` 는 이 값을 재고 시작한다.** 안 만나면 `E1-8` 이 `D-01`~`D-06` **6건**을 좌우하는 최고 가성비 엣지가 되고, 만나면 그 행은 **뺀다**.
- **일한 엣지**: `E1-8`(조건부) · `E1-9`(「천리안위성2A호」 질의에는 무조건 필요 — 그 문자열은 데이터셋 이름에 없다).
- **`DATA-REFERENCE §0 M-4` 를 지키려고 `[미확인]` 으로 남긴다.** 여기서 「하이픈 때문에 안 만난다」고 단정하면 그것이 이 문서의 M-4 재발이다.

### D-4. 「한국수자원학회 학회 발표에 쓴 다운스케일 자료」

- **tsvector 단독**: `한국수자원학회` 는 데이터셋 이름·원천 표기 어디에도 **한국어로 나타나지 않는다**(`SEED-DATA §5.4` 는 `한국수자원학회(KWRA)` 를 `source_label` 후보로만 적었다). `다운스케일` 도 `D-03`~`D-06` 이름에 없다. → **0 건.**
- **그래프**: `E1-11`(KWRA ≡ 한국수자원학회) → `source_label` B 가중치로 KWRA 묶음이 걸린다. `E5-8`(다운스케일 → 재격자화)로 재격자화 계열이 함께 펴진다 → `D-03`~`D-06`.
- **일한 엣지**: `E1-11` + `E5-8`(⑥).

### D-5. 「한반도 전체 식생 자료」

- **tsvector 단독**: `한반도` → `D-01` 1건(이름에 문자열이 있다). `식생` → topic `식생·NDVI` 로 `D-01`·`D-03`~`D-06`·`D-09`·`D-13`·`D-14`.
- **그래프**: `E2-1`(충청권 ⊂ 한반도, 하향 확장) → term set 에 `충청권` 이 붙어 `D-02`~`D-06` 의 이름이 A 가중치로 올라온다.
- **효과의 성격이 다르다** — 결과 **집합**이 아니라 **순위**가 바뀐다. `한반도` 조건이 순위에 실제로 반영된다.
- **일한 엣지**: `E2-1` (③).
- ⚠ 단 `D-02`(DEM 100 m 충청권)는 주제가 `지형·DEM` 이라 「식생」과 안 맞는데도 `충청권` 이름 매칭으로 올라온다 — **이것이 다음 절의 시작이다.**

### D-6. ⚠ 그래프가 결과를 **나쁘게** 만드는 자리 — 과확장

**질의: 「전처리한 강우 자료」**

- **tsvector 단독**: `전처리` 0건 + `강우` → `D-07`·`D-08`·`D-15` **3건**. 깔끔하다.
- **그래프를 순진하게 굴리면**: `전처리` 는 정본에서 **`Lv1` 전체를 부르는 포괄어**다(목업 「`Lv1 (전처리)`」). 만약 `전처리` 에 자식을 달면(품질검사·재격자화·재투영·크롭…) 그 자식들이 다시 자식을 갖고, **`E5` 를 깊이 제한 없이 타면 term set 이 방법 노드 25개 중 절반으로 부풀어 15건 중 12건이 나온다.** `P02 §4` 의 관련도 막대는 **전부 비슷한 길이가 되고**, `근거 한 줄` 은 「전처리 관련 용어와 일치」라는 **아무 말도 아닌 문장**이 된다. **`〈72〉-㉮` 가 「근거 한 줄이 사후 정당화로 전락」이라 경고한 것이 정확히 이 모양이다.**

**두 번째 과확장 — 방향을 안 지킬 때.** 질의 「Bilinear 로 만든 자료」에서 `E5` 를 **상향으로** 타면 `Bilinear → 재격자화 → {Nearest, IDW, Co-Kriging}` 으로 되내려와 **`D-04` 하나를 물었는데 `D-03`·`D-05`·`D-06` 이 함께 나온다. 4건 중 3건이 오답이고, `SEED-DATA §3.1` 이 넷으로 쪼갠 이유가 통째로 무너진다.**

**경계 넷 — `K1b`·`K4-b` 가 이것을 구조로 강제한다.**

1. **하향 전용.** `E5`·`E2` 의 확장은 **도착(상위)에서 출발(하위)로만** 간다. 질의어가 하위면 확장하지 않는다. `E1` 만 양방향이다.
2. **깊이 1.** 확장은 **한 홉**이다. 전이 폐포를 만들지 않는다. (깊이를 늘리려면 평가셋에 회귀 케이스를 먼저 넣는다.)
3. **팬아웃 상한.** 한 질의어의 확장이 **N 개(권고 N=6)** 를 넘으면 **그 질의어는 확장하지 않는다.** 넓은 말일수록 확장이 무가치하다는 성질을 그대로 규칙으로 만든 것이다.
4. **부모 금지 목록.** `전처리` · `품질검사` · `유역 집계` 는 **`E5` 의 도착 노드가 될 수 없다**(`K1b` 가 `expandable` 열로 강제). 시드에도 이들을 도착으로 하는 행이 **없다** — `E5-9`(유역 평균→유역 집계)가 유일한 예외라 **§F-7 에서 따로 물어본다.**

> **그리고 마지막 안전장치 하나** — **확장으로 걸린 결과는 `근거 한 줄` 에 그 엣지를 이름으로 적을 수 있어야 한다**(「'재격자화'의 한 가지인 'Bilinear' 로 일치」). 적을 수 없으면 확장하지 않는다. `P02` 의 「근거 없는 결과는 내놓지 않는다」를 확장에도 그대로 적용하는 것이고, **동시에 위 규칙 1~4 를 사람이 눈으로 검사할 수 있게 만든다.**

### E-2. 엣지 표 `d9_concept_edge`

| 열 | 타입·제약 | 왜 |
|---|---|---|
| `src` | `text NOT NULL REFERENCES d9_concept(concept_id)` | **같은 체인 안의 FK 는 허용된다** — 금지된 것은 `db/platform` 으로 넘어가는 FK 다 |

| `dst` | `text NOT NULL REFERENCES d9_concept(concept_id)` | |
| `source_grade` | `smallint NOT NULL CHECK (source_grade BETWEEN 1 AND 6)` | 노드와 같다 |
| `source_note` | `text NOT NULL CHECK (length(btrim(source_note)) > 0)` | 같다 |
| `created_at` | `timestamptz NOT NULL DEFAULT now()` | |

**방향성·대칭성 — 이것이 `K1b` 의 진짜 설계 질문이다. 답을 여기서 준다.**

- **저장은 한 방향으로 한 행만.** `같은 말이다` 를 두 행으로 넣으면 **한쪽만 지우는 사고**가 난다.
- **대칭은 조회에서 편다.** `K4-b` 는 `relation='같은 말이다'` 에 대해 `src`·`dst` 양쪽을 본다. `~의 한 가지다`·`안에 있다` 는 **`dst`(상위)로 찾아 `src`(하위)만 꺼낸다 — 하향 전용**(§D-6 경계 1).
- **정규화 제약 — `같은 말이다` 에만 `src < dst` 를 건다.** 같은 쌍이 순서만 바꿔 두 번 들어가는 것을 DB 가 막는다: `CHECK (relation <> '같은 말이다' OR src < dst)`
- **자기 참조 금지** — `CHECK (src <> dst)`.
- **PK `(src, relation, dst)`** — 재적재가 멱등해진다(기존 시드 3표의 `ON CONFLICT DO UPDATE` 규약을 그대로 승계).
- **비대칭 관계의 종류 무결성** — `CHECK` 로는 상대 행의 `kind` 를 못 보므로 **`K2b` 적재·커버리지 체크에서 검사**한다: `안에 있다` 는 **양끝이 `지명`**, `~의 한 가지다` 는 **양끝이 `방법`**. (트리거를 쓰지 않는 이유 = 기존 3표에 트리거가 하나도 없고, `d9` 표는 **선언만으로 읽히는 것**이 규약이다.)
- **`expandable=false` 인 노드가 `~의 한 가지다` 의 `dst` 가 되는 것을 막는 것**도 커버리지 체크(§E-4)의 일이다 — 두 표를 걸친 조건이라 CHECK 로 안 걸린다.

### E-3. 기존 3표와의 관계 — **합치지 않는다**

`d9_method_term`·`d9_topic_synonym`·`d9_place_alias` 는 **그대로 둔다.**

- 이유 ① — `K2`(적재)와 `k2-coverage-standard.tsv`(기준)가 이미 **갈라져** 완료 오라클을 이루고 있다. 표를 합치면 그 오라클이 무너진다.

- 이유 ③ — 합치면 `0002`·`0003` 을 되감아야 하고, `schema.sql` 이 선언 정본이라 `schema-diff` 게이트가 통째로 흔들린다.

## G. 이 문서가 하지 **않은** 것 (`DATA-REFERENCE §0` 규율)

- **DB 에 접속하지 않았다.** 노드·엣지의 검색 효과는 `SEED-DATA §3.1` 의 **데이터셋 이름 문자열에 대한 지면 대조**이고 `SELECT` 결과가 아니다. **`[미확인]`.**
- **`to_tsvector` 를 한 번도 실행하지 않았다.** §D-3 의 하이픈 토큰화는 **`[미확인]`** 이고 재는 SQL 한 줄을 적어 뒀다.
- **수문학 사실을 새로 주장하지 않았다.** 확신하지 못한 것은 전부 등급 ⑥ 으로 §F 에 올렸고(11줄), 특히 **`Co-Kriging → 재격자화`(F-4d)는 스스로 의심스럽다고 적었다.**
- **기존 문서·코드를 고치지 않았다.** `03-HANDOFF`·`PLAN-SoT`·`WORK-UNITS`·`ONTOLOGY-SCOPE`·`db/ai` 어느 것도 건드리지 않았다. 갱신은 판정 뒤 승인 세션의 일이다(`CLAUDE.md §6`).
- **마이그레이션을 쓰지 않았다** — `K1b` 의 일이다.
