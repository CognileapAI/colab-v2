## ⓓ1 `reclaimPreviews` op 신설 — 계약 동결 해제 **22차 · 등급 ㉯**

**배경**
데이터셋을 지운 것은 `core-api`(D3)이고, 미리보기 산출물을 가진 것은 `viz-render`(D7)다.
지운 쪽이 그린 쪽에 「이 파일들 것은 치워라」라고 말할 **통로가 지금 없다.**

**현재 상태**
- 이미 있는 통로 하나 = **이벤트 스풀**(D5 → D7). 그런데 그 봉투의 집계 루트가 `uploadId` 라
  **`datasetId` 를 구조적으로 실을 수 없고**, 발신자도 D5 로 고정돼 있다. 이 항목의 발신자는 D3 다.
- 다른 통로 = **공유 볼륨**. `core-api` 와 `viz-render` 사이에 없다.
- ⟹ 남는 것은 **HTTP op 하나**다. 선례가 둘 있다 — `createScreenshot`·`describeTarget`
  (둘 다 `contracts/seams/core-viz.yaml` 의 core → viz 호출).
- `core-viz.yaml` 현재 op **7**. 동결 해제 최신 = **21차**(`PLAN-SoT §9 〈376〉` · R-C).
  op 신설은 `X2-FREEZE-PROTOCOL §5-㉯` 축자 「**op 신설** — 501 표·op 총계가 움직인다」에 그대로 걸린다.
- `contracts/codegen/manifest.toml` 에 `core-viz` 항목이 **없다** ⟹ TS 생성물은 움직이지 않는다.

**여는 값 (축자)**

| 자리 | 값 |
|---|---|
| op | `reclaimPreviews` · `POST /reclaims` |
| 요청 | `PreviewReclaimRequest{targetId, fileIds[] minItems 1}` |
| 200 | `PreviewReclaimResult{targetId, stale, kept, unindexed, removed[]}` |
| 그 밖 | `400`(입력 형태) · `401`(서비스 토큰) · `503`(싱크·저장소 미구성) |
| 인증 | 기존 서비스 토큰 상속 — 새 인증 수단 0 |

⚠ viz 는 `RequestValidationError` 를 **400 으로 바꾼다**(`app/main.py`) — **422 는 내지 않는다.**
`require_caller` 는 401 만 낸다. 그래서 응답 집합이 200/400/401/503 **넷으로 닫힌다.**

**선택지의 뜻**

| 갈래 | 무엇을 뜻하는가 |
|---|---|
| **op 신설(22차 ㉯)** | core 가 viz 에 삭제 대상을 **직접 말한다.** 계약 1개 · op 7 → 8 · 마이그레이션 0 |
| 이벤트 계약을 연다 | 봉투에 `datasetId` 를 더하고 발신자를 D3 로 넓힌다. **이벤트 계약 개정 ＋ 마이그레이션** — ㉯ 이면서 훨씬 크다 |
| 배경 루프가 알아서 | 루프의 등급 판정(`ownership.grade`)이 묘비 데이터셋의 fileId 를 `d5_upload_file` 잔존 때문에 **「접수분」**으로 읽는다 ⟹ **영원히 회수되지 않는다.** 이 갈래는 성립하지 않는다 |
| 기각 | 화면 문구를 「파일만 지워져요」로 고친다. 산출물은 영구 잔존 |

**고르면 달라지는 것**
- op 신설 → 삭제 한 번이 **동기로** 산출물까지 닫는다. 실패하면 삭제가 500 으로 **롤백**되므로
  「DB 는 지워졌는데 그림만 남는」 중간 상태가 생기지 않는다. `core-viz` op **7 → 8**.
- 이벤트 계약 → 되돌리기 어려운 것(마이그레이션)이 붙고, at-least-once 라 **멱등이 필수**가 되며,
  발신자가 D5 인 자리에 D3 가 끼어들어 경계가 흐려진다.
- 기각 → 사용자가 「지웠다」고 들은 것과 버킷의 실물이 계속 갈린다. 그 차이는 에러를 내지 않으므로
  **아무도 세지 않는다** — 이 레포가 반복한 실패형이다.

**권고 — op 신설(22차 ㉯).** 근거 넷: ⑴ 통로가 그것 하나뿐임이 실물 조사로 닫혔다
⑵ 선례 두 건이 같은 seam 에 이미 서 있다 ⑶ 마이그레이션 0 · 계약 파괴 0(순수 첨가)
⑷ `§5-㉰-4`(집행 없는 신설)를 피한다 — 계약 · viz 라우트 · core 릴레이 · 삭제 경로 호출 ·
시험을 **한 회차에** 세운다.
**되돌리는 비용** — `core-viz.yaml` 의 op 한 덩이 제거 · viz 라우트 파일 1개 삭제 ·
`app/main.py` 2줄 · core `ports/relay.py`·`app/relay.py` 각 한 메서드 · `routes/deletion.py` 호출 1줄.
**DB 무변경 · 마이그레이션 0 이라 데이터 되돌림이 없다.**

## ⓓ2 `PreviewSinkPort` 에 `index`·`remove` 를 얹는가, Port 를 하나 더하는가

**배경**
산출물을 서빙 자리(dev = S3 `previews/`)에 **올리는** 자리는 `PreviewSinkPort.publish` 하나다.
이번에 필요한 동작이 둘 더 생긴다 — **표식을 남긴다**(`index`) · **지운다**(`remove`).

**현재 상태**
- `ports/preview_sink.py::PreviewSinkPort` = 메서드 **1개**(`publish`).
- 구현 2벌 — `LocalPreviewSink`(no-op · nginx 가 디렉터리를 그대로 서빙) ·
  `S3PreviewSink`(`put_object` 로 `previews/{파일명}`).
- `kernel/s3.py::S3Client` 에 `delete_objects(keys)`·`list_objects(prefix)` 가 **이미 있다.**
  다만 **삭제 호출자가 0건**이다(ⓓ6 참조).

**선택지의 뜻**

| 갈래 | 뜻 |
|---|---|
| **같은 Port 에 얹는다** | 「산출물이 서빙 자리에서 어떻게 놓이고 치워지는가」를 **한 이름**이 진다. 구현 2벌에 메서드 2개씩 추가 |
| Port 를 하나 더한다 | `PreviewIndexPort`·`PreviewRemovalPort` 를 새로 세운다. 주입 지점·설정·대역이 각각 늘어난다 |

**고르면 달라지는 것**
- 같은 Port → 주입 지점이 지금 그대로다(`spec.preview_sink` 하나). 대역도 한 벌이면 된다.
  대가는 **Protocol 이 넓어지는 것**(1 → 3) — 싱크를 새로 만들 때 구현할 메서드가 셋이 된다.
- Port 분리 → 각 Port 가 좁아진다. 대가는 **같은 저장소(S3 클라이언트 하나)를 세 Port 가 나눠 갖는 것**이고,
  셋이 언제나 함께 주입되므로 분리가 **이름만 늘린다.**

**권고 — 같은 Port 에 얹는다.** 근거 = 세 동작이 **같은 저장소·같은 접두·같은 수명**을 공유한다.
`publish` 가 놓은 것을 `remove` 가 치우고, `index` 는 그 둘을 잇는 표식이다. 갈라 두면
「접두(`prefix`)를 어느 Port 가 갖는가」가 곧바로 갈리고, 갈린 접두는 **조용히** 어긋난다.
**되돌리는 비용** — Protocol 2줄 · S3 구현 2메서드 · Local 구현 2메서드(no-op) 제거.

## ⓓ3 무엇을 「낡았다」로 판정하는가 — 지워진 fileId 집합 `D` 래퍼

**배경**
배경 루프의 판정(`ownership.grade`)은 **원장 등급**이다 — 「이 산출물의 원천 파일이 아직 표에 있는가」.
그런데 데이터셋을 지우면 `d3_file` 행은 사라지지만 `d5_upload_file` 행은 남는다 ⟹ 그 판정은
「**접수분에만 닿는다**」를 내고, 그것은 **고아가 아니다** ⟹ 영원히 회수되지 않는다.

**현재 상태**
- 회수 계산기 `invalidation.py` 는 `plan()` **하나**이고, 그 위에 래퍼가 셋 있다 —
  `reclaim_plan`(소유 회수) · `supersede_plan`(팔레트 교체) · `tile_reclaim_plan`(지도 타일).
  셋 다 같은 모양이다: **회수 대상이 아닌 키를 전부 `keep_keys` 로 넘긴다.**
  모듈 축자 = 「**계획기를 셋째로 만들지 않는다**」 · 「집행 문을 늘리지 않는다」.
- 산출물 한 벌마다 **사이드카 `.json`** 이 함께 놓이고, 그 안에 `sources`(fileId 배열)가 있다.

**제안하는 판정식 (넷째 래퍼 `deletion_plan`)**

> **낡았다(stale) ⇔ ① 판정 가능한 사이드카(v2)이고 ② `sources` 가 비어 있지 않고
> ③ `sources ⊆ D` 이고 ④ `tile-` 이 아니다.**
> 그 밖은 전부 **남긴다(kept)** — 사유를 계수로 센다(일부만 D · 사이드카 부재 · 구판 · 타일).
> `D = ∅` 이면 계획 자체를 세우지 않는다(`OutOfScope`).

**여기 붙는 세 가지 — 함께 판정 바란다**

| 갈래 | 내용 | 왜 물어야 하는가 |
|---|---|---|
| ㈎ `tile-` **무접촉** | 지도 타일은 D5 가 구운 것이라 이 문의 대상이 아니다. 사용자 지시 삭제에서도 **손대지 않는다** | 「데이터셋을 지웠는데 지도 타일이 남는다」가 의도인지 확인이 필요하다 |
| ㈏ CloudFront **300초 잔상 수용** | `/previews/*` 캐시가 300초다. 무효화 호출 선례 0 ⟹ **최대 5분간 옛 그림이 보일 수 있다** | 「지웠는데 아직 보인다」는 사용자 문의가 될 수 있다 |
| ㈐ 로컬 scan **합집합** ＋ `unindexed` 계수 | 표식(ⓓ7)은 이번 회차부터 생긴다. **그 전에 구워진 산출물은 표식이 없다** ⟹ 로컬 디렉터리 훑기로 보충하고, 표식 없이 잡힌 건수를 `unindexed` 로 **센다** | 세지 않으면 「옛 산출물이 얼마나 남아 있는가」를 아무도 모른다 |

**고르면 달라지는 것**
- 제안대로 → 회수는 **부분 소유에 안전하다.** 한 그림이 파일 3개에서 왔고 그중 2개만 지워졌으면
  그 그림은 **남는다**(사유 `partial`). 사이드카가 없거나 구판이면 **남는다** — 없는 근거로
  지우는 것이 오삭제이고, 이 레포가 그 실패를 이미 문면으로 못 박았다.
- ㈎ 를 뒤집으면 → 지도 타일도 지우게 되는데, 그 벌에는 사이드카가 **없어** `sources` 판정이
  성립하지 않는다. 타일은 별도 판독기(`tile_liveness`)가 따로 판정한다 — 두 규칙이 한 벌을 놓고 다툰다.
- ㈏ 를 뒤집으면 → CloudFront 무효화 호출을 새로 세워야 한다(자격·비용·실패 갈래 신설).
- ㈐ 를 빼면 → 이번 회차 **이전** 산출물은 영원히 회수되지 않는다(백필 ⓓ5 를 안 돌리는 한).

**권고 — 제안대로(㈎ 무접촉 · ㈏ 수용 · ㈐ 합집합＋계수).** 근거 = 넷째 래퍼는 **계산기를 늘리지 않고**
집행 문도 늘리지 않는다(앞선 셋과 같은 모양). 잔상 5분은 **되돌릴 수 있는 불편**이고,
무효화 배선은 되돌리기 어려운 자격·비용을 붙인다.
**되돌리는 비용** — `invalidation.py` 의 함수 하나 제거 ＋ 그 시험. **집행 코드 0 줄 변경.**

## ⓓ4 렌더 서비스가 **설정되지 않은** 배포에서 삭제가 어떻게 되는가

**배경**
`core-api` 는 `app.state.previews` 로 렌더 릴레이를 든다. 그런데 그 값이 **`None`** 인 배포가 있다 —
로컬 개발과 시험이다(viz 주소·토큰을 주지 않는다).

**현재 상태**
- dev·prod 는 그 토큰이 `:?`(필수) 로 걸려 있어 **빠지면 아예 기동하지 않는다** ⟹ 실제 운영에서
  `None` 이 나올 수 없다.
- 로컬·시험에서는 `None` 이 정상이고, 그 환경에는 **미리보기 산출물 자체가 없다.**

**선택지의 뜻**

| 갈래 | 뜻 |
|---|---|
| **건너뛴다 ＋ 로그** | `previews is None` 이면 회수를 생략하고 `event=dataset.previews_skipped code=PREVIEWS_UNCONFIGURED` 를 남긴다. 삭제는 204 로 끝난다 |
| 500 을 낸다 | 「회수할 수 없으면 지우지 않는다」를 끝까지 민다 |

**고르면 달라지는 것**
- 건너뛴다 → 로컬·시험에서 삭제가 **된다.** 대가 = 「관대한 기본값을 두지 않는다」는 이 레포의
  규율과 **긴장한다** — 그래서 이 건을 따로 회부한다. 완화가 아니라는 근거 둘: ⑴ 그 배포에는
  지울 산출물이 **없다**(싱크가 없으므로 올린 적이 없다) ⑵ 건너뛴 사실이 **로그 한 줄로 남는다** —
  조용히 넘어가지 않는다.
- 500 → 로컬·시험에서 **데이터셋을 하나도 못 지운다.** `DL-1` 의 시험 23건이 전부 red 가 되고,
  개발자가 그것을 우회하려고 대역을 끼우면 **그 대역이 진짜 배선을 가린다.**

**권고 — 건너뛴다 ＋ 로그.** 근거 = 운영 환경에서는 그 갈래에 **도달할 수 없고**(`:?` 필수),
도달 가능한 환경에는 **지울 대상이 없다.** 관대함이 아니라 **범위가 다른 것**이다.
**되돌리는 비용** — `routes/deletion.py` 의 분기 한 덩이를 `raise` 로 바꾼다(3줄).

⭑ **⟨증보 2026-09-13 · 어드바이저 ② 정정⟩ 「부르긴 했는데 실패했다」도 두 갈래다 — `RelayRefused`
(viz 4xx · 저쪽이 **읽어 보고 물리침**)는 재시도 문구 없이 500 이다.** 같은 요청은 같은 답을
받으므로 「잠시 뒤 다시 시도해 주세요」를 붙이면 사용자가 **고칠 수 없는 것을 반복**하게 되고,
그 반복이 운영자에게는 「간헐 장애」로 보인다. 문구 = 「미리보기 산출물 회수 요청이 거절되어
삭제를 되돌렸어요.」 ＋ `details.reason` 에 저쪽 상태·본문(고칠 사람은 우리다).
`RelayUnavailable`(못 닿음·5xx)은 재시도 문구를 **유지한다** — 회수도 삭제 재호출도 멱등이다.
⛔ **롤백과 봉투 코드는 둘 다 같다**(500 `PREVIEW_RECLAIM_FAILED`) — 가른 것은 **문구와 단서**뿐이다.

## ⓓ5 이번 회차 **이전** 산출물의 표식을 나중에 채우는가(백필)

**배경**
ⓓ7 의 표식은 **발행 시점**에 찍힌다. 이미 버킷에 있는 것들(dev `previews/` 402 객체)에는 표식이 없다.

**현재 상태**
- 표식이 없어도 **로컬 디렉터리에 있으면** 회수된다(ⓓ3-㈐ 합집합). 그런데 dev 의 EC2 디스크는
  일회용이고 로컬 캐시가 LRU 라, **로컬에서 밀려난 옛 산출물은 어느 쪽으로도 안 잡힌다.**
- 채우는 방법 = `previews/*.json` 사이드카를 훑어 v2 인 것만 골라 표식을 PUT 한다.
  **읽기 ＋ 쓰기만 하고 삭제는 0건**이다.

**선택지의 뜻**

| 갈래 | 뜻 |
|---|---|
| **GO — 단 dry-run 계수 먼저** | 스크립트를 만들되 **기본이 dry-run** 이고, dev 에서 「몇 벌에 표식을 찍을 것인가」를 **먼저 세어 보고**한 뒤 실행 판정을 받는다 |
| 만들지 않는다 | 옛 산출물은 영구 잔존한다(누적 402 벌) |
| 지금 바로 실행 | 계수 확인 없이 채운다 |

**고르면 달라지는 것**
- GO(dry-run 먼저) → 「표식을 몇 개 쓰는가 · 구판이라 건너뛴 것이 몇 벌인가」가 **숫자로 먼저** 나온다.
  그 숫자를 보고 실행을 판정한다. 표식은 **0바이트 객체**라 저장 비용이 사실상 없다.
- 만들지 않는다 → 이 회차 이후 새로 구운 것만 회수되고, 과거분은 다음 회차의 같은 조사를 다시 부른다.
- 지금 바로 → 사이드카 판독 실패가 몇 건인지 모르는 채 쓰기를 시작한다.

**권고 — GO(dry-run 계수 먼저).** 근거 = 쓰기만 하는 스크립트라 되돌림이 **표식 삭제 한 번**이고,
계수를 먼저 보면 「구판이 얼마나 되는가」라는 ⓓ3-㈐ 의 미지수도 같은 실행에서 닫힌다.
**되돌리는 비용** — `preview-index/` 접두 전체 삭제 1회. **산출물 자체는 건드리지 않는다.**

## ⓓ6 「S3 를 지우지 않는다」 잠금의 **범위를 가른다** (시험은 유지)

**배경**
지금 코드에는 「S3 삭제 금지」가 **두 겹**으로 걸려 있다 — 시험 2건과 독스트링 3곳.
이번 회차는 **사용자가 지시한 삭제**에서만 S3 를 지운다. 잠금을 **없애는 것이 아니라 범위를 적는 것**이다.

**현재 상태**
- `tile_reclaim.py` 는 배경 회수 루프다. 그 모듈 독스트링 ＋ `run_s3_observation` ＋ `S3ReclaimJob`
  **세 곳**이 「S3 를 지우지 않는다」를 적는다.
- `tests/test_s3_tile_reclaim.py` 의 시험 **2건**이 그것을 기계로 잠근다.
- 이 잠금이 생긴 이유 = 배경 루프가 **자동으로** 도는 자리라, 판정이 한 번 틀리면 **아무도 안 보는 사이에**
  사용자 데이터를 지운다.

**선택지의 뜻**

| 갈래 | 뜻 |
|---|---|
| **범위 분리** | 독스트링 3곳을 「**자동 회수 루프는** S3 를 지우지 않는다(사용자 지시 삭제는 `reclaim_on_delete` 별도 문)」로 고치고, **시험 2건은 한 글자도 고치지 않는다** ＋ 「삭제를 부르는 파일은 `reclaim_on_delete.py` 하나」를 잠그는 음성 시험을 **새로 더한다** |
| 잠금을 푼다 | 시험 2건을 지운다 |
| 잠금을 유지 | S3 는 안 지우고 로컬만 지운다 — dev 에서는 **아무것도 안 지워지는 것과 같다**(로컬은 일회용 디스크) |

**고르면 달라지는 것**
- 범위 분리 → 「배경 루프는 여전히 S3 를 0건 지운다」가 **참으로 남고**, 그것을 재는 시험도 그대로 돈다.
  새로 생기는 삭제 경로는 **호출자가 하나**임이 기계로 잠긴다.
- 잠금을 푼다 → 배경 루프가 나중에 S3 삭제를 하게 되어도 **아무도 못 잡는다.**
- 유지 → dev 에서 `DL-2` 가 성립하지 않는다.

**권고 — 범위 분리.** 근거 = 잠금이 막으려던 것은 「**자동으로** 도는 판정이 조용히 지우는 것」이고,
이번 경로는 **사람이 데이터셋 삭제를 누른 것**이 유일한 방아쇠다. 그 둘을 이름으로 갈라 두면
원래 잠금이 **약해지지 않는다.**
**되돌리는 비용** — 독스트링 3곳 문면 복원 ＋ 새 음성 시험 1건 제거.

## ⓓ7 표식을 어디에 두는가 — `preview-index/by-file/{fileId}/{contentKey}`

**배경**
「이 파일에서 나온 산출물이 무엇인가」를 **되묻는 길이 지금 없다.** 산출물 키는 내용 주소(해시)라
파일 ID 가 들어 있지 않고, 원장에도 산출물 행이 없다(설계상 일부러 그렇다).

**현재 상태 · 기각한 대안 넷**

| 대안 | 왜 기각하는가 |
|---|---|
| JSON 목록 파일 1개 | S3 에 원자적 덧붙임이 없다 ⟹ 동시에 두 렌더가 끝나면 **한쪽이 덮어쓴다** |
| 사이드카 전수 열거 | 삭제 한 번마다 `previews/` **전건 GET**. 「버킷 접두 스캔 금지」에 저촉 |
| core 가 키를 기록 | D7 의 사실을 D3 표에 적는다 — 불변규칙 1 위반 ＋ 마이그레이션 1 |
| 프로세스 메모리 | 재시작하면 사라진다 |

**제안 — 발행 시점에 파일별 표식 객체를 하나 놓는다.**
자리 = `preview-index/by-file/{fileId}/{contentKey}` · 본문 **0바이트.**
회수 때는 지워진 fileId 마다 목록 조회 **1회**씩 — 버킷 전체 스캔 0 · 비용이 지운 파일 수에만 비례한다.

**왜 `previews/` 아래가 아닌가 (이것이 핵심)**
`previews/` 는 **평평해야 한다.** 관측 코드(`legacy_preview_observation.observe`)가 그 접두 아래에
하위 경로가 하나라도 보이면 **red 를 낸다** — 「flat 구조가 아니다」. 표식을 그 아래 두면
그 검사가 **즉시 깨진다.** 그래서 **형제 접두**를 쓴다. 덤으로 CloudFront 는 `/previews/*` 만
바깥에 노출하므로 표식은 **인터넷에 보이지 않는다.**

**계약에 등재하는가** — `contracts/storage/layout.json` 에 **별도 top-level `previewIndex`** 로 적는다.
기존 `keys`/`roots` 표에 넣지 않는 이유 = 생성기 자기검증이 「미리보기 루트에 사는 종류는 **1개**」를
고정으로 확인한다. 표식은 **산출물이 아니라 산출물을 가리키는 표식**이라 그 표의 값이 아니다.

**선택지의 뜻**

| 갈래 | 뜻 |
|---|---|
| **형제 접두 ＋ 계약 등재** | 자리 규약이 `layout.json` **한 곳**에 산다. 세 단위가 같은 바이트를 생성으로 받는다 |
| 형제 접두 ＋ 계약 미등재 | viz 코드 안에만 적는다. 나중에 다른 단위가 같은 자리를 다르게 적을 수 있다 |
| `previews/` 아래 | 관측 검사가 깨진다 ⟹ 성립하지 않는다 |

**고르면 달라지는 것**
- 계약 등재 → 자리를 바꿀 때 고치는 곳이 **한 곳**이고 생성물 3벌이 따라온다. 드리프트를
  `generated-up-to-date` 게이트가 잡는다.
- 미등재 → 같은 규칙이 두 곳이 될 자리가 열린다. 이 레포는 그 실패를 이미 한 번 치렀다
  (격자가 렌더러에 영영 안 닿았다).

**권고 — 형제 접두 ＋ 계약 등재.** 근거 = 표식 자리는 「어디에 놓이는가」이고, 그 질문의 정본은
`layout.json` 하나다. 표식은 0바이트라 저장 비용이 사실상 0 이고, 조회는 지운 파일 수에만 비례한다.
**되돌리는 비용** — `layout.json` 한 덩이 ＋ 생성기 세 상수 제거 후 재생성 · 발행 경로 1줄 ·
버킷의 `preview-index/` 접두 삭제 1회. **산출물·원장 무접촉.**
