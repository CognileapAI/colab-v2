# Intent: 계보 제안의 「없다」는 모델이 아니라 구조가 말한다 — 근거 검증형 제안으로 재설계
메타 — 발의자: Ted(「근본적인 해결을 위해서 이건 어떻게 개선해야 하는가」 2026-09-24) · 정리: Claude(오케스트레이터) · 작성 2026-09-24 · 승인 **Q1~Q6 권고안 전부 승인 2026-09-24 (Ted, 「아까 인텐트 결정 6가지 권고대로 하고 진행해보자」)**

## 문제
- 두 차례 실측(`dev-package/reports/k3-lineage-probe/README.md`)에서 luna 는 **후보 밖 ID 를 만들지 않았고, 규격을 지켰고, 8초 안에 답했다.** 그런데 정답 부모를 후보에서 빼면 **16회 중 15회 무엇이든 골랐다.** 「모름」 확신도 0회.
- 고른 것의 정체가 문제를 말한다. 1차는 **자기 자신**(같은 이름·파일), 2차는 **자기 자식**(가공 단계가 더 높은 후손)이었다. 둘 다 사람은 즉시 배제하는 후보다 — **사람이 배제에 쓰는 정보(정체·가공 단계 순서)를 우리가 모델에 주지 않았다.**
- 현 설계는 「후보 목록을 주고 부모를 고르라」는 **선택 문제**다. 선택 문제에서 LLM 은 목록 안에 답이 있다고 전제하는 성향이 있고, 「없다」는 성향을 거스르는 답이다. 프롬프트 문장으로 누르는 것은 확률을 바꾸지 보장을 만들지 않는다(K4 결정성 4/12 문항이 같은 성질).
- 근거(rationale)는 사후 문장이다. 「일치한다」고 적었지만 무엇과 무엇이 일치했는지 **기계가 확인할 수 없다.** J3 grounding 검사가 부분문자열 대조에 그친 이유다.

## 원한 결과 (proposed outcome)
- O1. **정답이 후보에 없으면 제안이 비는 것이 구조로 보장된다** — 모델의 성향과 무관하게. 대조군(정답 제거·후손만·형제만) 3종에서 빈 제안 100%.
- O2. 제안마다 **기계가 검증한 근거**가 붙는다 — 「어느 필드가 어느 값으로 맞았는가」. 검증 안 되는 근거를 단 제안은 core-api 가 버린다.
- O3. 확신도는 모델의 기분이 아니라 **맞은 근거의 수와 종류**에서 나온다(보정을 구조로).
- O4. 가공 단계 규칙(부모 Lv ≤ 자기 Lv)이 **후보 층에서** 집행된다. 사람 폼이 이미 그렇게 한다(`LineageStep.tsx:24`).
- O5. 사람이 폼에서 고른 값(가공 단계)이 AI 요청에 실린다 — 사람이 아는 것을 AI 도 안다.

## 진단 — 「없다」는 어디서 나와야 하나
| 층 | 지금 | 근본 개선 |
|---|---|---|
| ① 후보 선정(core-api) | 주제 ∪ 토큰 필터, 자기 자신 제외 | **적격 필터**: 자기 자신 제외 + **Lv ≤ 업로드 Lv** + (있으면) 기간·격자·변수 신호 계산 → 적격 후보와 **신호표**를 함께 보냄 |
| ② 모델(ai-service) | 「부모를 고르라」 선택 문제 | **후보별 판정 문제**: 「이 후보가 입력이었다는 근거가 파일 메타에 있는가 — 있으면 어느 필드·어느 값인가」. 근거 필드를 **인용 형식**으로만 답한다 |
| ③ 검증(core-api) | 후보 밖 ID 폐기 | + **인용 검증**: 인용한 필드 값이 실제로 업로드 메타·후보 메타에 있고 실제로 맞는지 대조. 틀리면 그 제안 폐기 |
| ④ 확신도 | 모델 선언(확실/애매/모름) | **파생**: 검증된 근거 종류 수로 결정(예: 2종 이상 = 확실 · 1종 = 애매 · 0 = 제안 없음). 「모름」은 값이 아니라 **빈 제안**이 된다 |
| ⑤ 평가 | 대조군 1종(정답 제거) | 대조군 3종 + 코퍼스 확장(dev 28건, 골든 ID 재고정 뒤) |

## 왜 이것이 「근본」인가
- **신호가 이미 있다.** 업로드 메타는 `variables`·`crs`·`gridDescription`·`periodStart/End`·`fileName`(`core-ai.yaml` UploadedFileMeta:293-323), 후보의 자동 메타는 `variables`·`crs`·`grid`·`period_start/end`·`bundle_file_name`(`db/platform/schema.sql:558-567`). **같은 축이 양쪽에 있다.** 「이 후보가 이 파일의 입력이었나」는 상당 부분 축 대조로 결정된다.
- **K4 가 이미 낸 결정과 같은 모양이다.** 〈72〉-㉮ 「LLM 은 해석까지, 찾는 것은 core-api」. K3 도 「LLM 은 근거 인용까지, 적격 판정과 검증은 core-api」로 가면 두 기능의 분담 규칙이 하나가 된다.
- **프롬프트 개선은 이 위에 얹는 것이다.** 적격 필터가 후손·자기 자신을 이미 뺀 뒤라면 모델이 무엇을 골라도 「부모일 수 없는 것」은 아니다. 프롬프트 문장은 그때 순위 품질을 올리는 도구가 된다.

## 영향 범위
- 계약(`core-ai.yaml`): ⓐ 요청 `LineageSuggestionRequest.processingLevel`(선택 · 사람이 폼 ①에서 고른 값) ⓑ 후보 항목에 신호 요약 필드(선택 · 예: `signals: {periodOverlap, gridMatch, variableOverlap}`) ⓒ 응답 `ParentCandidateSuggestion.evidence[]`(선택 · `{field, uploadValue, candidateValue}`). 전부 선택 필드 — 파괴 아님, 서명 사항.
- core-api: 적격 필터 + 신호 계산 + 인용 검증 + 확신도 파생. 폼의 `processingLevelUserSet` 을 업로드 요청까지 싣는 배선(프런트 1곳 · 이 값은 이미 화면에 있다).
- ai-service: SYSTEM_PROMPT 를 「후보별 근거 인용」으로 재작성, 파서는 `evidence` 를 닫힌 열쇠로 읽음. 확신도는 모델에게 **묻지 않는다**(파생).
- 계약 파괴 여부: 아니오(선택 필드만). 서명 1건 필요.
- 화면: 제안 표시 복원(㉮)은 여전히 별건. 다만 ⓐ 를 위해 폼 값 하나를 요청에 싣는 배선은 필요.

## 설계트리 — Ted 와 같이 정할 자리
- **Q1 「없다」의 출처** — 모델의 자제(프롬프트) vs 구조(적격 필터 + 인용 검증). → 권고 **구조**. 이유: 두 실측이 「성향은 프롬프트로 누를 수 없다」를 보였고, K4 가 같은 결론을 냈다.
  - Q1a 프롬프트 두 문장 추가(결정 A)는 그래도 하나 → **한다, 단 순위 품질 도구로.** 「없다」의 보장으로 세지 않는다.
- **Q2 업로드 Lv 를 요청에 싣나** — 지난 판정(미해결 3)은 「이번엔 안 싣는다」. 실측이 그 값을 물었다. → 권고 **싣는다**(선택 필드). 폼 ①이 이미 값을 갖고 있어 사람이 아는 것을 AI 도 알게 되는 것뿐이다.
  - Q2a Lv 가 없는 업로드(사람이 안 고름)는 → 적격 필터를 건너뛰고 **제안을 내지 않는다**(「단계를 고르면 제안이 가능합니다」 사유). 반대안: 필터 없이 제안 — 후손을 부모로 낼 위험을 다시 연다.
- **Q3 모델의 일 — 고르기 vs 근거 인용** → 권고 **근거 인용**. 출력 = 후보별 `{parentDatasetId, evidence:[{field, uploadValue, candidateValue}], role}`. 인용 없는 후보는 제안 아님. core-api 가 인용을 대조해 틀리면 폐기(J3 가 검사가 아니라 **집행**이 된다).
  - Q3a 대조 규칙 — 기간은 겹침, 격자·CRS 는 정규화 동등, 변수는 교집합 ≥1, 파일명은 토큰 접두. 정본 없는 축은 만들지 않는다.
- **Q4 확신도** — 모델 선언 vs 파생 → 권고 **파생**(검증된 근거 종류 수). 모델의 `confidence` 필드는 읽지 않는다. 화면 enum(확실/애매/모름)은 유지되나 「모름」은 나오지 않는다(빈 제안이 그 자리).
  - 반대: 파생은 「모델이 왜 확신하나」의 설명력을 잃는다. 답: 설명은 인용된 근거 자체가 한다.
- **Q5 LLM 이 여전히 필요한가** — 신호 대조만으로 규칙 기반 제안이 가능하다. → 권고 **1단계는 규칙 기반 적격+순위, 모델은 근거 문장 조립과 동률 판정에 한정.** 반대: 파일명·설명의 자연어 단서(「HSR」 ↔ 「레이더 합성 반사도」)는 규칙이 못 잡는다 — 그 자리를 모델 인용에 남긴다. **실측으로 가른다**: 규칙만 / 규칙+모델 두 팔의 J2·J5 비교.
- **Q6 평가** — 대조군 3종(정답 제거·후손만·형제만) · 코퍼스 dev 28건(골든 ID 재고정 선행) · 결정성 기록. 합격선은 실측 전에 고정.

## 판정 기록 2회차 (2026-09-24 Ted · 「전부 권고대로 할게」 · 게이트 ① 조건 5건)
