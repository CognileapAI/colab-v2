# Intent: 시스템 관리자·교수 관리자 구분과 권한 오류 안내
메타 — 발의자: Ted · 작성 2026-09-16 · 승인 2026-09-16(사용자 「고고」)

## 문제
- DEV의 관리자 「전체 연구실 (읽기 전용)」 화면에서 데이터 상세·파일 목록은 보이지만 미리보기의 변수·시각 조회는 거절될 수 있다. 화면은 조회 오류를 숨긴 채 빈 선택칸·비활성 보기 버튼·빈 그림 영역을 남긴다.
- 관리자가 실제 자료를 점검하고 관리하려는 목적에 읽기 전용 제한이 맞지 않는다. 무소속 관리자가 새 자료의 대상 연구실을 지정할 경로도 없다.
- 기존 교수에게 부여한 서비스 전체 관리자 권한을 그대로 확대하면 다른 연구실까지 수정·삭제할 수 있다. 「시스템 관리자」와 「교수 관리자」의 이름·범위·기존 계정 전환을 구분해야 한다.

## 원한 결과 (proposed outcome)
- 시스템 관리자는 소속 연구실 유무와 관계없이 모든 연구실에서 현재 제품이 제공하는 기능의 전체 권한을 갖는다. 조회·미리보기 생성/변경·값 조회·다운로드·업로드·등록·수정·삭제·프로젝트 연결/해제·계보 편집·공개 범위/접근 관리·연구실/구성원 관리·계정 관리가 포함된다. 「나만 보기」와 지정 공개 자료도 시스템 관리자 권한으로 다룬다.
- 교수 관리자는 자기 연구실의 모든 자료·프로젝트·구성원을 관리한다. 자기 연구실에서는 다른 구성원의 「나만 보기」·지정 공개 자료까지 조회·미리보기·다운로드·수정·삭제·접근 관리할 수 있고, 자료 소유자·개별 허용 여부로 제한하지 않는다. 타 연구실의 관리자 권한, 서비스 전체 계정 관리, 시스템 관리자 지정·해제 권한은 갖지 않는다. 타 연구실 자료에 대한 일반 공개·개별 허용 등 기존 정상 접근 정책은 유지한다.
- 기존 교수에게 별도로 부여했던 시스템 관리자 권한은 회수하고 교수 역할·소속은 유지한다. 교수 계정이나 자료를 삭제·재생성하지 않는다. 별도로 지정한 시스템 관리자 계정은 유지한다.
- 기존 계정 전환 전에 실제 계정·연구실 역할·시스템 관리자 여부를 대조한 대상 목록을 만든다. 알려진 예전 계정 수를 현재 상태로 간주하지 않는다. 권한 회수는 이 목록의 기존 교수 겸직 계정에만 적용하고, 재실행해도 다른 계정이나 권한을 바꾸지 않는다. 변경된 계정의 기존 세션을 종료해 옛 시스템 관리자 권한이 남지 않게 한다. 전환 후 시스템 관리자가 최소 한 명 남는지도 확인한다.
- 전환 목록에는 「기존 교수 겸직: 회수」와 「별도 시스템 관리자: 유지」 및 각각의 지정 근거를 기록한다. 두 목록이 겹치거나 역할·지정 근거가 불분명하면 그 계정을 임의로 유지/회수하지 않고 전환 준비 오류로 보고한다. 모든 대상이 분류되기 전에는 전환 완료로 판정하지 않는다.
- 계정 목록·역할 표시·관리자 지정 동작에서 「시스템 관리자」와 「교수 관리자」를 구분한다. 데이터의 연구실 역할 `교수`와 시스템 관리자 자격은 별개로 유지하며, 표시 이름 변경만으로 다른 계정의 권한을 확대하지 않는다.
- 시스템 관리자는 기존 자료를 전체 보기에서 바로 조작한다. 서버가 대상 자료의 실제 연구실을 확인해 그 연구실에 변경을 적용한다. 시스템 관리자의 소속 연구실로 자료를 옮기거나 잘못된 연구실에 이력을 남기지 않는다.
- 새 데이터·프로젝트 등 소속을 정해야 하는 생성에서는 시스템 관리자가 대상 연구실을 선택한다. 선택한 연구실에 저장되고 새로고침·재조회 후에도 유지된다. 교수 관리자와 일반 사용자는 자기 연구실에 생성하며 이 경로를 이용해 다른 연구실에 생성할 수 없다.
- 관리자 화면의 「읽기 전용」 안내와 그 전제의 버튼 숨김·비활성화를 실제 권한에 맞춘다. 화면·API·데이터베이스·미리보기 서비스의 권한 판정이 일치한다.
- 이번 변경으로 다루는 화면과 요청에서 권한 부족은 「이 작업을 할 권한이 없어요」처럼 이유를 안내한다. 로그인 만료·대상 부재·서버 오류와 구별하며, 변수·시각 조회 실패도 빈 화면으로 숨기지 않는다. 재시도 가능한 실패에는 재시도 경로를 제공한다. 존재를 공개하지 않는 대상은 「대상이 없거나 접근 권한이 없어요」처럼 기존 비공개 경계를 유지한다. 공통 오류 처리의 전면 개편으로 확대하지 않는다.
- 현재 DEV에 올라간 데이터·파일·연구실 소속·프로젝트 연결·계보·계정을 보존한 채 변경을 적용한다. 기존 데이터 초기화나 재적재를 필요조건으로 삼지 않는다.
- 일반 구성원의 연구실·역할·공개 범위 제한은 그대로 유지한다. 시스템 관리자 지정·해제와 세션 무효화도 기존대로 동작한다. 교수 관리자 권한의 적용 범위는 위 역할 정의를 따른다. 일반 구성원에게는 「나만 보기」 등 공개 설정과 별도로 시스템 관리자·해당 연구실 교수 관리자가 관리 목적으로 접근할 수 있음을 공개 범위 안내에 명시한다.
- 관리자 무소속/소속 계정의 타 연구실 조작과 일반 사용자의 거절을 검증한다. 실제 브라우저에서 기존 자료 미리보기·수정 후 재조회, 신규 생성 대상 연구실 저장, 권한 오류 안내를 확인한다. 파괴적 동작 시험은 격리된 시험 데이터로 한다.
- 교수 관리자의 자기 연구실 관리 성공과 타 연구실 관리·시스템 관리자 승격 거절을 각각 확인한다. 기존 교수의 시스템 관리자 권한 회수 후 옛 세션 거절, 다시 로그인한 뒤 교수 관리자 표시·범위, 데이터·연결 관계 보존을 검증한다.

## 영향 범위
- 사용자 / 화면: 관리자 전체 보기, 데이터셋 상세·미리보기·등록·편집, 프로젝트, 연구실·구성원, 계정 관리, 공통 권한 표시와 오류 안내.
- 서비스 · 스키마 · 계약: 관리자 권한 원본과 요청 스코프, 데이터베이스 행 접근 정책, 대상 연구실 결정, 미리보기 중계·저장 접근, 생성 요청의 연구실 선택 계약, 관련 권한 회귀시험.
- 계약 파괴 여부: 기존 읽기 전용 권한 정책은 명시적으로 개정한다. 요청·응답 계약의 파괴 여부와 마이그레이션 상세는 후속 spec에서 확정하며, 일반 사용자 기존 요청의 호환성을 유지한다.

## 제약
- 시스템 관리자 원본은 기존 `account_admin.service_operator`, 교수 관리자 원본은 연구실 역할의 `교수`를 사용한다. 일반 연구실의 교수·구성원을 시스템 관리자로 자동 승격하지 않는다. 기존 교수 겸직 계정의 시스템 관리자 권한 회수는 이번에 사용자가 합의한 전환이다.
- 전체 권한은 기존 제품 기능의 권한 확대다. 연구실 역할·기능별 스위치·작성자/소유자·개별 접근 허용에 따른 권한 제한은 시스템 관리자에게 모든 연구실에서, 교수 관리자에게 자기 연구실에서 적용하지 않는다. 교수 관리자라는 이유로 시스템 관리 기능을 열지는 않는다. 계보 순환 금지, 자료 소속·참조 정합성, 필수 입력, 마지막 본체 파일 삭제 금지, 삭제 시 연결 자료 처리, 자기 자신/마지막 시스템 관리자 해제 금지 등 데이터와 서비스의 유효성 규칙은 유지한다. 이 규칙 때문에 거절되면 권한 부족으로 표시하지 않고 실제 이유를 안내한다.
- 무소속 관리자를 일반 사용자로 전환하려면 기존대로 연구실·역할을 먼저 지정한다. 관리자 해제 후 무소속 일반 계정이 생기지 않게 한다.
- 기존 자료의 연구실 소속을 임의 변경하거나 연구실 사이의 연결을 허용하는 정책 변경은 포함하지 않는다. 관리자 조작의 실제 행위자와 대상 연구실을 기존 감사 경로에 정확히 남긴다.
- 전체 POST 요청을 무조건 허용하거나 클라이언트가 보낸 관리자 표시만 신뢰하지 않는다. 서버에서 관리자 신원·작업 대상·선택한 연구실을 검증한다.
- 운영 데이터 삭제·계정 재생성·비밀번호 변경·초기화는 이 권한 구현 요청으로 실행하지 않는다. 제품 안의 관리자 권한 확대와 에이전트의 운영 실행 권한은 별개다.
- 사용자에게 검증 결과와 배포에 필요한 변경을 전달한다. 이번 요청의 재배포는 사용자가 수행한다.

## 설계트리 (grill-me 결과)
- Q1 관리자 범위 → A 읽기 전용 선택을 철회하고 모든 연구실의 전체 권한을 부여한다. 사용자 직접 제안.
- Q2 새 자료 소속 → A 기존 자료는 전체 보기에서 바로 조작하고, 새로 만들 때만 대상 연구실을 선택한다. 권장안 수용.
- Q3 권한 부족 표시 → A 권한이 없으면 그 이유를 화면에 안내한다. 사용자 직접 제안.
- Q4 현재 데이터와 배포 → A 기존 데이터 구조에서 관리자 권한을 수정하고 사용자가 새로 배포한다. 초기화·재적재는 하지 않는다.
- Q5 관리자 구분 → A 시스템 관리자와 교수 관리자로 나눈다. 시스템 관리자는 전체 연구실, 교수 관리자는 자기 연구실을 관리한다. 사용자 직접 제안.
- Q6 기존 교수 겸직 → A 별도로 부여한 시스템 관리자 권한을 회수하고 교수 관리자만 유지한다. 사용자의 「그래 이걸로좀더 INTENT」로 수용.
- Q7 교수 관리자의 자기 연구실 비공개 자료 → A 자기 연구실 전체 자료 관리. 다른 구성원의 「나만 보기」·지정 공개 자료도 조회·수정·삭제 가능. 권장안 수용.
