# Intent: 업로드에서 미리보기만 하기 선택을 제거한다
메타 — 발의자: samtae0610 · 방향 결정: Ted · 작성 2026-09-16 · 승인 2026-09-16(초안 제시 후 기존 묶음 PR 머지와 후속 진행 지시)

## 문제
- 파일을 업로드한 뒤 등록과 미리보기만 하기 중 하나를 선택하게 되어 있다. 기획에 없던 선택이며, Ted가 서버 부하를 이유로 선택 옵션을 빼기로 했다.

## 원한 결과 (proposed outcome)
- 업로드 접수 후 `보기만 할게요` 선택이 보이지 않고, `다음 →`를 통해 기존 등록 흐름으로 진행한다.
- 등록 과정에서 파일 내용을 확인하는 미리보기는 계속 사용할 수 있다.
- 전송 중단 후 이어올리기와 접수 완료 후 등록 복원을 유지한다.
- 닫기·브라우저에서 숨기기·기존 서버 만료 처리에 회귀가 없다.

## 영향 범위
- 사용자 / 화면: 업로드 접수 후 선택 영역.
- 서비스 · 스키마 · 계약: UploadModal의 버튼·전용 전이 함수·전용 import 및 관련 프런트 시험. API·DB 변경 없음.
- 계약 파괴 여부: 아니오. 기존 미등록 미리보기 진입 정책 중 업로드 화면의 선택지만 사용자 결정에 따라 개정한다. 직접 URL 계약은 유지한다.

## 제약
- 등록 중 미리보기와 이전/다음 이동을 유지한다.
- 긴 이름 때문에 입력칸을 넓히지 않는다. 이번 변경은 새 레이아웃이나 입력칸 확장을 요구하지 않는다.
- 이미 업로드된 파일이나 사용자 데이터를 삭제하지 않는다.
- 선택지 제거가 업로드 분석·렌더 비용 전체를 없앤다고 주장하지 않는다. 서버 부하 감소량은 미측정이다.

## 설계트리 (grill-me 결과)
- Q1 제거 방향 → A Ted의 이슈 댓글로 확정: 미리보기만 하도록 선택하는 옵션을 제거한다.
- Q2 제거 경계 → A 댓글의 선택 옵션에 한정해 `reg-viewonly`, `viewOnly()`와 전용 import를 제거한다. 미등록 미리보기 직접 URL 전체 폐지는 범위 밖이다.
- Q3 등록 중 미리보기 → A 기존 PreviewPanel을 유지한다. 해당 기능 삭제 요청은 없다.
- Q4 이어서 하기·닫기 → A 기존 독립 상태 경로를 유지하고 회귀를 검사한다.
