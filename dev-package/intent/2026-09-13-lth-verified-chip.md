메타 — 발의자: 이태헌(1차 검증 피드백) · 작성 2026-09-13 · 승인 미승인

## 문제
- 데이터셋 목록의 승인 칸에 영어 `Verified` 글자가 취소선·회색으로 그려진다. 실제 승인 건수는 0건이다.
- 검증자는 색과 선을 자세히 보지 않으면 「승인 완료」로 읽힌다고 보고했다.
- 같은 승인 상태를 가리키는 표기가 제품 안에 셋 있다 — 칸의 `Verified`(취소선) · 필터 값 「승인 전」 · 프로젝트 상세 표의 「승인됨」.

## 원한 결과 (proposed outcome)
- 검증 가능 문장 ⑴ — 승인 대기 행의 칸 글자가 Ted 가 고른 표기 하나로 고정되고, 같은 상태를 가리키는 화면 문자열이 한 값으로 모인다.
- 검증 가능 문장 ⑵ — 칸을 비우지 않는다는 기존 이유가 유지된다(「승인이 아니다」와 「아직 안 왔다」가 화면에서 갈린다).
- 검증 가능 문장 ⑶ — 현재 표기를 고정한 시험 4건이 고른 표기에 맞춰 green 이 된다.
- 판정 = Ted 가 유지·문안 변경·상태 3값 중 하나를 고르고 그 값이 원장에 적힌다.

- 사용자 / 화면: 데이터셋 목록의 승인 칸 · 프로젝트 상세의 소속 데이터셋 표. 검색 결과 카드는 배지 규칙이 달라 해당 없다.
- 서비스 · 스키마 · 계약: 문안만 바꾸면 `frontend/src/components/catalog/CatalogTable.tsx` · `frontend/src/components/project/ProjectDatasetTable.tsx` · `catalog.css` · `project.css` ＋ 시험 4건. 상태 3값을 쓰면 목록 행 계약에 열쇠 1개 추가 ＋ core-api 묶음 질의 신설.
- 계약 파괴 여부: 아니오 — 문안 변경은 계약 무변경, 상태 3값은 열쇠 추가(추가형). 단 **열 제목 `Verified` 를 바꾸면 계약 파괴**다(필터·정렬 값이 열 이름 문자열 · `frontend/src/components/catalog/columns.ts`).

## 설계트리 (grill-me 결과)
- Q1 기획자 권고의 4값(미검증 / 요청 없음 / 검토 대기 / 승인됨)을 지금 그릴 수 있나 → A 목록 행에는 불리언 하나만 실린다. 그릴 수 있는 상태는 둘이다.
- Q2 「검토 대기」의 판정원이 서버에 있나 → A 있다. `services/core-api/src/colab_core/app/routes/catalog.py` 앵커 `verification_pending = d2_access.pending_verification_of(db, dataset_id) is not None` — **상세 라우트 한 곳에서만** 계산된다(조사 C 추가 실측).
  - Q2a 목록에 싣는 비용 → A 계약 열쇠 추가 ＋ ids 묶음 판정 함수 신설(행마다 부르면 N+1). 선례 = 같은 파일 앵커 `unknown = d4_lineage.unknown_dataset_ids(db, ids)`. 크기 **M**, 계약 파괴 없음.
- Q3 열 제목까지 한국어로 바꾸나 → A 반대 — 열 이름이 필터·정렬 계약 값이라 파괴 변경이 된다.
- Q4 취소선·회색을 지우나 → A 유지를 권고한다. 「칸을 비우지 않는다」의 이유는 표기가 아니라 상태 구분이고, 취소선은 그 구분을 남긴다.
- Q5 표기 3종 통일을 같은 회차에 하나 → A 한다. 문안 변경안을 고르면 「승인 전」으로 모으는 것이 같은 작업 안에 들어간다.
