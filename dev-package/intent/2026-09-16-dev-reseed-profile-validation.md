# Intent: 개발 초기화의 계정 사전 확인과 자체 시험을 일관되게 만든다
메타 — 발의자: Ted · 작성 2026-09-16 · 승인 2026-09-16
## 문제
- 개발 초기화 자체 시험이 개인 컴퓨터의 외부 승인 계정 파일에 의존하여 로컬과 CI에서 결과가 달라진다. PR #87의 CI 실패 세 건은 자체 시험 한 건의 실패와 후속 집계 두 건의 연쇄 실패다.
- 계정 조회 실패로 이메일이 비거나 검사 도중 예상 밖 종료가 발생해도 일부 출력 검색만으로 시험이 통과할 여지가 있다. 형제 시험도 외부 파일 유무에 따라 검사 경로가 달라진다.
- 별도 실행 계정 파일을 지정해도 초기 신원 추출은 기본 승인 파일을 읽는다. 설정 준비 실패가 계정 값 소실과 부정확한 안내로 이어져 원인을 구분하기 어렵다.
## 원한 결과 (proposed outcome)
- 개인 계정 설정이 없는 환경에서도 관련 시험이 공개 예제로 만든 임시 파일을 사용하여 동일한 경로와 결과를 검증한다. 승인 기준과 실행 후보는 서로 다른 파일로 준비한다.
- 초기 신원 확인은 실제 실행 후보를 승인 기준과 대조한 뒤 수행한다. 파일 누락·권한 오류·심볼릭 링크·계정 정보 불일치·신원 override 불일치는 초기화 전에 거절한다.
- 정상 입력의 통과와 잘못된 입력의 거절을 각각 시험한다. 빈 이메일·조회 실패·예상 밖 종료·중복되거나 상충하는 판정 출력은 통과로 처리하지 않는다.
- 준비 실패 시 원인을 구별할 수 있는 계정 입력 오류를 남긴다. 비밀 값은 출력하지 않고 잘못된 입력으로 파괴 단계에 진입하지 않는다.
- 관련 계정 시험, 개인 설정과 분리한 preflight-secrets/preflight-red 시험, dev-reseed-selftest 및 전체 selftest의 실제 실행 결과를 확인한다. 종료코드와 검사·면제·실패 수를 기록하며 준비 실패를 통과로 보고하지 않는다.
## 영향 범위
- 사용자 / 화면: 개발 초기화 도구의 사용자와 CI 유지보수자. 제품 화면 변경 없음.
- 서비스 · 스키마 · 계약: dev-reseed 계정 사전 확인과 관련 시험. DB·API 스키마 변경 없음. 외부 승인 파일을 신뢰 기준으로 사용하는 정책 유지.
- 계약 파괴 여부: 아니오
## 제약
- 공개 계정 예제는 시험용 입력으로만 사용하며 실제 실행의 기본 계정으로 대체하지 않는다.
- 실제 개인 승인 파일·비밀 값을 열람하거나 기록하지 않는다. 시험은 임시 파일과 외부 실행 대역으로 수행한다.
- 실제 dev/운영 초기화·삭제·배포는 수행하지 않는다. 기존 검사 범위를 축소하거나 필수 입력을 완화하지 않는다.
- 의도적으로 실패하는 사전 검사 시험은 전체 종료코드 0을 강요하지 않는다. 기대한 실패 단계와 결과를 확인하여 예상 밖 종료와 구별한다.
- 승인 기준 파일 자체는 기존 접근 권한 정책 아래 신뢰한다. 별도 승인 지문·스냅샷 체계는 추가하지 않는다.
