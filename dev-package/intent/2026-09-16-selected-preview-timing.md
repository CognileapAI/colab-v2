# Intent: 선택한 미리보기만 실행하고 요청별 시간 측정
메타 — 발의자: Ted · 작성 2026-09-16 · 승인 2026-09-16 (대화의 목표·권고안 수락)
## 문제
- 상세 페이지를 여는 것만으로 선택 전 전체 데이터셋 렌더가 실행된다. 계보 조회도 렌더 부하를 만든다.
- 재적재 검사에서 요청 누적·메모리 부족·시간 초과가 발생했다. 약159초는 단일 파일 시간이 아니라 전체 대상 요청의 실패 관측 시간이었다.
- HTTP 응답, 큐 대기, 렌더 처리, 화면 표시 시간을 혼동하고 있다.
## 원한 결과 (proposed outcome)
- 파일·변수·시점을 고른 뒤 ‘보기’를 눌러 선택한 파일 한 건만 실행한다. 페이지 진입·선택 변경만으로 실행하지 않는다.
- 실행 중 중복 제출을 막고 종료 뒤 다시 실행한다. 실패한 파일을 다른 파일로 자동 대체하지 않는다.
- 화면에는 총 소요 시간, 진단 기록에는 요청·파일·선택값과 연결된 실제 대기·처리·표시 시간을 구분한다.
- 재적재 검증도 한 건씩 명시 실행·종료·실제 표시를 확인한다. 실패·미지원·미측정은 통과와 구분한다.
## 영향 범위
- 사용자 / 화면: 데이터셋 상세 및 확장 미리보기, 재적재 검증.
- 서비스 · 스키마 · 계약: frontend, viz-render 관측, dev-seed/dev-reseed 검증. DB 마이그레이션 없음.
- 계약 파괴 여부: 아니오. 기존 선택 API와 운영 관측 로그 사용.
## 제약
- 기존 UI·API·관측 도구 재사용. 원본 자료·계정·연구실 접근 변경 없음.
- 서버/브라우저 시계를 빼서 시간을 계산하지 않는다. 없는 측정값을0으로 만들지 않는다.
- 최신 develop 기반 격리 구현. 원격 push·PR 게시·배포·전체 초기화는 이번 작업에 포함하지 않는다.
## 설계트리 (grill-me 결과)
- Q1 실행 시점 → ‘보기’를 누를 때만 실행(권고안).
- Q2 시간 표시 → 화면 총 시간, 상세 시간은 진단 기록(권고안).
- Q3 실행 중 요청 → 현재 작업 종료 뒤 새로 보기(권고안). 취소 API는 제외.
- 세 권고안 제시 후 ‘좋아’를 수락으로 반영했다. 각 선택지를 개별 응답한 것으로 기록하지 않는다.
## 미해결 질문
- 없음. 구현상 새 범위가 필요하면 그 부분만 재검토한다.

- 전체 reseed 반복, 운영 배포, 외부 모니터링 서비스 도입.
