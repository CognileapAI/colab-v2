# Intent: 상단 셸의 「누를 수 있어 보이는데 동작 없는 자리」 3건을 닫는다
메타 — 발의자: 이태헌 · 작성 2026-09-13 · 승인 2026-09-13

## 문제
- 상단 「전체 연구실 (읽기 전용)」이 버튼이라 눌리지만 목록·안내·주소 변화가 없다(`D-1`).
- 상단 「내 계정 · 〈이름〉」이 펼침 화살표(`▾`)를 달고 있으나 메뉴가 열리지 않는다(`D-5`).
- 휴대전화 390px 상단에서 업로드·계정 관리·연구실 설정이 글자 없이 그림만으로 보인다(`I-9`).

## 원한 결과 (proposed outcome)
- 상단에서 누를 수 있는 요소는 전부 누르면 무엇이 일어나고, 동작이 없는 자리는 누를 수 없는 상태 표시로만 보인다.
- 검증 문장 ⑴ 「전체 연구실 (읽기 전용)」이 `button` 이 아니고 `▾` 가 없으며 키보드 초점을 받지 않는다.
- 검증 문장 ⑵ 「내 계정 · 〈이름〉」을 눌렀을 때 메뉴가 열린다, 또는 `▾` 가 없어 메뉴를 기대하게 하지 않는다.
- 검증 문장 ⑶ 390px 에서 상단 기능의 이름이 글자로 확인된다(도움말 또는 목록 안 라벨).
- 위 셋은 `frontend` 시험으로 확인 가능하다 — 현재 시험이 `lab-switcher`·`gnb-avatar` 를 이미 지목한다.

## 영향 범위
- 사용자 / 화면: 전 화면 상단 셸. 관리자 계정에서 특히 `D-1`. 휴대전화 폭에서 `I-9`.
- 서비스 · 스키마 · 계약: `frontend/src/shell/Gnb.tsx` · `frontend/src/shell/shell.css` · `frontend/src/shell/design-system.css` · `frontend/src/components/upload/UploadEntry.tsx`. core-api·`contracts/` 변경 0.
- 계약 파괴 여부: 아니오

## 제약
- 연구실 경계는 요청에서 오지 않는다(`CLAUDE.md §3-5`) — 연구실 선택 장치는 읽기 op 이 연구실 인자를 받아야 하므로 계약 판정이 선행한다.
- 대장 `BO-3` 가 전환 동작을 이미 범위 밖으로 적었다 — `dev-package/work-items.yaml` 앵커 `id: BO-3` 의 `note:` 축자
  > 범위 밖 = 특정 연구실 하나로 좁히는 전환 동작(읽기 op 이 연구실 인자를 받아야 하므로 계약 판정이 선행한다)
- 같은 `note:` 의 `[미확인]`(관리자 전 연구실 열람 실동작)이 이 피드백으로 일부 해소됐다 — 대장 갱신은 이 intent 범위 밖.
- 390px 에서 아바타는 숨는다 — `frontend/src/shell/design-system.css` 앵커 `.colab-ui .gnb .avatar { display: none; }` ⟹ `D-5` 는 데스크톱 한정.
- 로그아웃은 별 버튼으로 이미 서 있다 — `frontend/src/shell/Gnb.tsx` 앵커 `data-testid="gnb-logout"`(근거 주석 `PLAN-SoT §9 〈90〉-㉳`).

## 설계트리 (grill-me 결과)
- Q1 `D-1` 은 확정 판정의 반전인가 → A 아니다. `BO-3` 는 전 연구실 일괄 읽기까지가 완료 정의이고 전환 동작은 그 항목 밖이다. 지금 요구되는 것은 ⓐ 표기 정정이고, ⓑ 운영자에게 연구실 선택권을 줄지는 **새 제품 질문**이다.
  - Q1a ⓐ 는 무엇을 바꾸나 → A 상태 칩으로 바꾼다(`button` 해제 · `▾` 없음 · 읽기 전용 라벨). 사용자가 보는 것 = 누를 수 없는 범위 표시. 대가 = 관리자는 계속 전 연구실을 한꺼번에 본다. 크기 **S** · 근거 `frontend/src/shell/Gnb.tsx` 앵커 `data-testid="lab-switcher"`(속성이 `aria-label` 하나뿐 · `onClick` 부재).
  - Q1b ⓑ 의 대가 → A 읽기 op 에 연구실 인자를 더해 `contracts/` ＋ `services/core-api/src/colab_core/kernel/scope.py`·`app/deps.py` 를 개정한다. 크기 **L** · 계약 파괴 가능. 권고 = 별 대장 항목 후보로 등재하고 계약 판정을 먼저 받는다. **(권고안 수용 · Ted 2026-09-13 — 카드 ① ⓐ 를 이번에 집행 · ⓑ 는 관리자 기능 묶음에서 따로 판정)**
- Q2 `D-5` 는 메뉴를 만드는가 → A 이번 회차는 만들지 않는다. 사용자가 보는 것 = 이름 옆 화살표가 없어지고 단순 사용자 표시가 된다. 대가 = 계정 동작이 상단 개별 버튼으로 남는다. 크기 **S**.
  - Q2a 레포 자체 규칙과의 정합 → A 같은 파일이 연구실 전환기에는 「`▾` 를 달지 않는다 — 달면 없는 동작을 약속하게 된다」를 규칙으로 적었고 아바타에는 적용되지 않았다(조사 A `[추론]`). `▾` 제거가 그 규칙의 일관 적용이다.
  - Q2b 메뉴안(내 정보 · 비밀번호 변경 · 로그아웃)의 크기 → A **M** · `frontend` 한정. `I-9` 의 더보기 메뉴와 같은 부품이므로 한 묶음으로 판정한다.
- Q3 `I-9` 는 결함인가 → A 설계 차이다. 라벨 접기 사다리가 목업 정본이다 — `frontend/src/shell/shell.css` 앵커 `GNB 반응형 사다리` 주석의 목업 축자
  > 「좁아질수록 라벨부터 접고 아이콘만 남긴다. **마지막까지 지키는 건 주 내비와 업로드**다.」
  - Q3a 가시 이름을 주는 두 길 → A ⓐ `title` 속성 추가(**S** · `Gnb.tsx`·`UploadEntry.tsx`, 터치 기기에서 표시되지 않는 한계) ⓑ 더보기 메뉴에서 그림＋이름 동시 표시(**M** · 한 번 더 눌러야 하나 이름이 항상 글자로 보인다).
  - Q3b 권고 → A ⓑ(= 카드 ③ ⓒ). 더보기 목록은 **기능 진입(업로드 · 계정 관리 · 연구실 설정)** 만 담는다 — 아바타 메뉴(Q2b)는 카드 ② 판정대로 이번 회차에 만들지 않으므로 묶지 않는다. **(권고안 수용 · Ted 2026-09-13 — 카드 ③ ⓒ 더보기 목록)**

## 미해결 질문
- 해소(Ted 2026-09-13 · 카드 ①) — 운영자에게 연구실 선택 장치를 주지 않는다. 전 연구실 일괄 읽기를 유지하고 이 intent 는 ⓐ 의 표기 정정만 집행한다. ⓑ(선택 목록 신설 · 계약 판정 선행 · **L**)는 관리자 기능 묶음의 새 대장 항목 후보다.
- 해소(Ted 2026-09-13 · 카드 ③) — 모바일 상단 기능 아이콘은 **이번 회차에 ⓒ 더보기 목록(그림＋기능명)** 으로 집행한다. 아바타(내 계정) 메뉴는 카드 ② 대로 만들지 않는다(화살표 제거 · 단순 표시). `title` 도움말(Q3a ⓐ)은 데스크톱 마우스 보조 수단으로 함께 둘 수 있다.
- 아바타 메뉴·모바일 라벨의 대장 항목 유무 `[미확인]` — 해소 = `grep -n "아바타\|avatar\|계정 메뉴\|반응형" dev-package/work-items.yaml`.
