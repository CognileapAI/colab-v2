# Intent: 자료 설명 정본을 폴더에 세우고, 그 정본으로 dev 를 명령 한 줄에 다시 채운다
메타 — 발의자: Ted · 작성 2026-09-14 · 승인 미승인
상태 — 초안 — Ted 판정 대기

- 이 문서가 `dev-package/intent/2026-09-14-dev-reseed-workflow.md`(워크플로우 초안)를 흡수한다. 그 초안의 질문 5건은 아래 ㈏·㈒·㈓·㈔·㈕ 로 승계됐고, 새 질문 3건(㈎·㈐·㈑)이 더해졌다.

## 문제

- **설명 자료가 있었는데 등록 결과가 그것을 반영하지 못했다.** 참조자료의 각 유형 폴더에는 `#readme` 안에 워드·파워포인트 설명 문서가 실재한다(`01.level-data/01.precipitation/01.precipitation/#readme/#processing_description_Precipitation.docx` 등 · 설명 문서 후보 전수 10건 · `dev-package/reports/reference-data/2026-09-13-inventory-v2.md` 3·5 절). 그런데 dev 에 선 26건은 가공 단계가 전부 같은 값이다.
  - 원인 = **사람이 검토해 확정한 정본이 그 폴더에 없었다.** 실행에 쓰인 등재표(`dev-package/tools/dev-seed/plan-manifest.yaml`)는 설명 문서를 한 번 읽어 옮긴 파생물이고, 옮기는 과정에서 가공 단계 항목이 빠졌다. **오케스트레이터의 매핑 누락이다** — 제품 계산 결함이 아니다.
  - 실측 = 러너 코드·계획 파일에 가공 단계 관련 매치 0건(`dev-package/reports/r-dev-reset/feedback-2026-09-14.md` Item 2 ㉱). 등록 폼 기본값 `Lv2` 가 26건 전건에 그대로 저장됐다(같은 문서 ㉮·㉲).
- **가뭄 자료 2건이 화면에서 등록되지 않는다.** 서버·정본은 분석 실패에도 등록 201 을 요구하는데(같은 문서 Item 1 ㉰ · 정본 `Policy_업로드와_계보_확정:192`), 화면이 분석 실패 하나로 「다음 →」 단추를 잠근다(`frontend/src/components/upload/UploadModal.tsx:1527`). 결과 = `SPI-4weeks`·`SPEI-4weeks` 차단, 등재 28 대비 실적 26.
- **고른 값을 나중에 고칠 창구가 화면에 없다.** 상세 편집 폼에 분류 3축(분류·유형·가공 단계)이 없다(`frontend/src/components/detail/editFields.ts:85-95`). Ted 축자 「레벨은 편집상에서 수정이 되지 않음」. 서버는 `PATCH /datasets/{datasetId}` 로 받는다(`services/core-api/src/colab_core/app/routes/catalog.py:793-804`).
- **다시 채우는 일이 사람 손으로 12단계를 잇는 형태다.** 2026-09-13 회차는 배포 → 계수 → 앱 정지 → 스키마 재생성 → 확장 → 마이그레이션 2체인 → 권한 2건 → 기동 → 자체 점검 → S3 계획·적용 → 사후 계수 → 화면 투입 순으로 진행됐고 세 회차로 갈렸다(`dev-package/sessions/DR-2-run-2026-09-13.md`). 조각 넷(초기화 도구 · 부트스트랩 셸 · 배포 실행기 · 화면 투입 러너)은 실재하고, 넷을 한 번에 부르는 진입점만 없다.

## 원한 결과 (proposed outcome)

- ⓐ **유형별 설명 정본이 참조자료 폴더 안에 있다.** 자리 = 각 유형 폴더의 `DATASETS.md`(강수 · 식생 · 가뭄 · 포맷 확인용 4건). 각 행의 항목 = 이름 · 가공 단계 · 부모 · 파일 글롭 · 파일 건수 · 바이트 · 기준 격자 쌍 · 포맷 · 설명 문서 축자 · 미리보기 기대 · 비고. **Ted 확정 표시가 문서 안에 있다.**
- ⓑ **실행 계획은 그 정본에서 생성되는 파생물이다.** `dev-package/tools/dev-seed/plan-manifest.yaml` 과 `upload-plan.json` 이 `DATASETS.md` 4건을 읽어 만들어지고, 정본과 어긋나면 비영 종료한다(사람이 손으로 두 자리를 맞추지 않는다).
- ⓒ **명령 하나가 끝까지 돈다.** `dev-package/tools/dev-reseed/reseed.sh` 한 줄 ＋ 대화에서 부르는 이름 `/dev-reseed`. 단계 = `preflight → reset → bootstrap → up+doctor → s3 → prelude → seed(browser) → verify → report`. `--from <단계>` 재개 · `--dry-run` 무접촉 · 실행 중 사람 입력 0회 · 결과 JSON 1건(단계별 종료코드 · 소요 · 계수 · 차단 목록).
- ⓓ **재생성 뒤 dev 가 정본과 일치한다** — 데이터셋 **28**(가뭄 2건 포함) · 프로젝트 4 · 가공 단계가 정본대로(`Lv0`/`Lv1`/`Lv2` 분포가 정본 표와 일치 · 사람이 안 고른 것을 뜻하는 「미지정」 0건) · 계보 간선 **18** · 미리보기 포맷별 판정 결과표 1건(그려진 포맷과 안 그려진 포맷을 이름으로 남긴다).
- ⓔ **화면 결함이 정본대로 고쳐져 가뭄 자료가 「미리보기 없음」으로 등록된다.** 분석 실패가 등록을 막지 않고, 실패 안내 문면이 「등록은 됩니다」로 바뀐다.
- ⓕ **투입 실적과 정본의 차이가 항목명으로 설명된다** — 차단·미연결 항목은 조용히 넘어가지 않고 결과 JSON 과 보고에 이름·사유로 남는다.

## 제약

- 초기화 도구는 게이트 넷을 모두 만족해야 돈다 — ⑴ `--target dev` ＋ `--yes-reset-dev` ⑵ 버킷 이름 정확 일치 ⑶ 두 DB URL 호스트에 `-dev` 포함 ⑷ 계획 파일 키가 `uploads/`·`previews/` 안에만 존재(`.claude/rules/deploy.md:55-58`). 진입점이 이 넷을 우회하지 않는다.
- 현재 규칙은 초기화 실행마다 원장 행 ＋ Ted 명시 GO 를 요구하고 승인은 1회 소진이다(`.claude/rules/deploy.md:62`) — 무인 실행은 이 조건과 걸린다(㈒).
- `_ops/` 무접촉이 절대 조건이다. S3 삭제는 exact-key 계획 ＋ sha256 대조로만 한다(`.claude/rules/deploy.md:59-61`).
- 참조자료 폴더는 지금까지 읽기 전용으로 다뤄 왔다(`dev-package/reports/reference-data/2026-09-13-inventory-v2.md` 머리 축자 「레포 밖 · 무수정 · 읽기 전용」). ㈎ 가 그 취급을 바꾸는 자리다.
- 화면에서 데이터셋을 지우는 길이 없다(서버 501) — 오입력은 다음 초기화까지 남는다.
- 이미 등록된 데이터셋을 프로젝트에 붙이는 화면이 없다(순번 1 데이터셋이 프로젝트 미연결로 남아 있다 · `03-HANDOFF §4` 블로커 `74`). 재생성으로 닫히는 자리다.
- 폴더 표기는 `Lv.0`/`Lv.1`/`Lv.2`, 제품 값은 `Lv0`~`Lv3` 이다 — 정본 md 가 두 표기의 대응을 명시해야 한다.
- 비밀값은 표준입력·0600 파일로만 전달한다. argv·로그·결과 JSON·원장에 싣지 않는다.
- 배포 반입 게이트는 `origin/main` 조상만 허용한다.
- AI 없이도 완결(`CLAUDE.md §3`) — 이 범위에 AI 지점 없음. 러너는 계보 AI 제안 단추를 누르지 않는다.

## 미해결 질문

- ㈎ **자료 설명 정본 파일을 어디에 두는가**
  - 사용자가 보는 것: ⓐ 자료 폴더를 열면 그 안에 설명 md 가 같이 있다 / ⓑ 자료 폴더는 그대로이고 설명은 개발 저장소 안에만 있다.
  - 두 갈래의 대가: ⓐ 자료를 쓰는 사람이 같은 자리에서 설명을 보고 고칠 수 있다. 대신 지금까지 손대지 않기로 한 폴더에 파일이 생긴다. ⓑ 폴더가 원본 그대로 남고, 자료와 설명이 떨어져 있어 다음 사람이 설명의 존재를 모를 수 있다.
  - 권고: ⓐ — 폴더 안이 정본, 저장소 쪽은 그 복사본. 기존 자료 파일은 한 글자도 고치지 않고 `DATASETS.md` 만 새로 놓는다.
- ㈏ **가뭄 자료 2건을 어떻게 올리는가**
  - 사용자가 보는 것: ⓐ 지금 올라가고 미리보기 자리에 「이 형식은 지도로 못 그려요」가 뜬다 / ⓑ 지도까지 그려질 때까지 기다렸다가 올린다.
  - 두 갈래의 대가: ⓐ 화면 조건 한 줄을 정본에 맞추는 일이고, 가뭄 항목이 이번 재생성에서 등재표대로 선다. 지도는 안 나온다. ⓑ 지도 자료를 읽는 기능을 새로 만들어야 해서 회차가 크게 길어지고, 그때까지 가뭄 항목이 계속 비어 있다.
  - 권고: ⓐ 지금 수정 — 서버·정본이 이미 ⓐ 이고 화면만 어긋나 있다. 지도 자료 판독은 별도 안건으로 연다.
- ㈐ **등록할 때 「가공 단계」를 무엇으로 시작하는가**
  - 사용자가 보는 것: ⓐ 지금처럼 `Lv2`(도출된 2차 산출물)가 미리 골라져 있다 / ⓑ 아무것도 안 골라진 채로 시작하고 사람이 고른다.
  - 두 갈래의 대가: ⓐ 손이 덜 가고, 안 고른 것과 `Lv2` 로 고른 것이 영영 구분되지 않는다(필터의 「미지정」이 항상 0건). ⓑ 등록할 때 한 번 더 고르는 대신, 값이 자료 설명과 다르면 바로 드러난다.
  - 권고: ⓑ — 제품 변경이지만 작다. 「안 골랐으면 값이 없다」는 계약 산문의 전제와도 맞는다(`services/core-api/src/colab_core/domains/d3_catalog.py:1458-1470`).
