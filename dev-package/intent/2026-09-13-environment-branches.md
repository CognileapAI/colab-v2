# 환경별 브랜치 승인

2026-09-13 사용자: “main 에 이제 통합하지 말고”, “local-stage 라고 브랜치 만들고 거기에 넣자”, “pr(aws)는 실제 운영환경”, 제안 확인 “좋아좋아 그렇게 하자”.

목적: ST에서 검증 중인 코드를 main/DEV 및 실제 운영과 분리하고 검증된 변경만 순서대로 승격한다.

승인된 대응: codex 작업 → local-stage/ST(local-srv) → main/DEV(AWS) → production/PR(AWS 운영). 운영 승격·배포는 명시 승인, 동일 산출물과 커밋 기록을 요구한다.

이번 집행: 기존 검색 후속 수정의 local-stage 커밋·원격 반영·ST 배포. main 변경, DEV 배포, 실제 운영 자원 생성·배포는 범위 밖이다. production의 첫 기준점은 DEV 검증을 통과한 첫 운영 승인 커밋이며 아직 생성하지 않는다.

수용 기준: 전략 정본/진입점 일치, ST 감시 source local-stage, 검색 수정 커밋 보존, 백업·마이그레이션·ST 교체·검증 기록. 실제 운영 도구 준비는 별도 후속으로 기록한다.
