# Intent: 등록 화면의 설명문 규약과 부모 찾기 재현
메타 — 발의자: Ted(GitHub 이슈 작성 sungwooHa 회수) · 작성 2026-09-12 · 승인 미승인

## 문제
- 업로드 메타데이터 입력 탭에서 설명문 위치가 칸마다 다르다. 어떤 칸은 필드명 바로 아래, 어떤 칸은 사용자 입력란 아래에 있다(`CognileapAI/colab-v2#31`).
- 등록 마지막 단계의 부모 데이터 찾기 창에서 결과가 0행으로 표시된 화면이 첨부됐다(`CognileapAI/colab-v2#30`).
- 0행이 조회 결함인지 후보 부재인지 재현되지 않았다.

## 원한 결과 (proposed outcome)
1. 메타데이터 3열 행의 모든 설명문이 자기 칸의 입력 컨트롤 뒤에 표시된다. 기간 칸도 같은 순서다(#31).
2. 설명문의 문구 자체는 삭제하지 않고 그대로 유지된다(#31).
3. `frontend/test/register-steps-20260907.test.tsx` 의 설명문 위치 단언이 green 이다.
4. dev 실물에서 부모 데이터 찾기 창을 열었을 때 결과 0행이 재현되는지 여부가 기록된다. 기록에 후보 실재 여부 · 연구실 경계(RLS) 적용 · 자기 제외(`exclude_id`) 동작이 각각 포함된다(#30 ㈎).
5. 4의 기록이 「조회 결함인가 후보 부재인가」의 후속 판정 입력이 된다. 이 intent 는 코드 수정을 포함하지 않는다.

## 영향 범위
- 사용자 / 화면: 업로드 등록 단계의 메타데이터 입력 탭 · 계보 부모 데이터 찾기 모달(재현 확인만).
- 서비스 · 스키마 · 계약: frontend 단독. 수정 대상 = `frontend/src/components/upload/RegisterArea.tsx`. 조사 대상(읽기 전용 · 무수정) = `frontend/src/components/lineage/ParentPicker.tsx`. `frontend/src/components/upload/upload.css` 는 접촉하지 않는다.
- 계약 파괴 여부: 아니오. 근거 = `dev-package/reports/issues/2026-09-12-survey-SUMMARY.md` §7 — 착수 후보 범위에서 `contracts/` 변경 0건 · DB 마이그레이션 0건 · 동결 해제 서명 불요. 조사 B `#31` §5 축자 「`contracts/` 변경: 없음. DB 마이그레이션: 없음. 동결 해제 서명: 불필요」 · 조사 D `#30` — 재현 확인만 포함 · 코드 변경 0.

## 제약
- `CLAUDE.md §2`·`§3` 불변 규칙 중 걸리는 것 없음. `#30` 재현은 연구실 경계 자동 주입(`§3-5`)이 동작하는지를 관찰만 하고 그 동작을 바꾸지 않는다.
- 「AI 없이도 v2 는 완결된 제품이다」 유지 — 부모 데이터 선택은 사람이 직접 고르는 것이 기본이고 이번 변경이 그 성질을 바꾸지 않는다.
- 대화형 UI 도입 금지 — 설명문 위치 통일은 기존 폼 요소의 JSX 순서 변경이다.
- 갈래 ⓐ 로 한정한다 — `RegisterArea.tsx` 의 JSX 순서 이동만 수행하고 CSS 규칙으로 규약을 고정하는 갈래 ⓑ 는 채택하지 않는다. 사유 = ⓑ 는 `upload.css` 를 접촉해 I-1(`.up-banner`)·I-3(`#28`·`#29 ⑴`) 레인과 충돌한다(취합본 §3 충돌표 · §7 단서).
- 갈래 ⓐ 한정에 따라 이 intent 는 I-1·I-3 레인과 병렬 가능하다. `RegisterArea.tsx` 는 `#29 ⑵` 와 공유 후보이나 `#29 ⑵` 가 이번 회차 미착수라 충돌이 없다. `#29 ⑴` 의 수정 대상이 재현 결과에 따라 `RegisterArea.tsx` 로 확정되면 그 시점에 I-3 와 직렬로 전환한다.
- `#30` 재현은 dev 실물에서 수행하며 실측 회차(L4)에 동승한다. 데이터셋 행 삭제 등 비가역 조작을 하지 않는다.

## 설계트리 (grill-me 결과)
- Q1 설명문을 삭제할 것인가 위치를 통일할 것인가 → A 위치를 통일한다. 문면은 유지한다. 이슈 원문 축자 「설명에서 빼던가, 위치를 통일 시키든가」의 두 갈래 중 후자.
  - Q1a 통일 기준을 무엇으로 하는가 → A 입력 컨트롤 뒤. 3칸 중 기간 칸만 설명문이 컨트롤 위에 있고 나머지가 뒤이므로 다수 배치를 기준으로 삼는다(취합본 §1 `#31` 행).
  - Q1b 기간 칸 위 배치가 의도인지 → A 판정 문서 탐색 결과 무결과다(취합본 §5 미확인 11). 의도를 지지하는 기록이 없으므로 다수 배치로 통일한다.
- Q2 수정 갈래 → A ⓐ `RegisterArea.tsx` JSX 순서 이동만. `upload.css` 미접촉으로 I-3 와 병렬(취합본 §10 결함 4).
- Q3 부모 데이터 찾기를 어디까지 볼 것인가 → A ⓐ 0행 재현 확인만 이번에 하고 화면 형태는 새 항목으로 등재 (권장안 수용). 이번 회차 코드 변경 0.
  - Q3a 새 항목의 제안명 → A 「계보 부모 찾기 창을 데이터셋 목록 화면과 같은 표·열·정렬로 재구성」. 제안 단계이며 이 intent 가 번호를 발급하지 않는다.
  - Q3b 재현에서 무엇을 가리는가 → A dev 실물 후보 유무 · 연구실 경계 · 자기 제외 동작 셋(취합본 §5 미확인 9).
- Q4 설명문 배치 규약이 코드·문서 어디에 있는가 → A 없다. 통일 후 정책 문서에 한 줄 추가가 후속 항목이다(취합본 §9-4).
