# Intent: 휴대폰·패드 대응 — 디자인 시스템의 폭·입력 방식 규칙과 지도 미리보기 시범
메타 — 발의자: Ted(휴대폰 미리보기 지도 겹침 제보 → 전 화면 대응으로 확대 · 초안 agent) · 작성 2026-09-26 · 승인 2026-09-26(Ted · PR #162 병합 뒤 「권고대로」)

## 문제
- 휴대폰(≈390px)에서 데이터셋 상세 → 미리보기 → 보기를 누르면 범례 · 확대/축소/기본 배율로 · 「커서를 지도 위로」 · 「지도의 한 점을 누르면 그 자리의 값을 보여 줘요.」 · 스크린샷이 지도 위에서 서로 겹치고 지도 그림을 100% 가린다(Ted dev 실화면 · 변수 이름 `HLS.S30.T52SCE.2025361T022121.v2.0.B02`). 첫 배율에서는 그림을 눌러도 값 조회가 되지 않는다(탭 시 조회 0회).
- 전 화면 점검(36개 장면 · 10개 폭 · 터치 모의 · `dev-package/reports/responsive-audit/20260925/report.md`)에서 휴대폰·패드 문제가 화면마다 따로 나온다.
  - 폭 규칙 61개(16파일)가 값 17종으로 흩어져 있다. 같은 경계가 860·861·880·900, 720·740·760 처럼 여러 값으로 적혀 있다.
  - 16px 입력 글자는 폭 640px 이하 조건 안에만 있고, 토큰을 쓰지 않는 고정 px 부품은 13–40px 이다. 641px 이상 터치 기기(휴대폰 가로·패드)의 34–35개 장면이 마우스용 크기로 나온다. (`--control-height`·`.btn-sm` 은 2026-09-25 design-fix 후속 Q3c 로 이미 `pointer: coarse` 에서 44px.)
  - 마우스를 올려야만 보이는 정보(`title` 전용) 9곳 · `:hover` 34개(`(hover: hover)` 조건 0) · 더블클릭 「데이터에 맞춤」 대안 단추 없음 · 마우스 전제 문구(「커서를 지도 위로」·「끌어다 놓으세요」).
  - 휴대폰 가로(844x390)에서 맨 위 메뉴 2줄이 높이의 28%, 창 본문은 약 178px. 넓은 표 3종은 휴대폰에서 작업 단추가 화면 밖(옆으로 700–880px).
- `docs/design-system.md` 에 폭 단계 · 패드 규칙 · 좁은 화면 배치 · 입력 방식 규칙이 없다(640·900 여백 분기와 터치 44px 토큰만 있다).

## 원한 결과 (proposed outcome)
- (a) `docs/design-system.md` 에 다음이 적힌다: 폭 4단계(≤640 휴대폰 · 641–900 패드 세로 · 901–1180 패드 가로 · ≥1181 PC) · 판단 기준(화면 폭 기본, 지도·그림 위 도구 · 넓은 표 · 표 안내만 부품 칸 폭) · 터치 기기 규칙 · 낮은 높이 규칙(≈500px 이하 · 값은 시범 뒤 확정) · 넓은 표 원칙(휴대폰 카드 · 패드 이상 열 고정) · 지도·그림 위 도구 원칙.
- (b) 데이터셋 상세 · 업로드 · 미등록 미리보기 지도에서 지도 칸이 약 810px 미만이면 범례 · 값 결과 · 안내 · 스크린샷이 지도 아래에 있고, 지도 위에는 확대·축소 단추만 있다. 390px 에서 범례 · 값 결과 · 안내 · 스크린샷이 지도 그림을 가리는 면적 0.
- (c) 같은 지도에서 기본 배율의 한 손가락 끌기는 페이지를 스크롤하고, 확대한 상태에서만 지도를 옮긴다.
- (d) 터치 기기(`pointer: coarse`)의 모든 화면에서: 누름 칸 44px 미만 0(점검 대상 선택자 기준) · 입력 글자 16px 미만 0 · `title` 에만 있는 정보 0 · hover 색 변화는 `(hover: hover)` 조건 안 · 마우스 전용 동작마다 누름 대안 · 입력 방식에 맞는 문구.
- (e) 디자인 검사 게이트가 허용 폭 값 밖의 새 폭 조건을 red 로 잡는다. 기존 23개 값은 사유를 단 면제 목록에 있다.
- (f) 기준 캡처가 390 · 844x390 · 820 · 1024 · 1180 · 1440 × 라이트·다크(장면당 12장)이고, 1180 이하는 터치 모드다.
- (g) 시범 화면을 dev 에서 Ted 실기기(iPhone · 패드)로 확인한 결과가 남는다.

## 가치 가설
- 휴대폰·패드로 데이터셋을 보는 연구자는 지도와 범례를 가림 없이 보고 값 조회를 할 수 있어, PC 없이도 자료를 확인한다.
- 개발은 화면마다 폭 값을 새로 만들지 않고 정해진 단계를 쓰므로, 휴대폰·패드 문제가 화면마다 따로 재발하는 비용이 준다.
- 확인 방법: 점검 스크립트 재실행 전후 비교(390·507·820 지도 가림 %, 터치 폭 작은 누름 칸 수 · 16px 미만 입력 칸 장면 수) · 게이트의 새 폭 값 red 시험 · Ted 실기기 확인. PR 요약 「원한 결과 ↔ 실제 ↔ 근거」 표의 근거가 된다.

## 제약
- 확정 값 유지: 2026-09-25 design-fix 후속 Q3c(`pointer: coarse` 에서 `--control-height` 44px · `.btn-sm`)를 유지하고 넓힌다. 여백 토큰은 바꾸지 않는다.
- 이전 겹침 이슈 #120 의 요구(도구는 확대·이동 transform 과 함께 움직이지 않는다)를 지킨다. 좁은 폭 범례 위치 판정만 바꾼다(2라운드 Q7).
- `PreviewSlot.tsx` 머리말 「그림이 완성돼야 자리가 생기면 안 된다 · 바깥 치수 불변」: 지도 틀 치수는 고정하고 범례는 틀 밖 아래 블록으로 둔다. 완성 때 페이지가 범례 높이만큼 길어지는 것은 허용한다(2라운드 Q5).
- 미등록 미리보기 `.pv-map` 은 `flex-wrap: nowrap`(`preview.css:112-116` · #120). 아래 배치는 wrap 복귀가 아니라 새 블록으로 한다.
- 스크린샷 PNG 는 서버가 그린다(`ScreenshotButton.tsx:9-11`). 화면 배치 변화가 내려받는 파일에 영향을 주지 않는다.
- 새 문구는 spec 초안에 문구안으로 싣고 Ted 가 spec 승인 때 확정한다(2라운드 Q6). 기존 시험 단언은 지우지 않는다(`getByLabelText('범례')` 등).
- 점검은 로컬 모의 데이터였다. 모의 이름이 실제보다 짧다(데이터셋 이름 10–32자 vs UI 최대 80자 · 파일 경로 7–26자 vs 72자). spec 검증에 긴 이름을 넣는다.
- dev 확인 전 Ted 가 `test_admin@colab.invalid`(연구실 없는 운영자)을 다시 만들고 dev 재생성 승인 목록에 추가한다. 이후 에이전트가 테스트마다 비밀번호를 초기화한다(2라운드 Q8).
