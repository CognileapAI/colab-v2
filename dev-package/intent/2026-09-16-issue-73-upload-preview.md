# Intent: 긴 미리보기 선택값의 화면 넘침 해소와 그림의 데이터 대응 확인
메타 — 발의자: joddanddan-commits · 작성 2026-09-16 · 승인 2026-09-16

## 문제
- surface.grib 업로드 이슈 이미지에서 긴 변수 선택값이 패널 밖으로 넘고 변수 라벨이 줄바꿈된다.
- 큰 지도는 파란 띠와 경계, 작은 대표 그림은 전세계 형태로 보여 다른 데이터를 나타내는지 혼란스럽다.
- 썸네일은 좌표 없는 값층, 큰 지도는 투영된 지도층이라는 기존 차이가 있다. 모양 차이만으로 렌더 오류를 확정하지 않는다.
## 원한 결과 (proposed outcome)
- 긴 파일·변수·시각 선택값이 공용 선택칸의 컨테이너를 넘지 않고 라벨이 읽힌다. 잘린 값의 전체 내용을 확인할 수 있다.
- 업로드 인라인·확장보기·데이터셋 상세에서 동일한 배치 규칙을 지킨다.
- 큰 지도와 자동 대표 그림이 같은 파일·변수·시점·색 설정의 렌더 결과에 대응하는지 검증한다. 불일치가 재현되면 해당 원인을 고친다.
- 실제 surface.grib를 재현해 파란 띠의 원인을 원본 값·좌표·그림과 대조하고, 확인된 사실과 미확인을 나누어 기록한다.
- 수동 대표 그림 선택 및 자동 그림 복귀, 비지도형과 실패 구제 흐름을 보존한다.
## 영향 범위
- 사용자 / 화면: 업로드·확장·상세 미리보기.
- 서비스 · 스키마 · 계약: 우선 공용 프런트 선택칸과 실재현. 렌더 문제는 실제 원인 확인 후 기존 계약 안에서 수정한다.
- 계약 파괴 여부: 아니오. 투영 또는 thumbnail 계약 재정의는 이번 승인에 포함하지 않는다.
## 제약
- 그림의 투영·화면 구도를 강제로 일치시키거나 깨진 큰 그림에 작은 그림을 맞추지 않는다.
- 원본 GRIB 식별값을 자르거나 저장값을 바꾸지 않는다. 새 의존성·DB 변경 없음.
- 실제 브라우저에서 폭·선택 변경을 확인하며 과거 증거를 이번 실행 결과로 대신하지 않는다.
## 설계트리 (grill-me 결과)
- Q1 화면 넘침 → A 공용 선택칸을 최소 수정하고 세 화면에서 검증한다.
- Q2 두 그림의 모양 차이 → A 같은 데이터·선택값인지 먼저 확인하며 투영 차이를 오류로 단정하지 않는다.
- Q3 파란 띠 → A 실제 파일 재현으로 원인을 확인한다.
- Q4 수동 대표 그림 → A 사용자 선택을 유지한다.
