# Intent: 검색 결과의 범위 줄이 실제로 뒤진 범위와 건수를 말하게 한다
메타 — 발의자: 이태헌(1차 검증 피드백) · 작성 2026-09-13 · 승인 미승인

## 문제
- 관리자 로그인 상태에서 상단 표기는 「전체 연구실 (읽기 전용)」이고 데이터셋 목록은 26건이다.
- 같은 계정의 검색 결과 머리줄은 「고려대학교 수문학연구실 데이터 25건을 뒤졌어요」로 나온다 — 한 화면이 범위를 두 가지로 말한다.
- 결과 항목은 전 연구실에서 오고, 머리줄의 건수·연구실 이름은 소속 연구실에서 온다.

## 원한 결과 (proposed outcome)
- 검증 가능 문장 ⑴ — 관리자 검색 응답의 범위 줄 연구실 표기가 그 검색이 실제로 조회한 스코프와 같다.
- 검증 가능 문장 ⑵ — 범위 줄 건수가 같은 스코프의 데이터셋 목록 건수와 같다(관리자 = 전 연구실, 일반 구성원 = 소속 연구실).
- 검증 가능 문장 ⑶ — 관리자·일반 구성원 각 1건의 시험이 범위 줄 문자열과 목록 건수의 일치를 고정한다.
- 판정 = 화면이 사실과 다른 범위를 말하는 상태가 닫힘. 선택 장치 유무와 무관하게 성립한다.

## 영향 범위
- 사용자 / 화면: 연구실 홈 검색 · 검색 결과 머리줄. 관리자 계정에서만 값이 갈린다.
- 서비스 · 스키마 · 계약: `services/core-api/src/colab_core/app/routes/catalog.py`(분모 계산 자리 · 연구실 이름 조립) · `frontend/src/routes/SearchResultsPage.tsx`(출력). 스키마 무변경.
- 계약 파괴 여부: 아니오 — `contracts/schemas/common.json` 의 검색 범위 객체는 `labId`·`labName`·`searchedCount` 필수이고 `labName` 은 `minLength: 1` 문자열이므로 문안 교체만으로 성립한다(조사 A 확인).

## 제약
- 분모 계산 순서 제약 — `searched_count` 가 조건부 `with read_only_scope(...)` 블록보다 먼저 계산된다. 스코프를 맞추려면 계산 자리를 블록 안으로 옮기거나 읽기 전용 스코프를 한 번 더 연다. 크기 **M** 유지(advisor 게이트 ② 반영).
- 범위 객체의 `labId` 는 필수 Ulid 다 — 관리자에게도 소속 연구실 id 가 실리면서 `labName` 만 「전체 연구실」을 말하는 의미 불일치가 남는다. 계약은 무변경이고, 이 상태를 문서로 명시한다. 새 칸(스코프 종류) 신설은 `additionalProperties: false` 때문에 계약 개정이 필요하다(추가 칸이므로 파괴는 아니다).
- 「검색은 뒤진 범위를 먼저 밝히고」는 AI 응답 규격이다(`CLAUDE.md §3`) — 정합 수정은 규격 이행이고 새 판정을 요구하지 않는다.
- 운영자 읽기 확장은 승인 intent 근거로 서 있다 — `services/core-api/src/colab_core/app/deps.py` 축자 「운영자의 **읽기 요청에만** 전 연구실 스코프를 연다 (승인 intent 2026-09-12)」.

## 설계트리 (grill-me 결과)
- Q1 두 숫자가 왜 갈리나 → A 분모는 `scoped_db` 세션에서 계산되고 그 세션의 운영자 확장은 읽기 메서드에만 열린다. 검색은 `POST` 이므로 확장이 꺼진다. 결과 항목은 `read_only_scope(operator_read=...)` 라 전 연구실이다(조사 A).
- Q2 정합을 어디서 맞추나 → A 서버. 분모를 검색 실행과 같은 스코프에서 계산하고, 관리자일 때 범위 표기를 「전체 연구실(읽기 전용)」로 쓴다.
  - Q2a 화면에서만 고칠 수 있나 → A 불가. 반대(권장안 거부) — 화면은 서버가 준 건수를 그릴 뿐이고, 소속 연구실 건수를 전 연구실 결과의 분모로 쓸 근거가 없다.
- Q3 검색창 옆에 범위를 미리 적는 기획자 권고를 이번에 넣나 → A 넣지 않는다(권장안 부분 수용) — 건수를 미리 보이려면 별도 조회가 선다. 결과 머리줄이 이미 「결과보다 위이자 먼저」 규약이다(`frontend/src/routes/SearchResultsPage.tsx` 머리 주석 축자 「· 범위 줄이 결과보다 **위이자 먼저**다 (0건이어도, 장애여도)」).
- Q4 범위 선택기(전체 / 우리 연구실)를 함께 만드나 → A 분리한다. 선택기는 조회 범위를 요청이 지정하는 구조 변경이고, 상단 연구실 전환 동작 판정과 한 묶음이다.
- Q5 실데이터 25 대 26 의 내역 → A `[미확인]`. 해소 = dev DB `SELECT lab_id, count(*) FROM d3_dataset WHERE deleted_at IS NULL GROUP BY 1`. 코드상 차이는 「다른 연구실 소속 1건」으로 설명되고, **내역과 무관하게 스코프 갈림은 결함이다**.
