# Intent: 로그인 마무리(dev 반영)와 운영자 백오피스 확장 — 목록·재설정·비활성화
메타 — 발의자: Ted · 작성 2026-09-12 · 승인 미승인

## 문제
- 로그인 신뢰성·복구 코드는 `main` 에 병합됐으나 dev 에 배포되지 않았다(최신 dev 태그 `dev-20260911-2` 는 그 이전 커밋 · 계정 표·로그인 세션 표 마이그레이션 2건 dev 미적용). 로그인 입력 형태를 엄격히 한 계약 변경 1건이 「계약 파괴」 검사에서 red 로 남아 수용 기록으로만 보존되고 있어 전체 검사가 한 번의 실행으로 green 이 되지 못한다.
- 운영자 백오피스는 계정 추가 화면 1개뿐이다. 등록한 계정을 볼 목록이 없고, 비밀번호 분실·퇴소를 화면에서 처리하지 못해 운영자가 SQL 을 직접 만져야 한다.

## 원한 결과 (proposed outcome)
- 로그인 강화 코드가 dev 에 배포되고, 배포 후 자체 점검 15/15 와 전체 검사 green 이 **한 번의 실행**으로 확인된다. 계약 변경 1건(로그인 혼합 입력 400)은 Ted 서명(동결 해제)으로 정리해 red 가 남지 않는다.
- 계정 발급 흐름은 현행 유지 — 운영자가 백오피스에서 이메일·역할·연구실을 등록하고 초기 비밀번호를 직접 입력해 당사자에게 전달한다. 당사자는 첫 로그인에서 비밀번호 변경을 강제받고, 변경 전에는 다른 기능을 쓰지 못한다.
- 운영자 백오피스에 계정 목록(전 연구실 한 목록 · 이메일·이름·역할·연구실·상태·최근 로그인 · 열 필터)이 있다.
- 운영자가 특정 계정의 비밀번호를 재설정할 수 있다 — 새 초기 비밀번호를 직접 입력하면 첫 로그인 변경이 다시 강제되고, 그 계정의 기존 로그인(모든 기기)이 즉시 종료된다. 비밀번호 원문은 응답·로그에 남지 않는다.
- 운영자가 계정을 비활성화/재활성화할 수 있다 — 비활성화 즉시 로그인 거절 ＋ 기존 로그인 전부 종료. 데이터·소유권은 유지된다.
- 이전 항목 「이메일 식별 서비스 계정 직접 추가」는 현재 계정 추가 화면으로 완료 처리하고, 위 확장은 새 항목으로 대장에 등재한다.
- 별도 작업 사본의 실행 보고서 2개 디렉터리를 레포로 회수·커밋한 뒤 사본을 삭제한다. staging 자동배포 감시는 dev 배포 green 뒤 재개한다.

## 영향 범위
- 사용자 / 화면: 운영자 백오피스(계정 목록 · 재설정 · 비활성화/재활성화). 로그인·첫 변경 화면은 변경 없음.
- 서비스 · 스키마 · 계약: core-api 계정 라우트(목록 · 재설정 · 비활성화 엔드포인트) · 플랫폼 마이그레이션 1건(계정 상태 열) · `contracts/seams/fe-core.yaml` 추가(기존 엔드포인트 형태 유지).
- 인프라: 변경 없음(메일·IAM·도메인 없음).
- 계약 파괴 여부: 예(Ted 서명 필요) — 기존 수용분 1건(로그인 혼합 입력 400)의 동결 해제만. 신규 파괴 0.

- 전 기기 종료는 기존 자격 버전 대조 기계를 재사용한다(새 세션 저장 방식 도입 없음).
- AI 없이도 완결(`CLAUDE.md §3`) — 이 범위에 AI 지점 없음.
- 실패 제한·12시간 고정 만료·첫 변경 강제 등 앞선 intent 의 8정책은 그대로다.
- 완료 = dev 배포 green ＋ 자체 점검 15/15 한 번의 실행(`CLAUDE.md §0`).
