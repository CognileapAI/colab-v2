# Intent: 로그인 마무리(dev 반영)와 운영자 백오피스 확장 — 임시 비밀번호 메일 발송
메타 — 발의자: Ted · 작성 2026-09-12 · 승인 미승인

## 문제
- 로그인 신뢰성·복구 코드는 `main` 에 병합됐으나 dev 에 배포되지 않았다(최신 dev 태그 `dev-20260911-2` 는 그 이전 커밋 · 계정 표·로그인 세션 표 마이그레이션 2건 dev 미적용). 로그인 입력 형태를 엄격히 한 계약 변경 1건이 「계약 파괴」 검사에서 red 로 남아 수용 기록으로만 보존되고 있어 전체 검사가 한 번의 실행으로 green 이 되지 못한다.
- 운영자 백오피스는 계정 추가 화면 1개뿐이다. 초기 비밀번호를 운영자가 직접 입력해 전달하고, 계정 목록·비밀번호 재발급·비활성화가 없어 발급 이후의 운영 문의(비밀번호 분실·퇴소)를 화면에서 처리하지 못한다.
- 사용자가 비밀번호를 잃으면 스스로 복구할 경로가 없다. 플랫폼에 발신 메일 기능이 없다(정찰 `reports/stage3-login-hardening/recon-email-20260912.md`).

## 원한 결과 (proposed outcome)
- 로그인 강화 코드가 dev 에 배포되고, 배포 후 자체 점검 15/15 와 전체 검사 green 이 **한 번의 실행**으로 확인된다. 계약 변경 1건은 Ted 서명(동결 해제)으로 기준 계약을 갱신해 red 가 남지 않는다.
- 운영자가 계정을 추가하면 서버가 임시 비밀번호를 생성해 **선택된 이메일로 발송**한다. 임시 비밀번호는 응답·화면·로그 어디에도 나오지 않는다.
- 로그인 화면에 「비밀번호 찾기」가 있다. 이메일을 넣으면 등록 여부와 무관하게 같은 안내를 보이고, 등록된 계정이면 임시 비밀번호를 재생성해 메일로 보낸다.
- 운영자 백오피스에 계정 목록(전 연구실 · 이메일·이름·역할·연구실·상태·최근 로그인) · 타인 비밀번호 재발급(임시 비밀번호 메일) · 비활성화/재활성화가 있다.
- 임시 비밀번호는 발급 후 24시간 안에 첫 로그인해야 하고 첫 로그인에서 변경을 강제한다(기존 정책 유지). 재발급·비활성화 시 그 계정의 기존 로그인(모든 기기)이 즉시 종료된다.
- 메일 발송 실패 시 계정 생성·재발급은 완료로 두고 「메일 발송 실패 · 다시 보내기」를 보인다. 다시 보내기는 새 임시 비밀번호를 만든다.
- stage 에서 Ted 지정 수신 주소 1개로 실제 수신을 확인한다.
- 이전 항목 「이메일 식별 서비스 계정 직접 추가」는 현재 계정 추가 화면으로 완료 처리하고, 위 확장은 새 항목으로 대장에 등재한다.

## 영향 범위
- 사용자 / 화면: 로그인 화면(비밀번호 찾기) · 운영자 백오피스(계정 추가 폼에서 초기 비밀번호 입력 제거 · 계정 목록 · 재발급 · 비활성화) · 첫 로그인 변경 화면(임시 비밀번호 만료 안내).
- 서비스 · 스키마 · 계약: core-api 계정 라우트(임시 비밀번호 서버 생성·만료 시각·상태 열 · 목록/재발급/비활성화 엔드포인트 · 비밀번호 찾기 엔드포인트 ＋ 실패 제한) · 발신 메일 모듈(AWS SES · 동기 발송 · 자격은 `_FILE` 규약) · 플랫폼 마이그레이션(임시 비밀번호 만료·계정 상태) · `contracts/seams/fe-core.yaml`.
- 인프라: dev EC2 역할에 SES 발송 권한 추가(액세스 키 금지 유지) · SES 도메인 검증(`colab-hydro.com` · DKIM DNS 3건) · 샌드박스 해제 신청 · staging 은 0600 자격 파일.
- 계약 파괴 여부: 예(Ted 서명 필요) — ① 로그인 혼합 입력 400(기존 수용분의 기준 갱신) ② 계정 추가 요청에서 `initialPassword` 제거.

## 제약
- 임시 비밀번호·비밀번호 원문은 응답·화면·로그·큐에 나오지 않는다(기존 약속 유지).
- AI 없이도 완결(`CLAUDE.md §3`) — 이 범위에 AI 지점 없음.
- 배포 규칙: EC2 액세스 키 금지 · 관대한 기본값 금지(메일 자격 미선언이면 발송 경로는 실패로 계수, 조용한 통과 금지) · 앱 내 백그라운드 잡 금지(동기 발송으로 충족).
- 실패 제한은 기존 값(자격/클라이언트 각각 5회/15분)을 비밀번호 찾기에도 같게 적용하며 수치를 재질문하지 않는다.
- SES 샌드박스 상태에서는 검증된 수신 주소에만 발송된다 — 해제 전 실사용 불가를 완료 조건에 반영한다.
- 완료 = dev 배포 green ＋ 자체 점검 15/15 한 번의 실행(`CLAUDE.md §0`).
