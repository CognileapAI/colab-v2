# Intent: 업로드 세 단계의 입력 안내와 필수 조건을 기획에 맞춘다
메타 — 발의자: joddanddan-commits · 범위 결정: Ted · 작성 2026-09-16 · 승인 2026-09-16

## 문제
- 예시가 없거나 실제 값처럼 보여 입력 형식을 오해한다. 숫자·단위를 따로 받는 칸의 예시에도 단위가 들어 있다.
- 첨부 기획과 현재 관측 간격·Lv0 출처 필수 여부가 다르다.
- 세 단계에서 자동 표시 정보·기간과 간격·변수와 대표 그림·계보와 외부 출처의 역할을 더 명확히 안내해야 한다.

## 원한 결과 (proposed outcome)
- 신규 등록에서 관측 간격의 숫자와 단위를 필수로 받는다. Lv0이면 출처 주소와 내려받은 날도 필수다. 화면 배지·제출 검사·서버 검사·계약을 일치시킨다.
- 누락 시 해당 단계/입력칸으로 이동하여 원인을 알리고 등록 요청 또는 서버 저장을 막는다. 정상 입력 시 저장·재조회로 값 보존을 확인한다.
- 기존 필수인 분류·유형·가공 단계·이름·기간 시작·설명과 선택인 기간 종료·좌표계·격자·변수·프로젝트 등은 유지한다.
- 좌표계 예시 `예: EPSG:5179`, 관측 간격 예시 `예: 10`과 안내 `숫자를 입력하고 단위를 선택해주세요`, 변수 네 칸의 목업 예시 `예: tp`/`mm`/`0 ~ 240`/`2.4 %`를 표시한다. 예시는 저장값이 아니다.
- 실제 UI에 맞는 자동 정보 설명, 기간/간격 및 대표 변수의 의미, 외부 출처와 부모 연결의 차이를 기존 화면 안에서 짧게 안내한다. “사람이 적어요”를 제거한다(#77과 겹치는 문면).
- #79 선택 제거와 함께 검증하며 등록 중 미리보기·복원·가공 단계 보존·계보 선언 복원을 유지한다.

## 영향 범위
- 사용자 / 화면: 업로드 분류·메타데이터·연결 및 공용 변수 편집 표의 예시.
- 서비스 · 스키마 · 계약: 신규 DatasetCreate 등록의 관측 간격 필수와 Lv0 출처 조건부 필수, 관련 서버/프런트 검증·시험 및 생성 타입. DB 마이그레이션 없음.
- 계약 파괴 여부: 예. 기존 선택 필드의 신규 등록 필수화. Ted가 충돌하는 세 항목을 제시받고 “엉 기획대로 하자”로 승인했다. 기존 데이터 수정 API까지 확대하지 않는다.

## 제약
- 2026-09-15의 관측 간격·Lv0 출처 선택 유지 판정을 이번 신규 등록 범위에서 개정한다. 원문 이력은 보존한다.
- 자동 메타데이터 입력 기능, 프로젝트 검색·필터, 공개 범위 정책, 기본 분류값·대표 변수 자동 선택을 새로 만들지 않는다.
- #80/#82에서 승인된 사용자 선택/체크 상태 보존, 숨은 비Lv0 출처값 전송 생략을 유지한다.
- 입력칸 폭을 늘리거나 새 CSS 체계·의존성·DB 변경을 도입하지 않는다.
