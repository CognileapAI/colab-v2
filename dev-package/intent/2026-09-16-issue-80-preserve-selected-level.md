# Intent: 계보 연결 시 선택한 가공 단계 유지
메타 — 발의자: joddanddan-commits · 작성 2026-09-16 · 승인 2026-09-16

## 문제
- 업로드 분류 화면에서 기본값 Lv.0을 그대로 둔 뒤 Lv.3 데이터를 계보에 연결하면, 앞서 보였던 단계가 Lv.3으로 자동 변경된다.
- 같은 Lv.0이라도 기본값으로 두었는지 직접 변경했는지에 따라 연결 가능한 후보가 달라져 사용자가 결과를 예측하기 어렵다.
- 기존 승인에서 기본 선택값의 계산값 추종을 허용했으므로, 이번 변경은 단순 누락 보완과 함께 그 동작을 개정하는 요청이다.

## 원한 결과 (proposed outcome)
- 화면에 표시된 가공 단계가 계보 연결 후보의 상한이 된다. 기본값과 직접 선택한 값에 동일한 규칙을 적용한다.
- 계보를 연결하거나 해제해도 선택한 단계는 자동으로 바뀌지 않는다. 처음 표시하는 값은 기존 Lv.0을 유지한다.
- 자기 단계보다 높은 단계의 후보는 보이되 연결할 수 없고, 그 이유를 표시한다. 같은 단계 또는 낮은 단계는 기존처럼 연결할 수 있다.
- 연결 후 자기 단계를 낮춰 충돌이 생기면 연결을 자동 삭제하지 않는다. 충돌을 안내하고, 연결을 해제하거나 단계를 올려 해소할 때까지 등록을 막는다.
- 계보에서 계산한 단계와 사람이 선택한 단계는 구분한다. 계산값과의 불일치만으로는 등록을 막지 않는 기존 규칙을 유지한다.
- 저장 요청과 등록 후 조회에서도 사용자가 선택한 단계가 유지된다.

## 영향 범위
- 사용자 / 화면: 데이터셋 업로드의 분류 선택과 계보 연결, 단계 간 이동 및 등록.
- 서비스 · 스키마 · 계약: 우선 프런트 상태 처리와 관련 회귀시험. 기존 서버의 부모 단계 검증과 저장 계약을 재사용한다. 스키마 변경은 계획하지 않는다.
- 계약 파괴 여부: 아니오. 조사 중 계약 변경 필요성이 발견되면 구현 범위를 확정하기 전에 별도로 보고한다.

## 제약
- 부모 단계 ≤ 자기 단계 규칙과 같은 단계 연결 허용을 유지한다.
- 계산 단계는 기존 산식과 Lv.3 상한을 유지하고, 선택값을 덮어쓰는 근거로 사용하지 않는다.
- 기존 승인 문서의 자동 추종 결정을 이 범위에서 개정한다. 원문은 삭제하지 않으며 관련 기록에 개정 표시를 유지한다.
- 새로운 의존성·저장 열·가공 단계 정의를 도입하지 않는다.
- 기본 Lv.0 유지, 직접 선택, 같은 단계 연결, 초과 후보 차단, 연결 후 단계 하향, 연결 해제, 단계 왕복을 회귀시험과 실제 브라우저 동작으로 검증한다.
- 정적 분석만 수행한 상태이며, 실제 재현·회귀시험·저장 후 조회 검증은 아직 실행하지 않았다.

## 설계트리 (grill-me 결과)
- Q1 작업 순서와 분석 방식 → A Ted의 현 대화 지시에 따라 첫 항목으로 intent를 작성한다. 전체 순서는 계보 단계·기간 보존 → 미리보기·계보 표시 → 입력 안내·레이아웃 개선이며, 미리보기 전용 선택 제거도 업로드 묶음에 포함한다.
- Q2 현재 단계가 자동 변경되는 이유 → A 기존 승인된 기본값 자동 추종 구현 때문이다. 새 이슈는 먼저 표시·선택한 단계가 후보를 제한하도록 요청한다. 이 intent는 자동 추종을 제거하는 개정을 명시한다.
- Q3 같은 단계도 연결을 막는가 → A 기존 규칙대로 같은 단계는 허용한다. 초과 단계만 막으며 범위를 확대하지 않는다.
- Q4 이미 연결한 뒤 단계를 낮추면 어떻게 하는가 → A 기존 규칙대로 연결은 유지하고 충돌 안내 및 등록 차단을 적용한다. 자동 삭제하지 않는다.
- Q5 계산 단계와 다르면 저장을 막는가 → A 기존 불일치 안내 규칙을 유지한다. 부모가 자기 단계를 초과하는 충돌과 계산값 불일치를 구분한다.
