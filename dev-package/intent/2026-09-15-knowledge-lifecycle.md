# Intent: 지속 업로드에 따른 근거 기반 지식 구축과 독립 실행
메타 — 발의자: Ted · 작성 2026-09-15 · 승인 2026-09-15(의도와 문서 작성 범위; 구현·배포 승인 아님)

## 후속 실행 승인 — 2026-09-15
- 사용자 원문: "그럼 이제 해". 합의한 계획의 로컬 제품 구현·검증을 시작한다.
- 아래 문서 작업 당시의 범위·승인 기록은 이력으로 보존한다. 제품 구현 제외는 이 후속 요청으로 변경되었으며, 배포·통합·커밋·push·실제 Sonnet 평가 보류는 유지한다.
- 구현 단계·실측·미달은 [실행 계획](../prd/rounds/R-KNOWLEDGE-LIFECYCLE.md)에서 추적한다. 이 추가 승인은 전체 결과 달성이나 운영 활성화를 뜻하지 않는다.

## 문제
- 자료가 계속 등록·변경되는데 특정 평가 자료만 수동 보완하면 새 자료의 의미 검색 품질을 유지할 수 없다.
- 온톨로지 정의, 자료별 사실·관계, 검색 인덱스를 혼합하면 중복 개념과 근거 없는 관계가 누적되고 독립 운영이 어렵다.
- 후속 개발자가 의도·도메인 책임·설계 선택의 이유를 추적할 개발 스펙과 ADR이 필요하다.

## 원한 결과 (proposed outcome)
- O1. 새 자료의 확인 가능한 사실과 기존 개념 연결이 자동 축적되며 검색에 활용된다. 같은 개념에 연결하는 것을 온톨로지 확장과 구분한다.
- O2. 온톨로지는 개념·관계 정의와 버전을 소유하고, 자료별 KG는 출처가 있는 사실·연결을 소유하며, 검색 인덱스는 재구축 가능한 조회 모델로 취급한다.
- O3. 업로드·검색 요청과 별도 프로세스로 지식 구축을 실행하고, 후속 별도 인스턴스나 함수형 실행으로 이동할 수 있도록 실행 환경과 처리 로직을 분리한다.
- O4. 중복 실행·순서 역전·실패 재시도·파일 교체·삭제에도 오래된 결과가 최신 지식을 덮어쓰거나 검색에 재등장하지 않는다.
- O5. 근거로 검증된 매핑은 자동 반영하고, LLM의 새 개념·불확실한 관계는 제안과 확정 지식으로 구분한다.
- O6. 기존 28개 자료와 실무자 기대 질문뿐 아니라 신규 업로드·재처리·교체·삭제·실패 복구로 동작을 검증한다. 평가용 답을 개념 정본에 하드코딩하지 않는다.
- O7. intent → 개발 spec → ADR → 실행 계획 → 검증의 추적 관계를 문서화한다. 이번 요청의 산출 범위는 문서이며 제품 구현 완료를 뜻하지 않는다.

## 영향 범위
- 사용자 / 화면: 기존 업로드·검색 이용자. 새 UI는 선결정하지 않는다.
- 서비스 · 스키마 · 계약: 자료 관리, 온톨로지 관리, 자료별 지식 구축, 검색 조회 모델 및 이들 간 버전·이벤트 계약. 기존 도메인과 워커를 우선 재사용한다.
- 계약 파괴 여부: 이번 문서 작업은 없음. 후속 spec에서 현행 계약과 대조해 판정하며 파괴 변경을 자동 승인하지 않는다.

## 제약
- 다른 도메인의 저장소를 직접 수정하지 않고 소유 도메인의 명시 계약을 통한다. 논리 경계 분리가 즉시 별도 DB 도입을 뜻하지 않는다.
- 연구실·자료 접근 권한을 유지한다. 비공개 자료에서 유래한 제안·근거가 공용 온톨로지를 통해 노출되지 않아야 한다.
- 자료 ID·원본 버전·온톨로지 버전 및 처리 버전과 출처를 추적한다. LLM의 제안 자체를 사실의 원본 근거로 재사용하지 않는다.
- 업로드 요청에서 무거운 분석을 기다리지 않는다. 기본 검색은 등록 후 제공하고 의미 검색 보강은 통상 30분 이내를 초기 목표로 삼는다. 측정된 SLA 또는 고정 실행 간격으로 주장하지 않는다.
- 전체 자료 재분석 대신 변경분을 묶어 처리한다. 무변경이면 모델을 호출하지 않는다.
- 삭제·권한 변경에 따른 검색 차단은 배치 완료를 기다리지 않는다. 파일 교체 시 이전 버전의 근거로 최신 자료를 확정 판정하지 않는다.
- 온톨로지 제안 승인 주체·운영 절차, 처리량·비용 한도, 실행 스케줄의 세부값은 spec에서 명시하며 임의의 운영값을 배포하지 않는다.
- 기존 Sonnet 평가 보류는 유지한다. 문서 작성은 유료 모델 호출·설정 변경·배포 권한을 부여하지 않는다.

## 설계트리 (grill-me 결과)
- Q1 독립 실행 범위 → A 후속 구현은 별도 기동 워커까지 검증한다. 별도 서버·Lambda 배포는 제외한다(권고 수용).
- Q2 자동 확정 범위 → A 파일의 확인된 사실·검증된 기존 매핑만 자동 반영하고 새 개념·불확실한 관계는 검토한다(권고 수용).
- Q3 반영 목표 → A 기본 검색은 바로 제공하고 지식 분석은 통상 30분 이내를 초기 목표로 삼는다. 실제 처리량으로 조정한다(권고 수용).
- Q4 검증 범위 → A 기존 자료·실무자 질문과 신규 업로드·재처리·교체·삭제·실패 재시도를 포함한다(권고 수용).
- Q5 이번 요청의 작업 범위 → A 도메인의 의도·개발 스펙·ADR을 충분히 갖추는 문서 작업. 구현·운영 변경은 실행하지 않는다.

## 미해결 질문
- 목적과 이번 문서 작업 범위 수준에서는 없음. 운영 세부 설계의 확정은 spec·ADR의 근거 조사 및 검토 단계이며 이 intent로 완료를 주장하지 않는다.

## 범위 밖 (명시 제외)
- 이번 턴의 제품 코드·DB·실행 설정 변경, 모델 호출, 전체 재시드, 통합·배포·커밋·push.
- Lambda 확정, 신규 메시지 브로커·그래프 DB 도입을 선결정하는 것.
- 업로드마다 온톨로지 전체 재생성, 모든 LLM 제안 자동 승인, 검색 실패만을 근거로 사실 확정.
