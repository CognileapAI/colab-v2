# Intent: 미리보기 상자의 조작 자리
메타 — 발의자: Ted(GitHub 이슈 작성 sungwooHa 회수) · 작성 2026-09-12 · 승인 미승인

## 문제
- 미리보기 그림 왼쪽 위에 64×64 축소본이 하나 더 표시된다(`CognileapAI/colab-v2#26`).
- 파일·변수·시각 고르개가 미리보기 틀 안에 있어 그림이 나오면 스크롤 위로 밀려 보이지 않는다(`CognileapAI/colab-v2#25` ⑵).
- 확대·축소·기본 배율 버튼이 인라인 미리보기에서는 상자 스크롤 맨 아래에 있어 스크롤해야 보인다(`CognileapAI/colab-v2#27`).
- 확장보기에서 같은 버튼이 그림 오른쪽에 세로로 눌리고 글자가 두 줄로 접힌다(`CognileapAI/colab-v2#28`).
- 확장보기 그림 위에 기간 라벨과 「달력에서 고르기」가 겹쳐 보인다는 보고가 있고, 화면 캡처 재취득이 불가해 재현되지 않았다(`CognileapAI/colab-v2#29` ⑴).
- 업로드 화면 진입 후 「지도 그리는 중…」 표시가 길게 이어진다. 렌더 소요를 재 본 회차가 0회다(`CognileapAI/colab-v2#25` ⑴).

## 원한 결과 (proposed outcome)
1. 미리보기 그림 위 지도 자리에서 64×64 축소본이 표시되지 않는다. 같은 축소본이 접히는 자리(대표 그림 고르개 `up-thumb-img` 옆)에서 표시되어 결정 `〈88〉` 묶음 3 의 표시 목적을 유지한다(#26).
2. 파일·변수·시각 고르개가 미리보기 틀 밖 고정 줄에 표시되고, 그림이 렌더된 뒤에도 스크롤과 무관하게 계속 보인다. 인라인 미리보기 · 확장보기 · 데이터셋 상세 세 화면에서 동시에 같은 배치다(#25 ⑵).
3. 인라인 미리보기에서 확대·축소·기본 배율 버튼이 스크롤 없이 보인다(#27).
4. 확장보기에서 같은 세 버튼의 글자가 한 줄로 표시되고 그림에 눌리지 않는다(#28).
5. 대장 `WU-C4` 완료 정의 축자 「`useZoomPan/.pv-zoom` 을 상세·업로드·확장보기가 공유」가 유지된다 — 세 화면이 같은 부품·같은 배치 규약을 쓴다.
6. 확장보기에서 기간 라벨·「달력에서 고르기」가 그림 위에 겹치는지 여부가 브라우저 재현으로 확인되고, 촬영 뷰포트 폭(1023px 이하 1열 접힘 해당 여부)과 함께 기록된다. 그 기록이 후속 판정의 입력이 된다(#29 ⑴).
7. 같은 실측 회차(L4)에서 업로드 진입→그림 표시 렌더 소요와 `createRender` 호출 횟수·컴포넌트 재마운트 발생 여부가 기록된다. 그 값이 분석 구간 값과 함께 Ted 의 합격선 지정 입력이 된다(#25 ⑴).

## 설계트리 (grill-me 결과)
- Q1 그림 위 64×64 축소본을 지울 것인가 → A ⓑ 지도 자리에서 빼고 접히는 자리(대표 그림 고르개 옆)로 옮긴다 (권장안 수용). 결정 `〈88〉`-3 의 표시 목적은 유지하고 지도 위 중복만 제거하며, 재판정 기록을 남긴다.
  - Q1a 조사 C 가설 B(서버가 한 렌더에서 두 산출물을 준다)를 채택하는가 → A 채택하지 않는다. 결정 `〈88〉` 축자 「①②가 항상 함께 구워진다」와 코드 주석 축자 「①썸네일 — 성공 응답에도 실린다(`〈88〉` 묶음 3)」로 성립하지 않는다(취합본 §8 · `[advisor 앵커 · 미재확인]`).
- Q2 파일·변수·시각 고르개를 미리보기 틀 밖으로 뺄 것인가 → A ⓐ 틀 밖 고정 줄로 옮긴다 (권장안 수용). 인라인·확장·상세 세 화면 동시 적용. 규약 R-C-2 개정 기록을 남긴다.
  - Q2a 틀 안에서 해소할 갈래(ⓑ)를 먼저 시도하는가 → A 시도하지 않는다. Ted 판정이 ⓐ 다.
- Q3 확대·축소 버튼의 자리를 어떻게 정할 것인가 → A ⓐ 접힘·가림 해소까지만 고친다 (권장안 수용). 고정 배치 재설계는 범위 밖.
  - Q3a 확장보기 접힘의 원인 → A 오버레이 본문 `display:flex` 의 방향 미선언으로 기본 `row` 가 적용되고 그림 폭 상한이 없다(취합본 §1 `#28` 행 · 「코드에 존재」 등급).
  - Q3b 인라인의 가림 원인 → A 확대 줄이 뷰포트에 겹치지 않고 세로 흐름의 형제 요소다(같은 표 `#27` 행).
- Q4 미리보기 위에 보이는 기간 입력을 어떻게 볼 것인가 → A ⓐ 재현부터 하고 결과에 따라 판정 (권장안 수용). 재현은 L4 회차에 동승하고 코드 변경 0.
  - Q4a 기간 달력 팝오버 자체의 존치를 다투는가 → A 다투지 않는다. 존치는 종전 판정이다(`.claude/rules/colab-rules.md §6-2` 축자 「Ted 지정 예외는 판정으로만 성립(실례 = rev2 기간 달력 팝오버 판정-2 ⓑ)」).
  - Q4b `#29 ⑴` 의 수정 대상 파일 → A `RegisterArea.tsx` 문자열 1곳이 실물 소유자다(조사 C `5-3` 이 조사 B `§7` 의 미확인을 닫음). 수정 여부는 재현 결과에 따른다.
- Q5 렌더 소요의 합격선을 무엇으로 할 것인가 → A ⓐ 한 실측 회차(L4)로 분석 구간과 함께 재고 값을 본 뒤 Ted 가 지정 (권장안 수용).
  - Q5a `#25 ⑴` 의 원인을 실측 전에 확정하는가 → A 확정하지 않는다. 가설 A(원천 렌더 시간)와 가설 B(`key` 재마운트로 자동 렌더 반복)는 배타가 아니다(취합본 §8 · §5 미확인 3·4).
