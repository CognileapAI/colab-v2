# S3 — 업로드 저장 백엔드 (비로컬 벌)

> 업로드 바이트 저장의 **로컬/S3 분기** 운영 정본 (`PLAN-SoT §9 〈276〉·〈277〉`).
> 절차가 실제와 다르면 이 문서를 고친다. 고칠 때의 불변 규칙은 루트 `CLAUDE.md` "업로드(S3)" 절.

## 0. 구조 한 장

| 저장 모드 | 어디서 | 바이트 경로 | 설정 |
|---|---|---|---|
| `local` (기본) | 로컬 개발 · 현 staging | FE → core-api(form-data) → 디스크(`COLAB_CORE_UPLOAD_DIR`) | 추가 설정 없음 — **로컬 개발에 AWS 가 필요 없다** |
| `s3` | dev/prod 배포 | FE → **S3 직행**(프리사인드, 멀티파트·중단 재개) · core-api 는 컨트롤 플레인만 — **예외 = 묶음 다운로드**(core-api 가 S3 GET 을 zip 으로 흘려보낸다, `〈278〉`-(다)) | `COLAB_CORE_STORAGE_MODE=s3` + 아래 §1 벌 |

- 분기점은 `ports/storage.py`(저장 Port)와 `routes/upload_transfers.py`(전송 9 op — local 모드에선 전부 501, FE 가 그 신호로 form-data 폴백).
- 저장 **키**는 두 모드가 완전히 같다 — 정본은 `contracts/storage/layout.json` 생성물이고, 폴더째 업로드의 경로는 키가 아니라 원장 메타(`relative_path`)에 산다.
- **에뮬레이터(MinIO 등) 금지** — SigV4 가 직접 구현(`kernel/sigv4.py`, boto3 없음)이라 에뮬레이터의 관대함이 검증을 무력화한다(관대한 통과 → 진짜 S3 에서 403).

## 1. dev·prod 벌 신설 런북 (그 배포가 설 때)

환경 벌 = {버킷 · 전용 IAM 정책 · 전용 사용자 · env 한 벌} 이 함께 태어난다. 순서:

1. **IAM 정책** `colab-platform-s3-uploader-<환경>-policy` — Resource 는 그 환경 버킷 ARN 만.
   local 용으로 만들었던 3문(업로드 조작 · 멀티파트 · Diagnostics) 구성과 대칭.
   **prod 는 Diagnostics 문을 뺀다** — doctor 진단 항목이 ─ 로 나오는 게 정상이고 왕복으로 판정한다.
2. **사용자** `colab-platform-s3-uploader-<환경>` (콘솔 로그인 해제) + 위 정책 부착 + 액세스 키 발급.
   키는 어떤 채팅·커밋에도 붙여넣지 않는다 — 배포 시크릿 저장소로만.
3. **버킷** `colab-platform-data-<환경>` — 리전 ap-northeast-2(서울) · Block Public Access 전부 유지 ·
   Versioning Enable · SSE-S3.
4. Permissions — **CORS**: `AllowedOrigins` 는 그 환경의 실오리진만(prod 와일드카드 금지) ·
   Methods `PUT/GET/HEAD` · ExposeHeaders `ETag·Content-Length·Content-Range·Accept-Ranges·x-amz-request-id·x-amz-id-2`.
   **Bucket policy**: `DenyInsecureTransport`.
5. Management — 라이프사이클 2개: `abort-incomplete-multipart-7d`(중단 재개의 최후 백스톱) ·
   `expire-noncurrent-30d`. **전체 만료 규칙은 걸지 않는다**(장부-창고 어긋남 방지).
6. **배포 환경변수 한 벌**: `COLAB_CORE_STORAGE_MODE=s3` · `COLAB_CORE_S3_BUCKET` ·
   `COLAB_CORE_S3_REGION` · `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`(또는 ECS/IMDS 롤).
   반쪽 설정(모드만 s3, 버킷 없음)은 기동이 거부된다 — 의도된 동작이다.
7. 생성 직후 §2 의 doctor 10/10 · smoke 전 항목 ✓ 로 검증한다. 콘솔 눈으로 판정하지 않는다.

> 버킷 삭제가 필요하면: 버저닝 탓에 "비어 보여도" 거부된다 — 콘솔 **Empty → Delete** 순서로.

## 2. 운영 진단 도구 (`services/core-api/ops/` — 제품 밖, 배포 이미지에 안 실림)

`services/core-api` 에서, 해당 벌 env 를 실은 채:

| 도구 | 언제 | 실행 |
|---|---|---|
| `s3_doctor` | 버킷 설정이 맞는지 (신설·문제 발생 시) | `.venv/bin/python ops/s3_doctor.py --bucket <버킷>` |
| `s3_smoke` | 업로드 기계가 실제로 도는지 (서명 관련 수정 후) | `.venv/bin/python ops/s3_smoke.py --bucket <버킷>` |

> **백엔드 코드를 고쳤으면 uvicorn 재기동까지가 배포다** — Vite 는 자동 반영되지만 백엔드는 아니다.

## 3. s3 모드의 동작 요약

- **접수 전 = 전송 원장** (`d5_upload_transfer*`, 이어올리기 창 72h): initiate 가 전략(16MiB
  미만 단일 PUT / 이상 8MiB 파트 멀티파트)을 정하고, 브라우저가 프리사인드 URL 로 직접 올린다.
- **완결 = 접수**: 서버가 S3 실측(ListParts·HeadObject 크기 대조)으로 전 파일을 확인한 뒤에만
  같은 ULID 로 `d5_upload` 가 서고 `upload.accepted` 가 발행된다 — 그 뒤는 기존 파이프라인 세계다.
- **중단 재개**: 탭이 죽어도 S3 와 원장이 기억한다. 모달 상단 배너 → [이어서 올리기] → 같은
  파일 재선택 → **빠진 파트만** 전송. 파트의 정본은 S3 ListParts — 자기 보고를 믿지 않는다.
  ⟨추가 2026-09-02 · `〈281〉`-㉺⟩ **메인 화면(S-01)에도 카드가 선다** — 모달을 닫으면 「올리다 만 것이
  있다」는 사실 자체가 사라졌다. 모달 배너는 **그대로 두고 카드를 더한 것**이지 옮긴 것이 아니다.
  ⚠ **미완결은 두 종류다** — 전송 미완(72h · 서버 목록 op) 과 **등록 미완**(24h · 목록 op 이 계약에 없어
  브라우저가 기억한다 · 등록 여부는 `UploadStatus.registered` 가 말한다). 카드가 둘을 합쳐 보여준다.
  ⚠ **재시도는 재개다** — 새 `initiate` 를 부르면 시도마다 원장이 늘어 실패 세트가 쌓인다.
  ⚠ **메인 배치는 Ted 판정 대기**(`Policy_홈_대시보드 §8` 개정 · `〈277〉`-⑧-⑶ 번복) — 먼저 집행하고 판정을 청했다.
- **폴더 업로드**: 드롭존이 폴더를 재귀로 펼치고(숨김 제외) `폴더/이름` 을 원장 메타로 보존한다 —
  접수(`d5_upload_file`)와 등록(`d3_file.relative_path`, `0009`) 둘 다. 로컬 form-data 경로도 `relativePaths` 로 같은 값을 싣는다.
- **다운로드**(`〈278〉`-(다)): 발급 op 가 **200 티켓**(HMAC 서명·10분)을 주고 브라우저가 `url` 로 간다.
  파일 단위 = **프리사인드 GET**(S3 가 직접 준다) · 묶음 = `GET /downloads/{ticket}` 이 S3 GET 을
  `ZIP_STORED` 로 흘려보낸다(core-api 경유 — 대용량 실측은 I-D 몫). 바이트 시점에 연구실 경계·body_access 가
  다시 판정된다. 이력 `d8_download`(파일 단위는 `file_id`).
- **정리**: 만료된 미완결 전송은 initiate/incomplete 경로의 지연 정리가 **원장 주도로** 치운다
  (버킷 루트 스캔 금지). 라이프사이클 7일 규칙이 최후 백스톱.

## 4. 열린 갭 (dev 배포 작업의 몫)

- **pipeline-worker·viz-render 는 로컬 경로만 읽는다** — s3 모드에선 전송·접수까지만 성립하고
  포맷 감지·축 판별·미리보기는 미동작이다. = `WORK-UNITS` **V-3**(완료 정의 미작성, 방식 판정 뒤).
  I-D(dev 환경, `〈279〉`)가 이것에 의존한다.
- ~~`relative_path` 는 원장(d5)까지만~~ → `〈278〉`-(나)·`0009` 로 닫힘(등록 후 트리 표시).
- s3 모드 **묶음 다운로드가 core-api 트래픽**을 만든다 — 대용량 실측(현 실측 166 MB 까지)은 I-D 몫.
- ~~본체 전송 진행률~~ → **막대는 섰다**(2026-09-02 · `§D.7 ①` 근거). **문구만** 정본
  (`S1-PLAN-REFOUND §E.2`) 개정 대기다.
- **S3 고아 바이트를 치우는 주체가 없다** — 워커 만료가 DB 행만 지운다. 09-02 실측 3건 26,579,847 B 를
  목록으로 고정해 손으로 지웠다. 판별식 = `d3_dataset`·`d5_upload`·열린 전송 **셋 다 없어야 고아**. **별도 WU**.
- **완결된 전송 원장 행이 안 지워진다** — `complete()` 는 도장만 찍고 만료 스윕은 `completed_at IS NULL`
  만 고른다. 바이트가 아니라 **행**의 누수다(`〈281〉`-㊂-⑶).
- **상태 2 목록 op 이 없다** — 브라우저 저장으로 우회해 다른 기기·시크릿창에서는 못 되찾는다.
