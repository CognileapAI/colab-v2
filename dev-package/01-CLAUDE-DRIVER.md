# 01 · CLAUDE DRIVER — 세션 구동 규약

> 새 세션을 열 때 이 문서의 **킥오프 프롬프트**를 붙여넣는다. 그 외의 설명은 필요 없다.

---

## A. 킥오프 프롬프트 (복사해서 붙여넣기)

```
CoLAB v2 개발 세션. 작업 폴더는 이 저장소의 dev-package 상위 디렉터리다.

먼저 이 순서로 읽어라. 읽기 전에 코드를 쓰지 마라.
  1. dev-package/03-HANDOFF.md   ← 지금 어디까지 왔는가. 여기가 진실원
  2. dev-package/DOMAINS.md       ← 경계. 무엇을 무엇과 섞지 않는가
  3. dev-package/WORK-UNITS.md    ← 완료 정의와 의존 그래프
  4. dev-package/PLAN-SoT.md      ← 설계 근거와 결정 로그
  5. dev-package/sessions/<이번 WU>.md

이번 세션의 작업 단위: WU-____

규약:
- 진입조건을 먼저 확인한다. 충족되지 않았으면 구현하지 말고 그 사실을 보고한다.
- 계약을 먼저 동결하고, 실패하는 테스트를 먼저 쓰고, 그 다음 구현한다.
- 완료 판정은 게이트 green이다. 내 판단이나 네 판단이 아니다.
- 도메인 경계를 넘는 코드를 쓰지 않는다. 넘어야 한다면 그것은 경계 설계 문제이므로 멈추고 보고한다.
- 세션 종료 시 03-HANDOFF.md를 갱신한다.
- 문서에 절대경로를 적지 않는다.
```

## B. 세션 안에서의 규약

### B1. 진입조건 확인이 먼저다

`WORK-UNITS.md` 의 해당 WU 행에서 진입조건을 읽고, 실제로 충족됐는지 **확인한 뒤** 시작한다. 문서가 "닫힘"이라고 적혀 있어도 실물이 없으면 문서가 틀린 것이다 — 그때는 `03-HANDOFF` 를 먼저 고친다.

### B2. 순서: 계약 → 실패 테스트 → 구현 → 게이트

| 단계 | 산출물 | 다음으로 넘어가는 조건 |
|---|---|---|
| 계약 | seam 스펙 / 스키마 / 이벤트 봉투 | 계약 게이트 green |
| 실패 테스트 | 수용 기준을 코드로 | red 확인 (**green으로 시작하는 테스트는 오라클이 아니다**) |
| 구현 | 도메인 코드 | 위 테스트 green |
| 게이트 | — | 전 게이트 green + (I2 이후) staging 배포 green |

### B3. 경계를 넘어야 할 때

도메인 경계를 넘는 코드가 필요해 보이면, **그건 대개 경계가 잘못 그어졌다는 신호다.** 우회하지 말고 멈춘 뒤 셋 중 하나를 보고한다.

1. Port를 하나 추가하면 되는가 (경계 유지)
2. 도메인 하나가 잘못 쪼개졌는가 (`DOMAINS.md` 개정 필요)
3. 기획이 애매한가 (정본 확인 필요)

### B4. AI 도메인에서의 추가 규약

D9·D10을 만질 때는 아래를 **테스트로** 지킨다. 관례로 지키지 않는다.

- D10에서 D4(Lineage)로 쓰는 경로가 존재하지 않음 — 음성 테스트
- 제안 응답의 확신도는 enum 3값(확실/애매/모름). 숫자·퍼센트 금지
- 근거 필드는 필수(nullable 아님)
- 검색 근거는 한 줄 고정, 탐색 범위 고지 필수
- 배치 승인 엔드포인트 없음
- AI 실패 시 화면이 **정직한 빈 상태**로 떨어진다 — 억지 제안 금지

### B5. 절대 하지 않는 것

- PoC·v1 코드를 복사해 오기 (**참조는 지식이지 코드가 아니다** — `PLAN-SoT §6`)
- 게이트를 우회하거나 임시로 끄기
- 생성된 타입·클라이언트를 손으로 고치기
- 문서에 절대경로 적기
- "나중에"로 남기기 — 차단이면 차단 해제를 WU로 만든다

## C. 세션 종료 규약

끝내기 전에 반드시:

1. `03-HANDOFF.md §1` 해당 WU 상태 갱신 (✅ / 🟧+사유 / ⛔+원인)
2. `03-HANDOFF.md` 상단 **최종 갱신 · 현재 단계 · 다음 WU** 갱신
3. 새 결정은 `PLAN-SoT §9` 에 값과 근거를 적는다
4. 새 블로커는 `03-HANDOFF §4`
5. 다음 세션이 확인할 **진입조건을 명시**한다

> 갱신하지 않고 끝낸 세션은 다음 세션의 시간을 두 배로 쓰게 만든다. v1에서 이 규약이 지켜진 구간만 인계가 성립했다.

## D. 모델·에이전트 운용

- 도메인 하나 = 에이전트 하나가 스펙·스키마·테스트·구현을 통째로 드는 단위 (`DOMAINS.md §1-B`)
- 독립 WU는 병렬 dispatch — 조율 비용이 사실상 0이므로 직렬로 둘 이유가 없다
- 병렬 전 조건: 계약이 동결돼 있을 것. 계약 전 병렬은 드리프트만 만든다
