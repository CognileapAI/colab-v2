## 3. 데이터셋 경계 — 폴더를 어떻게 자르는가

지배 규칙은 `DATAMODEL-BASELINE §4.3`:

> **포맷 · 변수 목록 · 좌표계 · 격자 — 모든 조각이 같아야 한다. 하나라도 다르면 조각이 아니라 다른 데이터다.**
> 기간 = 조각들의 **합집합** · 용량 = **합계** · 마지막 수정 = 조각 중 **가장 늦은 값**

- **「역할이 다른 파일은 한 데이터셋에 담지 않는다」** — 담으면 계보가 데이터셋 층·파일 층으로 갈라져 어긋났을 때 판정할 수 없다
- **「파일에는 계보가 없다. 계보는 데이터셋 사이에만」** — 그래서 **자르는 방식이 곧 계보의 해상도**다

### 3.5 기준 격자 파일 — 정본이 정의해 두고 실물이 없던 자리

`DATAMODEL §4.3` 은 파일 종류를 **`본체` | `기준 격자 파일`** 둘로 두고 *「본체 1건 이상 + 기준 격자 파일 0~1건」* 이라 했다. **여태 그 두 번째 값에 해당하는 실물이 인벤토리에 없었다.** 있었다 — `04.Lat_Lon_info` 다.

**포맷 5종 폴더 전부에 있고, 형상이 대응 자료의 격자와 정확히 일치한다** (npy 헤더 직접 파싱, 2026-08-23):

**왜 이것이 중요한가 — `DR-9` 의 해답이 여기 있다.**
PoC 는 HSR 의 위경도를 **dummy `linspace` 로 합성**했고, 좌표를 못 찾으면 **임의 격자를 지어내고 「성공」을 반환**했다(4곳). **그럴 이유가 없었다 — 실제 좌표가 원천에 있다.** **D5 는 지어내지 않고 이 파일을 읽는다.**

**격자가 파일 안에 없는 포맷이 있다 — 실측상 하나다.** 바이너리(HSR)는 헤더에 좌표도 **투영 파라미터도 없어**(36~63 B 가 전부 0) 위경도를 밖에서 받아야만 한다. **그래서 `기준 격자 파일` 이라는 종류가 정본에 있는 것이고**, 이 16 건이 그 자리를 채운다.
> ⚠ **정정(2026-08-23)** — 여기 원래 「HDF4·NetCDF 도 투영 격자라 위경도를 따로 받아야 한다」고 적혀 있었다. **실측하니 nc·tif·hdf·grib 4종은 파일 내부 정보만으로 격자가 계산된다**(동봉 격자 대비 오차 1.3e-5°~0.0). 동봉 배열을 쓰는 것은 편의이지 필수가 아니다. 반대로 **HSR 은 필수다** — `DATA-REFERENCE §1.1`·`§0 M-8`, 정본 `DATA-PIPELINE-MEASUREMENT.md`.

> ✅ **닫혔다 — `〈58〉` ⓐ 2건 허용** (2026-08-23 Ted). 그리고 **후주입 요구가 함께 붙었다**: 「기준 격자 파일은 웹 프런트에서도 지도로 나타낼 수 있어야 하고 **후주입이 가능해야** 한다」.
>
> **후주입이 없으면 그 데이터는 영영 안 보인다.** 격자가 파일 안에 없는 포맷은 좌표를 밖에서 받아야 하는데, 업로드 시점에 격자가 없으면 데이터셋은 **존재하되 지도에 못 그린다.** 나중에 구해도 붙일 길이 없으면 **다시 올려야 하고, 그러면 계보가 끊긴다.**
>
> **S2 에 걸리는 것** — 원천은 격자와 본체가 **같이** 있으므로 S2 는 후주입 경로를 안 타도 된다. **다만 「본체 + 격자 2건」이 한 데이터셋이라는 모양은 S2 가 처음 만든다.**
>
> ⚠ **`레이더합성자료포맷정보.pdf` 가 이 폴더에 있다**(`file_format_3_bin/04.Lat_Lon_info/`). CID 인코딩이라 못 읽었다(§8) — **`F-4` 의 남은 미확인(3블록이 참 스펙인가)의 답이 여기 있을 수 있다.**

## 4. 계보 후보 — 원천이 이미 가지고 있는 것

**이 원천의 가장 큰 값은 파일이 아니라 계보다.** 세 갈래가 이미 구조로 존재한다.

### 4.1 KWRA 다운스케일 — 1:4 팬아웃 (가장 완결적)

```
D-01  GK-2A NDVI 2 km 한반도 (Lv.0)
  │
  ├─[주입력]──→ D-03  Nearest    1 km   가공 방식 = 최근린보간
  ├─[주입력]──→ D-04  Bilinear   1 km   가공 방식 = 이중선형보간
  ├─[주입력]──→ D-05  IDW        1 km   가공 방식 = IDW (k=12, p=2)
  └─[주입력]──→ D-06  Co-Kriging 1 km   가공 방식 = Regression Kriging
                        ▲
D-02  DEM 100 m 충청권 ──[보조입력]──┘   (Co-Kriging 의 보조 변수)
```

**부모 하나에 자식 넷, 관계마다 가공 방식이 다르다.** `DATAMODEL §4.2` 가 *「가공 방식을 데이터셋에 붙이면 부모가 여럿일 때 어느 부모의 가공인지 말할 수 없다」* 며 **관계에 부착**하기로 한 그 설계의 실물 예제다.

그리고 **D-02 → D-06 관계가 `보조입력`이다.** 원천 README 가 명시한다 — *「DEM: 고도 격자. 본 예시의 **Co-Kriging** 에서 보조 변수로 사용」*. 이는 Lv 계산 규칙 *「(주입력 부모 중 최대 Lv) + 1, **보조입력은 계산에서 뺀다**」* 을 검증하는 자리다 — **D-06 의 Lv 는 1 이어야 하고, DEM(Lv.0)이 그 값을 바꾸지 않아야 한다.**

> **S2·P3 의 검증 자산.** 이 묶음 하나로 카탈로그·계보 그래프·시각화·다중 부모·부모 역할 2값·가공 방식 부착이 **한꺼번에** 채워진다. **S2 는 이것을 가장 먼저 적재한다.**

> **⟨개정 2026-08-26 — `〈104〉`⟩ 계보 간선 5 는 불변이다.** 이 다섯은 전부 `D-01`·`D-02`→`D-03`~`D-06` 사이에 있고, **여섯 데이터셋 모두 적재 대상이다.**
> **⟨증보 2026-08-26⟩ 이 다섯은 그대로 있고, 여기에 `D-09` → `D-16` 1건이 더해져 총 6 이 됐다.** 신설분은 이 묶음이 아니라 `§4.2` 식생 사슬 쪽이다 — 상세는 `§3.1` 증보 표.
> ⚠ **「보조입력 1건이 `D-10` 관련」은 거짓이다** — 보조입력 간선은 `D-02`(DEM 100 m 충청권) → `D-06` 하나이고, `D-10`(식생 모델 보조입력 4종)은 이 묶음이 아니라 `§4.2` 식생 사슬 쪽이다. **`§4.2` 의 Lv.1→Lv.2 사슬은 Lv.2 가 적재 대상이 아니어서 간선으로 세어진 적이 없다.** 따라서 제외분 차감 = **0**.

### 4.2 level-data — Lv.0 → Lv.1 → Lv.2 사슬

원천 폴더가 **가공 단계를 폴더 이름으로 이미 선언**하고 있다(`Lv.0` · `Lv.1` · `Lv.2`).

| 주제 | 사슬 | 원천 문서가 밝힌 가공 |
|---|---|---|
| **강우** | Lv.0 (HSR 반사도 + RN15 지상강수) → Lv.1 → Lv.2 | WGS84 변환 · crop · U-Net 예측. *Z-R 관계식(Marshall-Palmer)의 한계를 U-Net 이 보완* |
| **식생** | Lv.0 (GK2A NDVI, LCC) → Lv.1 → Lv.2 | DQF 필터 · WGS84 변환 · crop · 월평균 · 100 m 균등분할 → U-Net 공간상세화 |

**식생 사슬은 보조입력 4종이 병렬로 들어간다** — `Lv.1_(Model_Input_Data)` 의 DEM · Aspect · LULC · HLS_S30_NDVI. 이것도 `보조입력` 부모 역할이다.

> **원천 문서가 Lv.1 과 Lv.2 의 차이를 스스로 대조해 놨다** — *「Lv.1 은 값이 변하지 않는 균등분할, Lv.2 는 U-Net 으로 지형에 따라 값이 실제로 달라진다」*. 데이터셋 설명란에 그대로 쓸 문장이다.
>
> **⟨증보 2026-08-26⟩ 식생 사슬의 Lv.0 → Lv.1 구간이 실제 간선으로 섰다** — `D-09` → `D-16` · 부모 역할 `주입력` · 가공 방식은 SRC-E `[2] Lv.1` 처리 과정 8단을 옮겨 적었다. **Lv.1 → Lv.2 구간은 미연결** — Lv.2 `.npy` 가 적재 범위 밖이고 보조입력 4종(`D-10`)이 적재 제외다. 종전 문장은 무수정이다.
>
> ⚠ **가뭄은 `원천` 계보 상태로 들어간다.** Lv.0 이 폴더에 없고, 문서는 *「기상관측소 강우 관측자료에서 산정」* 이라고만 말한다. 강우 폴더의 자료와 물리적으로 이어지는지 **확인할 수 없다** — 이을 근거가 없으므로 **잇지 않는다.** 계보 상태 4값 중 **`원천`** 이 정확히 이 경우다.

### 4.3 포맷 견본 — 계보 없음

`02.File-format/` 의 견본들은 **서로 이어지지 않는다.** 전부 Lv.0 · 계보 상태 `원천` 이다. 목적이 다르다 — **D5 파서가 5포맷을 실제로 여는지 보는 것**이다.

| 실데이터 | 배정 |

> **S2 에 걸리는 것** — 적재가 `유출·수문` 같은 값을 넣어도 **DB 는 막지 않는다.** `D-11`·`D-12` 의 `[주제 무근거]` 는 **NULL 로 남길 수 있다**(열이 nullable 이므로 규칙 위반이 아니다). **비워 두는 쪽을 택한다** — 없는 값을 지어내는 것보다 낫고, 나중에 사람이 채울 수 있다.
> ✅ **결정됐다 — `〈55〉` 주제를 DB 열거값으로 강제한다** (2026-08-23 Ted). `topic` 에 4값 CHECK 를 걸고 **nullable 은 유지한다**(「값이 있다면 넷 중 하나」이지 「반드시 있다」가 아니다). **`D-11`·`D-12` 는 NULL 로 적재한다** — 억지로 배정하면 검색·분류가 조용히 틀리고, 4값을 늘리는 것은 정본 개정이라 여기서 할 일이 아니다.

> ⚠ **주제 4값이 실데이터를 다 담지 못한다.** 가뭄지수·지표면온도·기온이 남는다. **이건 시드 문제가 아니라 정본 문제**이고, `㊸-④-2` 가 *「목업 쪽 불일치는 정본 갱신 대상으로 표시」* 한 것과 같은 성격이다. **Ted 판단이 필요하다** — 4값을 늘릴 것인가, 이 데이터셋들을 넣지 않을 것인가, 억지로 배정할 것인가. **기본값 = 정본을 안 건드리고 `[주제 무근거]` 로 남긴다**(D-11·D-12).

## 6.5 S2 착수 전에 알아야 할 것 — PoC 조사 결과

**S2 의 완료 판정 셋 중 둘이 PoC 에 선례가 없다.** 물려받는 게 아니라 새로 만드는 것이라는 뜻이다.

| S2 완료 판정 | PoC 선례 | 뜻 |
|---|---|---|
| ① 카탈로그에서 **보이고** 상세가 열린다 | ✅ 있다 — 등재 직후 `READY` 로 열람 가능 | 물려받을 수 있다 |
| ② **재실행 멱등** — 두 번 돌려도 데이터셋이 안 는다 | ❌ **없다.** 콘텐츠 해시·checksum·dedup 이 **전무**하고 **같은 파일 두 번 = 독립 데이터셋 두 개** | **S2 가 스스로 만들어야 한다.** 있는 것은 *재처리* 멱등(`ON CONFLICT DO NOTHING`)뿐이고 *재적재* 멱등이 아니다 |
| ③ IS3 백업·복원 리허설 재통과 | — | S2 몫 그대로 |

**그리고 적재 경로의 전제가 다르다.** `㊾-③` 은 **「업로드 → 파싱 → COG → 계보 확정」이 한 흐름**임을 전제하는데, **PoC 는 등재와 파싱이 분리돼 있었다**(archive-first — 등재는 파일을 안 열고, 파싱은 선택적 후속 워커). **v2 에서 그 흐름이 실제로 이어지는지가 S2 의 첫 시험이다**(`DR-14`).

**다중 파일 합치기는 절반만 선례가 있다** — PoC 도 여러 파일을 한 데이터셋에 담았고 **포맷 동일 검사**(1종이면 그 값 · 2종 이상이면 `MIXED`)와 **용량 합산**은 했다. 그러나 **기간 union · bbox · CRS 집계가 없고**, 워커는 **첫 파일에서만 메타를 뽑고 bounds 는 마지막 파일 것을 쓴다.** `DATAMODEL §4.3` 의 합치는 규칙(*기간 = 합집합*)은 **새로 구현해야 한다.**

> ⚠ **`MIXED` 는 v2 에 없는 개념이다.** v2 의 합치는 규칙은 *「포맷이 하나라도 다르면 조각이 아니라 다른 데이터다」* 라 **섞이면 데이터셋을 나눈다.** PoC 는 섞인 채로 `MIXED` 를 기록했다 — **같은 상황에 반대로 답한 것**이라 뽑아 오면 안 된다.
