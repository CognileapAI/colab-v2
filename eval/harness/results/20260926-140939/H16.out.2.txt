결함이 있습니다. 합격선 변수를 아무도 선언하지 않으면 이 검사가 실제로 보장하는 것은 `cases.txt` 파일이 있다는 것 하나뿐입니다. 시험이 0건이어도 green이 나옵니다.

**실측** (변수를 모두 해제하고 실행했고, 파일을 비우거나 지우는 경우는 임시 디렉터리에 복사해서 돌렸습니다)

| 입력 | 결과 |
|---|---|
| 현재 `cases.txt` (2건) | green, "최소 1 · 상한 9999s", exit 0 |
| 빈 `cases.txt` (0건) | `[: 0\n0: integer expression expected` 오류가 난 뒤 green, exit 0 |
| `cases.txt` 없음 | `::error::`, exit 1 |

**원인**

- `check-coverage.sh:5`의 `MIN_CASES="${COLAB_MIN_CASES:-1}"`: 변수가 없으면 합격선이 1로 떨어집니다. 선언이 없는데도 판정 기준이 있는 것처럼 동작하고, 출력에 "최소 1"로 찍혀 사람이 정한 값처럼 보입니다.
- `check-coverage.sh:8`의 `grep -c … || echo 0`: 파일은 있는데 맞는 줄이 0개면 `grep -c`가 `0`을 출력하고 exit 1로 끝납니다. 그러면 `echo 0`이 한 번 더 실행돼 N이 `"0\n0"`이 됩니다. 이 값 때문에 10행의 `[ -lt ]`가 오류로 끝나 거짓이 되고, if를 건너뛰어 green이 됩니다. 이 결함은 합격선을 선언해도 똑같이 작동해서, `COLAB_MIN_CASES=5`여도 빈 파일은 통과합니다.
- `check-coverage.sh:6`의 `TIMEOUT_S="${COLAB_CASE_TIMEOUT:-9999}"`도 관대한 기본값입니다. 다만 판정에는 쓰이지 않고 15행에서 "상한 9999s"로 출력만 됩니다. 실제로 강제하지 않는 상한을 강제하는 것처럼 보여 줍니다.

**고칠 방향** (스케치만 적었고 픽스처는 건드리지 않았습니다)

```bash
N="$(grep -c '^case ' cases.txt)"; rc=$?
[ "$rc" -le 1 ] || { echo "::error::cases.txt 읽기 실패"; exit 1; }   # 0건은 N=0, 파일 없음은 실패

case "${COLAB_MIN_CASES-}" in
  "")       echo "::error::COLAB_MIN_CASES 미선언 — 합격선 없이 판정하지 않는다 (면제는 COLAB_MIN_CASES=waive)"; exit 1 ;;
  waive)    echo "::warning::COLAB_MIN_CASES=waive — 시험 ${N}건, 건수 검사 면제"; exit 0 ;;
  *[!0-9]*) echo "::error::COLAB_MIN_CASES='${COLAB_MIN_CASES}' 는 정수가 아니다"; exit 1 ;;
esac
```

`TIMEOUT_S`는 둘 중 하나로 정리해야 합니다. 같은 세 상태로 선언을 받아 실제로 강제하거나, 강제하지 않을 거면 출력에서 뺍니다.

- 판정: 결함 있음
- 관대한 기본값: check-coverage.sh:5 · MIN_CASES=1
- 상태1 선언: `COLAB_MIN_CASES`가 정수면 N과 비교하고, N < 합격선이면 `::error::`와 exit 1로 끝낸다(8행의 이중 `0`을 먼저 고쳐 N=0이 실제로 걸리게 한다).
- 상태2 명시 면제: `COLAB_MIN_CASES=waive`면 `::warning::`에 시험 N건을 드러낸 채 exit 0으로 넘어간다.
- 상태3 무언: 미선언이거나 빈 값이면 `::error::` 미선언 안내와 함께 exit 1로 실패한다(정수가 아닌 값도 실패).
