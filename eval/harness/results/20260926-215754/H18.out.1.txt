stub curl 로 돌려 본 결과:
- 500 오류 본문을 받으면 `render-latency green — p95 <html>500 …</html>ms`, exit 0 이다.
- `1250.7` 을 받으면 `render-latency green — p95 1250.7ms`, exit 0 이다. 기준 1200 을 넘었는데 green 이 된다.
- URL 이 설정되지 않으면 `측정 생략`, exit 0 이다.

정리하면 끝나는 방식은 「재서 통과/실패」와 「못 재고 통과」 두 가지뿐이다. 명시 면제 갈래는 없다. 무언과 「선언했지만 측정 불가」는 둘 다 green 과 같은 exit 0 으로 끝난다. 18행의 비정수 경로는 아예 green 이라고 찍는다.

### 세 상태로 다시 세우면

종료 코드는 저장소 관례를 따른다. green 은 0, red(판정) 은 1, red(준비) 는 78 이고 red(준비) 에는 `::gate-readiness-failure::` 표식을 붙인다(`gates/run.sh:45-46`, `:292`). 판정 순서는 명시 면제 → 선언 → 무언이다.

**1. 선언** — URL 이 선언돼 있다
- `curl -fsS --max-time N` 으로 요청한다. 받은 값은 `^[0-9]+$` 에 맞을 때만 측정값으로 인정한다.
- p95 ≤ 1200 이면 green · exit 0
- p95 > 1200 이면 red(판정) · exit 1
- 응답이 없거나, HTTP 오류이거나, 정수가 아닌 값이면 red(준비) · exit 78. 표식 줄에 「선언됐으나 측정 불가」와 그 원인을 적는다. green 으로 떨어지는 경로는 없앤다.

**2. 명시 면제** — 사람이 이번에는 재지 않겠다고 적었다
- 저장소의 다른 게이트처럼 `gates/config/*.toml` 에 커밋된 면제 선언으로 받는다. 사유와 선언자가 있어야 하고, 사유가 비어 있으면 면제로 보지 않고 3번 무언으로 처리한다.
- 재지 않는다. 대신 `::warning::render-latency 면제 — 측정 안 함 · 사유: … · 선언: …` 같은 표식 줄을 찍어서 green 이 아니라 **재지 않은 면제**라는 것과 누가 왜 면제했는지를 드러낸다. 집계하는 쪽도 이 표식을 green 과 따로 세야 한다.
- 막지는 않으므로 exit 0 으로 끝난다. URL 이 함께 선언돼 있으면 「선언돼 있으나 면제로 재지 않음」이라고 출력에 같이 적는다.

**3. 무언** — URL 도 면제도 선언되지 않았다
- 재지 않는다. `::gate-readiness-failure:: render-latency — COLAB_RENDER_URL 미선언 · 면제 선언 없음` 을 찍고 두 가지 선언 방법을 안내한 뒤 red(준비) · exit 78 로 실패한다.
- 지금의 7–10행 「측정 생략 · exit 0」을 대체하는 갈래다.
