스크립트를 줄 번호와 함께 읽고, 합격선 변수를 비운 채로 직접 돌려 봤습니다.

**합격선 파일이 없을 때의 흐름** (`check-config.sh`)
- 5행: `COLAB_THRESHOLD_FILE` 가 설정되지 않았으면 `CONF=""` 가 됩니다.
- 7행: `[ -z "$CONF" ]` 가 참이므로 이 분기로 들어갑니다. 변수는 있는데 가리키는 파일이 없을 때(`! -f`)도 같은 분기로 들어갑니다.
- 8행: 「합격선 파일이 없어 검사를 건너뜁니다.」를 출력합니다. 종료하지 않고 if 블록을 빠져나갑니다.
- 18–19행: `check-config green` 을 출력하고 `exit 0` 으로 끝납니다.

실제 실행 결과(`env -u COLAB_THRESHOLD_FILE bash ./check-config.sh`):
```
합격선 파일이 없어 검사를 건너뜁니다.
check-config green
exit=0
```

**옳은가 — 옳지 않습니다**
- 이 경우는 규약 셋 중 어디에도 들어가지 않습니다.
  - 선언되어 검사한 경우가 아닙니다. 합격선이 없어 10–15행이 한 번도 실행되지 않았습니다.
  - 명시적으로 면제한 경우도 아닙니다. 면제를 선언하는 값이 없고, 건너뛴 건수도 드러내지 않습니다.
  - 남는 것은 「아무 말도 없음」입니다. 규약상 이 경우는 실패해야 하는데, 스크립트는 반대로 green 을 냅니다.
- 8행은 skip 문구를 찍어도 18행에서 그대로 green·exit 0 으로 이어집니다. 종료 코드만 보는 게이트나 CI 에게는 통과한 실행과 구분되지 않습니다.
- 저장소 규약에 따르면 입력이 선언되지 않아 못 돈 것은 red(준비)이고 exit 78 입니다(`infra/prod/tests/ship-gate.sh:10` — exit 0 green · exit 1 red(판정) · exit 78 red(준비)). 따라서 7행 분기는 red(준비) 표식과 빠진 입력 이름(`COLAB_THRESHOLD_FILE`)을 출력하고 `exit 78` 로 끝나야 합니다.

**같은 모양의 결함이 두 군데 더 있습니다**
- 12행: 합격선 파일이 비었거나 숫자가 아니면 `[ "$N" -lt "$MIN" ]` 이 오류를 내고 종료 코드 2를 돌려줍니다. if 는 이를 거짓으로 취급하므로 이번에도 18행 green 으로 흘러갑니다. 이 경우도 red(준비)여야 합니다.
- 11행: `artifacts/` 디렉터리가 없어도 `2>/dev/null` 때문에 오류가 가려지고 N=0 으로 셉니다. 산출물이 0건인 것과 디렉터리가 없는 것을 구분하지 못합니다.

- 판정: 결함 있음
- 모양: 입력(합격선 파일)이 선언되지 않으면 skip 문구만 찍고 green 으로 떨어지는 조용한 통과(silent skip)
