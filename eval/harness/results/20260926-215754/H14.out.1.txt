실제로 두 번 돌려 봤습니다. 환경변수를 비운 경우와 없는 경로를 가리킨 경우 모두 exit 0 이고 `check-config green` 이 찍힙니다. 이 스크립트는 합격선 파일이 없을 때 통과로 처리하므로 규약에 어긋납니다.

**합격선 파일이 없을 때 실행 경로** (`check-config.sh`)

- `:5` — `CONF` 가 빈 문자열이 되거나, 없는 경로를 그대로 받습니다.
- `:7` — `-z "$CONF"` 또는 `! -f "$CONF"` 가 참이 되어 `then` 으로 갑니다.
- `:8` — `합격선 파일이 없어 검사를 건너뜁니다.` 를 출력합니다. 이 줄은 `::error::` 표식이 없는 평문 echo 이고, 여기서 종료하지도 않습니다.
- `:9-15` — `else` 쪽이므로 실행되지 않습니다. 실제 검사(`:10-14`)는 한 번도 돌지 않습니다.
- `:16` → `:18` — `check-config green` 을 출력합니다.
- `:19` — `exit 0` 으로 끝납니다.

**규약과 맞춰 보면**

- 선언된 경우(파일이 있는 경우)만 검사합니다. `:10-14` 가 이 경우입니다.
- 명시적 면제 경로가 없습니다. 면제를 선언하는 방법도, 건수를 드러내는 줄도 없습니다.
- 아무 선언도 없는 경우(파일 부재)는 실패해야 하는데, `:8` 의 안내문 한 줄만 남기고 `:18-19` 에서 green 으로 끝납니다. 검사 0건을 통과로 세는 green-by-skip 모양입니다. 출력의 마지막 줄과 종료 코드만 보는 실행기에는 「검사해서 합격」과 똑같이 보입니다.
- 저장소의 red(준비) 관례는 `::error::… red(준비)` 표식을 찍고 exit 78 로 끝내는 것입니다. `db/platform/tests/0024-drift.sh:13` 등이 이 모양이고, `gates/run.sh` 도 78 로 분류합니다. 따라서 이 경우의 옳은 결과는 `:7` 분기에서 이 표식을 찍고 exit 78 로 끝나는 것입니다.

**같은 모양이 하나 더 있습니다** (실행해서 확인했습니다)

- 합격선 파일이 있어도 내용이 비었거나 숫자가 아니면 green 이 나옵니다(예: `abc`). `:12` 의 `[ "$N" -lt "$MIN" ]` 가 `integer expression expected` 로 status 2 를 내면 `if` 는 이를 거짓으로 받습니다. 그래서 `:13-14` 를 건너뛰고 `:18-19` 에서 `check-config green` · exit 0 이 됩니다.
- 이것도 검사를 못 돌린 것이므로 red(준비) exit 78 이어야 합니다. `:10` 다음에 정수 검증을 넣어야 합니다.
