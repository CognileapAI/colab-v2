## 결론

합격선 변수가 선언되지 않은 환경에서 이 검사가 실패하는 경우는 `cases.txt` 파일이 없을 때 하나뿐입니다. 시험이 0건이어도 통과합니다. 따라서 이 검사는 시험 건수를 보장하지 않습니다.

## 줄별 근거 (`check-coverage.sh`)

- **5행** `MIN_CASES="${COLAB_MIN_CASES:-1}"`: `:-` 는 변수가 없을 때와 빈 문자열일 때를 같게 다룹니다. 선언하지 않은 경우와 `COLAB_MIN_CASES=` 로 비워 둔 경우 모두 합격선이 조용히 1로 떨어집니다. 3행의 `set -u` 도 `:-` 에 가려져 이를 잡지 못합니다.
- **6행** `TIMEOUT_S="${COLAB_CASE_TIMEOUT:-9999}"`: 이것도 관대한 기본값입니다. 실제로 쓰이는 곳은 15행 출력문뿐이라 집행되지 않습니다. 그런데 green 출력에 "상한 9999s"가 찍혀 상한이 있는 것처럼 보입니다.
- **8행** `grep -c ... || echo 0`: `case` 가 0건이면 grep 이 `0` 을 출력하고 종료코드 1을 냅니다. 이어서 `echo 0` 도 실행되므로 `N` 에 두 줄짜리 문자열 `"0\n0"` 이 들어갑니다.
- **10행** `[ "$N" -lt "$MIN_CASES" ]`: 이 비교가 "integer expression expected" 오류를 내면 `if` 가 거짓으로 처리됩니다. 그 결과 15행의 green 으로 빠집니다. 합격선을 5로 선언해도 0건이면 통과합니다.

## 실측 (임시 디렉터리 사본에서 실행, 픽스처는 수정하지 않음)

| 환경 | 입력 | 결과 |
|---|---|---|
| 선언 없음 | 현 `cases.txt` (2건) | green, exit 0 (최소 1) |
| 선언 없음 | case 0건 파일 | `[` 오류 뒤 green, exit 0 |
| 선언 없음 | 파일 없음 | `::error::`, exit 1 |
| `COLAB_MIN_CASES=` (빈 값) | 2건 | green, exit 0 (최소 1) |
| `COLAB_MIN_CASES=5` | 2건 | `::error::`, exit 1 |
| `COLAB_MIN_CASES=5` | 0건 | `[` 오류 뒤 green, exit 0 |

## 고칠 방향

- 5행의 기본값을 없애고 세 상태로 나눕니다. 면제는 같은 변수의 명시 값 `exempt` 로 받으면 스위치가 하나로 유지됩니다.
- 선언된 값이 양의 정수가 아니면 실패시킵니다. 빈 값도 여기에 해당합니다. `0` 은 사실상 이름표 없는 면제이므로 `exempt` 로 가도록 거절하는 것을 권합니다.
- 8행은 `|| echo 0` 을 빼고 grep 종료코드를 직접 봅니다. 0(있음)과 1(0건)은 정상 집계로 받고, 2(파일 없음·읽기 실패)는 실패로 처리합니다. 그러면 `N` 이 항상 한 줄 정수가 됩니다.
- 6행은 두 가지 중 하나를 택합니다. 상한을 실제로 집행하도록 같은 세 상태 규칙을 적용하거나, 집행하지 않을 거라면 변수와 출력 문구를 지웁니다.

- 판정: 결함 있음
- 관대한 기본값: check-coverage.sh:5 · COLAB_MIN_CASES=1
- 상태1 선언: `COLAB_MIN_CASES` 가 양의 정수면 N < 값일 때 `::error::` 와 exit 1, 아니면 green (정수가 아니면 exit 1)
- 상태2 명시 면제: `COLAB_MIN_CASES=exempt` 면 "합격선 면제 — 시험 N건"을 `::warning::` 으로 출력하고 exit 0
- 상태3 무언: `COLAB_MIN_CASES` 가 없거나 비어 있으면 "합격선 미선언"을 `::error::` 로 출력하고 exit 1
