## 지금 스크립트가 하는 일 (`gate-render-latency.sh`)

| 줄 | 조건 | 지금 동작 | 실제로 해당하는 상태 |
|---|---|---|---|
| 7–10 | `COLAB_RENDER_URL` 없음 | 「측정 생략」 출력, exit 0 | 무언 |
| 12–16 | URL은 있는데 curl 응답이 비었음(연결 실패·시간 초과) | 「측정 생략」 출력, exit 0 | 선언했지만 못 잼 |
| 18 | 응답이 숫자가 아님(HTML 오류 페이지 등) | `[ -gt ]`가 에러(status 2)를 내고 if가 거짓으로 빠져 23행 **green**, exit 0 | 선언했지만 못 잼 |
| 18–20 | p95 > 1200 | red, exit 1 | 선언 |
| 23–24 | p95 ≤ 1200 | green, exit 0 | 선언 |

세 경우를 직접 돌려 확인했다.
- URL 없음: exit 0
- `http://127.0.0.1:1`(연결 불가): exit 0
- 숫자가 아닌 응답(`<html>404</html>`): `integer expression expected`가 뜬 뒤 `render-latency green — p95 <html>404</html>ms`, exit 0

`set -e`가 없고 curl에 `-f`도 없어서, HTTP 오류 본문이 그대로 P95 값으로 들어간다.

**빠진 갈래**
- **명시 면제 갈래가 아예 없다.** 사람이 「이번엔 재지 않는다」고 선언할 수단이 없다. 그래서 URL을 안 넣은 것(무언)이 사실상 면제 역할을 하고, 그것도 조용히 통과한다.
- **「못 잼 → 실패」 갈래가 없다.** 무언(7–10), 선언했는데 응답 없음(12–16), 숫자가 아닌 응답(18→23)이 모두 exit 0으로 끝난다. 「못 잰 것」이 「문제 없음」으로 세어진다.
- 「생략」 출력에 `::warning::` 같은 표식이 없어서 CI 화면에서는 green과 구별되지 않는다.
- 부수적으로, curl에 `--max-time`이 없어 응답이 늦으면 게이트가 멈출 수 있다.

## 세 상태로 다시 세우면

exit 코드는 두 가지 실패를 나눠 쓰자는 제안이다. 1은 잰 결과가 기준을 넘은 경우, 2는 잴 준비가 안 된 경우다. 핵심은 못 잰 경우가 절대 0으로 끝나지 않는 것이다.

**상태 판별 순서**
1. `COLAB_RENDER_URL`과 면제 선언(예: `COLAB_RENDER_LATENCY_EXEMPT=<사유>`)이 둘 다 있으면 → 선언이 모순이다. 준비 red, exit 2.
2. 면제 선언만 있고 사유가 비어 있지 않으면 → 상태 2.
3. URL만 있으면 → 상태 1.
4. 둘 다 없거나 면제 사유가 빈 문자열이면 → 상태 3.

**상태 1 — 선언**
- `curl -fsS --max-time N`으로 실제로 잰다.
- 응답이 정수인지 확인한다(`[[ $P95 =~ ^[0-9]+$ ]]`).
- p95 ≤ 1200 → green, exit 0
- p95 > 1200 → 판정 red, exit 1
- 연결 실패·HTTP 오류·시간 초과·숫자가 아닌 값 → 준비 red, exit 2. 선언해 놓고 못 잰 것이므로 통과시키지 않는다.

**상태 2 — 명시 면제**
- 재지 않는다.
- 대신 드러낸다: `::warning::render-latency 면제 — 측정 안 함, 사유: <사유>`를 출력하고, 가능하면 선언한 사람과 커밋/PR을 함께 남긴다.
- 종료는 exit 0이지만 **green이라고 출력하지 않는다.** 요약에는 「면제(미측정)」로 따로 센다.

**상태 3 — 무언**
- 재지 않는다.
- `::error::render-latency — 렌더 URL도 면제 선언도 없음, 측정 불가`를 출력하고, 어떻게 풀면 되는지(URL을 선언하거나 사유를 적어 면제하라)도 함께 적는다.
- 준비 red, exit 2.
