결함이 있습니다. 게이트가 잴 수 없을 때마다 exit 0으로 끝나고, 사람이 재지 않기로 적어 둘 방법도 없습니다. 스크립트는 고치지 않았고, 세 가지 경우를 `/tmp`에서 직접 돌려 재현한 뒤 임시 파일을 지웠습니다.

## 지금 스크립트가 끝나는 방식 (`gate-render-latency.sh`)

| 줄 | 조건 | 출력 | exit | 실제 의미 |
|---|---|---|---|---|
| 7–10 | `COLAB_RENDER_URL` 없음 | 「측정 생략」 | 0 | 무언인데 통과 |
| 12–16 | URL은 있는데 응답이 비었음 (서버 안 뜸·연결 거부) | 「측정 생략」 | 0 | 선언했는데 못 쟀고, 그래도 통과 |
| 18–21 | p95가 1200 초과 | red | 1 | 재서 실패 (정상) |
| 23–24 | p95가 1200 이하 | green | 0 | 재서 통과 (정상) |
| 18→23 | 응답이 숫자가 아님 (HTML 오류 페이지, `850.3` 같은 소수) | 「green — p95 `<html>…`ms」 | 0 | 못 쟀는데 green으로 표시 |

재현 결과:
- **URL 미설정:** 「측정 생략」, exit 0.
- **`http://127.0.0.1:9`(연결 거부):** 「측정 생략」, exit 0.
- **응답이 `<html>502 Bad Gateway</html>`:** 줄 18의 `[`가 `integer expression expected` 오류를 내고 거짓으로 끝납니다. `set -e`가 없어서 스크립트는 그대로 23줄로 넘어가 `render-latency green`을 찍고 exit 0으로 끝납니다.

원인:
- `curl -s`에 `-f`가 없어서 HTTP 4xx/5xx 응답의 본문도 값으로 받아들입니다.
- 시간 제한(`--max-time`)이 없어서 응답이 없으면 게이트가 멈출 수 있습니다.

빠진 갈래는 두 가지입니다.
1. **명시 면제가 없습니다.** 사람이 「이번엔 재지 않는다」고 적을 입력이 스크립트에 없습니다. 그래서 설정을 잊은 경우와 일부러 뺀 경우를 구별할 수 없고, 둘 다 exit 0 「측정 생략」 한 줄로 끝납니다.
2. **「못 쟀으면 실패」가 없습니다.** URL을 선언했는데 재지 못한 경우가 전부 통과로 끝납니다.

## 세 상태로 다시 세울 때

먼저 면제 입력을 하나 새로 둡니다. 예: `COLAB_RENDER_LATENCY_WAIVE="<사유>"`. 사유가 비어 있으면 면제로 치지 않습니다. 면제는 URL보다 먼저 확인합니다. CI 전역 변수처럼 URL이 늘 설정돼 있어도, 그 회차만 면제할 수 있어야 하기 때문입니다.

**1. 선언 (URL 있음, 면제 없음)**
- `curl -fsS --max-time N`으로 요청하고, 응답이 `^[0-9]+$`인지 확인합니다.
- p95가 1200 이하면 green, exit 0.
- p95가 1200을 넘으면 red(판정), exit 1.
- 연결 실패, 시간 초과, HTTP 오류, 숫자가 아닌 응답이면 red(준비), exit 2. 선언은 측정하겠다는 약속이라, 못 잰 결과는 실패로 셉니다.

**2. 명시 면제 (사유가 적힌 면제 값 있음)**
- curl을 호출하지 않습니다.
- `::warning::render-latency WAIVED — 미측정 · 사유: <사유>` 한 줄을 남깁니다. 가능하면 step summary에도 같은 줄을 적습니다.
- 드러내야 할 것은 세 가지입니다.
  - 이번 회차에는 **재지 않았고** 값을 모른다는 사실
  - 면제 사유
  - URL이 선언돼 있었다면, 선언은 있었지만 면제로 건너뛰었다는 사실
- exit 0으로 끝나지만, 출력 표시와 집계는 green과 따로 셉니다. 「미측정」이지 「통과」가 아닙니다.

**3. 무언 (URL도 면제도 없음)**
- 측정하지 않습니다.
- `::error::render-latency — 선언 없음: COLAB_RENDER_URL 또는 COLAB_RENDER_LATENCY_WAIVE 중 하나를 선언하라`를 남깁니다.
- red(준비), exit 2. 지금처럼 exit 0으로 끝나면, 선언을 잊은 경우가 통과로 집계됩니다.

exit 2는 판정 red(exit 1)와 준비 red를 구분하려고 제가 고른 값입니다. 둘 다 0이 아니므로 CI에서는 어느 쪽이든 실패로 처리됩니다.

- 판정: 결함 있음
- 지금 빠진 갈래: 명시 면제 갈래가 아예 없고 「선언했는데 못 잼」도 실패로 끝나지 않아, 무언(7–10)·응답 없음(12–16)·숫자 아닌 응답(18→23 green)이 모두 exit 0으로 합쳐진다
- 상태1 선언: `curl -f --max-time`으로 p95를 재고 정수인지 확인한 뒤 판정, 못 재면 red(준비) · exit 0(p95 ≤ 1200) / 1(p95 > 1200) / 2(못 잼)
- 상태2 명시 면제: 측정하지 않고 green과 구별되는 WAIVED 경고 줄로 「이번 회차 미측정 · 면제 사유 · 선언 URL이 있었다면 그 사실」을 드러내며 green으로 세지 않는다 · exit 0
- 상태3 무언: 측정하지 않고 「선언 없음 — URL 또는 면제 중 하나를 선언하라」 오류를 남겨 red(준비)로 끝낸다 · exit 2
