엉뚱한 값을 넘기면 스크립트는 검사를 하나도 하지 않고 green · exit 0 을 낸다. 규약에 어긋나는 결함이다. 빈 값은 0건이 아니라 매니페스트 전체를 검사하는데, 이것도 옳지 않다.

**실측 (이 디렉터리에서 직접 실행)**

| 넘긴 인자 | 매칭 줄 | 출력 마지막 줄 | exit |
|---|---|---|---|
| `nonexistent/` | 0 | `check-manifest green — 불일치 0건` | 0 |
| `service/` (오타) | 0 | `check-manifest green — 불일치 0건` | 0 |
| `""` (빈 값) | 4 (전부) | `::error::불일치 4건` | 1 |
| 인자 없음 | — | `line 5: $1: unbound variable` | 1 |
| `services/` (정상) | 2 | `::error::불일치 2건` | 1 |

**엉뚱한 값일 때 흐름 (범위와 맞는 줄 0건)**

- `check-manifest.sh:6`: `BAD=0` 으로 시작한다.
- `check-manifest.sh:8-17`: manifest 네 줄이 모두 `:10` 의 `"$SCOPE"*` 와 맞지 않아 `:11` 의 `continue` 로 빠진다. `:13-16` 의 존재 검사는 한 번도 돌지 않는다.
- `check-manifest.sh:19`: `BAD` 가 0 이라 `[ "$BAD" -ne 0 ]` 이 거짓이 되고 `:24` → `:25 exit 0` 으로 끝난다.
- 원인: 스크립트는 「불일치 수」만 세고 「검사 대상 수」는 세지 않는다. 그래서 「0건을 검사해서 불일치 0」과 「N건을 다 검사했고 불일치 0」을 구별하지 못한다.

**빈 값과 인자 없음**

- 빈 값 `""`: `:10` 의 패턴이 `*` 가 되어 네 줄 모두가 대상이 된다. 호출자가 의도한 범위가 말없이 전체로 넓어진다. 이 픽스처에서는 실물 파일이 없어서 red 가 나왔을 뿐이다. 파일이 모두 있는 저장소라면 범위를 무시한 green 이 나온다.
- 인자 없음: `set -u` 때문에 `:5` 에서 bash 가 중단된다. 실패로 끝나기는 하지만, 스크립트가 일부러 막은 것이 아니고 안내문도 bash 기본 메시지뿐이다.

**고칠 방향 (픽스처라서 파일은 고치지 않았다)**

- `:5`: 빈 값이나 누락이면 명시적인 `::error::` 를 내고 exit 1 로 거부한다.
- `:10`: 매칭된 줄마다 대상 수를 1 늘린다.
- 루프 뒤: 대상 수가 0 이면 `::error::` 를 내고 exit 1 로 끝낸다. 이 검사를 `:19` 보다 먼저 둔다.
