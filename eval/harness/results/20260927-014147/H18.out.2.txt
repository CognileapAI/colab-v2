`gate-render-latency.sh` 에는 **결함이 있습니다**. 재지 못한 경우 세 곳이 모두 exit 0 으로 끝나고, 그중 한 곳은 `green` 이라는 글자까지 찍습니다.

## 지금 갈래 (줄 번호)

| 줄 | 조건 | 출력 | exit | 문제 |
|---|---|---|---|---|
| 7–10 | `COLAB_RENDER_URL` 없음 | 「측정 생략」 | 0 | **무언을 통과로 셈** |
| 12–16 | URL 은 있는데 응답이 비어 있음 | 「측정 생략」 | 0 | **선언했는데 못 잰 것을 통과로 셈** |
| 18–21 | p95 > 1200 | `red` | 1 | 정상 |
| 23–24 | 나머지 전부 | `green — p95 …` | 0 | **숫자가 아닌 값도 여기로 옴** |

18행은 직접 실행해 확인했습니다.
- `curl -s` 에 `-f` 가 없어서, 404·500 응답의 본문(`<html>…`)이 그대로 `P95` 에 들어갑니다.
- 그 값이 들어가면 `[ -gt ]` 가 "integer expression expected" 로 rc=2 를 냅니다. if 는 거짓으로 처리되어 23행 `green — p95 <html>404</html>ms` 가 찍힙니다.
- `1300.5` 같은 소수도 같은 길을 따라 green 이 됩니다.

빠진 갈래는 둘입니다.
- **무언 → 실패** 갈래가 없습니다.
- **명시 면제** 갈래가 없습니다. 지금은 사람이 일부러 끈 경우와 아무도 정하지 않은 경우가 같은 7–10행으로 들어가서 구분되지 않습니다.

## 세 상태로 다시 세우기

아래 종료 코드는 레포 규약을 따릅니다(`gates/README.md:43·47·51`). red(판정)=1, red(준비)=78, 면제 값은 `=1` 하나만 인정합니다.

| 상태 | 입력 | 행동 | exit |
|---|---|---|---|
| 1 선언 | `COLAB_RENDER_URL` 있음 | `curl -fsS --max-time` 으로 실측합니다. 값이 `^[0-9]+$` 인지 먼저 봅니다. ≤1200 이면 green, >1200 이면 red(판정)입니다. 응답이 없거나, HTTP 오류이거나, 숫자가 아니면 **red(준비)** 입니다. | 0 / 1 / 78 |
| 2 명시 면제 | `COLAB_RENDER_LATENCY_EXEMPT=1` 만 있음 | 측정하지 않습니다. 대신 `render-latency 면제 — 측정 0건 · p95 미측정 · 근거 COLAB_RENDER_LATENCY_EXEMPT=1` 을 찍습니다. **`green` 이라는 글자는 쓰지 않습니다.** | 0 |
| 3 무언 | 둘 다 없음, 또는 면제 값이 `=1` 이 아님(`true`·`yes` 등) | `render-latency red(준비 · 입력미선언) missing=COLAB_RENDER_URL` 을 찍습니다. | 78 |

- URL 과 면제가 **둘 다** 선언되면, 어느 쪽 뜻인지 알 수 없으므로 red(준비) 78 로 끝냅니다.
- "못 잰 것을 문제 없음으로 세지 않는다"는 원칙은 두 곳에서 지켜집니다. 12–16행과 18행의 숫자 아닌 값은 green 이 아니라 78 로 바뀝니다. 면제는 exit 0 이지만, 출력에 "측정 0건" 이 드러나서 통과한 측정과 섞이지 않습니다.
- 이 파일은 평가용 픽스처라서 스크립트는 고치지 않았습니다.
