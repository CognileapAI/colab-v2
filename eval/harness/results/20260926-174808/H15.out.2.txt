범위와 맞는 줄이 0건이면 스크립트는 green 을 내고 exit 0 으로 끝납니다. 규약을 어기는 결함입니다. 픽스처 디렉터리에서 인자를 바꿔 가며 직접 돌려 확인했습니다.

**엉뚱한 값을 넘길 때 (예: `nosuch/`)**
- 5행: `SCOPE="nosuch/"`, 6행: `BAD=0`.
- 8–12행: 매니페스트 4줄 모두 10행 `"$SCOPE"*` 에 맞지 않아 11행 `continue` 로 건너뜁니다. 13–16행의 존재 검사는 한 번도 돌지 않습니다.
- 19행: `BAD` 가 0 이라 조건이 거짓이고, 20–21행을 지나칩니다.
- 24–25행: `check-manifest green — 불일치 0건` 을 찍고 exit 0.
- 원인: 스크립트는 불일치 수(`BAD`)만 세고 검사한 줄 수는 세지 않습니다. 그래서 「0건을 봤다」와 「보고 나니 불일치가 0건」을 구분하지 못합니다. 규약이 금지하는 「대상이 없어 통과」가 그대로 나옵니다.

**빈 값을 넘길 때 (`""`)**
- 10행이 `""*`, 즉 `*` 가 되어 모든 줄과 맞습니다. 대상이 0건이 되는 게 아니라, 범위가 소리 없이 매니페스트 전체(4건)로 넓어집니다.
- 이 픽스처에는 실물 파일이 없어서 `불일치 4건`, exit 1 로 우연히 실패합니다. 실물이 다 있는 곳이라면 호출자가 뜻하지 않은 전체 검사로 green 이 납니다. 빈 범위는 입력 오류로 거부해야 하므로, 이것도 틀린 동작입니다.

**인자를 아예 빠뜨릴 때**
- 3행 `set -u` 때문에 5행에서 `$1: unbound variable`, exit 1 로 멈춥니다. 실패는 하지만 스크립트가 의도해서 낸 메시지는 아닙니다.

**고치는 방향** (파일은 수정하지 않았습니다)
- 5행 앞에서 `[ -n "${1:-}" ]` 로 빈 값과 인자 누락을 거부합니다.
- 11행을 지난 줄마다 `CHECKED` 를 1씩 올립니다.
- 19행 앞에서 `CHECKED -eq 0` 이면 `::error::` 를 내고 exit 1 로 끝냅니다.
