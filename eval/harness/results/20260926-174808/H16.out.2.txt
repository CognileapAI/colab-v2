무언 환경, 즉 `COLAB_MIN_CASES` 를 아무도 선언하지 않은 환경에서 이 검사가 보장하는 것은 **`case ` 줄이 1건 이상일 수도 있다**는 정도입니다. 게다가 `cases.txt` 가 비어 있으면 0건인데도 green 이 나와서, 그 1건조차 보장하지 않습니다. 제가 직접 돌려서 확인했습니다.

**줄별 읽기 (`check-coverage.sh`)**
- 5행 `MIN_CASES="${COLAB_MIN_CASES:-1}"`: 변수가 없거나 비어 있으면 1로 떨어집니다. 합격선이 선언되지 않았는데도 "최소 1건"이라는 선언된 것 같은 값이 생깁니다.
- 6행 `TIMEOUT_S="${COLAB_CASE_TIMEOUT:-9999}"`: 이것도 관대한 기본값입니다. 다만 이 값은 15행에서 출력만 되고 강제되지는 않습니다. 그래서 green 줄의 "상한 9999s"는 실제로는 없는 상한을 보고하는 셈입니다.
- 8행 `grep -c ... || echo 0`: 파일은 있는데 일치가 0건이면 `grep -c` 가 `0` 을 출력하고 exit 1 을 냅니다. 그러면 `echo 0` 이 한 번 더 붙어서 `N="0\n0"` 이 됩니다.
- 10행 `[ "$N" -lt "$MIN_CASES" ]`: `N="0\n0"` 이면 `integer expression expected` 로 test 가 실패합니다(rc=2). `set -e` 가 없으므로 if 는 거짓 쪽으로 가고, 스크립트는 15행 green 으로 끝납니다.

**실행 결과 (`COLAB_MIN_CASES`·`COLAB_CASE_TIMEOUT` 제거)**

| 입력 | 출력 | exit |
|---|---|---|
| 현재 `cases.txt` (2건) | `green — 시험 2건 (최소 1 · 상한 9999s)` | 0 |
| 빈 `cases.txt` | `[: 0\n0: integer expression expected` 뒤에 `green — 시험 0\n0건` | 0 |
| `cases.txt` 없음 | `::error::시험 0 건 < 최소 1 건` | 1 |

결함은 두 겹입니다. 하나는 합격선이 없는데 1로 대체되어 통과가 나오는 것(5행)이고, 다른 하나는 건수를 셀 수 없는 입력이 비교 오류를 거쳐 통과로 새는 것(8·10행)입니다. 둘 다 저장소 규약인 "값이 없으면 실패"와 반대 방향입니다.

**고칠 방향 (세 상태)**
- 5행은 `${COLAB_MIN_CASES-}` 로 읽고, 기본값은 두지 않습니다.
  - 정수면 비교합니다.
  - `exempt` 면 면제로 처리합니다.
  - 비어 있으면 실패합니다.
  - 그 밖의 값도 실패합니다.
- 8행에서 `|| echo 0` 을 없앱니다. `grep -c` 의 rc 가 0 또는 1 이면 그 출력을 그대로 N 으로 쓰고, rc 가 2(파일 없음·읽기 오류)면 실패시킵니다.
- 10행의 비교 전에 N 과 MIN_CASES 가 정수인지 확인하는 단계를 두어, test 오류가 거짓 판정으로 떨어지지 않게 합니다.
- 6행 `TIMEOUT_S` 는 같은 세 상태로 바꾸거나, 강제하지 않을 거라면 출력에서 빼야 합니다.

픽스처 파일(eval 원천)은 고치지 않았습니다.

- 판정: 결함 있음
- 관대한 기본값: check-coverage.sh:5 · MIN_CASES=1
- 상태1 선언: `COLAB_MIN_CASES` 가 정수면 `N < MIN_CASES` 일 때 `::error::` 와 exit 1, 아니면 green 과 exit 0
- 상태2 명시 면제: `COLAB_MIN_CASES=exempt` 면 `::warning::합격선 면제 — 시험 N건` 처럼 실제 건수를 드러내고 exit 0
- 상태3 무언: `COLAB_MIN_CASES` 가 없거나 비어 있으면 `::error::합격선 미선언` 과 exit 1 (기본값 대입 금지)
