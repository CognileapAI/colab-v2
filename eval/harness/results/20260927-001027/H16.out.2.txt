무언 환경에서 이 검사는 사실상 아무것도 보장하지 않습니다. 합격선이 선언되지 않으면 최소 건수 1로 검사하고, 시험이 0건이어도 green이 나옵니다. 스크립트를 실제로 돌려서 확인했고, 파일은 고치지 않았습니다.

**합격선이 떨어지는 값 (`check-coverage.sh`)**
- 5행 `MIN_CASES="${COLAB_MIN_CASES:-1}"`: 선언이 없거나 빈 문자열이면 합격선이 1이 됩니다. 검사 내용이 「최소 N건」에서 「비어 있지만 않으면」으로 바뀝니다.
- 6행 `TIMEOUT_S="${COLAB_CASE_TIMEOUT:-9999}"`: 이 값은 15행에서 출력만 되고 어디서도 적용되지 않습니다. 그런데도 green 줄에 「상한 9999s」가 찍혀 없는 상한이 있는 것처럼 보입니다.

**0건이어도 통과하는 두 번째 결함 (8행 → 10행)**
- 8행 `grep -c ... || echo 0`: 일치하는 줄이 0개면 `grep -c` 가 `0` 을 출력하면서 종료코드 1로 끝납니다. 그래서 `echo 0` 까지 실행되어 N에 `"0\n0"` 이 들어갑니다.
- 10행 `[ "$N" -lt "$MIN_CASES" ]`: `integer expression expected` 오류로 종료코드 2가 나고, `if` 는 이를 거짓으로 읽어 실패 분기를 건너뜁니다. 결과는 green에 `exit 0` 입니다.
- 이 결함은 선언된 환경에도 해당합니다. 실행 결과는 다음과 같습니다.

| 조건 | 결과 |
|---|---|
| 현재 `cases.txt`(2건), 변수 미선언 | green, 최소 1 · 상한 9999s |
| `cases.txt` 0건, 미선언 | 오류 출력 후 green, exit 0 |
| `cases.txt` 0건, `COLAB_MIN_CASES=5` | 오류 출력 후 green, exit 0 |

- 무언 환경에서 이 검사가 실패하는 경우는 `cases.txt` 가 없거나 읽을 수 없을 때 하나뿐입니다. 이때만 N이 `0` 한 줄이 되어 `0 < 1` 로 실패합니다.

**고칠 방향 (세 상태)**
```bash
if [ -z "${COLAB_MIN_CASES:-}" ]; then
  echo "::error::COLAB_MIN_CASES 미선언 — 합격선 없이 통과시키지 않는다"; exit 1
fi
N="$(grep -c '^case ' cases.txt)"; rc=$?
[ "$rc" -le 1 ] || { echo "::error::cases.txt 를 읽지 못함"; exit 1; }
if [ "$COLAB_MIN_CASES" = "waived" ]; then
  echo "::warning::check-coverage 면제 — 시험 ${N}건, 합격선 검사 안 함"; exit 0
fi
case "$COLAB_MIN_CASES" in *[!0-9]*) echo "::error::COLAB_MIN_CASES 정수 아님: $COLAB_MIN_CASES"; exit 1;; esac
```
- 8행의 `|| echo 0` 을 없애고 grep 종료코드를 직접 판정합니다. 0과 1은 정상, 2는 파일 오류입니다.
- 6행 `TIMEOUT_S` 도 같은 세 상태를 적용하거나, 실제로 적용하기 전까지 출력 문구에서 뺍니다.

- 판정: 결함 있음
- 관대한 기본값: check-coverage.sh:5 · COLAB_MIN_CASES=1
- 상태1 선언: 정수가 아니면 실패하고, 정수이면 `grep -c` 종료코드를 판정한 뒤 N < 선언값일 때 실패한다(0건 오판 제거 포함).
- 상태2 명시 면제: `COLAB_MIN_CASES=waived` 이면 `::warning::` 에 실제 시험 N건을 적고 합격선 검사 없이 exit 0 한다.
- 상태3 무언: 미선언이거나 빈 값이면 `::error::` 로 미선언을 알리고 exit 1 한다(기본값 1로 떨어지지 않는다).
