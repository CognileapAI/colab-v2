# eval/s2b-alayer — 검색 평가셋 **A층** 실행기

`dev-package/sessions/S2b-SEARCH-EVALSET.md` 의 A층 16건을 **아무나 재현할 수 있게** 한다.

## 왜 있는가

직전 회차(`dev-package/sessions/DRIFT3-MEASURE.md §3`)가 A층을 실제로 돌려 보니 실패 8건의
**정체가 바뀌어 있었다** — `Q-07` 실패→통과, **`Q-08`·`Q-09` 통과→실패(회귀)**, `Q-12` 0→1건.
원인은 2026-08-27 에 채운 설명 2건이 새 토큰(「충청」·「다운스케」·「위성」)을 넣어 순위를 옮긴 것이다.
**그런데 그 회귀를 아무도 못 보고 있었다** — 레포에 A층 실행 수단이 없어 **회차마다 손으로 재현**했고,
그래서 「언제 나빠졌는가」를 추적할 수 없었다. 이 디렉터리가 그 손 절차를 스크립트로 고정한다.

## 왜 `gates/` 가 아닌가 · 왜 `eval/k4-search/` 옆인가

- **`gates/` 가 아니다** — 2026-08-29 Ted 판정으로 **검색 평가셋은 이번 릴리즈 판정 대상에서 뺐다**
  (의미 검색이 들어오면 지금 실패의 상당수가 놓인 층 자체가 바뀐다). **합격선을 걸지 않는다.**
  `gates/` 는 합격선이 걸린 검사기의 자리다. 여기 넣으면 없는 합격선을 만드는 것이 된다.
- **`eval/` 이다** — `eval/README.md` 가 이 디렉터리를 「AI 평가셋」의 자리로 못 박았고, **모델·프롬프트
  교체 시 회귀 판정의 근거**가 그 용도로 적혀 있다. 이 실행기가 정확히 그 일을 한다.
- **`eval/k4-search/` 와는 별개 하네스다**(직전 회차 보고 확인 완료) — 그쪽은 `SEED-DATA §3.1` 시드
  15건을 **일회용 DB** 에 올려 **그래프 전/후**를 비교한다. 이쪽은 **staging 실물 적재분 12건**에
  **평가셋 기대값**을 대조한다. 대상도 절차도 다르므로 섞지 않고 형제로 둔다.

## 무엇을 내는가 — **판정이 아니라 값**

합격/불합격을 반환하지 않는다. 내는 것은 둘이다.

1. **항목별 값** — 결과 집합·순위·어느 팔(`tsvector` / `pg_trgm`)·1단 확장.
2. **기준선 대비 변화** — `충족→미충족`(회귀) · `미충족→충족` · `집합·순위 변화`.
   **이 줄이 이 실행기의 값어치다.** 직전 회차가 못 보고 있던 것이 정확히 이것이다.

`충족`/`미충족` 은 **합격/불합격이 아니라** 「정본의 기대문과 실물이 맞는가」의 값이다.

## 파일

| 파일 | 무엇 |
|---|---|
| `run.py` | 2단 절차 실행 + 기준선 대조 |
| `evalset.json` | A층 16건의 질의·고정 검색어·기대. **정본을 술어로 옮긴 것뿐**이고 기대를 고친 것이 없다 |
| `baseline.json` | 직전 실측값. `--write-baseline` 으로 박는다 |

**기대값은 이 실행기가 고치지 않는다.** 정본은 `S2b-SEARCH-EVALSET.md` 이고, 실물에 맞추려고
기대를 손대는 것이 이 레포가 금지한 「검사 대상 축소」다(`§3-2`).

## 돌리는 법

```
python3 eval/s2b-alayer/run.py                  # 값 + 기준선 대비 변화
python3 eval/s2b-alayer/run.py --repeat 3       # 회차 안 결정성(md5 반복)
python3 eval/s2b-alayer/run.py --json out.json  # 원자료
python3 eval/s2b-alayer/run.py --write-baseline # 이번 값을 기준선으로
```

기본 접속 대상은 `colab_v2_staging_pg` · `colab_v2_staging_ai_service` 다(`--pg`·`--ai` 로 바꾼다).

## 2단 절차 — 손으로 하던 것 그대로

| 단 | 무엇 | 어디서 |
|---|---|---|
| **1단** | 고정 검색어(`§2.9.1` 무수정)를 `SqlDictionaries.expand` 에 넣어 사전·그래프 확장을 얻는다 | staging `ai-service` 컨테이너 **실호출** |
| **2단** | 확장된 검색어로 `d3_catalog._SEARCH` → (0건이면) `_SEARCH_TRGM` 을 던진다 | staging `colab_platform` |

**2단 SQL 을 여기에 다시 적지 않는다.** `run.py` 가 `services/core-api/.../d3_catalog.py` 에서
`_PREFIX_TSQUERY`·`_SEARCH`·`_SEARCH_TRGM`·`TRGM_THRESHOLD` **원문을 읽어** 파라미터만 묶는다.
베껴 적으면 제품이 바뀌었을 때 평가셋만 옛 규칙을 재게 된다. 제품 SQL 의 **모양이 바뀌면 실행기는
조용히 옛 SQL 을 쓰지 않고 `못 쟀다` 로 끝난다.**

## ⛔ green-by-skip 을 만들지 않는다

**종료 코드는 판정이 아니라 「잴 수 있었는가」다.**

| rc | 뜻 |
|---:|---|
| `0` | A층 16건을 **전건 실행**했다 |
| `2` | **못 쟀다** — 컨테이너 부재 · 1단 실패(사전 미배선 포함) · SQL 실패 · **대상 데이터셋 0건** · 매니페스트와 실물 불일치 · 항목 수 ≠ 16 · 제품 SQL 모양 변경 |

- **「대상 0건」도 실패다.** 빈 DB 를 재고 0건을 통과로 세지 않는다.
- **못 돈 것을 요약줄이 숨기지 않는다** — 층 밖 `Q-19`·`Q-20` 과 B층 16건은 **미실행 건수로 매번
  찍힌다**. `[미확인]` 이지 통과가 아니다.
- **판정 불가는 판정하지 않는다** — `Q-12` 는 기대문의 「등」때문에 통과·실패가 갈리지 않는다.
  `판정보류` 로 남기고 관측값을 적는다(Ted 판정 자리).

## 운영 스택 경계

- **읽기 전용.** 2단은 `SELECT` 뿐, 1단은 `READ ONLY` 트랜잭션(`app/dictionaries.py`)의 사전 조회뿐이다.
  정지·재기동·`down`·DDL·`DELETE`/`UPDATE` **0회**.
- **컨테이너 안에 파일을 남기지 않는다** — 1단은 `python -c`, 입력은 stdin, 2단 SQL 도 stdin 이다.
- **접속 문자열·비밀번호를 인자·출력 어디에도 두지 않는다** — 컨테이너 안의 `Settings.from_env()` 와
  `psql` 로컬 소켓만 쓴다.
