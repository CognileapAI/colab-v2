# eval/s2b-alayer-g2 — 검색 평가셋 **2세대**

**기대값을 데이터에서 도출한다.** 1세대(`eval/s2b-alayer/`)는 지우지 않았다 — 두 세대가 나란히 있다.

## 왜 세대를 갈랐나

1세대의 기대는 산문 정본을 술어로 옮긴 것이었고, **그 산문이 설명 본문 적재보다 먼저 쓰였다.**
그래서 「이 낱말은 이 적재분에 없다」고 단언하는 기대가 여럿 남았는데 실물에는 그 낱말이 있었다
(`dev-package/sessions/K4-ALAYER-ADJUDICATION.md` — 실패 9건 중 6건이 이 노후였다).
건별로 기대를 고치면 **회차마다 같은 노후를 다시 다투게 된다.** 그래서 기대의 출처를 바꿨다.

## 지켜야 하는 한 줄 — ⛔ **검색 결과에서 기대를 뽑지 않는다**

검색이 내는 것을 정답으로 적으면 평가셋은 아무것도 검사하지 못하고 **오늘의 동작을 정의상 옳다고
증명하는 변경 감지기**가 된다. 그 함정을 구조로 막았다.

- 입력과 기대가 **다른 파일**이다 — `cases.json` 에는 질의와 「무엇을 확인하려는가」만 있고 기대가 없다.
  `selftest.py` 가 입력 파일에 기대값이 섞여 들어오는 것을 시험으로 막는다.
- 기대는 `derive.py` 가 **셋에서만** 만든다 — 적재된 `name`·`topic`·`summary` **원문**, `ai-service`
  사전·그래프의 **확장 실측**, 릴리즈가 내세우는 성질(**낱말 접두 매칭**).
- 도출에 제품의 SQL·`tsvector`·`ts_rank` 를 **쓰지 않는다.** 순수 파이썬으로 따로 센다.
- 건마다 **도출 근거**를 남긴다 — 어느 데이터셋의 어느 칸에 그 낱말이 있었는지와 **원문 발췌**.
  사람이 원문을 열어 대조할 수 있어야 감사 가능한 기대다.

## 도출 규칙 (감사 가능하게 못 박는다)

낱말 = `[0-9A-Za-z가-힣]+` 의 최대 연속. 매칭 = 어떤 낱말이 검색어로 **시작**하면 맞은 것(대소문자 무시).
**낱말 가운데는 맞지 않는다** — 그것을 맞히려면 형태소 분석이 필요하고 그 수단은 폐기된 것이라
릴리즈가 내세우는 성질이 아니다. 하이픈으로 갈리는 검색어(`GK-2A`)는 셈법이 갈리는 자리라 **넣지 않았다.**

## 건의 갈래 넷

| 갈래 | 기대 | 도출 |
|---|---|---|
| `derived_exact` | 정확한 집합 | 확장 뒤 검색어가 1개인 질의. 그 낱말을 낱말 접두로 갖는 데이터셋 전부 |
| `derived_bounds` | **교집합 ⊆ 결과 ⊆ 합집합** | 확장이 2개 이상인 질의. **검색어 결합 규칙(OR/AND)은 정본이 유보했으므로 이 평가셋이 정하지 않는다** — 어느 쪽이든 성립하는 경계만 건다 |
| `derived_field_order` | 이름 매칭이 본문 매칭보다 앞 | 색인 가중치 선언(이름 A · 주제 B · 설명 C — 생성 컬럼 `search_vector`) |
| `out_of_scope` | **없음** | 기대를 데이터에서 정할 수 없는 자리. 관측만 하고 **통과로도 실패로도 세지 않는다** |

## 돌리는 법

```
python3 eval/s2b-alayer-g2/selftest.py            # fail-closed 자기 시험 (컨테이너 불필요)
python3 eval/s2b-alayer-g2/derive.py              # 실물 측정 + 기대 도출을 보여만 준다
python3 eval/s2b-alayer-g2/derive.py --write      # evalset-g2.json 을 다시 쓴다
python3 eval/s2b-alayer-g2/derive.py --check      # 커밋된 기대 = 지금 실물인가
python3 eval/s2b-alayer-g2/run.py --repeat 2      # 대조 실행 + 기준선 대비 변화
python3 eval/s2b-alayer-g2/run.py --write-baseline
```

`run.py` 는 **실행 직전에 기대를 다시 도출해 커밋된 파일과 대조**한다. 다르면 적재분이나 사전이
움직였다는 뜻이고 **못 쟀다(rc=2)로 끝난다.** 그때 할 일은 `--write` 로 다시 뽑고 무엇이 달라졌는지
회차 문서에 적는 것이지, **제품 결과에 맞춰 기대를 고치는 것이 아니다.**

## ⛔ green-by-skip 을 만들지 않는다

종료 코드는 판정이 아니라 「잴 수 있었는가」다 — `0` 전건 실행 · `2` 못 쟀다(컨테이너 부재 · 사전
미배선 · SQL 실패 · **대상 0건** · **설명 본문이 빈 데이터셋** · 제품 SQL 모양 변경 · 커밋된 기대와 실물 불일치).
`범위 밖` 은 요약줄에 **따로 세어** 찍히고 통과에 합산되지 않는다. 못 도는 층(검색 중단 시 응답 ·
연구실 경계 · 자연어 해석)은 **미실행로 매번 찍힌다** — `[미확인]` 이지 통과가 아니다.

## 파일

| 파일 | 무엇 |
|---|---|
| `cases.json` | 입력. 질의·확인 의도만. **기대 없음** |
| `common.py` | 실물 측정 · 낱말 접두 매칭 · 기대 도출 |
| `derive.py` | 기대를 다시 만든다 / 검사한다 |
| `run.py` | 제품 경로 실행 · 대조 · 기준선 |
| `evalset-g2.json` | 도출된 기대 **＋ 건별 도출 근거와 원문 발췌**. 손으로 고치지 않는다 |
| `baseline-g2.json` | 직전 실측 |
| `selftest.py` | 실패 픽스처로 fail-closed 를 증명한다 |

## 운영 스택 경계

**읽기 전용.** 2단은 `SELECT` 뿐, 1단은 컨테이너 안 사전 조회뿐이다. 정지·재기동·`down`·DDL·`DELETE`/`UPDATE` 0회.
컨테이너 안에 파일을 남기지 않는다(입력은 stdin). 접속 문자열·비밀번호를 인자·출력 어디에도 두지 않는다.
