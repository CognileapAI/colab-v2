# 업로드와 계보 — 긴급 범위 rev1

> **이 폴더는 전달용 사본이다.** 정본은 이 레포 밖 기획 작업공간에 있다.
> 레포 안에 기획 문서를 두지 않는다는 `planning/README.md` 의 규칙과 헷갈리지 않도록,
> `planning/` 이 아니라 `deliverables/` 아래에 둔다.

## 왜 여기 있나

기존 정본(`40 COLAB-기획/…_260818_이태헌/`, 에픽 E-00~E-07)에 **없는 별건**이다.
2026-08-26 업로드 목업 피드백 10건을 받아 긴급 범위로 따로 만든 rev1 이고,
개발·디자인 검토자에게 **링크 하나로 건네려고** 이 레포에 올렸다.

`gates/run.sh planning-freshness` 는 정본 8개 패키지(E-00~E-07)를 검사한다.
이 폴더는 그 대상이 아니다 — 검사 범위를 늘리지 않는다.

## 무엇이 들었나

| 경로 | 무엇 |
|---|---|
| `package/업로드_계보_260826_rev1.html` | **개발·디자인 전달본.** 화면 + UI 스펙 65항목 + PRD·정책·검증 문서를 한 파일에 담았다 |
| `mockups/업로드_계보_260826_rev1.html` | 화면 목업 (스펙 오버레이 없음) |
| `documents/` | PRD · 정책 · 검증 마크다운 3종 (패키지에 임베드된 것과 같은 내용) |
| `references/` | 2026-08-26 업로드 목업 기획 피드백 원본 (PDF) |

## 어떻게 보나

패키지 HTML 은 외부 의존이 없는 단일 파일이다. **내려받아 브라우저로 열면 된다.**
GitHub 은 HTML 을 렌더링하지 않으므로 저장소에서 바로 보이지는 않는다.

패키지 안에서 쓸 수 있는 것:

| 자리 | 무엇 |
|---|---|
| 화면 아래 안내 바 | 화면 이동 (업로드 · 데이터셋 상세 · 상태별 변형) |
| 안내 바 `Δ 변경점` | 이번에 바뀐 자리에 배지를 켠다. 배지에 올리면 무엇이 왜 바뀌었는지 나온다 |
| 안내 바 `목록` | 변경 29건 전체. 누르면 그 화면·단계로 데려가 자리를 짚는다 |
| 우측 하단 연필 버튼 | UI 스펙 넘버링 (65항목) |
| 우측 하단 문서 버튼 | PRD · 정책 · 검증 3탭 |

## 범위

- **들어간 것** — 업로드 전체 화면 모달(파일 놓기 · 등록 3단계: 분류 → 메타데이터 입력 → 연결),
  데이터셋 상세(계보 · 미리보기 · 활용 · 접근)
- **뺀 것** — AI 활용 전부(2026-08-24 회의 결정), 데이터셋 목록 화면, 검증 상태 워크플로우,
  미리보기 뒷단(변수 전환 · 값 조회 · 겹쳐 보기)

자세한 범위와 근거는 패키지 안 PRD 탭 §5 를 본다.
