# PRD: 업로드와 계보 (긴급 범위) rev1

## 1) 한 줄 요약
- 대학원생이 파일을 올리면서 메타데이터와 계보(어디서 왔나)를 직접 기록하고, 서버가 그린 미리보기 한 장으로 내용을 바로 확인하여, 연구실 구성원 누구나 출처를 믿고 데이터를 찾아 쓰게 하는 기능이다.

## 2) 배경 / 문제
### 2.1 배경
- 연구실 데이터는 개인 PC와 저장 장치에 흩어져 있고, 파일의 내용과 가공 이력을 아는 사람은 올린 사람뿐이다.
- 2026-08-24 회의에서 업로드와 계보를 긴급 우선순위로 확정했다. 당장은 AI 활용을 배제하고, 사람이 직접 적는 방식으로 먼저 연다.
- 회의에서는 서버가 그리는 미리보기가 불가 판정이었으나, 재검토(실측 보고와 PNG+경계 좌표 데모)로 "첫 변수 한 장을 자동으로 그리는 수준"은 가능함을 확인했다(첫 화면 1장 0.03~0.33초).
- 2026-08-26 목업 피드백 10건을 받아 rev1 로 반영했다. 분류 체계는 고려대가 정의한 세 축(분류·유형·가공 단계)을 정본으로 삼고, 임의로 만들었던 주제 6종은 걷었다.

### 2.2 문제
- 파일 자체에서 읽을 수 있는 정보는 확장자와 용량뿐이라, 파일명만으로는 무엇인지 알 수 없다. 확장자는 포맷을 특정하지도 못한다(.hdf 하나가 HDF4-EOS·HDF5 둘을 가리킨다).
- 무엇을 가공해 만든 데이터인지(계보)가 사람 기억에만 있어, 올린 사람이 없으면 신뢰할 수 없다.
- 내용을 확인하려면 내려받아 전용 도구로 열어야 해서, 열어보기 전에는 쓸지 말지 판단할 수 없다.
- 등록 절차가 무거우면 아무도 올리지 않는다. 계보를 모른다는 이유로 등록을 막으면 데이터가 들어오지 않는다.

## 3) 고객가치
### 3.1 내부 고객 가치
- 올리는 사람(대학원생): 파일을 놓고 아는 만큼만 적으면 등록이 끝난다. 미리보기가 자동으로 그려져 내용 확인과 대표 그림이 함께 해결된다.
- 찾는 사람(연구실 구성원): 데이터셋 상세에서 계보·기본 정보·미리보기를 보고 내려받기 전에 쓸지 말지 판단할 수 있다.
- 승인하는 사람(교수): 연구실 데이터의 출처와 활용 현황(어느 과제·논문에 쓰였나)이 화면에 남는다.

### 3.3 사업적 가치 (필요 시)
- 계보와 메타데이터가 쌓이는 것이 이후 단계(검증·상품화·중개)의 전제 자산이 된다.

## 4) 대상 사용자 및 대표 시나리오
### 4.1 대상 사용자
| 사용자 그룹 | 역할 | 주요 니즈 |
|---|---|---|
| A2 대학원생 | 실사용자 · 업로드와 계보 기록 | 빠르게 올리고, 아는 만큼만 적고, 나중에 바로잡고 싶다 |
| A1 교수 | 예산 집행 · 승인 | 연구실 데이터의 출처와 활용 현황을 믿고 확인하고 싶다 |

### 4.2 대표 시나리오 (Top 3)
1) 대학원생이 가공한 강우 자료(*.nc) 조각 4개를 한 번에 끌어다 놓는다. 분석이 끝나면 분류·유형·가공 단계를 먼저 고르고(정의·예시를 보며), 변수별 값을 적고, 가공 전 데이터(Lv1)를 찾아 연결한다. 이 데이터가 Lv2 라 찾기 모달에는 Lv0~Lv2 후보만 고를 수 있고, 연결한 뒤 프로젝트를 연결하고 데이터셋을 만든다.
2) 가공 전 데이터를 찾지 못한 대학원생이 "못 찾은 것이 있어요(기록 없음)"로 남기고 등록을 마친다. 뒤에 상세 화면의 계보 빈 상태에서 "계보 채우기"로 바로잡는다.
3) 구성원이 데이터셋 상세를 열어 계보 그래프에서 가공 전 데이터로 이동해 원본을 확인하고, 미리보기를 확대해 범위를 본 뒤 내려받는다.

## 5) 범위 (Scope)
### 5.1 In-scope (이번 릴리즈)
- 업로드 전체 화면 모달
  - 장면1: 파일 놓기(끌어다 놓기·파일 고르기), 포맷 무관·같은 확장자 여러 개 일괄, 파일 분석(올리기 → 읽기 → 확장자·용량 확인) 후 다음 활성
  - 장면2: 좌측 바로 미리보기(서버가 첫 변수·기간 평균 한 장을 자동으로 그림) + 우측 등록 3단계(분류 → 메타데이터 입력 → 연결)
  - 분류: 고려대 3축(분류·유형·가공 단계)을 첫 단계에서 고른다. 고른 값 아래 정의·대표 예시를 보인다
  - 메타데이터 직접 입력(자동은 확장자·용량뿐), 변수별 행 입력(단위·값 범위·결측률·대표), 공개 범위, 대표 그림 자동 생성과 직접 교체
  - 계보 등록: 가공 전 데이터 직접 찾기·연결, 모름(기록 없음) 표시, 원천 표기, Lv0 출처 주소·내려받은 날, 자기 Lv 이하 후보만 연결(가공 단계 필터)
  - 연관 프로젝트·논문 연결(여러 개), 프로젝트 빠른 생성(유형·이름만)
- 데이터셋 상세(긴급 범위)
  - 계보 첫 섹션: 족보 그래프(원천·가공 전·이 데이터·파생·활용 배지), 계보 상세 행, 기록 없음 빈 상태와 계보 채우기, 계보 수정·추가 모달
  - 미리보기: PNG+경계 좌표 뷰어(휠 확대·끌어 이동·커서 위경도·보기 초기화), 확장보기, 미지원 형식 실패 상태
  - 활용 프로젝트(쓰임 문장 포함) · 접근·다운로드 · 파일 목록(조각, 접힘 기본)

### 5.2 Out-of-scope (이번 제외)
- AI 활용 전부(메타데이터 자동 추출, 계보 자동 제안, LLM 검색). 2026-08-24 회의 결정.
- 이종 포맷 일괄 업로드(한 데이터셋은 한 확장자다), 업로드 중 이어받기.
- 미리보기의 변수 바꾸기·시각 선택·값 조회·겹쳐 보기·팔레트 조정.
- 데이터셋 목록 화면(뒤에 깔린 문맥으로만 존재), 검증 상태 워크플로우, 권한 세분화.

### 5.3 Phase 2+ (후속 후보)
- AI 메타데이터 추출·계보 제안(회의에서 "당장은 배제"이지 폐기가 아님).
- 미리보기 변수·시각 선택, 겹쳐 보기.
- 조각별 메타데이터(조각마다 다른 기간 등) 관리.

## 6) 요구사항 요약 (Feature Summary)
> 상세 동작/규칙/예외는 기능 정책문서, 검증 항목은 검증문서에서 관리 (SSOT)

- 파일에서 자동으로 읽는 값은 확장자와 용량뿐이며, 나머지 메타데이터는 사람이 적는다. 확장자로 포맷을 단정하지 않고 `*.nc` 처럼 확장자 그대로 적는다.
- 필수 입력은 데이터셋 이름 · 분류 · 유형 · 가공 단계 · 기간 · 설명이다. 설명에는 칸을 따로 만들지 않은 필수 항목(보간 방법·산출 수식 등)도 적는다.
- 변수는 여러 개이며 단위·값 범위·결측률을 변수마다 받는다. 대표 변수 하나가 목록·상세에서 데이터셋을 대신한다.
- 공개 범위를 업로드에서 받는다. 기본값은 연구실 구성원 전체다.
- 분류·유형·가공 단계는 고려대 정의를 그대로 쓴다. 분류 5종 · 유형 6종 · 가공 단계 Lv0~Lv3 네 단이다.
- 가공 단계는 자동으로 맞추지 않는다. 규칙은 `부모 Lv ≤ 자기 Lv` 이며 같은 단계 가공을 허용한다(실사례 Lv0 > Lv1-A > Lv1-B > Lv2). 분류에서 고른 자기 Lv 가 기준이고, 연결에서는 그 이하만 고를 수 있다. 연결 뒤 자기 Lv 를 낮추면 연결에 확인 필요 표시가 붙고 데이터셋 만들기가 막힌다.
- Lv0 원시 데이터는 출처 주소와 내려받은 날이 필수다.
- 계보를 모르면 등록을 막지 않고 "기록 없음"으로 남긴다. 상세 화면에서 나중에 채운다.
- 파일이 놓이면 서버가 미리보기 한 장을 자동으로 그리고, 그 축소본이 대표 그림 기본값이 된다.
- 포맷은 가리지 않는다. 미리보기를 못 그리는 확장자여도 등록·계보·다운로드는 그대로 가능하다.
- 같은 확장자 파일 여러 개를 한 데이터셋으로 묶는다. 확장자가 섞이면 첫 종류만 받고 알린다.
- 업로드를 닫으면 입력 내용이 사라지므로 닫기 전에 확인을 받는다. 원본 파일은 영향 없다.
