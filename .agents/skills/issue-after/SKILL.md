# 해결 결과 기록

## Intent

이슈를 읽는 사람이 문제 원인, 해결 방법, 실제 해결 여부를 수정 전·후 근거로 확인할 수 있게 한다.

## 실행

브라우저 검증 전에 [환경·계정 선택](../verification-before-completion/SKILL.md)을 적용한다. 특정 계정이나 dev 로그인을 모든 작업에 일괄 요구하지 않는다.

1. 이슈 본문과 댓글을 읽고 [issue-before](../issue-before/SKILL.md)가 남긴 문제 현상 댓글·재현 조건·스크린샷을 찾는다. 같은 수정 버전의 해결 결과 댓글이 이미 있으면 확인해 재사용한다. 이전 댓글을 해결 결과로 덮어쓰지 않는다.
2. 실제 변경 diff와 관련 코드·검증 근거를 읽는다. ‘무엇이 원인이었는지 → 어떤 처리를 어떻게 바꿨는지 → 그 변경이 왜 증상을 해결하는지’를 쉬운 한국어로 설명한다. 파일명만 나열하거나 ‘버그 수정’으로 대신하지 않는다. 원인 미확정은 그대로 표시한다.
3. [agent-browser](../agent-browser/SKILL.md)를 읽고 사용한다. CoLAB에서는 [작업 규율](../colab-v2-work/SKILL.md)도 적용한다. Linux에서는 저장소 루트의 `python3 scripts/agent-bridge.py run-tool browser -- <인자>`를 쓴다.
4. 실제 대상 환경의 수정 버전을 확인하고 첫 댓글과 같은 화면 크기·데이터 조건·재현 순서로 검증한다. 조건이 다르면 차이를 명시한다. 실제 조작 결과를 확인하며, 저장 문제라면 조회·새로고침 후 유지 여부까지 확인한다. 스크린샷만으로 동작 성공을 판정하지 않는다.
5. 수정 후 이미지를 저장하고 직접 확인한다. 첫 댓글의 수정 전 이미지와 나란히 배치한다. 이전 증거가 없으면 ‘수정 전 화면 미확보’를 명시하고 수정 후 결과만 제시한다. 이전 화면을 재구성하거나 운영 환경을 되돌려 전후 근거를 만들지 않는다.
6. 아래 형식의 본문을 파일로 작성하고 [issue-before의 게시 절차](../issue-before/SKILL.md#게시-절차--두-스킬-공통)를 적용해 해결 결과 댓글 하나를 게시한다. 첫 댓글 링크를 연결하고 게시 후 본문·이미지를 확인한다. 댓글 URL과 검증 상태를 인계한다.

## 댓글 형식

```markdown
## 해결 결과
- 문제 현상 기록: 첫 댓글 링크 또는 기존 기록 없음
- 문제 원인:
- 어떻게 고쳤는지: 바꾼 처리와 그 이유를 설명
- 확인 환경·버전·시각:

### 수정 전·후
| 수정 전 | 수정 후 |
| --- | --- |
| 이미지 또는 미확보 표시 | 이미지 |

### 검증 결과
- 확인한 조작과 기대 결과:
- 실제 결과:
- 판정: 해결 확인 / 문제 지속 / 일부 확인 / 환경 부족으로 미실행
- 남은 사항: 있으면 기재
```

검증이 실패하거나 실행되지 않았어도 사실대로 결과를 기록할 수 있다. 배포되지 않은 코드를 운영에서 검증했다고 쓰지 않으며, 확인한 범위를 넘어 ‘완전 해결’로 표현하지 않는다. 이 스킬 실행 자체는 제품 수정·배포·이슈 닫기를 포함하지 않는다.
