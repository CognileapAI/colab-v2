# 문제 현상 기록

## Intent

이슈를 읽는 사람이 어떤 조건에서 어떤 문제가 발생하는지 재현 순서와 실제 화면으로 확인할 수 있게 한다. 수정 후 보고는 [issue-after](../issue-after/SKILL.md)가 별도 댓글로 담당한다.

## 실행

브라우저 검증 전에 [환경·계정 선택](../verification-before-completion/SKILL.md)을 적용한다. 특정 계정이나 dev 로그인을 모든 작업에 일괄 요구하지 않는다.

1. 대화에서 이슈 URL과 대상 환경을 확인하고 이슈 본문·기존 댓글을 읽는다. 대상이 여러 개라 식별할 수 없으면 필요한 정보만 묻는다. 같은 재현 건의 현상 댓글이 이미 있으면 링크와 증거를 확인해 재사용한다.
2. [agent-browser](../agent-browser/SKILL.md)를 읽고 사용한다. CoLAB에서는 [작업 규율](../colab-v2-work/SKILL.md)도 적용한다. Linux 실행은 저장소 루트에서 `python3 scripts/agent-bridge.py run-tool browser -- <인자>`를 사용한다.
3. 테스트 URL, 확인 시각, 대상 버전(SHA 또는 확인 불가), 화면 크기, 격리 계정·데이터, 재현 순서, 기대 결과, 정리 범위를 기록한다. 로컬 HEAD를 배포 버전으로 간주하지 않는다. 같은 조건을 수정 후에도 쓸 수 있도록 작업의 증거 디렉터리에 저장한다.
4. 실제 클릭·입력으로 재현하고 화면 변화 뒤 snapshot을 갱신한다. 문제가 나타난 단계의 스크린샷과 관찰 결과를 저장하고 이미지를 직접 확인한다. 재현되지 않으면 시도한 조건과 ‘재현 안 됨’을 적는다. 원인은 추측해 확정하지 않는다.
5. 아래 형식으로 댓글 본문을 파일에 작성한 뒤 게시 절차를 수행한다. 게시 URL, 이미지 경로, 재현 조건을 작업 인계에 남긴다. 여기서 제품 코드를 수정하거나 해결 결과 댓글을 만들지 않는다.

## 댓글 형식

```markdown
## 문제 현상
- 확인 환경·버전·시각:
- 재현 순서:
  1. …
- 기대 동작:
- 실제 현상:
- 재현 결과: 재현됨 / 재현 안 됨 / 환경 부족으로 미실행

### 수정 전 화면
![문제가 나타난 단계 설명](업로드 후 확인한 이미지 URL)
```

## 게시 절차 — 두 스킬 공통

- 이 스킬의 ‘이슈 댓글 기록’ 실행 요청은 지정 이슈에 해당 댓글 하나를 게시하는 범위다. 초안만 요청했으면 게시하지 않는다. 스킬 생성·설명 요청은 실행 요청이 아니다. 이미 받은 게시 승인은 다시 묻지 않는다. 이슈 닫기·PR 게시·다른 채널 알림은 포함하지 않는다.
- 이미지에서 비밀번호·토큰·개인정보가 노출되지 않았는지 확인한다. 인증된 이슈 화면의 첨부 기능이나 사용 가능한 공식 도구로 이미지를 업로드한다. agent-browser의 snapshot으로 실제 파일 입력 요소를 찾은 뒤 upload하고, 업로드 완료 후 생성된 URL을 사용한다. 추측한 업로드 API, 임의 공개 호스팅, 로컬 파일 경로를 첨부 URL로 쓰지 않는다.
- 텍스트 게시는 사용 가능한 이슈 도구를 쓴다. GitHub CLI를 쓰면 `gh issue comment <이슈-URL> --body-file <본문-파일>`로 실제 줄바꿈을 보존한다. 이미지 업로드를 CLI 댓글 명령이 대신한다고 가정하지 않는다.
- 게시 직전 이슈 대상·본문·첨부를 확인하고 적용되는 저장소 게시 전 검토를 수행한다. 게시 후 댓글을 다시 읽어 본문과 이미지가 실제 이슈에서 보이는지 확인하고 댓글 URL을 반환한다.
- 게시 응답이 끊기면 기존 댓글을 조회해 성공 여부부터 확인한다. 같은 재현 건·같은 단계의 댓글을 중복 생성하지 않는다. 불확실한 상태에서 재시도를 반복하지 않는다.
- 인증·첨부 기능이 없으면 본문과 이미지 파일을 보존하고 ‘게시 미완료’ 및 막힌 지점을 보고한다. 이미지가 빠진 상태를 첨부 완료라고 보고하지 않는다. 이미 게시된 댓글에서 문제가 발견되면 URL과 누락을 기록하고, 다른 댓글을 잘못 고칠 수 있는 `--edit-last`는 사용하지 않는다.
