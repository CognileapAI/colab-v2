# CoLAB Ponytail

현재 사용자 요청·합의한 결과와 관련 코드를 읽은 다음 [Ponytail 원본](../ponytail/SKILL.md)의
재사용 → 표준 라이브러리 → 플랫폼 기능 → 최소 구현 순서를 적용한다. Codex는 파일을 직접
읽고, Claude도 공통 원본을 읽는다. 원본을 직접 호출했어도 이 프로젝트 경계를 함께 적용한다.

- 기본은 `full`, 요청하면 `lite` 또는 `ultra`다. 강도는 구현 방법의 단순화 정도이며
  어떤 모드에서도 명시한 기능·수용 조건·접근성·보안·데이터 손실 방지는 줄이지 않는다.
  범위 변경이 필요하면 이유와 대안을 제시하고 사용자의 결정을 받는다. 기존 승인은 다시 묻지 않는다.
- 코드를 줄이기 전에 관련 흐름과 호출자를 확인한다. 기존 코드·표준 기능이 해결하면 재사용한다.
  별도 조사 보고서·추상화·설정·의존성을 단순화 검토 자체를 위해 만들지 않는다.
- 저장소의 기존 시험 도구와 해당 변경에 필요한 검증을 사용한다. 원본의 간단한 self-check로
  필수 검사를 대체하거나 검사 범위를 축소하지 않는다. 실패·면제·미실행을 성공으로 바꾸지 않는다.
- 사용자 요청 산출물과 적용되는 기록·인계는 유지한다. 원본의 세 줄 출력 선호보다 요청한 설명과
  검증 근거가 우선이다. 참고 템플릿의 HTML 산출물 의무를 CoLAB에 새로 추가하지 않는다.
- 보호 경로·훅·권한과 현재 대화의 승인 범위를 유지한다. 이 스킬은 커밋·push·PR 게시·병합·배포·삭제
  권한을 부여하지 않는다. PR 게시는 사용자 담당이다.
- `stop ponytail`, `normal mode`, `포니테일 끄기`를 요청하면 단순화 모드를 해제한다.
  선호는 현재 세션 안에서만 유지하며 원본의 ACTIVE EVERY RESPONSE는 비코딩 요청에 적용하지 않는다.
  상시 활성화·모드 추적·metrics 훅과 부가 스킬은 설치하지 않는다.

원본 본문은 수정하지 않는다. 프로젝트 차이는 이 파일에 두고, 원본 갱신은
[출처 기록](../VENDORED.md)의 고정 커밋·본문·라이선스를 대조한다.
