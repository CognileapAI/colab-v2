모든 신규 기능 표시

STAGE 1 · 파일 보관

실패해도 기록을 잃지 않게

  • 저장 기록이 확인된 파일만 정리 후보로 고릅니다.
  • 삭제에 실패한 파일의 기록은 남겨 다시 시도할 수 있게 합니다.
  • 등록된 자료와 진행 중인 전송은 보호합니다.
새 회수 기능의 기본값은 관찰 모드입니다. 실제 S3 객체 삭제는 미실행입니다.
STAGE 1 · 개발 검증

시험을 나눠 동시에 실행

  • 서비스 시험을 서로 분리된 시험용 DB에서 병렬 실행합니다.
  • 검사하지 못했거나 실패한 항목을 성공으로 표시하지 않도록 보완했습니다.
검사 범위를 줄이지 않았습니다. 같은 코드 기준의 최종 시간 비교는 별도 확인이 남아 있습니다.
STAGE 2 · 위치 설정

한 번 만든 격자를 다시 쓰기

  • 같은 연구실에서 배열 크기가 맞는 격자, 즉 위치 정보를 찾아 가져옵니다.
  • 교수는 자주 쓰는 격자를 연구실 기본값으로 지정할 수 있습니다.
  • 격자 복사 중에는 등록이 먼저 진행되지 않게 막습니다.
STAGE 2 · 확인과 찾기

위치 차이를 알고 자료 찾기

  • 파일 형식·내용이나 실제 경계·한 칸의 크기가 다르면 안내합니다.
  • 지도에 나올 예상 범위를 보여 줍니다.
  • 목록에서 ‘지도 있음 / 지도 없음 / 아직 모름’을 표시하고 골라 볼 수 있습니다.
STAGE 2 · 미리 보기

기다리는 동안 먼저 확인하기

  • 첫 본체 파일의 임시 미리보기를 먼저 띄우고 최종 결과로 바꿉니다.
  • 실제 처리 완료 표본으로 예상 남은 시간을 안내합니다.
  • 색상표와 색 구간 수(3~9개)를 고를 수 있습니다.
전체 파일의 최종 결과와 임시 화면을 구분합니다.
STAGE 2 · 운영 확인

문제가 생긴 경로를 추적하기

  • 주 API에서 시각화·AI 서비스까지 요청의 추적 정보를 이어 줍니다.
  • 서비스 요청과 파일 처리 결과를 같은 형식의 로그로 남깁니다.
  • 알람의 첫 발생과 복구를 구분하는 기능을 구현했습니다.
외부 알람 연결과 실제 통지는 아직 하지 않았습니다.
STAGE 2 · 미리보기 보관

쓰이지 않는 미리보기 살펴보기

  • 파일 처리와 미리보기 서비스가 변경 알림을 공유하도록 연결했습니다.
  • S3에 있는 원본과 미리보기를 비교해 사용 여부를 관찰하는 경로를 만들었습니다.
자동 삭제하지 않습니다. dev에서는 조사할 파일이 작업 용량 한도를 넘어 첫 관측을 끝내지 못했습니다.
STAGE 2 · 접근 경계

연구실·계정이 빠진 요청 거절

  • 내부 시각화 요청 5곳에서 연구실과 계정 정보를 필수로 맞췄습니다.
  • 계정 정보가 없거나 빈 요청도 서버가 거절합니다(HTTP 400).
다른 연구실의 자료를 숨기는 기존 경계는 유지합니다.

확인한 것과 남은 것

새 기능 구현과 Stage 전체의 완료 판정은 구분합니다.

  1. 확인: dev 배포 진단 15개 통과. 합성 파일 업로드·등록·미리보기 색 변경·다시 열기·지도 필터 확인.
  2. 자동 검사: 전체 검사와 입력 보정 후 확인을 마쳤지만, 기존 캐시 19벌의 소유 판정과 비활성 로그인 버튼의 대비 검사에 실패가 남았습니다.
  3. 남은 수용 조건: 격자 재사용 등 나머지 dev 여정, 파일 관측의 용량 제약, 운영 자동 실행·외부 알람, ‘나만 보기’의 접근 규칙과 화면 문구 확인.

신규 목록에서 제외: 이미 있던 폴더 구조 보존·서버 좌표축 판별. Google 로그인, 화면·PNG 격자선과 눈금은 승인된 후속 작업입니다.
