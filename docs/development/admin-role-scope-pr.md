# 시스템 관리자 전체 권한과 교수 관리자 연구실 범위 분리

전체 연구실에서 자료는 보이지만 미리보기 요청은 거절되고 화면에 오류가 나타나지 않던 문제를 고친다.
시스템 관리자는 모든 연구실을, 교수 관리자는 자기 연구실의 비공개 자료까지 관리한다.
일반 구성원의 기존 제한과 데이터 무결성 규칙은 유지한다.

## 변경

- 기존 자료의 실제 연구실을 서버가 확인해 조회·변경·감사 기록에 사용한다. 시스템 관리자가 새 데이터·프로젝트를 만들 때만 소속 연구실을 선택한다.
- 미리보기 후속 요청과 다운로드는 현재 권한을 다시 검사한다. 업로드를 닫았다가 다시 열어도 선택한 연구실이 유지된다.
- 화면에서 두 관리자 역할을 구분하고, 공개 범위 안내에 관리자 접근을 알린다. 미리보기 권한 부족·조회 실패와 재시도 경로를 표시한다.
- 기존 교수에게 별도로 부여한 시스템 관리자 자격을 검토 목록에 따라 회수하는 도구를 제공한다. 교수 역할·소속·자료·비밀번호를 보존하고, 회수 계정의 기존 세션만 종료한다.
- platform `0033_admin_body_access`는 권한 정책만 변경한다. 기존 자료가 있는 DB의 증분 적용·되돌리기에서 전체 저장자료 보존을 확인했다.

## 검증

부모 직접 재실행 최종 결과: 프런트 1,538건, core-api 1,381건, viz-render 542건 통과.
core-api 제외 6건, viz-render 제외 42건은 게이트의 기존 E2E/performance 선택자에 따른 것이며 skip은 모두 0건이다.
로컬 실제 브라우저에서 다른 연구실 업로드·등록 재개·미리보기·수정 후 재조회, 관리자 회수 후 재로그인,
교수의 자기 연구실 비공개 관리, 일반 구성원의 본문·다운로드 제한을 확인했다.
관련 개별 게이트 17종과 프런트 배포 빌드도 통과했다. 최종 검사 상태·개별 실행 근거·intent 대조는 [구현 계획](../../dev-package/prd/rounds/R-ADMIN-ROLE-SCOPE.md)에 기록한다.

## 배포와 제한

[계정 전환·배포 절차](admin-role-transition.md)를 따른다. 새 전체 권한 서버를 노출하기 **전에**
실제 계정 목록을 검토하고 기존 교수의 시스템 관리자 자격을 먼저 회수한다.
그 뒤 platform 마이그레이션 → viz → core-api·프런트 순으로 적용한다. 데이터 초기화는 필요하지 않다.

실제 DEV 계정 전환·배포·원래 NetCDF 자료의 재검증은 실행하지 않았다. 브라우저 검증은 격리된
로컬 GeoTIFF·multipart 경로이며 실제 S3 이어올리기는 포함하지 않는다. 무소속 관리자 생성은
API·컴포넌트 시험으로 확인했다. 타 연구실 행위자의 이름을 볼 수 없는 경우 실제 계정 ID를 표시한다.
미리보기 이슈 #42는 DEV 재검증 전까지 열어 둔다.

## 사용자 게시 절차

`develop` 대상 PR을 게시한다. 이 문서의 제목과 변경·검증·배포 내용을 PR 본문으로 사용할 수 있다.
