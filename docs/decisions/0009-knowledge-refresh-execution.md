# ADR-0009: 변경분 기반 독립 지식 구축 워커

- 상태: proposed
- 날짜: 2026-09-15
- 대체함: 없음
- 대체됨: 없음

## 배경
업로드와 검색은 지연에 민감하고 지식 분석은 외부 호출·재시도·부하 편차가 있다.
기존 search_refresh_worker는 HTTP 앱과 분리된 once/loop/status 진입점을 제공한다.
그러나 성공 후 next_run은 86400초이고, loop의 30초 대기는 새 자료를 30초마다 처리한다는 뜻이 아니다.

## 결정
- 기존 독립 진입점·bounded runner·영속 작업 큐와 lease를 재사용한다. 새 scheduler나 범용 워크플로 엔진은 만들지 않는다.
- 업로드 완료·메타데이터·근거·파일 변경은 소유 도메인의 영속 변경 기록과 결합한다. 신호 유실은 조정 작업으로 복구한다.
- 변경분 큐 처리와 온톨로지 manifest 점검/전체 조정의 시계를 분리한다. 큐가 있으면 일일 주기를 기다리지 않는다.
- 기본 검색은 즉시 사용 가능하며, 의미 보강은 통상 30분 이내를 초기 운영 목표로 둔다. 고정 30분 지연 또는 처리량 보장으로 해석하지 않는다.
- 변경이 없으면 모델 호출 0회. 결정적 매핑은 모델 없이 처리하고 동일 권한 범위의 동일 입력·처리 버전만 재사용한다.
- 삭제·권한 취소는 조회 시 현재 원장으로 즉시 차단한다. 비동기 무효화는 저장소 정리이며 권한 집행을 대신하지 않는다.
- 처음에는 기존 패키지를 별도 프로세스로 실행한다. 함수형 실행 adapter와 별도 인스턴스 배포는 범위 밖이다.

## 검토한 대안
- 업로드 요청에서 동기 분석: 모델 장애가 업로드 장애로 전파되어 제외.
- 매일 전체 재구축: 새 자료 반영 지연과 반복 모델 비용이 크므로 초기 backfill/복구에만 제한.
- 처음부터 Lambda·새 큐 도입: 실행시간·파일 크기·동시성 실측이 없고 기존 실행기와 중복되어 유예.

## 결과와 감수한 비용
새 실행 환경으로 옮길 경계는 확보하지만 클라우드 배포 가능성을 아직 검증한 것은 아니다.
실행 횟수보다 큐 대기시간·처리시간·실패·stale 결과·호출량을 관측해야 한다.
재시도와 중복 제거가 필요하며, 모델 budget 소진 시 기본 검색은 유지하되 의미 보강 지연을 드러낸다.

## 재검토 조건
허용된 동시성에서 큐 대기가 목표를 초과하거나 파일 처리 자원·실행시간이 현 워커에 맞지 않으면 실행 환경 분리를 평가한다.
모델별 비용 상한과 실측 처리량이 확보된 배포 검토에서만 주기·동시성을 조정한다.
