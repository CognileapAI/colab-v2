# ADR-0008: 온톨로지·자료별 지식·검색 조회 모델의 소유권 분리

- 상태: proposed
- 날짜: 2026-09-15
- 대체함: 없음
- 대체됨: 없음

## 배경
지속 업로드에 따라 자료별 지식은 늘지만 기존 개념 정의는 매번 바뀌지 않는다.
DOMAINS의 D9는 개념뿐 아니라 실제 데이터셋 엔티티 그래프를 소유한다.
현재 카탈로그의 검색 근거·개념 annotation을 D9 정본으로 부르면 소유권이 뒤집힌다.
기존 D4 계보는 사람이 확정한 관계의 정본이며 AI가 자동으로 수정할 수 없다.

## 결정
- D3는 자료·파일 버전·확인된 메타데이터의 정본, D4는 확정 계보의 정본으로 유지한다.
- D9 안에서 개념 정의와 자료 엔티티의 근거 있는 연결을 구분한다. 새 도메인 번호는 만들지 않는다.
- D3 검색 근거와 annotation은 출처를 보존한 검색 조회 모델이며 D9 개념·연결 정본을 대체하지 않는다.
- 지식 구축은 application 조정 책임이다. D5 추출 결과, D3 자료 snapshot, D4 읽기 Port, D9 조회/반영 계약을 조합하며 상대 테이블에 직접 접근하지 않는다.
- D10은 후보만 제안한다. 확인된 파일 사실과 승인된 매핑 규칙의 결정적 연결만 자동 반영한다. 문구 일치와 모델 확신만으로 과학적 의미를 확정하지 않는다.
- 새로운 개념·불확실한 연결은 별도 제안 상태로 보관한다. Ted 또는 명시 지정된 승인자가 출처·정본 근거를 확인한다. 계보 자동 확정이나 일괄 승인 API는 추가하지 않는다.
- D9 반영 계약은 신뢰된 조정자와 별도 권한으로 제한한다. D10 모델 도구에 지식 확정 권한을 주지 않는다.
- 자료별 KG 및 제안은 연구실·출처 접근 범위를 유지한다. 공용 개념 승격 시 비공개 인용문·자료 식별자는 복사하지 않는다.

## 검토한 대안
- D3에 모든 지식을 저장: 기존 구현 활용은 쉽지만 D9 소유권과 충돌하고 검색 전용 모델이 지식 정본이 된다.
- D9로 자료·파일·계보 원장을 이동: 원본의 권한·수명주기가 이중화된다. ID와 버전 있는 참조만 둔다.
- 새 KG 서비스·그래프 DB부터 도입: 현재 필요한 저장·조회 패턴의 한계를 측정하기 전에 운영 비용이 생긴다. 기존 AI DB와 Port를 우선한다.

## 결과와 감수한 비용
독립적인 온톨로지 발전과 재구축 가능한 검색 모델을 얻지만, D9 반영 후 검색 반영까지 일시 지연이 생긴다.
도메인 간 분산 트랜잭션 대신 버전 확인·중복 방지·재시도로 수렴해야 한다.
새 반영 계약과 자료 엔티티 저장은 기존 조회 중심 경계를 확장한다. 계약 동결·보안 검토 전 구현하지 않는다.

## 재검토 조건
기존 저장소가 검증된 질의·처리량을 감당하지 못하거나 도메인 승인권·공유 범위가 변경될 때 재검토한다.
자료 소유권 변경은 이 ADR만 수정하지 않고 DOMAINS 및 관련 계약을 함께 대조한다.

## 로컬 구현 구체화 — 2026-09-15
- 사용자 "그럼 이제 해" 이후 내부 source authority와 D9 replace 저장을 구현했다. 전체 인증·수명주기 완료가 아니며 단계별 실측은 실행 계획을 따른다.
- 자료별 지식은 기존 AI DB의 별도 `knowledge` schema에 둔다. public D9 사전에 일괄 적용되는 guardian/조회 ACL이 비공개 자료로 확장되는 것을 피한다. 새 DB 제품이나 도메인은 도입하지 않는다.
- D9 writer는 공용 사전 5표의 SELECT로 실제 현재 manifest를 확인한다. core 복제본만으로 release 최신성을 판정하지 않는다. 공용 사전 쓰기와 D10의 KG 쓰기 권한은 주지 않는다.
- D3 authority callback은 기존 core listener에 둘 수 있지만 D9 writer는 별도 entrypoint/설정으로 조립한다. 이는 코드 경계이며 별도 인스턴스 배포를 실행한 것이 아니다.
- 파일 측정은 D5 immutable receipt와 등록 시 최종 bytes를 확인하고 D3에 bounded snapshot을 결합한다. 정상 viewer가 업로더일 필요는 없으므로 이후 D3 현재 권한/revision으로 조회한다. D5 RLS는 lab-only이며 업로더 제한은 Port/app 계층이다. 별도 DB credential 격리로 주장하지 않는다.
- 관계 변경 증분은 D4 retained dataset incident-set revision과 D3 source별 처리 cursor로 구현·검증했다. 중간 사건 전부가 아닌 최신 상태 수렴이 목적이므로 별도 outbox를 만들지 않는다. 관계 ID/확정 시각은 원장에 남기고 softdelete도 기존 계보를 보존한다. 이 결정은 mappings=[] 단계에서 파생 관계 정리 완료를 뜻하지 않는다.
